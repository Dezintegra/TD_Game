# Работа над TD Game

Общие технические правила проекта находятся в [CLAUDE.md](CLAUDE.md).
Перед изменениями прочитайте его целиком, порциями при необходимости:
Git и рабочие деревья, OpenSpec, CI, архитектура, конвейер и проверки.
Имя файла историческое: эти правила действуют и для Claude, и для Codex.
Не копируйте весь файл сюда: он превышает стандартный лимит автоматически
загружаемых инструкций Codex.

## Различия инструментов

- Дополнительное рабочее дерево определяется через `git worktree list`
  и файл `.git`, а не по наличию `.claude` в пути. Запрет записи в `main`
  из дополнительного дерева распространяется и на деревья Codex.
- Для новых задач Codex предпочитайте управляемый приложением режим Worktree.
  Уже назначенное задаче дерево используйте повторно, не создавайте вложенное.
  Корень деревьев Codex — `$CODEX_HOME/worktrees`; если `CODEX_HOME` не задан,
  используйте `$HOME/.codex/worktrees`. Пользовательский Worktree root из
  Settings → Worktrees имеет приоритет, если он явно известен.
- Ручные деревья Codex создавайте через `git worktree add` в подкаталоге
  `manual/<проект>-<задача>` того же корня. Не создавайте их рядом с основным
  репозиторием или в `.claude/worktrees`. Это правило расположения для Codex
  уточняет общий пример из CLAUDE.md; назначенные супервизором деревья
  не переносите и не пересоздавайте.
  Ручные ветки Codex называйте `codex/<имя>`. Служебные ветки конвейера
  остаются `worktree-<id>`; не переименовывайте их.
- Автоуборка приложения относится к управляемым деревьям, связанным с задачами;
  расположение ручного дерева в папке Codex не включает её автоматически.
  Ручные деревья убирайте через `git worktree remove` после доказанного вливания
  и проверки отсутствия чужих изменений. Не обещайте, что путь отменяет
  проверку политики удаления. Управляемые деревья оставляйте штатной уборке
  приложения; архивирование задачи и настройки хранения управляют их сроком жизни.
- Согласие на отдельное дерево, уже данное в разговоре, действует на всю
  доработку. В автономном этапе дерево уже назначено супервизором.
- Шесть OpenSpec-навыков Codex находятся в `.agents/skills`; Claude —
  в `.claude/skills`. Артефакты у них общие, в `openspec/`.
- Названия средств Claude в старых документах не означают, что они
  доступны в Codex. Используйте его средства чтения, правки и команд.
  Если действительно не хватает данных — уточните у пользователя.
- Полный `pnpm verify` в дополнительном дереве не запускайте: только
  узкие проверки изменённых файлов, остальное — CI того же PR и коммита.
- Не перехватывайте карточки и деревья работающего супервизора.

Для запуска обоих исполнителей и игры из PowerShell читайте
[docs/agent-setup.md](docs/agent-setup.md).
