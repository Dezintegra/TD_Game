# Арена

Инструмент разработки: безголовые матчи, запись игры и разбор поведения
противника под управлением компьютера. Частью игры не является
и в поставку не входит.

## Зачем

Поведение противника до сих пор оценивалось глазами: «топчется»,
«не наступает», «вроде стало лучше». Наблюдения верные, но измерить их
было нечем, воспроизвести — тоже, а причину не видно вовсе: мир
показывает, что случилось, и не показывает, чего противник **хотел**.

Арена этим и занимается. Ядро и противник детерминированы, поэтому матч
восстанавливается из seed и команд, а решения — прогоном заново.

## Как пользоваться

Сначала сборка (арена запускается из `dist`, не из исходников):

```bash
pnpm --filter @td/arena build
```

Прогнать двадцать матчей компьютер-против-компьютера:

```bash
node --no-warnings apps/arena/dist/main.js run --matches 20 --seed 1000
```

Полный матч до предела в двадцать игровых минут считается около восьми
секунд на ядро; двадцать матчей на восьми ядрах — порядка полуминуты.

Собрать базу и посмотреть сводку:

```bash
node --no-warnings apps/arena/dist/main.js ingest
```

```bash
node --no-warnings apps/arena/dist/main.js report
```

Сводка по одному матчу — с его идентификатором:

```bash
node --no-warnings apps/arena/dist/main.js report s1000-baseline-2026-08-vs-baseline-2026-08
```

Сравнить две настройки напрямую — разными профилями у сторон:

```bash
node --no-warnings apps/arena/dist/main.js run --matches 20 --profiles baseline-2026-08,wall-light-2026-08
```

## Матч человека

Пока идёт `pnpm dev`, клиент пишет **тонкую** запись своих матчей —
seed, профили и команды человека с номерами тиков, порядка пятидесяти
килобайт на матч. Она ложится в `.matchlog/human-<seed>.jsonl`.

Подробности из неё достаются воспроизведением:

```bash
node --no-warnings apps/arena/dist/main.js replay .matchlog/human-s1337.jsonl
```

Воспроизведение сверяет контрольные суммы и при расхождении
останавливается с указанием тика. Расхождение почти всегда означает одно:
код изменился с момента записи. Разбирать матч, которого не было, нельзя,
поэтому подробный лог в этом случае не создаётся.

Воспроизведение кончается там же, где кончилась запись. Продолжать
дальше технически можно — противник доиграет сам, — но это было бы
«что было бы, если бы человек бросил играть», выданное за запись матча.

## Где что лежит

Всё в `.matchlog/` в корне репозитория, под `.gitignore`:

| | |
|---|---|
| `s<seed>-<профили>.jsonl` | подробный лог матча арены |
| `human-<seed>.jsonl` | тонкая запись матча человека |
| `<...>-replay.jsonl` | подробный лог воспроизведения |
| `arena.sqlite` | база для запросов |

## Запросы

Сводка отвечает на частые вопросы; на остальные отвечает SQL. Схема —
в `src/schema.ts`, шесть таблиц. Две из них стоит знать в лицо:

- **`attempt`** — попытки потратить энергию. Здесь живёт «чего
  не произошло»: `result` говорит, чем кончилось (купил, копит, махнул
  рукой), `note` — что помешало (нет денег, нет места, очередь полна).
  В мире ни один из этих случаев следа не оставляет;
- **`frontier`** — оценки **всех** рубежей каждого решения, а не только
  выбранного. Если победивший рубеж обошёл соседний на два процента,
  это дрожь, а не решение, и увидеть это можно только имея обе оценки.

Пример: на что противник копит и как долго.

```bash
sqlite3 .matchlog/arena.sqlite "select note, result, count(*) from attempt group by note, result order by 3 desc"
```

## Чего арена не делает

Не оценивает, стал ли противник лучше. Она считает величины: долю
выигранных матчей, самую дальнюю достигнутую долю пути, распределение
причин несостоявшихся покупок, отрыв выбранного рубежа от следующего.
Вывод из этих величин — работа человека.

Различие не педантичное. Инструмент, который сам решает, что хорошо
и что плохо, незаметно начинает измерять то, что подтверждает его
представление о хорошем.
