# Ночная проверка чувствительности тестов

Workflow «Чувствительность проверок» запускается ежедневно в 02:30 UTC и вручную через Actions → Run workflow. Реальный прогон не входит в CI каждого PR. В ручном запуске выберите нужную ветку: вне main это диагностика с артефактами без записи Issue; на main пережившие проверки публикуются и при ручном запуске.

Каталог `scripts/mutation/catalog.mjs` содержит три пары существующих проверок: здоровье базы под обстрелом, различимость стадий возведения башни и уменьшение энергии при покупке стены. Они проверяют чувствительность только к указанным крайним множителям. Это не полное покрытие правил, не оценка баланса и не доказательство качества каждого теста.

| Исход     | Значение                                                                          | Код общего прогона              |
| --------- | --------------------------------------------------------------------------------- | ------------------------------- |
| detected  | Нейтральный тест прошёл, под подтверждённой порчей упало утверждение в его теле   | 0, если все пары detected       |
| survived  | Тот же тест под порчей остался зелёным                                            | 1                               |
| uncovered | Валидная мутация не имеет ни одной пары; не запускалась                           | Сам по себе не меняет код       |
| error     | Ошибка каталога, контроля, настройки, импорта, hook, пропуск, авария или тайм-аут | 2; имеет приоритет над survived |

Пустой список пар — ошибка. Потерянный файл или переименованный тест — тоже ошибка, а не uncovered. Две пары к одной мутации оцениваются отдельно. Ожидаемая краснота теста считается detected только после успешного нейтрального контроля, подтверждения применения tuning, изменения производной величины и выполнения тела теста. AssertionError в hook не засчитывается.

Каждая фаза работает в свежем процессе с одним Vitest worker-потоком; предельный срок процесса — десять минут. На Windows завершение процесса завершает и worker-потоки, на Linux снимается его группа процессов. Настройка сбрасывается после теста, но изоляция не зависит от успеха этого сброса. Исходники, игровые процессы и golden-эталоны не изменяются.

## Результаты и уведомления

В `.matchlog/mutation/<run-id>/` сохраняются `summary.json`, `summary.md`, а также отдельные каталоги baseline/mutant с дескриптором, свидетельством setup, отчётом reporter и stdout/stderr. Сводка содержит SHA, полное имя теста и Actions URL. GitHub хранит артефакты 30 дней, включая красные прогоны; отсутствие сводки делает шаг явно красным.

На main модуль публикации создаёт или обновляет открытый Issue с маркером `td-mutation-canaries`. В нём перечислены все survived с настройками, именами и результатами фаз, ошибки исполнения вынесены отдельно. Автоматического закрытия Issue нет. Ошибка API делает workflow красным; артефакты сохраняются. Вне main сохраняются те же результаты и красный статус survived, но Issue не записывается.

## Добавление пары

1. Добавьте мутацию с уникальным `id`, описанием и положительным конечным множителем существующего RuleTuning. Единица не является порчей; ноль недопустим.
2. В `pairs` укажите `mutationId`, путь файла от корня репозитория, `fullName` массивом точных имён describe/it, `rationale` с ожидаемым нарушением и `probe` — одну производную величину из ключей RuleTuning.
3. Убедитесь, что тест в нейтральном контроле проходит, а выбранный множитель действительно меняет производную величину. Относительные утверждения могут законно пережить изменение: не удаляйте такую пару молча и не ослабляйте утверждение ради зелени.
4. Запустите отдельную приёмку и изучите JSON. При расширении каталога обновите ожидаемое число пар в acceptance-тесте.

Короткие проверки оснастки:

```powershell
npx vitest run --root scripts mutation/model.test.mjs mutation/execute.test.mjs mutation/run.test.mjs mutation/issue.test.mjs mutation/workflow.test.mjs
```

Реальная приёмка всех трёх пар, два прохода подряд:

```powershell
npx vitest run --root scripts --config mutation/acceptance.config.ts
```

Один обычный локальный прогон с сохранением отчёта:

```powershell
node scripts/mutation/run.mjs
```

Acceptance-файл намеренно называется `run.acceptance.mjs`, без суффикса `.test.mjs`. Его конфиг не подключается к workspace, package.json, Turbo или PR workflow. Импорт runner ничего не запускает. Сторож проверяет эту границу без исполнения реальных игровых пар.
