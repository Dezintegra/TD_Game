# Claude и Codex

## Обычная работа

Откройте репозиторий или отдельное рабочее дерево в Claude Code либо Codex.
Общие правила находятся в `CLAUDE.md`; `AGENTS.md` направляет Codex к ним
и поясняет различия инструментов. История разговоров между приложениями
не переносится: передавайте имя изменения OpenSpec, ветку и номер PR.

В Codex доступны проектные навыки:

- `$openspec-propose` — подготовить изменение;
- `$openspec-explore` — исследовать вопрос;
- `$openspec-apply-change` — реализовать задачи;
- `$openspec-update-change` — обновить план;
- `$openspec-sync-specs` — синхронизировать требования;
- `$openspec-archive-change` — архивировать изменение.

Claude сохраняет свои `/opsx:*` и навыки из `.claude/skills`. Оба работают
с одним каталогом `openspec/`. Навыки Codex лежат в `.agents/skills` и не
требуют глобальных prompts. Если навык не появился, откройте новую сессию.
При обновлении OpenSpec проверяйте diff: проектные дополнения не должны
потеряться при повторной генерации.

## Рабочее дерево и игра в PowerShell

После согласования дерева с пользователем и сверки основной ветки:

```powershell
git worktree add .claude/worktrees/my-change -b codex/my-change origin/main
Set-Location .claude/worktrees/my-change
pnpm install --frozen-lockfile
$env:CLIENT_PORT = '5199'
$env:PORT = '3055'
$env:VITE_API_URL = 'http://127.0.0.1:3055'
$env:VITE_WS_URL = 'ws://127.0.0.1:3055/game'
$env:COMPUTER_SECRET = 'local-development'
pnpm dev
```

Пример портов выбирайте свободным для этого дерева. Клиент открывается
на `http://127.0.0.1:5199`. Не копируйте производственные секреты в дерево.
Настройки `.claude/launch.json` принадлежат Claude; запуск выше работает
из терминала обоих приложений.

## Автономный супервизор

Запускайте из основного дерева после вливания изменения:

```powershell
pnpm supervisor --provider=claude
pnpm supervisor --provider=codex
```

Это альтернативные команды, не два одновременных процесса. `--provider`
передаётся в форме `--provider=codex`. Не вставляйте отдельный `--`: пускатель
намеренно отвергает неизвестные доводы, чтобы не запустить конвейер случайно.
Прямая форма: `node supervisor/bin/launch.mjs --provider=codex`.

Поле `provider` можно сохранить в `supervisor/pipeline.config.json`;
ключ запуска имеет приоритет. Без поля и ключа остаётся Claude.
`--shadow`, `--detached`, `--quiet`, `--stop` сохраняют прежнее значение.
У обоих исполнителей один замок `.pipeline/supervisor.lock`, одна доска
и один реестр. Для смены исполнителя завершите текущий процесс через Ctrl+C
и дождитесь его выхода. Новый запуск не останавливает уже работающий.

Память каждой сессии помечена провайдером. Старые записи считаются Claude.
После смены провайдера прерванная задача получает новую сессию с прежним
назначением и журналом; чужой идентификатор не передаётся в resume.

## Настройка Codex

Нужен доступный Codex CLI и его собственная авторизация (`codex login`).
Проверка приложения: `node supervisor/bin/codex-runner.mjs codex --version`.
На Windows обёртка поддерживает npm-установку и `codex.exe`; нестандартный
путь задаётся в `codexCommand` до исполняемого файла либо `bin/codex.js`.
Секреты доски по-прежнему читает супервизор из своей среды.

- `codexModel` — явно выбранная модель Codex. `stageModel` относится к Claude.
- `codexWindowsSandbox` — Windows sandbox: `elevated` по умолчанию.
  `unelevated` можно выбрать явно, если он разрешён политикой станции;
  автоматического переключения и отключения sandbox нет.
- `codexMaxTaskTokens` — бюджет тяжести задачи Codex, по умолчанию **25 000 000** токенов; положительное целое число, `null` отключает проверку.
- `maxTaskCostUsd` — денежный предел Claude, по умолчанию 25; на Codex не влияет.

Считается сумма входных и выходных токенов всех сессий задачи. Кэшированные
входные уже входят в input_tokens и второй раз не прибавляются. Это объём
обработки контекста, включая повторное чтение, а не размер уникального кода.
По 30 последним логам Claude на 05.09.2026 прежнему порогу $25 соответствовало
примерно 24,8 млн токенов; 25 млн — округлённая начальная эвристика. Это не
пересчёт тарифов Codex и не квота подписки ChatGPT.

На границе этапов достижение бюджета отправляет задачу в decompose для
повторного анализа и дробления. Сам анализ и сквозные состояния восстановления
освобождены от проверки. Лимиты времени и продолжений сохраняются: CLI
сообщает usage в конце хода, поэтому немедленного прерывания по токенам нет.

Счётчик хранится в `.pipeline/codex-usage.json` основного дерева отдельно
от отчётов. Он учитывает сообщённый расход даже при неудачном выходе процесса
или неверном отчёте, сохраняется при перезапуске, смене этапа и провайдера.
Для resume берётся максимум накопительного расхода сессии, поэтому повторная
обработка события не удваивает сумму. Новые сессии прибавляются. Удаление
истории сессии не сбрасывает счётчик. При переносе супервизора на другую машину
перенесите и этот файл: счётчик локальный, в карточку доски он не записывается.

Без usage расход неизвестен; при включённом бюджете такой ответ не принимается
как успешный. Токены прерванного до выдачи usage хода оценить нельзя. Повреждённый
файл счётчика останавливает запуск, чтобы не обнулить бюджет незаметно.

На Windows адаптер явно включает sandbox и именованный профиль td-pipeline,
наследующий :workspace. Для коммитов профиль разрешает запись в общую .git
проекта и Git-каталог назначенного рабочего дерева. Обычный workspace-write
защищает эти каталоги от записи даже при дополнительных writable_roots.
Доверие Git safe.directory передаётся через окружение только для основного
и назначенного дерева, без глобального изменения Git и wildcard.
На остальных системах сохраняется workspace-write. Сеть включена,
approval_policy=never. Правила администратора продолжают действовать.

Личный config.toml не подмешивается (--ignore-user-config), поэтому Windows
sandbox задаётся адаптером явно; авторизация CLI сохраняется. Список разрешений
Claude не управляет командами Codex. Подробности штатных профилей:
[Permissions](https://learn.chatgpt.com/docs/permissions) и
[Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox).

Перед первым рабочим оборотом супервизор проверяет реальное выполнение
читающей Git-команды через Codex. Одного ответа модели недостаточно: нужны
успешное событие команды, ожидаемый вывод и успешное завершение процесса.
Проба идёт из пустого временного каталога через git -C к проекту,
чтобы не готовить всё основное дерево как writable-root. Она ограничена двумя минутами; при отказе конвейер завершится до выдачи
задач. Диагностика — .pipeline/codex-readiness.log. На ручной паузе и в теневом
режиме проба не выполняется. Она не проверяет SSH, GitHub и сервер выкладки.

Если уже идущий этап получает declined, отказ попадает в журнал и создаётся
.pipeline/pause. Новые этапы не выдаются, текущие могут закончить отчёт.
Перезапуск паузу не снимает: сначала разберите причину, затем снимите её вручную.
Не отключайте sandbox для исправления отказа. Проверяйте точный путь и сообщение.

## Проверки адаптера

05.09.2026 на Windows проверены:

- CLI через обёртку: `codex-cli 0.146.0` (npm) и `0.153.4` (exe);
- настоящий ответ модели без инструментов: thread.started, agent_message,
  turn.completed с usage; разбор соответствует этим событиям;
- реальное продолжение сессии через resume с сохранением thread_id;
- usage после resume накопительный: из него вычитается сохранённый итог
  предыдущего захода, чтобы не учесть его дважды;
- узкие тесты запуска, завершения, токенового бюджета и разделения сессий.

После исправления 05.09.2026 проверен реальный связанный Git worktree:
Codex создал evidence.txt, выполнил git add и git commit (801b2c4),
завершил с кодом 0; независимая проверка показала новый коммит и чистое дерево.
Это отдельный тестовый репозиторий, без push и выкладки.

(код 0). Доступ к конкретному серверу и SSH проверяется соответствующим этапом.
