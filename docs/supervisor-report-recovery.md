# Неприменённый отчёт и самообновление

Отчёт — итоговый JSON завершившегося этапа. До переноса на доску он находится
в памяти супервизора. Новая версия кода на диске не меняет уже работающий
процесс: тот дожидается завершения этапов и переноса отчётов, затем перезапускается.

## Сбой 8 сентября 2026

Старый процесс 29368 отвергал отчёт `0027-arena-hides-the-nuke-that-never-fired:triage`,
объявлявший ожидание `0030-razobrat-pochemu-yadernyy-udar-pochti-pe` в `failed`.
Сообщение «предшественник остановлен без результата» не означало `closed`:
старый обработчик употреблял его и для `failed`. Приёмка такого ожидания
уже была исправлена в main (PR 210), но непустая очередь мешала загрузить исправление.

Для восстановления под собственной паузой были сохранены исходный лог,
полный JSON и снимок доски в `.pipeline/report-recovery-20260908/` основного дерева.
После тихого оборота с нулём этапов отчёт применён обновлённым `transferBlocked`:
без создания новых карточек, изменения 0030 и запуска повторной сессии.
Полный отчёт доставлен в журнал 0027, карточка переведена в `blocked`.

Повтор старого обработчика обнаружил второй дефект: DELETE уже снятого
назначения возвращал `member is not on the card`. Для однократного завершения
старого обработчика под паузой восстановлено только собственное назначение
на 0027; сам супервизор затем штатно снял его и освободил очередь.
Это восстановление конкретного старого процесса, не регулярная процедура.

Проверено по `.pipeline/cycle.log`:

- 09:07:41 UTC: новый процесс 24268;
- 09:09:20 UTC: запущен новый этап 0037:triage;

## Защита от повторения

Ошибки содержания при проверке зависимостей, категорий и передачи частей
помечаются явно. Полный отвергнутый JSON сначала доставляется в журнал,
затем исходная задача направляется в `postmortem`, а отвергнутый `postmortem`
— в `failed`. Смена этапа, уже произошедшая независимо, не откатывается.
Расход учитывается один раз. Очередь освобождается только после подтверждённой
записи, поэтому сбой Trello не превращается в потерянный отчёт.

Журнал доставляется частями с ключом повтора; длинные строки JSON склеиваются
без добавления переводов строк внутрь значений. Полный ответ не хранится
в описании карточки, где действует собственный лимит текста. Короткая запись
перехода использует существующий конверт доставки. После частичной записи
перенос завершает конверт даже в режиме ожидания самообновления.

При ошибке снятия назначения свежий GET проверяет собственный идентификатор
участника. Подтверждённое отсутствие означает успешное освобождение.
Невозможность прочитать карточку и сохраняющееся назначение остаются ошибкой.

Сообщение ожидания самообновления перечисляет `taskId:stage` отчётов.
«Ожидает завершения текущей работы» заменяет двусмысленное «сливает работу».

## Следующий уровень надёжности

Отдельная задача 0233 (`persist-unapplied-stage-reports`) остаётся нужной.
Предлагаемое решение — дисковая очередь с атомарной записью отчёта до признания
этапа завершённым, идентификатором доставки и восстановлением при старте.
Удаление записи допускается только после подтверждения применения или
сохранённого отказа. Тогда обновление сможет переживать временную недоступность
доски, а аварийное завершение процесса не потеряет ещё не перенесённый ответ.

Дополнительно нужен тест всего жизненного цикла: отчёт → частичная доставка →
перезапуск → повтор → единственный переход и единственный расход. В диагностике
стоит показывать возраст очереди, последнюю причину отказа и время следующей
попытки. Это расширение не следует подменять удалением отчётов по таймеру.
