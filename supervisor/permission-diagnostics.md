# Диагностика применения разрешений

Этот протокол уточняет способ получения свидетельств, а не права исполнителя.
Статический matcher, файл настроек и аргумент settings не доказывают применение
запрета. Живые вызовы делает только доступный native-инструмент проверяемой
сессии. Классификатор не запускает программы и не моделирует движок разрешений.

## Допуск технического уточнения

Технически неполный план можно уточнить только внутри подтверждённой карточки:
требования, приёмка, безопасность и внешние предусловия остаются неизменными.
До новых опытов записать в собственные design/tasks факт и свидетельство пробела,
гипотезу, допустимые действия и пути, лимит и критерий остановки; сохранить
отдельным коммитом и немедленно отправить. Исходную незавершённую проверку
оставить открытой. Новый коммит или PR сами по себе не дают done.

Явный запрет плана нельзя отменить техническим уточнением. Изменение требований
требует самостоятельного согласования и аудита. Чужие артефакты разрешено менять
только по прямому назначению; общее исключение этого права не даёт.

## Опись источников

Сначала прочитать help/version установленного CLI и код формирования запуска.
Не угадывать доступные ключи, порядок источников и имена инструментов.
Записать cwd, provider, версию, permission mode, Git SHA, идентификатор захода,
разрешённые имена ключей запуска, путь и SHA-256 репозиторного permission-снимка.

Для каждой роли stage-settings / project / local / user / managed / CLI override
записать наличие, known/unknown, применимость к инструменту и доступное
подтверждение загрузки. В пути заменить пользовательский префикс на `<user>`.
Непроверенный источник не считать отсутствующим. Ошибка доступа означает unknown.

Не публиковать содержимое или хеш личных/managed настроек, значения env, auth,
токены, MCP-конфиг и полный argv процесса. Новых разрешений на чтение личных
файлов этот протокол не требует. Для репозиторного снимка допустимы относящиеся
к опыту permissions и их SHA. Для личных источников — только безопасные метаданные.

События отбирать белым списком: session/tool id, tool_use_id, команда стенда,
тип результата, очищенный относящийся к нему текст и код программы.
Не сохранять сырой поток в коммит с намерением очистить его позже.
Противоречивые, потерянные и несвязанные события остаются unknown.

## Независимый контроль

Использовать изолированный локальный стенд исходного плана. Проверить абсолютный
путь `<проба>` и одинаковый quoting. Безвредные команды чтения:

```powershell
git -C <проба> rev-parse --show-prefix
git -C <проба> rev-parse --is-inside-work-tree
```

Baseline-сессия получает неизменённый полный снимок исходных правил и выполняет
обе команды по одному разу. Additive-сессия получает копию того же снимка
с единственным добавлением: точный deny первой команды для соответствующего
native-инструмента, без wildcard и хвоста `:*`. Исходные allow/deny сохраняются.
Контроль должен получить policy-denied, соседняя команда — program-result
с кодом 0. Оба чтения безопасны даже при неприменённом запрете.

Добавочный deny действует только в изолированной сессии; stage-settings и другие
сессии не перенастраиваются. Свидетельство отказа политики связывается с вызовом
через tool_use_id. Рассказ модели, отказ запуска CLI, тайм-аут, ошибка Git
и Everything up-to-date не заменяют policy-denied. Не повторять отклонённый вызов
через child_process, другую оболочку или инструмент. Отсутствующий инструмент
не эмулируется. Не менять provider, режим или глобальную конфигурацию,
не отключать проверки и не использовать bypassPermissions.

Сопоставимость доказывается единственным добавлением deny и неизменностью
остальных источников, версии, режима, cwd и инструмента. Различные digest
baseline/additive ожидаемы, разные session обязательны. Успех произвольного
минимального canary-файла ничего не доказывает об исходном stage-settings.

## Нормализация и классификация

Одноразовый сборщик импортирует `classifyPermissionEvidence` из
`supervisor/lib/permission-evidence.mjs`. Вход — нормализованные доказательства,
а не утверждения агента. Нормализатор обязан сверить реальные native-события,
их полноту, команду и tool_use_id; неизвестное нельзя заполнять ожидаемым ответом.

- `contexts.baseline` и `contexts.additive`: session, tool, digest соответствующего
  репозиторного снимка. Каждое событие привязано к своему контексту.
- `loading.baseline/additive`: та же привязка, provenance `launch-metadata`,
  status `confirmed`, `not-applied` или `unknown`. Confirmed означает достоверный
  источник запуска; само применение дополнительно подтверждает независимый контроль.
  Not-applied означает достоверно отсутствующий/другой требуемый источник,
  а не неуспешный canary. Неизвестное происхождение — unknown.
- `comparison.onlyAdditiveDeny` и `otherSourcesUnchanged`: true только после
  доказанного сравнения снимков и безопасных метаданных остальных источников.
- `independent.baseline/denied/companion`, `positive`, `negative`: session, tool,
  digest, toolUseId, command, native, complete, kind и exitCode при запуске программы.
  Kind — `program-result`, `policy-denied` или `missing`. Native=true означает
  инструментальное событие, не текст модели. Positive/negative относятся к baseline.
- `nativeToolAvailable` и `complete` устанавливаются только при подтверждении
  доступности и полноты. Противоречия нормализуются как неполнота, не выбирается
  удобное событие из нескольких несовместимых результатов.

| Доказательство                                                                           | settings    | target       | verified |
| ---------------------------------------------------------------------------------------- | ----------- | ------------ | -------- |
| Независимый контроль годен, positive дошёл до программы, negative отвергнут политикой    | applied     | enforced     | true     |
| То же, negative дошёл до программы, включая ошибку Git                                   | applied     | not-enforced | false    |
| Требуемый источник достоверно не передан или передан другой                              | not-applied | unknown      | false    |
| Неизвестный источник, отсутствующий инструмент/companion, тайм-аут, несовпавшая привязка | unknown     | unknown      | false    |
| Применение подтверждено, positive отказан или отсутствует                                | applied     | unknown      | false    |

Verified подтверждает только эту пару событий. Успешное изменение SHA актуальным
lease и сохранение SHA при устаревшем lease проверяются отдельно по приёмке 0078.
Unit-тесты классификатора не являются живым доказательством применения настроек.

## Ограниченная ветвь: оба контроля прошли

Сохранённый опыт используется как исходный факт. Не повторять неизменный
эксперимент: до запуска записать новую гипотезу и конкретную разницу условий.
Лимит — три новые сессии по пять минут: baseline чтения, additive deny,
одна проверка только после доказанного исправления способа загрузки.
Третья сессия не разрешает менять force-deny. Исправление запуска допустимо
лишь внутри одноразового стенда, с причиной и diff, сохраняя режим и все запреты.

В журнале опытов сохранять номер попытки, гипотезу, разницу условий, начало,
длительность, контексты, очищенные события и вывод. На продолжении учитывать
использованные попытки; новая дата или session id не обнуляют лимит.

Оба контроля прошли при applied — исследуемый запрет не сработал, причина
не установлена автоматически. Допустимы чтение точных имён инструментов/команд,
сверка источников, режима и ошибок загрузки. Canary тоже прошёл — unknown,
если нет достоверного доказательства not-applied. Изменение force-deny
не входит в эту ветвь; исходная условная правка при перекрытии lease остаётся
за 0078. Прохождение обоих контролей не подтверждает перекрытия lease.

При исчерпании лимита или отсутствии безопасного следующего действия сохранить
неполный результат и причину: blocked при конкретной внешней предпосылке,
question только при выборе владельца, иначе failed при подтверждённой
невозможности завершения. Применяется действующий routing contract, новых
состояний нет. Done требует фактической приёмки всех задач текущей карточки.

## Продолжение 0078

Доставка guard-permission-diagnostics — предпосылка, не выполнение 0078.
После её вливания исходный исполнитель штатно подтягивает main в сохранённый
implement и согласует хунки протокола, сохраняя PR 227, код и probe-results.
Пункт 1.1 остаётся открытым до исходной приёмки. Повторный запуск поручает
супервизор; новый PR вместо PR 227 и повтор исходной матрицы без новых условий
не нужны. Этот протокол не разрешает править доску.
