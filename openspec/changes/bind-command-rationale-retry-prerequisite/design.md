## Context

Свежая база проработки — 3cccea2; fetch и merge origin/main завершились успешно, merge сообщил Already up to date. `dependencies.mjs` проверяет принадлежность taskId к dependsOn, совпадение links.pr, MERGED, дату и базу. `dependency-evidence.mjs` собирает доказательства; `scan.mjs:389–403` удерживает задачи перед квотами и пределами попыток. Код 0242 в main ещё отсутствует. Его опубликованный design прочитан из origin/worktree-0242-dat-otchetu-etapa-adresnoe-poruchenie-na; это контракт для планирования, не доказательство поставки.

В опубликованном tasks.md 0181 уже есть запрет начинать правку до появления целевых документов через main. Снимок назначения называет 0181 implement, 0175 pr; состояние живых процессов из этих статусов не выводится. Доска не читалась и не изменялась.

## Goals / Non-Goals

Цель — адресно закрепить и проверить одно ранее пропущенное предусловие. Границы — в proposal; новая семантика допуска и прямой доступ исполнителя к доске исключены.

## Decisions

### 1. Поручение применяется только доставленным каналом

В последний отчёт implement после подтверждения поставки 0242 включается следующий фрагмент:

```json
{
  "dependencyUpdates": [{
    "taskId": "0181-ispravit-v-mark-every-command-block-lozh",
    "dependsOn": ["0175-razmetit-komandnye-bloki-supervisor-skil"],
    "dependencyResults": [{
      "taskId": "0175-razmetit-komandnye-bloki-supervisor-skil",
      "kind": "merged-pr",
      "pr": 132
    }],
    "reason": "Задача 0250: повторный implement 0181 требует закрытия 0175 и подтверждённого вливания PR 132 в main; прежние зависимости и метаданные сохранить."
  }]
}
```

Это дополнение, не полная замена массивов. Идентичное условие — no-op с подтверждением; конфликтующий PR — диагностируемый отказ, не перезапись. Занятая карточка не перехватывается. Отсутствие канала или сведений о ревизии принимающего супервизора означает вопрос о доставке в отчёте, без неподдерживаемого поля. Одного MERGED PR 177 недостаточно: обработчик должен работать на активных станциях, включая защиту устаревшего старта. Самостоятельное обновление/перезапуск супервизора запрещено.

Альтернативы: только dependsOn теряет проверку артефакта; только dependencyResults невалидно; related и комментарий не дают машинного удержания; прямой PUT обходит сериализацию. Поэтому используется ровно операция 0242 без доработки её кода.

### 2. Воспроизводимая изолированная проверка

В implement проба импортирует настоящие функции dependencies, сборщика evidence и scan; GitHub runner и состояние подменены, сеть, Trello и spawn не вызываются. Исходник пробы, SHA кода, команды, входы и полный вывод сохраняются в verification.md. Проверять решения сканера и неизменность всего снимка, не только возвращаемый boolean.

Матрица с полными ID из payload:

| Условия | Ожидаемый результат |
| --- | --- |
| 0175 не closed при правильном MERGED PR 132 | Удержание |
| 0175 closed; OPEN либо CLOSED без merge | Удержание |
| PR недоступен, timeout, неверный JSON, пустой ответ | Удержание без failure; следующий снимок перепроверяет |
| Нет/пустая/невалидная mergedAt, другая база, другой number либо links.pr | Удержание |
| 0175 closed и PR 132 MERGED с валидной датой в main | Штатный допуск на следующем снимке |
| Правильный PR, но иная прежняя зависимость не закрыта | Удержание |
| Повторные отрицательные снимки при нулевых, ненулевых и предельных attempts | Нет start/continuation/отказа по лимиту; все счётчики сохранены |
| Живой этап или готовый отчёт 0181 | Не прерывать процесс, не терять отчёт |
| Положительное доказательство, но failed/postmortem или иные ограничения | Не обходить штатное восстановление и ограничения |

Для положительного контроля использовать готовую к запуску модель implement без других блокировок и подтвердить настоящее действие start/continuation. Для отрицательных случаев сохранить ту же модель, меняя одно условие, чтобы посторонний блокировщик не маскировал сломанный допуск. Затем отдельно проверить ограничения recovery, квот и прежних зависимостей.

После поставки 0242 проверить через его настоящий адаптер на поддельном хранилище: дополнение двух полей, сохранность прежних массивов, человеческого текста, неизвестных метаданных, статуса, attempts, recovery/postmortem, returnTo, links; повтор/no-op; busy; конфликт PR; ошибка readback; устаревший старт другой станции после записи. Использовать существующие тесты канала и адресный сценарий 0181 без создания второго механизма.

### 3. Подтверждение записи отделено от передачи

Супервизор применяет dependencyUpdates до перехода источника и независимо перечитывает карточку. Review 0250 принимает свидетельство с адресатом, прежними и новыми зависимостями, сохранностью прочих метаданных и успешным readback. При нехватке свидетельства возвращает вопрос/замечание через отчёт. Исполнитель не пишет на доску и не выдаёт модельный результат за реальное сохранение. Этот контроль следующего этапа не является незакрываемым пунктом ожидания собственного отчёта implement.

### 4. Реализация 0181 остаётся отдельной сессией

После штатного допуска сессия 0181 проверяет `gh pr view 132 --json number,state,mergedAt,baseRefName`, обновляет только своё назначенное дерево отдельными вызовами `git -C <дерево-0181> fetch origin` и `git -C <дерево-0181> merge origin/main`. До правки требуются proposal.md, design.md и tasks.md `mark-every-command-block` в свежей базе либо в её единственной архивной копии. Отсутствие/неоднозначность документов означает не начинать реализацию и вернуть предусмотренный этапом отчёт. Копирование из ветки 0175 не заменяет main. Задача 0250 не исполняет эти команды в чужом дереве.

Геймплей, рассинхрон и реконнект не затронуты. Эталоны sim и PROTOCOL_VERSION не меняются; запреты Math.random, Date.now и дробного состояния мира остаются прежними.

## Risks / Trade-offs

- Канал 0242 ещё не доставлен → подготовить модельные свидетельства, передачу отложить через вопрос о поставке; не делать циклических ожиданий в сессии.
- Реальная 0181 может быть занята → штатный busy канала, без снятия чужого назначения и перехвата.
- Состояние изменится после readback → новый снимок и повторная проверка перед стартом средствами 0242; единовременное свидетельство не даёт вечного допуска.
- Предмет 0175 архивируют → проверять единственную архивную копию после обновления базы, не угадывать путь по дате.

## Migration Plan

Сначала поставка 0242 и сверка её фактического контракта, затем адресный отчёт implement, readback супервизора и приёмка review. До поставки допускается только изолированная проверка. При отказе доставки сохранить отчёт и причину по штатному каналу; уже подтверждённые зависимости не удалять. Архивация человеком после зависимого изменения, с --skip-specs.

## Open Questions

Продуктовых вопросов нет. Операционная готовность 0242 и ревизий активных супервизоров требует подтверждения перед передачей; при его отсутствии implement возвращает question о поставке, а не объявляет работу завершённой.
