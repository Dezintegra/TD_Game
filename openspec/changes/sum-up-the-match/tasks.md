# Задачи

Порядок снизу вверх: сперва накопитель, который проверяется без
интерфейса, затем компонент графика, который проверяется без матча,
и только потом сборка экрана — там уже нечего доказывать, кроме того,
что всё сошлось.

Обратный порядок дал бы экран, рисующий пустоту, и невозможность
отличить «накопитель молчит» от «график не рисует».

Первым идёт шаг 1.1: после него есть что закоммитить, а значит можно
открыть черновой pull request. До открытия PR проверки CI на пуши
в ветку не запускаются вовсе, и все следующие шаги проверялись бы
вслепую.

## 1. Накопитель: ряды

- [ ] 1.1 `apps/client/src/game/summary.ts`: тип итога
      (`MatchSummary` — ряды по сторонам, счётчики, шаг ряда) и создание
      пустого накопителя. Ряд — обычный массив чисел, предел точек
      `SUMMARY_MAX_POINTS = 1024` с обоснованием в комментарии.
      *Проверка:* `npx vitest run apps/client/src/game/summary.test.ts` —
      пустой накопитель отдаёт пустые ряды и нулевые счётчики.
      *После этого шага:* черновой PR открывается
      (`gh pr create --draft`), дальше каждый пуш проверяется CI.

- [ ] 1.2 Снятие точки раз в игровую секунду: `observe(world)` берёт
      точку при `tick % CHECKSUM_INTERVAL_TICKS === 0`, пользуясь
      готовым `sidesOf`. Четыре величины по каждой стороне: юниты,
      постройки кроме базы, прочность базы, казна.
      *Проверка:* тест — прогон синтетического мира на 300 секунд даёт
      ровно 300 точек; величины совпадают с посчитанными по миру
      напрямую; постройка «база» в число построек не попала.

- [ ] 1.3 Прореживание по достижении предела: каждая вторая точка
      отбрасывается, шаг ряда удваивается, первая точка остаётся первой.
      *Проверка:* тест — 3000 секунд дают не больше 1024 точек, шаг
      вырос вдвое дважды, первая точка относится к началу матча.

## 2. Накопитель: потери и удары

- [ ] 2.1 Опознание новой записи о взрыве по равенству
      `expiresAtTick − tick` полной длительности жизни вида.
      *Проверка:* тест на связь с ядром — для каждого вида взрыва
      запись, только что созданная `recordBlast`, опознаётся новой,
      а она же тиком позже — нет. Тест обязан упасть, если `recordBlast`
      начнёт считать срок иначе.

- [ ] 2.2 Счёт потерь по видам (юнит, генерал, постройка) и ядерных
      ударов; удар записывается стороне ударившего, потери — стороне
      погибшего.
      *Проверка:* тест — мир, в котором за один тик погибли юнит, генерал
      и башня разных сторон, даёт три величины порознь у своих сторон;
      ядерный взрыв прибавляет удар владельцу и не прибавляет ему потерь.

- [ ] 2.3 Сброс при пересборке: кадр с номером тика, не большим
      предыдущего, обнуляет накопитель целиком.
      *Проверка:* тест — прогон, повторно поданный с начала, даёт те же
      числа, что и одиночный, а не удвоенные.

- [ ] 2.4 Время первого выстрела: первая секунда, на которой
      в подтверждённом мире непусто `world.shots`.
      *Проверка:* тест — мир без выстрелов отдаёт «выстрелов не было»,
      мир с первым выстрелом на 47-й секунде отдаёт 47.

## 3. Подключение к матчу

- [ ] 3.1 Вызов `observe` из `onFrame` в `bootstrap.ts`, на
      `guest.confirmed`. Накопитель заводится в замыкании `startMatch`,
      поэтому новый матч начинается с пустого.
      *Проверка:* сквозная проверка — матч с компьютером, по исходу
      в накопителе непустые ряды; второй матч подряд начинается
      с пустых.

- [ ] 3.2 Поле `summary` в store и его наполнение **один раз**,
      в `onOutcome`, рядом с `setOutcome`. Величины уезжают в «видимых»
      единицах.
      *Проверка:* тест store — до исхода `summary` равно `null`;
      сквозная проверка — по ходу матча ни одной перерисовки ради
      накопления (счётчик перерисовок в тестовой обёртке).

- [ ] 3.3 Замер цены: `pnpm bench:tick` до и после изменения, числа
      в теле коммита. Прирост сверх шума — повод разбираться, а не
      округлять.
      *Проверка:* два прогона стенда, обе цифры и разность записаны
      в коммит.

## 4. Компонент графика

- [ ] 4.1 Построение точек отдельной чистой функцией: величины
      в координаты, шаг сетки, разрывы на пропусках.
      *Проверка:* `npx vitest run packages/ui/src/chart-points.test.ts` —
      известный ряд даёт известные координаты; пропуск даёт разрыв,
      а не проведённую насквозь линию.

- [ ] 4.2 `packages/ui/src/LineChart.tsx`: две серии, две оси, подписи
      времени в минутах и секундах, цвета и шрифты — токенами
      из `tokens.css`, ни одного литерала.
      *Проверка:* тест — разметка содержит две `polyline`; проверка
      токенов (`tokens.test.ts`) не находит литеральных цветов.

- [ ] 4.3 Отметки событий на оси времени (ядерные удары) с указанием
      стороны.
      *Проверка:* тест — три удара дают три отметки на своих местах
      по времени и своих цветов по стороне.

## 5. Экран итога

- [ ] 5.1 Четыре графика в `ResultOverlay`: войско, постройки, прочность
      базы, казна. Кнопки выхода и перезапуска остаются видны без
      прокрутки.
      *Проверка:* сквозная проверка — после матча видны четыре графика;
      кнопка выхода в области видимости без прокрутки.

- [ ] 5.2 Таблица чисел: длительность, потери по видам, ядерные удары,
      время первого выстрела, наибольшее войско с минутой, доля времени
      в перевесе по войску (доля точек ряда — так и подписано).
      *Проверка:* сквозная проверка — числа на экране совпадают
      с накопителем; подпись доли называет способ подсчёта.

- [ ] 5.3 Матч без рядов: `NoShow`, `Left` до первого тика, остановка
      после неизлечимого расхождения — исход показывается, графиков
      и таблицы нет, сказано, что показывать нечего.
      *Проверка:* сквозная проверка — соперник не подключился, окно
      итога без пустых осей и с объяснением.

- [ ] 5.4 Узкий экран: графики в один столбец, ничего не выходит
      за края, кнопки на виду.
      *Проверка:* сквозная проверка на ширине телефона; снимок экрана
      приложен к PR.

## 6. Свидетельство того, что ничего не сдвинулось

- [ ] 6.1 Убедиться, что эталоны детерминизма и профилей **не менялись**
      этим изменением: `git diff --stat origin/main -- packages/sim`
      пуст.
      *Проверка:* пустой диф по `packages/sim` в PR; матчевый набор
      в CI зелёный.

- [ ] 6.2 Убедиться, что зависимостей не прибавилось: в
      `apps/client/package.json` и `packages/ui/package.json` нет ни
      одной библиотеки графиков.
      *Проверка:* диф `package.json` в PR не содержит новых
      зависимостей; `pnpm-lock.yaml` не тронут.

## Прогон арены

Не нужен, и это решение, а не пропуск. Изменение не трогает ни правил
игры, ни цен, ни дохода, ни силы юнита, ни темпа: в `packages/sim`
не добавляется ни строки. Мерить нечего — исход матчей измениться
не может.

Если по ходу реализации в ядро всё же пришлось что-то тронуть, значит
изменение вышло за собственные границы, и правильный ответ — вернуть
границы, а не заказать прогон.
