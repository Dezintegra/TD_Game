## Границы коммита и проверки

Все команды выполняются в назначенном дереве; `git -C .` означает именно его. Перед работой освежить основу отдельными вызовами `git -C . fetch origin` и `git -C . merge origin/main` по действующим правилам implement.

Рабочие пути пункта 1.1: только `openspec/changes/preserve-shared-field-nuke-warning/verification.md` и отметка его выполнения в `openspec/changes/preserve-shared-field-nuke-warning/tasks.md`. Добавить их явным перечнем через `git -C . add -- openspec/changes/preserve-shared-field-nuke-warning/verification.md openspec/changes/preserve-shared-field-nuke-warning/tasks.md`. Не включать несвязанные правки внутри этих файлов.

До коммита проверить имена через `git -C . diff --cached --name-only` и весь текст через `git -C . diff --cached`; после коммита — `git -C . show --format=fuller --stat HEAD` и `git -C . show --format= --patch HEAD`. Проверить отсутствие изменений кода и основных спецификаций в полном diff PR. После отправки `git -C . log --oneline '@{u}..HEAD'` должен быть пуст.

Если свежая основа выявит содержательное противоречие с принятой дельтой, не менять код или чужое изменение молча: вернуть конкретное замечание по контракту этапа. Синхронизация `openspec/specs/`, архивация, установка зависимостей, тесты игры, арена и замер кадров в этот план не входят.
