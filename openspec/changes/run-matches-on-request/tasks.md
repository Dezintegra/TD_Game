## 6. Приёмка

- [x] 6.1 Состав сверен, и строже, чем планировалось.
  - `git diff HEAD~2 -M -- '*.test.ts'` по всем тринадцати файлам даёт **одну
    изменённую строку**, и та — комментарий со старым именем файла. Логика тестов
    не тронута нигде, поэтому потерять или задвоить проверку было негде.
  - По числам: 1336 + 133 = 1469 против 1463 в линии «до». Разница в шесть
    объясняется коммитом `570e6d1`, прилетевшим в общее дерево во время замера.
- [ ] 6.2 Снять линию «после» на **свободной машине**.
  - Не сделано: всё это время на машине работали девять соседних сессий
    (17–42 процесса node), свободной она не была ни разу. Снятые цифры записаны
    в `README.md` с оговоркой. Переснять обе линии подряд — оставшаяся работа.
- [x] 6.3 Проверки прогнаны по отдельности, а не одной `verify:all`.
  - `pnpm lint` — зелёный, 45 с. `pnpm typecheck` — зелёный, 50 с. `pnpm build` —
    зелёный. `pnpm test` — 1336 тестов, зелёный. `pnpm test:match` — 133 теста,
    13 мин 14 с, **одно падение**.
  - Падение — в `siege.match.test.ts`, тест «состав войска доходит до Теслы →
    осадный профиль заказывает Теслу»: `expected 0 to be greater than 0`.
    Тот же тест падал и в линии «до», снятой на `main`.
  - Непричастность доказана: `git diff 570e6d1 HEAD -M` по исходникам `ai`, `sim`
    и `shared` даёт две строки, обе — комментарии со старыми именами файлов;
    сам `siege` показывает «0 insertions(+), 0 deletions(-)».
  - Причину надо различать зондом, а не гадать: у этого теста два разных сценария
    падения — «окно кончилось» и «профиль не доживает до покупки». Второй пришёл
    вместе с ветеранскими рангами, и удлинение окна от него не помогает. Решение
    относится к балансу, а не к разделению наборов, поэтому здесь не чинится.
