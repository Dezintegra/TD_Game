## Правила фиксации и проверки

Каждый пункт — отдельный самостоятельно проверяемый коммит. На implement перед работой выполнить освежение базы командами `git -C <дерево> fetch origin` и `git -C <дерево> merge origin/main`; `<дерево>` — назначенное рабочее дерево. Конфликты и отправку обрабатывать по контракту implement. Команды запускать отдельными вызовами из назначенного дерева, без составных оболочечных строк.

В индекс каждого шага добавлять явным списком только перечисленные в нём рабочие пути и `openspec/changes/accept-perf-port-flags/tasks.md` с отметкой его выполнения. Проверить имена и содержание через `git -C <дерево> diff --cached --name-only` и `git -C <дерево> diff --cached`, затем состав созданного коммита через `git -C <дерево> show --stat --oneline HEAD` и `git -C <дерево> show --format=fuller HEAD`. Несвязанные изменения внутри разрешённых файлов также недопустимы. Отправка — `git -C <дерево> push`; проверка хвоста — `git -C <дерево> log --oneline '@{u}..HEAD'`.

Команды узких проверок покрываются `PowerShell(npx vitest:*)`, `PowerShell(npx eslint:*)`, `PowerShell(npx prettier:*)`; git — `PowerShell(git -C:*)`, команды инструкции — `PowerShell(pnpm e2e:perf:*)` в `supervisor/config/stage-settings.json`. Расширение разрешений не требуется.

Полный verify, сборка игры, браузерный perf и арена не входят в эти шаги. Форма артефактов проверяется `openspec validate accept-perf-port-flags --strict` и `openspec status --change accept-perf-port-flags`. Проверки CI отслеживает супервизор; их ожидание не является пунктом реализации. `supervisor/skills/deploy.md`, чужие изменения OpenSpec и основные спецификации в эти коммиты не входят.
