Пробовать спорный шаблон средствами текущего Codex недостаточно. На design CLI-диагностика не запускается.

## Goals / Non-Goals

Доставить пригодный для продолжения 0078 протокол, доказательную классификацию и одинаковые границы технического уточнения в implement/revise. Не выполнять исходную проверку и не менять deny. Не вводить новый матчинг, состояния доски, скрытые перезапуски, сборщик личных настроек или новую систему логов.

## Decisions

### 1. Общий протокол и малый классификатор

Общий текст живёт в `supervisor/permission-diagnostics.md`; implement/revise содержат одинаковое правило допуска и ссылку, исходный design 0078 — конкретные команды стенда и ссылку на общий контракт. Классификатор `supervisor/lib/permission-evidence.mjs` — чистая функция по нормализованным свидетельствам, без запуска программ, чтения настроек и собственного matcher. Одноразовая диагностика 0078 импортирует его для итогового решения. Так регрессия проверяется на независимых входах; тесты не притворяются живым доказательством загрузки.

Минимальный вход: привязка к session/tool/config digest, loading evidence (подтверждено / достоверно отсутствует / неизвестно), независимый контроль (baseline program result, additive policy denial и allowed companion), positive и negative (program-result / policy-denied / missing), признак полноты. Недостоверные или противоречивые события дают unknown. Выход: `settings: applied | not-applied | unknown`, `target: enforced | not-enforced | unknown`, `verified: boolean` и причина. verified=true только для applied + полного positive program-result + negative policy-denied. Условия корректности lease и SHA стенда остаются дополнительной приёмкой 0078: verified не закрывает задачу сам.

| Свидетельства | settings | target | verified |
| --- | --- | --- | --- |
| Привязка и независимый контроль годны, positive дошёл до программы, negative отвергнут политикой | applied | enforced | true |
| То же, но negative дошёл до программы | applied | not-enforced | false |
| Достоверно передан другой/не передан требуемый источник | not-applied | unknown | false |
| Есть только файл, аргумент settings, matcher или рассказ модели | unknown | unknown | false |
| Нет события, инструмента, companion либо совпадения контекста | unknown | unknown | false |
| applied подтверждено, но positive отказан или отсутствует | applied | unknown | false |

### 2. Безопасное независимое свидетельство

Для 0078 будущая проверка проходит только внутри локального стенда, указанного исходным планом. Команды чтения для каждого реально доступного native-инструмента: `git -C <проба> rev-parse --show-prefix` (контроль) и `git -C <проба> rev-parse --is-inside-work-tree` (соседняя). `<проба>` заменяется проверенным абсолютным путём с тем же quoting во всех сравниваемых вызовах. Обе команды безвредны даже при неприменении запрета.

Первый новый заход использует неизменённый снимок исходных правил и вызывает обе команды один раз. Второй получает копию того же полного снимка с единственным добавлением в deny: точное правило для контрольной команды соответствующего инструмента, без wildcard и без хвоста `:*`. Исходные allow/deny сохраняются. Этот запрет ужесточает только изолированную диагностику, не записывается в stage-settings и не затрагивает работу других сессий. Контроль вызывается один раз; соседняя команда обязана выполняться. Допускается совпадение allow с добавленным deny: проверяется именно приоритет применённого запрета.

Свидетельство действия — связанный по tool_use_id инструментальный отказ политики второму вызову, при выполнении первого и companion. Общий отказ запуска процесса, промпт «не выполняй», сообщение модели и ненулевой код Git не годятся. Не запускать отклонённую команду через child_process и не подменять native-инструмент другим. Обёртка готовит файлы и запускает конечную сессию, но исследуемые вызовы делает только сессия своим инструментом.

Подтверждение относится к снимку, инструменту и режиму именно этих заходов, не ко всем настройкам машины. Оно переносится на исходный шаблон только при доказанном единственном различии снимков и совпадении остальных источников. Успех canary на произвольном минимальном файле не доказывает применение исходного stage-settings.

### 3. Опись источников без секретов

Сначала читаются установленный CLI help/version и код формирования запуска; поддержка ключей и порядок источников не угадываются. Для каждого источника записать роль (явный stage-settings / project / local / user / managed / CLI override), наличие, статус known/unknown, путь с заменой пользовательского префикса на `<user>`, применимость к выбранному инструменту и подтверждение из доступных метаданных загрузки. Зафиксировать cwd, provider, версию, режим, разрешённые имена ключей запуска, путь и SHA-256 репозиторного permission-снимка, SHA Git и связь с заходом. Содержимое user/managed, env, auth, MCP-конфиг и полный argv процесса не печатать; непроверенные источники не считать отсутствующими.

Для репозиторного снимка допустимы сами относящиеся к опыту permissions и их SHA. Для личных/managed источников — только метаданные наличия/применения, без полного содержимого и его хеша. Из событий публикуется белый список: session/tool id, команда стенда, тип результата, относящийся к нему очищенный текст и код программы. Не складывать полный сырой поток в коммит с надеждой вычистить позже. Невозможность безопасно получить сведения означает unknown; этот проект не требует новых разрешений на чтение личных файлов.

### 4. Оба контроля проходят: ограниченная ветвь

Сохранённый результат 0078 используется как исходный факт; повторять ту же force-матрицу ради подтверждения уже известного нельзя. Новая информация — опись и независимый контроль. До запусков записать гипотезу и разницу условий. На всё уточнение выделено три новые сессии максимум по пять минут: baseline чтения, добавочный deny и одна дополнительная проверка только при доказанном исправлении способа загрузки (например, передавался другой файл). Третья сессия не разрешает менять force-deny. На продолжении учитывать уже использованные попытки по сохранённому журналу опытов; новая дата/идентификатор сессии не является изменением условий.

Если оба исследуемых контроля прошли, а независимое подтверждение годно, вывод — исследуемый запрет не сработал. Дальше допустимо чтение точных инструментальных имён и формы команды, сверка источников/режима и ошибок загрузки. Достоверно отсутствующий источник — not-applied; нет достаточного свидетельства причины — unknown. Canary тоже прошёл — это не доказательство конкретного дефекта шаблона и не основание объявить настройки точно неприменёнными.

Исправление способа запуска допустимо только в одноразовом стенде при сохранении режима и всех запретов, с явной причиной и diff. Недоступен безопасный способ или исчерпан лимит — сохранить результат, вернуть blocked при конкретной внешней предпосылке, question только при выборе владельца, иначе failed с доказанной невозможностью завершения. Не менять provider/глобальную конфигурацию, не выключать проверки, не повторять отказ другим инструментом. Исходная условная правка deny при доказанном перекрытии lease остаётся за 0078 и её приёмкой; прохождение обоих контролей такого разрешения не даёт.

### 5. Технически неполный план

В implement/revise уточнение разрешается только когда это дополнительный способ получить недостающее свидетельство по уже согласованной приёмке, а не отмена явного ограничения. До опытов исполнитель дописывает собственные design/tasks: факт, пробел, гипотезу, действия, предел, исходы остановки и допустимые пути. Сохраняет отдельным коммитом и немедленно отправляет. Исходная незавершённая проверка остаётся открытой. Уточнение само по себе не даёт done и не заменяет независимый аудит нового требования. При внешней предпосылке действует существующий routing contract, без новых статусов.

Оговорить границы рядом с запретами самовольной замены плана и требований в обоих скиллах; не оставлять противоречащие безусловные формулировки. Исключение не позволяет менять чужие артефакты без прямого назначения. Для 0296 назначение прямо заказывает обновление протокола 0078; общего права переписывать чужой план отсюда нет.

### 6. Доставка обновлённого протокола 0078

На implement сначала освежить main. Если каталог уже появился, использовать его и сверить с PR 227. Если отсутствует, получить только `.openspec.yaml`, `proposal.md`, `design.md`, `tasks.md` из `48808202e8168a51c70e16af64fab15631b296d7` через `git -C <дерево> restore --source=48808202e8168a51c70e16af64fab15631b296d7 --worktree -- <точный путь>` отдельным вызовом на каждый файл. Это явно разрешённая подготовка без merge чужой ветки; код, тест 0078 и probe-results не импортируются. Доказательства probe-results читаются через `git -C <дерево> show <SHA>:<путь>` и остаются в PR 227.

В исходном design заменить лимит «исходная настройка и кандидат» явными отдельными границами новой диагностики, вставить классификацию/ссылку и правило остановки. В tasks сохранить открытый 1.1, исходную приёмку lease/force и условие изменения deny, добавить использование классификатора и новых доказательств. Уточнить допустимые пути технических поправок и отбора очищенных результатов. В proposal сохранить первоначальную цель и Non-goals, обосновать отсутствие собственной дельты: новая общая норма вводится этим изменением, а 0078 по-прежнему проверяет прежнее право отправки. Добавить ссылку на зависимость доставки протокола. Не копировать наш узкий заказ вместо исходного предложения.

Для 0296 доставка обновлённых текстов и проверки классификации — завершённый результат; для 0078 это только предпосылка. После вливания 0296 исходный исполнитель штатно подтягивает main в прежнюю ветку и согласует только хунки протокола, сохраняя probe-results, код и PR 227. Повторный запуск/разблокирование поручает супервизор, 0296 доску не правит. При исчезновении/архивации исходной цели или её существенном изменении не выбирать замену молча: остановиться по текущему контракту с доказательством.

### Alternatives

Только regex-тест отвергнут: он повторяет исходное предположение. Проба через Codex не проверяет Claude permissions. Произвольная смена deny не объясняет причину и выходит за предпосылку. Ожидание вливания PR 227 создаёт обратную зависимость. Полный merge его ветки привёз бы незавершённую реализацию. Вторая дельта о праве force-with-lease продублировала бы исходный заказ. Только текстовый сторож не проверяет различение неполных событий, поэтому используется чистый классификатор с отрицательными фикстурами, но без имитации движка разрешений.

## Risks / Trade-offs

- У CLI нет безопасной описи effective settings: честный unknown вместо догадки; протокол всё равно пригоден для остановки без ложного успеха.
- Источники изменились между заходами: свидетельство несопоставимо, verified=false.
- Поведение стороннего CLI меняется: результат ограничивается зафиксированной версией; этот этап не утверждает сегодняшнюю семантику неподтверждённых ключей.
- Интеграция исходных артефактов пересекается с PR 227: только выбранные файлы, проверка полного diff и сохранение открытых задач исходной карточки.

## Migration Plan

Два атомарных шага: чистый классификатор с тестами; затем единая доставка общего протокола, двух скиллов, обновлённых артефактов 0078 и сторожа текста. Первый уже позволяет открыть draft PR. Живые пробы остаются в implement 0078, не являются условием done 0296. Откат — revert собственных коммитов без изменений состояния доски и без отката чужой реализации.

Геймплей, реконнект/рассинхрон, sim и раскладка протокола не затрагиваются; эталоны детерминизма и PROTOCOL_VERSION не меняются. Math.random, Date.now и float в состоянии мира не вводятся.

## Open Questions

Продуктовых вопросов нет. Конкретная причина прохождения force остаётся предметом 0078; наличие безопасных метаданных у установленной версии CLI устанавливается при её диагностике и имеет предусмотренный исход unknown.
