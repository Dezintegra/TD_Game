# Шаги реализации

Каждый шаг — отдельный коммит, отправляемый сразу. Каждый собирается
и проверяется сам по себе: «следующего шага, который всё починит», ни
у одного из них нет.

Порядок шагов 1 и 2 обратен порядку рассказа в `design.md` намеренно:
опознание процесса заводится **до** дескриптора, потому что дескриптор
обязан записать имя образа уже при рождении этапа. Заведи их наоборот —
и в `live.image` попадёт `undefined`, а значит каждый живой сирота будет
судиться протухшим и починка не заработает вовсе.

Проверки идут узкие и местные — по своим файлам, не полным набором
(правило 6 в `CLAUDE.md`):

```
npx vitest run --root supervisor lib/<файл>.test.mjs
npx eslint supervisor/lib/<файл>.mjs
npx prettier --check supervisor/lib/<файл>.mjs
```

Полный набор гоняет CI. Из дополнительного дерева `pnpm verify` не
запускается.

## 1. Опознание процесса: спросить систему об имени образа

- [x] В `supervisor/lib/run-stage.mjs` завести `createProbeProcess(run, platform)`
      по образцу `createKillTree` (`run-stage.mjs:309`): возвращает
      `(pid) => ({ known, alive, image })`.
- [x] Windows: `tasklist /FI "PID eq <pid>" /NH /FO CSV`, имя образа —
      первое поле CSV. Ответ «нет такого процесса» приходит текстом,
      а не кодом возврата: строку, не начинающуюся с кавычки, читать
      как «процесса нет».
- [x] Прочие системы: `ps -p <pid> -o comm=`, ненулевой код возврата —
      «процесса нет».
- [x] Неудача самой команды (нет `tasklist`, вывод не разобрался) даёт
      `known: false` — «спросить не удалось», и это НЕ равно «процесса нет».

**Проверка:** `npx vitest run --root supervisor lib/run-stage.test.mjs` —
тесты на подставном `run`: живой процесс с именем образа; отсутствующий
процесс; неразобравшийся вывод даёт `known: false`. Живых процессов
тесты не поднимают.

**После этого шага открыть черновой pull request** — до него проверки CI
на пуши в ветку не запускаются вовсе:

```
gh pr create --draft --base main --title "Идущий этап переживает смену супервизора" --body-file <файл>
```

## 2. Дескриптор живого этапа ложится на диск и стирается

- [x] `createSupervisor` принимает довод `probe` — тот самый
      `createProbeProcess` из шага 1; `supervisor/bin/supervise.mjs`
      собирает его из `runCommand` и передаёт вместе с
      `machine: hostname()` и `supervisorPid: process.pid`.
- [x] В `supervisor/lib/supervisor.mjs` при удавшемся порождении писать
      в `known[at]` поле
      `live: { pid, image, machine, supervisorPid, startedAt, timeoutMs }`
      и звать `saveStages`. Писать **после** проверки `handle.pid`
      (`supervisor.mjs:189`): у процесса без номера дескриптора быть не должно.
      Отметок времени в дескрипторе вышло две — `startedAt` строкой для
      записи в журнал задачи и `startedMs` числом для счёта срока, — ровно
      как у дескриптора собственного ребёнка.
- [x] **Имя образа спрашивается у системы прямо при рождении** — вызовом
      `probe(handle.pid)` сразу после проверки номера, — и кладётся полем
      `image`. Из настройки `claudeCommand` оно не выводится: почему
      именно так, сказано в `design.md`, Решение 2.
- [x] Опросить не удалось (`known: false`) либо `probe` не передан —
      `live` пишется **без** `image`, причина уходит в `log`. Дескриптор
      без `image` не ломает запись: судьба такого сироты разобрана
      шагами 3 и 4 как «жив, но неопознан».
- [x] В `finish` стирать `live` и звать `saveStages` — при любом исходе,
      включая снятие по сроку и неразобравшийся отчёт.
- [x] `remembered` (`supervisor.mjs:404`) научить переносить `live`,
      сохранив терпимость к записи-строке прежней раскладки.
- [x] Имя станции и номер супервизора приходят доводами `machine`
      и `supervisorPid`, а не читаются из `node:os` внутри: счётная часть
      супервизора уже принимает так же и часы, и порождение.

**Проверка:** `npx vitest run --root supervisor lib/supervisor.test.mjs` —
новые тесты: после `spawnStage` сохранённый снимок несёт `live`, и в нём
названы **и `pid`, и `image`**, причём `probe` позван именно с номером
порождённого процесса; при `known: false` снимок несёт `live` без `image`,
а причина легла в журнал; после завершения процесса `live` в снимке нет;
запись прежней раскладки (голая строка) читается без `live` и без ошибки.

## 3. Сироты при запуске попадают в перечень идущих

- [x] `createSupervisor` при сборке разбирает прочитанные `stages`: каждая
      запись с `live` — сирота. Довод `probe` у него уже есть с шага 2.
- [x] Дескриптор с чужим `machine` не судится: стирается, причина уходит
      в `log`.
- [x] Опознание сироты даёт один из четырёх исходов:
  - процесса с таким номером нет — **исчез**;
  - `alive`, и `image` совпал с `live.image` — **жив и опознан**;
  - `alive`, но `image` с `live.image` не совпал — **протух**: номер
    переиспользован посторонним процессом;
  - `known: false` либо в дескрипторе нет `image` — **жив, но неопознан**.
- [x] `running()` отдаёт живых сирот — и опознанных, и неопознанных —
      наравне с собственными детьми; `busy()` считает их же. Заодно
      `spawnStage` отвечает теснотой на задачу, занятую живым сиротой:
      без этого второй процесс на его дереве завёлся бы прямо здесь.

**Проверка:** `npx vitest run --root supervisor lib/supervisor.test.mjs` —
супервизор собирается поверх `stages` с `live` и подставным `probe`:
сирота, чьё опознание **совпало** с `live.image`, отдаётся в `running()`;
при несовпадении имени образа — не отдаётся; сирота с дескриптором
**без `image`** отдаётся как неопознанный; дескриптор чужой станции стёрт,
причина в журнале.

## 4. Развод сирот по обороту: исчез, протух, пережил срок

- [x] Завести `sweep()` — обход сирот, годный для вызова раз в оборот.
- [x] Сирота исчез либо протух — убрать из перечня, стереть `live`
      **не сразу**, а поставить исход в очередь `orphanOutcomes`
      (см. шаг 5); стирание — по удавшейся записи.
- [x] Сирота жив и опознан, но `nowMs() - live.startedMs >= live.timeoutMs` —
      снять `killTree(pid)` и поставить исход «снят по сроку». Возраст,
      которого сверить нечем, снятия не даёт вовсе: этап уходит из перечня
      с исходом «оставлен работать».
- [x] Сирота жив, но неопознан — **не снимать никогда**. Пока его срок
      не вышел, он числится идущим: место занято, продолжение не выдаётся.
      Срок вышел — убрать из перечня с исходом «срок вышел, опознать
      не удалось, процесс не снят», и `killTree` при этом НЕ зовётся.
      Причина в журнал цикла — один раз на сироту, а не каждый оборот.

**Проверка:** `npx vitest run --root supervisor lib/supervisor.test.mjs` —
пять тестов на подставных `probe`, `killTree` и часах: исчезнувший даёт
исход и уходит из `running()`; переживший срок опознанный снят, и `killTree`
позван с его номером; протухший даёт исход, а `killTree` НЕ позван;
неопознанный в пределах срока остаётся в `running()`; неопознанный
за сроком уходит из `running()` с исходом, и `killTree` НЕ позван.

## 5. Исход сироты доезжает до журнала задачи

- [ ] Супервизор отдаёт наружу `orphanOutcomes` — очередь по образцу
      `reports` (`supervisor.mjs:44`), с методом «забыть исход».
- [ ] `scan.mjs`: новый вид действия `note-orphan` в `ACTIONS` — **перед**
      `continue-stage`; на каждый исход из нового довода состояния
      `orphans` назначается действие, если задача есть в бэклоге.
- [ ] `execute.mjs`: обработчик `note-orphan` пишет журнал через
      `io.amendTask(taskId, text, message, source)` и зовёт «забыть исход»
      только при удавшейся записи. Поля задачи не трогаются.
- [ ] Текст записи называет: этап осиротел при смене супервизора, номер
      прежнего процесса, отметку начала, чем кончился (исчез, протух, снят
      по сроку либо оставлен неопознанным), что отчёт потерян и сделанное
      надо искать в ветке.

**Проверка:**
`npx vitest run --root supervisor lib/scan.test.mjs lib/execute.test.mjs` —
сканер при непустых `orphans` даёт `note-orphan` и ставит его раньше
`continue-stage`; исполнение зовёт `amendTask`, не зовёт `saveTask`,
и при неудачной записи исход из очереди не убирает.

## 6. Сшивание в супервизоре: обход и остановка

- [ ] Звать `supervisor.sweep()` в начале `turn()`, до чтения
      `supervisor.running()` в `state`.
- [ ] Положить `orphans: supervisor.orphanOutcomes` в `state` и метод
      «забыть исход» в `io`.
- [ ] Убедиться, что `stopAll()` сирот не трогает: снимает только
      собственных детей.

**Проверка:** `node --check supervisor/bin/supervise.mjs`;
`npx eslint supervisor/bin/supervise.mjs supervisor/lib/supervisor.mjs supervisor/lib/scan.mjs supervisor/lib/execute.mjs supervisor/lib/run-stage.mjs`;
`node supervisor/bin/cycle.mjs` — печатает решение и завершается, ничего
не делая: мира он не трогает и работы не порождает.

## Прогон арены не требуется

Правил игры, цен, дохода, силы юнита и темпа изменение не задевает:
правок за пределами `supervisor/` и `supervisor/README.md` в нём нет ни
одной. Заявки на задачу-прогон в отчёте нет намеренно — заказывать нечего.
