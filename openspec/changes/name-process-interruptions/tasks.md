## 1. Уточнить диагностику обрыва в обоих обработчиках

- [x] 1.1 Одним атомарным коммитом (до 2 часов) заменить префикс причины обеих веток `run.error` на «процесс оборвался: », сохранив исходное `error.message`, `failed`, остальные поля и порядок условий. В `run-stage.test.mjs` переименовать ошибочно названный тест несостоявшегося запуска с процессом, у которого есть `pid`, и использовать ошибку обрыва; в `provider.test.mjs` добавить соответствующую проверку Codex. Для обоих обработчиков проверить полную строку `why` и `failed`, а также сохранение `timeout` и причины снятия при сочетании `killedBy` с `run.error`. Выполнить перечисленные ниже проверки и отметить этот пункт в собственном `tasks.md` тем же коммитом. После отправки этого первого коммита реализация уже позволяет открыть черновой PR по правилам этапа.

Проверки шага выполняются из назначенного рабочего дерева; `.` в командах Git обозначает именно его:

- Узкий прогон: `npx vitest run --root supervisor lib/run-stage.test.mjs lib/provider.test.mjs lib/supervisor.test.mjs lib/execute.test.mjs`. Новая причина проверяется у каждого обработчика; существующие сценарии отсутствующего `pid` и `not-born` остаются зелёными, не регистрируют незаведённый этап и не списывают продолжение вместо отказа порождения. Это проверка реализации, на этапе design её не запускать.
- Формат и линт рабочих файлов: `npx prettier --check supervisor/lib/run-stage.mjs supervisor/lib/provider.mjs supervisor/lib/run-stage.test.mjs supervisor/lib/provider.test.mjs` и отдельным вызовом `npx eslint supervisor/lib/run-stage.mjs supervisor/lib/provider.mjs supervisor/lib/run-stage.test.mjs supervisor/lib/provider.test.mjs`. Эти формы и `npx vitest:*` покрыты `supervisor/config/stage-settings.json`.
- Допустимые изменения и явный список добавления: `git -C . add -- supervisor/lib/run-stage.mjs supervisor/lib/provider.mjs supervisor/lib/run-stage.test.mjs supervisor/lib/provider.test.mjs openspec/changes/name-process-interruptions/tasks.md`. Последний путь разрешает только отметку выполненного шага; остальные — описанные рабочие правки.
- Перед коммитом проверить имена путей командой `git -C . diff --cached --name-only`, затем содержание командой `git -C . diff --cached`: только две строки диагностики, связанные тесты и собственная отметка выполнения. После коммита сверить имена через `git -C . show --format= --name-only HEAD` и содержание через `git -C . show --format= HEAD`. Посторонние изменения даже внутри разрешённых файлов недопустимы.

Каждая команда запускается отдельным вызовом. Проверки полного проекта, арена и ожидание CI не входят в шаг: результат CI обрабатывает супервизор. Каталог `specs/` не создаётся, чужие дельты и основные спецификации не редактируются.
