## Context

На свежей `origin/main` обе ветки `run.error` содержат «запуск не состоялся»: `supervisor/lib/run-stage.mjs:246–247` и `supervisor/lib/provider.mjs:198–199`. В `supervisor.mjs:374–387` отсутствие `handle.pid` возвращает `not-born` до регистрации процесса и разбора его ответа. Поэтому диагностический текст противоречит уже действующему разделению двух видов сбоя.

Подставной процесс в `run-stage.test.mjs` имеет `pid = 4242`; существующий тест «это отказ настройки, а не упавший этап» подаёт ему `spawn claude ENOENT` и проверяет только наличие `ENOENT`. Такой тест не защищает смысл причины и неверно называет моделируемый случай.

## Goals / Non-Goals

**Goals:** одинаково назвать обрыв в двух обработчиках, сохранить исходное сообщение ошибки и проверить границу с отказом порождения.

**Non-Goals:** изменение lifecycle, счётчиков, маршрутизации, формата ответа, токенового реестра, поиска ошибок API и общей обработки исключений. Границы заданы также в proposal.

## Decisions

1. В обеих существующих ветках использовать префикс «процесс оборвался: » и прежнюю подстановку `run.error.message`. Формулировка прямо называет уровень сбоя и не утверждает его причину. Альтернатива «ошибка процесса» менее определённа; старое «запуск не состоялся» смешивает два пути диагностики. Отдельный форматтер для двух строк добавил бы зависимость без полезного поведения.
2. Порядок условий и возвращаемые поля сохранить. Снятие по сроку или остановке обрабатывается раньше `run.error`; ошибка процесса раньше разбора успешного ответа или ошибок API. Добавлять проверку `pid` в функции чтения не нужно: они получают результат выполнения, а допуск процесса принадлежит супервизору. Проверять `error.message` на ENOENT ради выбора класса нельзя: класс задаётся фактом рождения, не текстом ошибки.
3. Одним коммитом изменить обе строки и тесты. Для Claude использовать подставной процесс с известным `pid`, событием `error` и сообщением об обрыве; переименовать вводящий в заблуждение существующий тест. Для Codex добавить прямой вызов `readCodexAnswer` с `run.error`, без снятия, проверив `failed` и полную строку `why`. В обоих случаях утверждать точную причину, чтобы старый префикс делал тест красным. Проверить сочетание ошибки со снятием: оно сохраняет существующий `timeout` и причину снятия. Живой запуск исполнителя не нужен: ошибка и очередность веток воспроизводятся без сети и оплаты сессии.
4. Существующие проверки процесса без номера в `supervisor.test.mjs` и отказа `not-born` в `execute.test.mjs` служат регрессией: незаведённый процесс не попадает в running, продолжение не расходуется, счёт отказов порождения сохраняет прежний смысл. Production-код этих модулей не правится.
5. Дельты нет по обоснованию proposal. `supervise-the-pipeline` и `count-only-real-launches` задают основание, но нового требования поверх них не вводится. Связанные изменения `name-both-outcomes-in-the-log`, `pause-on-api-overload`, `reconcile-codex-token-usage` и `preserve-codex-report-on-usage-error` не требуют иной подписи `run.error`; их словари, поля и порядок обработки сохраняются. При освежении базы перед реализацией повторно сверить обе ветки: соседняя работа с `provider.mjs` может дать текстовый конфликт, но сама по себе не является зависимостью вливания или архивации.

## Risks / Trade-offs

- Исправлена только одна копия строки → один атомарный шаг и отдельная проверка каждого обработчика.
- Тест всё ещё проверяет лишь исходную ошибку → точное равенство `why` с новым префиксом, а не только `toContain`.
- Вместе с текстом случайно изменён приоритет веток → проверки снятия при одновременно заданном `run.error` и просмотр diff.
- Изменение русского текста может затронуть внешнего читателя журналов → это намеренная диагностическая поправка; внутренняя маршрутизация опирается на `outcome`/`reason`, а не новый префикс.

Игровой цикл, реконнект и рассинхрон не затрагиваются. Изменений в `packages/sim` нет: новые источники случайности/времени или дробные значения состояния не вводятся, эталоны детерминизма не обновляются. Раскладка протокола не меняется, рост `PROTOCOL_VERSION` не нужен.

## Migration Plan

Миграции данных нет. После штатного вливания новые ответы получают уточнённую причину; старые журналы не переписываются. Откат одного коммита возвращает прежние строки и тесты. Архивация без дельт выполняется последующим уполномоченным этапом с `--skip-specs`.

## Open Questions

Нет: формулировка и границы выводятся из постановки, кода и существующих требований.
