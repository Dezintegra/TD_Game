## Context

Назначение 0070 ограничено проработкой. Свежая база `734733f`, merge origin/main ответил `Already up to date.`. Сканер чистый: строит план по снимку, затем исполнитель последовательно исполняет действия. В `scan.mjs:334–340` внешний benchmark опрашивается, но отбор сессий с `:568` его не исключает. В `execute.mjs:237–263` чтение свежее, а этап назначения приходит из ранее построенного action: одной свежести хранилища мало.

`backlog-trello.mjs:364–373` уже обновляет byId, описание и колонку исходной карточки после успешного PUT. Эту половину подтверждаем тестами без второго механизма записи. `io.mjs:549` возвращает pending без `links.run`; поэтому запрещать продолжение всех внешних benchmark навсегда нельзя.

## Goals / Non-Goals

Цель: разделить внешний опрос и выдачу сессии одной задаче по свежим оборотам, сохранить запуск без номера и доказать видимость последовательных записей. Границы — proposal; общий контроль устаревших action, конкуренция машин и восстановление исторических карточек не входят.

## Decisions

1. При создании опросов собирать множество taskId реально добавленных `poll-external` либо вывести его из уже созданных actions перед отбором сессий. Проверять его до лимитов и добавления в waitingForSession. Позднее удаление только continue-stage отвергнуто: оно оставляет fail-stage и может зря занять слот. Общий запрет любых двух действий отвергнут: заметка об осиротевшем этапе и последующий запуск допустимы.
2. В ветви внешнего benchmark назначать опрос при наличии `links.run`. Без номера оставить обычный отбор сессии. Это техническое следствие контракта readExternal, а не новый продуктовый выбор. Исключение только для успешного ответа отвергнуто: сканер ещё не знает ответа, а при pending новая сессия тоже не нужна. Опрос CI не менять.
3. После успеха или ошибки прогона штатный applyExternal сохраняет interpret или существующий путь ошибки; следующая сессия определяется новым оборотом. При pending или недоступности связи остаётся повтор опроса без расхода продолжения. Живые процессы эта правка не останавливает. Применение отчётов, удержание бюджета и диагностика задержек сохраняют собственные предохранители.
4. Свежесть Trello проверять реальным адаптером и подставным HTTP-клиентом. Два saveTask разделены readTask того же экземпляра; сверять статус, оба изменённых поля, тело второго PUT и исходные desc/idList. На отказ PUT память не должна показывать новый переход. Перечитывать всю доску после записи отвергнуто: существующее обновление уже даёт нужную видимость без сети. Это не обещание слияния изменений из произвольных ранее сохранённых копий объектов.
5. Дельта ADDED в существующей `pipeline-supervision-resilience`: новые отдельные инварианты, без замены существующих требований о живых процессах и эксклюзивности. Открытые supervise-the-pipeline/count-only-real-launches затрагивают те же файлы, но другой уровень — способ возобновления и учёт после порождения. Основы для нашей дельты уже архивированы; зависимости от открытых изменений нет.

## Validation design

В scan.test проверить наличие опроса одновременно с отсутствием continue-stage и fail-stage по тому же id, включая достигнутый лимит. Добавить положительный контроль другой задачи со свободным слотом, benchmark без номера, локального замера и опроса CI. Исправить прежнее ожидание продолжения внешнего benchmark, если его фикстура уже содержит номер, сохранив отдельный случай без номера.

В execute.test выполнить настоящий результат scan через исполнитель с подставным IO: успех внешнего прогона, pending и недоступность; проверить статус, отсутствие spawnStage и отсутствие добавленного продолжения/журнала выдачи. Для успеха снять свежий снимок, просканировать снова и проверить назначение interpret. Изолированные заглушки, сами фильтрующие action, не доказывают исправление.

В backlog-trello.test защитить второй инвариант адаптером, не подставной Map вместо него. Сеть и живые сессии не нужны. Узкие проверки назначены этапу implement; design запускает только OpenSpec CLI.

## Risks / Trade-offs

- Новый этап получает сессию не раньше следующего оборота → это цена свежего выбора; опрос не резервирует вычислительный слот.
- Отсутствие номера могло бы запереть запуск → отдельная ветвь допуска с положительным регрессионным контролем.
- Поздний фильтр оставил бы решение об исчерпании → исключение до лимитов и проверка maxContinuations.
- Соседние правки scan/execute → перед реализацией освежить базу и сохранить их предохранители; не переносить чужие требования в нашу дельту.

## Migration Plan

Миграции данных нет. Доставить правку и тесты обычным PR; новый код начнёт действовать при штатном обновлении супервизора. Откат — откат коммита реализации, без изменения карточек. Исполнитель этой задачи не перезапускает работающий супервизор.

Симуляция, рассинхрон и реконнект игры не затронуты. Эталоны детерминизма и PROTOCOL_VERSION не меняются. Новых зависимостей от Math.random, Date.now или вещественного состояния мира не появляется: пакеты игры не меняются. Арена и замер кадров не нужны.
