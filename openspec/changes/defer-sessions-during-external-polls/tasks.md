## 3. Правила состава и проверки каждого коммита

Этот раздел — условия двух пунктов выше, не дополнительный шаг. Команды исполняются по одной из назначенного дерева. `.` в командах Git означает это дерево; при другом рабочем каталоге заменить его абсолютным путём назначения. Формы узких проверок сверены с `supervisor/config/stage-settings.json`; полный verify и ожидание CI не входят в задачи исполнителя.

Пункт 1.1 добавляет только `supervisor/lib/scan.mjs`, `supervisor/lib/scan.test.mjs` и отметку собственного пункта в `openspec/changes/defer-sessions-during-external-polls/tasks.md`. Пункт 2.1 добавляет только `supervisor/lib/execute.test.mjs`, `supervisor/lib/backlog-trello.test.mjs` и отметку собственного пункта в том же tasks.md. Каждый путь передавать `git -C . add --` явным перечнем; несвязанные изменения внутри этих файлов недопустимы.

Перед коммитом проверить имена `git -C . diff --cached --name-only` и содержание `git -C . diff --cached`. После коммита немедленно выполнить `git -C . push`, затем сверить имена и содержание созданного коммита `git -C . show --stat --oneline HEAD` и `git -C . show --format=fuller HEAD`. Проверить отсутствие хвоста `git -C . log --oneline '@{u}..HEAD'`. Отметка выполненного пункта обязательна и допустима вместе с его рабочими правками; остальные файлы и несвязанные изменения не допускаются.
