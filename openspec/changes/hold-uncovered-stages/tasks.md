# Задачи

Каждый пункт — отдельный коммит, собирающийся и проверяемый сам по себе.
Проверки набором конвейера зовутся как `pnpm test:pipeline`: обычный
`vitest` тестов инструмента не находит вовсе, ему нужен ключ
`--root supervisor`.

## 1. Завести `supervisor/config/permissions.mjs` и перевести на него сторожа вливания

Перенести из `supervisor/config/transitions.test.mjs` в новый модуль
`patternOf` и `coversCommand` вместе с их пояснениями; добавить
`uncoveredCommands(permissions, commands)` (перечень непокрытых с именем
оболочки), `STAGE_COMMANDS` с единственной пока записью `review`
(нынешний `MERGE_PATH`) и `uncoveredForStage(permissions, stage)`.
Тест начинает импортировать их и своих копий не держит. В `supervisor/README.md`
дописать новый файл в перечень `config/`.

**Проверка:** `pnpm test:pipeline` зелёный, и все пять существующих проб
на порчу (`сужение широкого правила…`, `запрет, совпавший с приставкой…`,
`сужение до точных правил без хвоста…`, `запрет точной формы, дословно
равный команде…`, `запрет точной формы, короче команды…`) проходят
без единой правки в них.

После этого пункта открывается **черновой pull request**: до его появления
проверки CI на пуши в ветку не запускаются вовсе.

## 2. Объявить команды выкладки и завести сторожа с реестром закрытых этапов

Добавить в `STAGE_COMMANDS` запись `deploy` с двумя командами из
`skills/deploy.md`: `ssh -o BatchMode=yes -o ConnectTimeout=15 dezintegra "true"`
и `node scripts/deploy.mjs --ref <хеш>`. В тесте завести реестр осознанно
закрытых этапов — `deploy` с причиной («боевой сервер — решение человека»,
снимается задачей 0117) — и два сторожа: этап либо покрыт, либо числится
закрытым; закрытый этап действительно не покрыт.

**Проверка:** `pnpm test:pipeline` зелёный на сегодняшней настройке.
Проба на порчу тем же набором: временно добавленное в `allow` правило
`Bash(ssh:*)` и `PowerShell(ssh:*)` вместе с `node scripts/deploy.mjs:*`
краснит сторожа «закрытый этап открылся» — проба ставится тестом
на выдуманной настройке, а не правкой `stage-settings.json`.

## 3. Сторож расхождения перечня команд со скиллом этапа

Проверить, что каждая команда из `STAGE_COMMANDS` встречается в правилах
своего этапа (`supervisor/skills/<этап>.md`) — по её началу, без доводов:
у выкладки это `ssh -o BatchMode=yes -o ConnectTimeout=15 dezintegra`
и `node scripts/deploy.mjs --ref`, у вливания — `gh pr view`, `gh pr ready`,
`gh pr merge`.

**Проверка:** `pnpm test:pipeline` зелёный; изменение любой строки
в `STAGE_COMMANDS` на несуществующую в скилле краснит тест и называет
разошедшуюся команду.

## 4. Читать настройку разрешений в картину мира

Завести `readPermissions(home, config)` в `supervisor/lib/read-state.mjs`:
путь считается от каталога инструмента, отсутствующий или неразобравшийся
файл даёт `null`. Пробросить в состояние полем `permissions` из
`bin/supervise.mjs` и `bin/cycle.mjs` — обоим читателям одинаково.

**Проверка:** тест на чтение в `read-state.test.mjs` (файл есть → списки
правил; файла нет → `null`; испорченный JSON → `null`, без исключения).
Живьём: `node supervisor/bin/cycle.mjs` печатает решение и не падает.

## 5. Удержание в сканере

В `supervisor/lib/scan.mjs` посчитать удержанные задачи до счёта занятости:
задача удержана, если `uncoveredForStage` по её этапу вернул непустой
перечень. Удержанные исключаются из `engaged` и из проверки на исключительный
этап, пропускаются в разделе 6 (выдача сессии стоящему этапу) и в разделе 7
(взятие из очереди — по первому этапу задачи), а причина ложится в `notes`
записью, начинающейся словами «ждёт починок конвейера» и называющей
непокрытые команды. Нет поля `permissions` — нет и удержания, но есть
запись о том, что проверить было нечем.

**Проверка:** тесты в `scan.test.mjs` — задача в `deploy` при непокрытых
командах не получает `continue-stage` и не растит продолжений; соседняя
задача очереди при этом берётся в работу (не «исполнитель занят»);
при покрытых командах сессия выдаётся как прежде; без `permissions`
удержания нет.

## 6. Свести концы: живой смотрящий прогон и запись в README конвейера

Прогнать `node supervisor/bin/cycle.mjs` на настоящей доске и убедиться,
что решение печатается, а задача, стоящая в выкладке (если такая есть),
названа удержанной с перечнем команд. Дописать в `supervisor/README.md`
абзац о том, что этап с непокрытыми командами не начинают, — рядом
с описанием сканера.

**Проверка:** вывод `node supervisor/bin/cycle.mjs` содержит строку
удержания либо, если задач в выкладке нет, — прежнее решение без единой
новой жалобы; `pnpm test:pipeline` зелёный; CI по pull request зелёный.
