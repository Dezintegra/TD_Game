## Context

stageModel и codexModel задают одну модель на все этапы. Назначение уже
содержит stage; менять автомат состояний для маршрутизации не требуется.

## Goals / Non-Goals

Выбирать модель при каждом запуске и resume. Не менять провайдера, маршруты
карточек и активные процессы. Ручные сессии соблюдают общую инструкцию.

## Decisions

Добавить stageModels с картами claude и codex: ключ этапа, затем default,
затем прежнее stageModel/codexModel. Карта проекта имеет приоритет, чтобы
общая настройка CLI не направляла рутинные этапы в Astra. В переносимых
умолчаниях конкретных моделей нет; все версии задаёт TD_Game.

triage формирует постановку кандидата; interpret толкует результаты;
postmortem разбирает ошибки: Astra / Fable 5.1.
implement, revise, benchmark, deploy исполняют работу: Terra / Opus 4.8.
decompose, design, audit, review и новые этапы: Sol / Opus 5.
Создание PR входит в implement/revise; pr и cleanup не запускают модель.
Ревью как целый этап остаётся Sol, включая его штатное завершение слиянием.

Проверка готовности Codex использует маршрут deploy; простая проба сервера
использует default. Выбор по словам описания отвергнут: он нестабилен и может
считать любое упоминание ошибки основанием для Astra.

## Risks / Trade-offs

Доступность моделей зависит от аккаунта: автоматической подмены нет.
Идентификаторы Claude подтверждены в установленном claude.exe:
claude-opus-4-8, claude-opus-5, claude-fable-5-1.
Codex использует gpt-5.6-terra, gpt-5.6-sol, gpt-6-astra.
Смешанный этап работает на одной модели; отдельный разбор сбоя — postmortem.

## Migration Plan

После вливания конфигурация применяется к новым запускам супервизора.
Работающие процессы не прерывать. Откат — revert изменения.
