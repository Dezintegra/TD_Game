# Задачи

Каждый шаг — отдельный коммит, проверяемый сам по себе. Изменение
не заводит ни строки кода приложения: правятся два файла конвейера
и один текст OpenSpec, поэтому ни сборки, ни матчевых тестов, ни замеров
здесь нет, а проверки везде узкие и идут по своим файлам.

**Команды даны формой, покрытой правилами разрешений** — `git -C <дерево> …`,
где `<дерево>` — путь из поля `worktree` назначения. Это ровно то правило,
которое изменение и вводит; список задач, написанный иначе, опровергал бы
сам себя.

## 1. Открыть черновой pull request на артефактах проработки

- [x] Артефакты проработки (`proposal.md`, `design.md`, `tasks.md`,
      `specs/dev-pipeline-worker/spec.md`) уже лежат в ветке отдельным
      коммитом — отправить ветку, если она ещё не отправлена
      (`git -C <дерево> push -u origin HEAD`), и открыть черновой pull
      request в `main`:
      `gh pr create --draft --base main --title "<заголовок>" --body-file <файл>`.
- [x] Тело pull request писать файлом: `--body` длинной прозой
      отказывается ещё до `gh`.

**Проверка:** `gh pr view <номер> --json number,state,isDraft` отвечает
`OPEN` и `true`; `gh pr checks <номер>` показывает запущенные проверки.
Шаг стоит первым не из вежливости: до появления pull request пуши
в ветку не запускают CI вовсе, и каждый следующий коммит остался бы
непроверенным.

## 2. Сказать в скилле проработки о форме команд и поставить сторожа

Правило и его сторож едут **одним коммитом**. Порознь они не проверяемы:
сторож без правила красен, правило без сторожа переживёт первую же
переписку файла.

- [x] В `supervisor/skills/design.md`, шаг 10 (`tasks.md`), добавить пункт
      о форме команд **последним в перечне шага 10**: сразу после пункта
      про заявку с полем `area: "pipeline"`, кончающегося словами
      «продуктовой работе поля не ставят вовсе» (строка 199 в `main`),
      и **выше** пустой строки перед заголовком «11. **Проверь форму.**».
      Ниже не спускаться ни строкой: ограждение шага 11 (строка 203)
      правит чужая ветка — pull request 132, см. `design.md`, Решение 8.
      Текст пункта выписан в `design.md`, Решение 5 («Целевой текст пункта
      целиком»), — брать его дословно, вместе с отступами: сторож сверяет
      подстроки и читает файл сырым, без склейки строк.
- [x] В `supervisor/config/transitions.test.mjs` добавить проверку
      из `design.md`, Решение 6 («Целевой текст проверки»), **последней
      в `describe('этапы и скиллы')`**: после закрывающей строки
      `it('сторож формулы падает на прежней её редакции')` (нынешние
      строки 737–750) и перед закрывающей `describe` строкой 751. Место
      выбрано, чтобы разойтись с задачей 0173: она вставляет свой `it()`
      в тот же `describe`, но перед сторожем формулы. Помощник `skillText`
      в файле уже есть — заводить заново не надо.
- [x] Больше в этих двух файлах не менять **ничего**: ни соседних пунктов
      шага 10, ни заголовков и ограждений шага 11, ни раздела запретов,
      ни прочих сторожей.
- [x] **Конфликт при слиянии в любом из этих двух файлов — повод
      остановиться и назвать его в отчёте**, а не разрешать по своему
      представлению о чужом тексте: значит чужая правка (0175 или 0173)
      легла не туда, где её ждало `design.md`, Решение 8, и разбирать
      её вслепую опаснее задержки на этап.
- [x] Править инструментом редактирования файла. `Set-Content`, `Out-File`
      и перенаправление `>` не применять: Windows PowerShell 5.1 читает
      UTF-8 как ANSI и превращает кириллицу в мохибейк.

**Проверка**, вся по своим двум файлам:

- `npx vitest run --root supervisor config/transitions.test.mjs` — зелёный,
  и новая проверка в перечне прогнанных. Ключ `--root supervisor`
  обязателен: без него тесты конвейера не находятся вовсе, и прогон
  зеленеет, ничего не прогнав. Нет `node_modules` в дереве — сначала
  `pnpm install --frozen-lockfile`;
- сторож обязан **падать** без правки скилла, и проверяются **обе**
  его половины порознь: половина, зелёная сама по себе, — это половина
  сторожа, которой нет. Убедиться дёшево и без правки истории: временно
  убрать из скилла подстроку `git -C <дерево>`, прогнать тот же тест,
  увидеть красноту с текстом `design.md: git -C <дерево>`, вернуть
  подстроку; затем то же со второй подстрокой — убрать
  `Перечень покрытого живёт`, увидеть красноту с её именем, вернуть.
  Сторож, зеленеющий на чём угодно, — не сторож;
- `npx prettier --check supervisor/skills/design.md supervisor/config/transitions.test.mjs`
  — зелёный;
- `npx eslint supervisor/config/transitions.test.mjs` — зелёный;
- `git -C <дерево> diff --stat` показывает ровно два изменённых файла.

## Чего в списке нет

- **Прогона арены не заказывается.** Правила игры, цены, доход, сила
  юнита и темп не задеты ни одной строкой: правятся правила этапа
  конвейера, его сторожевой тест и текст списка задач OpenSpec — всё
  вне пакетов монорепозитория.
- **Замеров кадров и стоимости тика нет** по той же причине: отрисовка
  и шаг мира не тронуты.
- **Правки правил разрешений нет.** `git merge:*` не заводится —
  `design.md`, Решение 3; об этом отдельная задача 0172.
- **Сторожа над списками задач чужих изменений нет** — `design.md`,
  Решение 4.
- **Архивации изменения нет.** Она переписывает `openspec/specs/`,
  её очередь задана зависимостями дельт, и решение принимает человек.
  Здесь важно одно: изменение архивируется **после**
  `agent-backlog-pipeline`, которое заводит способность
  `dev-pipeline-worker` (см. «Зависимости» предложения).
