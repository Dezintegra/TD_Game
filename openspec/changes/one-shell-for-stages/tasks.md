# Шаги реализации

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе.
Проверка у всех шагов, трогающих `supervisor/`, одна и та же и названа
у каждого прямо: `pnpm test:pipeline` (это `vitest run --root supervisor`;
голый `npx vitest` тесты конвейера не находит и зеленеет, ничего
не прогнав).

- [ ] 1. **Перевести командные блоки скиллов на разметку `powershell`.**
      Двадцать восемь блоков ```` ```bash ```` в пяти скиллах:
      `implement.md` (7), `revise.md` (6), `benchmark.md` (7),
      `review.md` (5), `audit.md` (3). Заодно снять из `audit.md`
      утверждение, что `openspec` «виден из любой оболочки»: 03.09.2026
      в Git Bash он не нашёлся (задача 0129).

      _Проверка:_ поиском по `supervisor/skills/` не остаётся ни одного
      вхождения ```` ```bash ````; `pnpm test:pipeline` зелёный (сторожа
      скиллов уже есть и не должны покраснеть от разметки).

      _После этого шага открывается черновой pull request_
      (`gh pr create --draft --base main`), иначе проверки CI не запустятся
      ни на одну следующую отправку.

- [ ] 2. **Завести в каждом из десяти скиллов оговорку об оболочке.**
      Три утверждения дословно по дельте `dev-pipeline-worker`: оболочка
      одна — PowerShell; отказ означает не ту оболочку, а не запрет
      действия, и команду надо повторить; примеры общих памяток проекта
      с разметкой `bash` правилу не перечат. В `audit.md` оговорка
      заменяет нынешнюю фразу «на этой машине Bash ненадёжен», в
      `deploy.md` — сводится с уже стоящим там требованием PowerShell
      ради `tar`.

      _Проверка:_ поиском видно оговорку во всех десяти скиллах;
      `pnpm test:pipeline` зелёный.

- [ ] 3. **Написать сторожа скиллов** — новым файлом
      `supervisor/config/shell.test.mjs`, а не внутри
      `transitions.test.mjs`: тот сейчас переписан изменением
      `hold-uncovered-stages`, и общий файл дал бы конфликт при вливании.
      Сторож проверяет: ни один скилл не показывает команду блоком `bash`;
      оговорка стоит в каждом. Обязательны пробы на порчу — скилл
      с наведённым `bash`-блоком и скилл без оговорки обязаны краснеть.

      _Проверка:_ `pnpm test:pipeline` зелёный; временно наведённый
      `bash`-блок в любом скилле делает его красным.

- [ ] 4. **Снять из `allow` все правила `Bash(...)`** в
      `supervisor/config/stage-settings.json` — тридцать восемь строк.
      `deny` не трогать. Тем же коммитом свести мерку покрытия к одной
      оболочке, иначе сторож покрытия объявит непокрытой каждую команду:

      - если `hold-uncovered-stages` уже влито — `SHELLS`
        в `supervisor/config/permissions.mjs`;
      - если ещё нет — перечень оболочек внутри `uncoveredMergeCommands`
        в `supervisor/config/transitions.test.mjs`.

      Перед снятием сверить попарно, что у каждого снимаемого правила есть
      пара `PowerShell(...)`. Известное исключение одно: `git switch` —
      пару ему не заводить, переключение веток скиллы запрещают.

      _Проверка:_ `pnpm test:pipeline` зелёный, включая сторожа покрытия
      команд вливания; в `allow` поиском не находится ни одного `Bash(`.

- [ ] 5. **Дописать сторожа правил** в тот же `shell.test.mjs`: `allow`
      не содержит правил `Bash(...)`; `deny` сохраняет запреты в обеих
      оболочках; у каждой команды, названной в перечне исключений,
      исключение объявлено явно. Пробы на порчу обязательны — настройка
      с возвращённым `Bash(pnpm install:*)` в `allow` обязана краснеть,
      настройка с `Bash(...)` только в `deny` — оставаться зелёной.

      _Проверка:_ `pnpm test:pipeline` зелёный; правило `Bash(...)`,
      временно возвращённое в `allow`, делает его красным.

- [ ] 6. **Записать причину правила словами** — `$shellNote`
      в `stage-settings.json` и раздел в `supervisor/README.md`: какие
      программы не нашлись в Git Bash 03.09.2026 (`pnpm`, `openspec`,
      `sh`), где лежит след (`.pipeline/logs/0149-…-implement.log`),
      почему перечень не проверяется исполнением (в CI на Linux они есть,
      а на станции ответ плавает) и как читать отказ на команде.

      _Проверка:_ `pnpm test:pipeline` зелёный;
      `npx prettier --check supervisor/README.md supervisor/config/stage-settings.json`
      проходит.
