# Шаги реализации

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе.
Проверка у всех шагов, трогающих `supervisor/`, одна и та же и названа
у каждого прямо: `pnpm test:pipeline` (это `vitest run --root supervisor`;
голый `npx vitest` тесты конвейера не находит и зеленеет, ничего
не прогнав).

- [x] 1. **Перевести командные блоки скиллов на разметку `powershell`
      и переписать тела, которые PowerShell не разбирает.** Двадцать
      восемь блоков ```` ```bash ```` в пяти скиллах: `implement.md` (7),
      `revise.md` (6), `benchmark.md` (7), `review.md` (5), `audit.md` (3).
      Заодно снять из `audit.md` утверждение, что `openspec` «виден
      из любой оболочки»: 03.09.2026 в Git Bash он не нашёлся (задача 0129).

      **Смена разметки сама по себе шага не закрывает.** Четыре тела
      в PowerShell либо не разбираются, либо меняют смысл, и оставить их
      как есть значило бы заменить молчаливый код 127 молчаливой ошибкой
      разбора на том же месте:

      - `git -C <дерево> log --oneline @{u}..HEAD` — `audit.md:69`,
        `implement.md:72`, `implement.md:213`, `revise.md:202`. **Голый**
        `@{` начинает у PowerShell литерал хеш-таблицы, и разбор падает
        до вызова `git` («Missing '=' operator after key in hash literal»).
        Это ровно проверка неотправленного хвоста, то есть проверка следа
        этапа. Писать `'@{u}..HEAD'` в одинарных кавычках — проверено
        пробой 03.09.2026 в этом дереве, команда отработала и напечатала
        пустой хвост.

        Запрещается при этом **голый** `@{`, а не `@{` вообще: в кавычках
        это уже не литерал, а строка, и она уезжает в `git` дословно.
        Различение обязательно — запрет на `@{` без оговорки объявил бы
        незаконным само предписанное здесь лечение, и шаги 1 и 3 не смогли
        бы позеленеть одновременно;
      - `gh workflow run arena.yml --ref <ветка> \` и `gh run list … \`
        с продолжением на следующей строке — `benchmark.md:76-79`.
        Обратная косая у PowerShell строку не переносит, продолжение уедет
        отдельным доводом. Писать обе команды в одну строку: они короткие,
        и предел длины команды (~965 байт, задача 0072) им не грозит;
      - `CLIENT_PORT=5199 PORT=3055 pnpm e2e:perf` — `benchmark.md:202`.
        Приставки переменных окружения у PowerShell нет вовсе, строка будет
        понята как имя команды `CLIENT_PORT=5199`. Писать голое
        `pnpm e2e:perf`, а про порты сказать словами. Почему это не потеря
        возможности — разобрано в `design.md`, разделом «Порты замера:
        единственная потеря, и та мнимая».

      _Проверка:_ поиском по `supervisor/skills/` не остаётся ни одного
      вхождения ```` ```bash ````, ни одного **голого** `@{` (все четыре
      вхождения стали `'@{u}..HEAD'`, то есть перед `@{` стоит кавычка),
      ни одной строки, кончающейся на `\`, внутри командных блоков;
      `pnpm test:pipeline` зелёный (сторожа скиллов уже есть и не должны
      покраснеть от разметки).

      _После этого шага открывается черновой pull request_
      (`gh pr create --draft --base main`), иначе проверки CI не запустятся
      ни на одну следующую отправку.

- [x] 3. **Написать сторожа скиллов** — новым файлом
      `supervisor/config/shell.test.mjs`, а не внутри
      `transitions.test.mjs`: тот сейчас переписан изменением
      `hold-uncovered-stages`, и общий файл дал бы конфликт при вливании.
      Сторож проверяет: ни один скилл не показывает команду блоком `bash`;
      оговорка стоит в каждом. Обязательны пробы на порчу — скилл
      с наведённым `bash`-блоком и скилл без оговорки обязаны краснеть.

      **Сверх разметки сторож ловит три формы тела**, каждая из которых
      в PowerShell тиха: голый `@{` (литерал хеш-таблицы вместо ревизии),
      строка командного блока, кончающаяся на `\` (перенос по-башевски),
      и `ИМЯ=значение` в начале команды (приставка переменных окружения).
      Без этого шаг 1 разъедется со скиллами при первой же правке: формы
      вернутся под разметкой `powershell`, и разбор снова упадёт молча.

      **Первая форма ловится голой, а не всякой.** Красным делает `@{`,
      перед которым не стоит кавычки — ни одинарной, ни двойной; `'@{u}'`
      и `"@{u}"` обязаны оставаться зелёными. Обе формы проверены пробой
      в PowerShell этого дерева 03.09.2026: обе разобрались и напечатали
      пустой хвост, потому что в кавычках `@{` — строка, а не литерал
      хеш-таблицы. Запрет без этой оговорки красил бы ровно то написание,
      которое предписывает шаг 1, и два шага не смогли бы позеленеть
      одновременно.

      _Проверка:_ `pnpm test:pipeline` зелёный; временно наведённый
      `bash`-блок в любом скилле делает его красным, и то же порознь —
      наведённые голый `@{u}..HEAD`, хвостовая `\` и `PORT=1 pnpm build`
      в блоке `powershell`. Обратная проба обязательна: `'@{u}..HEAD'`
      в кавычках красным его не делает — иначе сторож написан запретом
      на `@{` вообще, и это заметят только четыре скилла спустя.

- [ ] 4. **Снять из `allow` все правила `Bash(...)`** в
      `supervisor/config/stage-settings.json` — тридцать восемь строк.
      `deny` не трогать. Тем же коммитом правятся **два** места в наборе
      тестов, и оба обязательны: без любого из них шаг не собирается сам
      по себе, а имплементация встаёт посреди перехода — правила уже сняты,
      а тесты ещё требуют их обратно.

      1. **Мерка покрытия** — иначе сторож объявит непокрытой каждую
         команду:

         - если `hold-uncovered-stages` уже влито — `SHELLS`
           в `supervisor/config/permissions.mjs`;
         - если ещё нет — перечень оболочек внутри `uncoveredMergeCommands`
           в `supervisor/config/transitions.test.mjs` (строка 265).

      2. **Сторож «перечень сценариев открыт точной формой»** —
         `supervisor/config/transitions.test.mjs:373-392`. Строки 389-391
         дословно требуют `Bash(pnpm run)` в `allow` для обеих оболочек,
         то есть требуют вернуть ровно то, что этот шаг снимает. Свести
         его перечень оболочек к одному `PowerShell`. Смысл сторожа при
         этом сохраняется целиком: он стережёт отсутствие хвоста `:*`
         у `pnpm run`, а не число оболочек.

      Перед снятием сверить попарно, что у каждого снимаемого правила есть
      пара `PowerShell(...)`. Сверено при проработке: пары есть у 37 правил
      из 38. Известное исключение одно: `git switch` — пару ему не заводить,
      переключение веток скиллы запрещают.

      _Проверка:_ `pnpm test:pipeline` зелёный, включая сторожа покрытия
      команд вливания и сторожа точной формы; в `allow` поиском
      не находится ни одного `Bash(`.

- [ ] 5. **Дописать сторожа правил** в тот же `shell.test.mjs`: `allow`
      не содержит правил `Bash(...)`; `deny` сохраняет запреты в обеих
      оболочках. Пробы на порчу обязательны — настройка с возвращённым
      `Bash(pnpm install:*)` в `allow` обязана краснеть, настройка
      с `Bash(...)` только в `deny` — оставаться зелёной.

      **Тем же шагом завести перечень команд, обязанных остаться
      покрытыми** — тридцать семь тел снимаемых правил (`git -C:*`,
      `git push:*`, `pnpm install:*`, `openspec:*` и прочие по файлу),
      и сторож требует на каждое правило `PowerShell(<тело>)` в `allow`.
      Исключение объявляется явно и одно: `git switch:*` — пары ему
      не заводят, переключение веток скиллы запрещают.

      Без записанного перечня сценарий «Снятое правило осталось без пары»
      неисполним в принципе: снятое правило исчезает из файла бесследно,
      и узнать, чья пара пропала, сторожу неоткуда. Перечень — не движущаяся
      цель, а снимок круга команд на день снятия: законное сужение круга
      потребует стереть строку из перечня, то есть станет видно дифом
      и потребует довода. Это ровно та громкость, ради которой заведено
      всё изменение.

      _Проверка:_ `pnpm test:pipeline` зелёный; правило `Bash(...)`,
      временно возвращённое в `allow`, делает его красным; временно снятое
      `PowerShell(git push:*)` делает его красным и называет `git push:*`.
