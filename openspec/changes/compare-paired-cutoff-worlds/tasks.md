## Правила поставки обоих шагов

Все команды выполняются в назначенном дереве; `git -C .` означает именно его. Формы `git -C:*`, `npx vitest:*`, `npx eslint:*`, `npx prettier:*` сверены с `supervisor/config/stage-settings.json`. Прямой запуск новой CLI оболочкой не является обязательной проверкой этапа: CLI проверяется дочерним процессом внутри покрытого вызова Vitest. Примеры в README предназначены пользователю команды.

Для шага 1 явный список добавления: `scripts/analysis/paired-cutoffs.mjs`, `scripts/analysis/paired-cutoffs.test.mjs`, `openspec/changes/compare-paired-cutoff-worlds/tasks.md`. Для шага 2 к этому списку добавляется только `apps/arena/README.md`. Перед каждым коммитом использовать `git -C . add -- <явный список путей шага>`, проверить `git -C . diff --cached --name-only` и `git -C . diff --cached`: допустимы только рабочие правки шага и его отметка в tasks.md, без несвязанных изменений внутри разрешённых файлов. После коммита проверить `git -C . show --stat HEAD` и `git -C . show --format=fuller HEAD`, затем немедленно `git -C . push`. Общий лимит количества файлов вместо проверки путей и diff не использовать.

Финальная проверка артефактов: `openspec validate compare-paired-cutoff-worlds --strict` и `openspec status --change compare-paired-cutoff-worlds`. Полный verify, сборка, матчевые тесты, арена и ожидание CI в задачи реализации не включены. На design все пункты остаются открытыми; создание артефактов не является выполнением реализации.
