# Задачи

Каждый пункт — отдельный коммит, собирающийся и проверяемый сам по себе.
Проверки набором конвейера зовутся как `pnpm test:pipeline`: обычный
`vitest` тестов инструмента не находит вовсе, ему нужен ключ
`--root supervisor`.

## 1. Довезти стоимость этапа до отчёта

В `supervisor/lib/supervisor.mjs` добавить `costUsd` к записи, уходящей
в очередь отчётов, и к записи об отказе сервера модели. Отсутствие
стоимости в ответе считать нулём.

**Проверка:** `pnpm test:pipeline` зелёный. В `supervisor.test.mjs` два
случая: отчёт несёт стоимость из ответа; ответ без стоимости даёт ноль,
а не роняет перенос.

**Проба на порчу:** убрать подстановку нуля — краснеет второй случай.

## 2. Завести счёт расхода вне `attempts`

В `supervisor/lib/task-file.mjs` добавить `addSpent(task, usd)` — прибавляет
к полю `spentUsd` верхнего уровня, не ниже нуля и не трогая `attempts`.
Поля в `attempts` не заводить: его обнуляют три места, и предел спора умер
именно поэтому.

**Проверка:** `pnpm test:pipeline` зелёный. В `task-file.test.mjs` три
случая: расход прибавляется; `resetAttempts` его не трогает; вход
в сквозное состояние его не трогает.

**Проба на порчу:** перенести `spentUsd` внутрь `attempts` — краснеют
второй и третий случаи. Это главная проба изменения: она сторожит урок
задачи 0216.

## 3. Накапливать расход при переносе отчёта

В `supervisor/lib/execute.mjs`, в переносе отчёта, прибавлять `report.costUsd`
к задаче — на всех исходах отчёта, включая `rejected` и остановку.

**Проверка:** `pnpm test:pipeline` зелёный. В `execute.test.mjs` два случая:
отчёт `done` наращивает расход; отчёт `rejected` наращивает его тоже.

**Проба на порчу:** прибавлять только на `done` — краснеет второй случай.

## 4. Останавливать задачу, упёршуюся в потолок

В `supervisor/lib/scan.mjs` рядом с проверками `maxContinuations`
и `maxSpawnFailures` добавить проверку потолка: рабочий этап сессии
не получает, задача останавливается, причина называет истраченное и потолок
числами. Сквозные состояния (`CROSSCUT`) проверке не подлежат.

**Проверка:** `pnpm test:pipeline` зелёный. В `scan.test.mjs` три случая:
расход выше потолка останавливает рабочий этап и называет оба числа;
расход ниже потолка сессию не задерживает; задача в разборе с расходом выше
потолка сессию получает.

**Проба на порчу:** снять исключение для сквозных состояний — краснеет
третий случай.

## 5. Настройка и схемы

В `supervisor/config/defaults.mjs` добавить `maxTaskCostUsd: 25`
с пояснением, откуда взята величина (обычная задача $15–25, самая дорогая
честная за сутки $37, 0216 — $76). В `REQUIRED` не вносить: умолчание
годное.

В `supervisor/config/task-schema.json` и `manage/schema.json` добавить
`spentUsd` верхнего уровня и `attempts.apiErrors`, которого схемы запрещают,
а код пишет с 03.09.2026 (задача 0220).

**Проверка:** `pnpm test:pipeline` зелёный; запись задачи с обоими полями
проходит схему.

## 6. Правила дробления

В `supervisor/skills/triage.md` (шаг 4) заострить мерку единицы обратным
признаком: если части приходится проверять порознь — это несколько заявок.

В `supervisor/skills/design.md` добавить шаг «оцени дробность» перед
заведением изменения: работа, части которой вливаются отдельными pull
request, не оставляя остальные сломанными, дробится заявками, а этап
кончается исходом `question`.

В `supervisor/skills/postmortem.md` — при причине остановки «потолок
стоимости» первым делом смотреть, не дробится ли задача.

**Проверка:** `pnpm test:pipeline` зелёный (сторожа содержимого скиллов
живут в `transitions.test.mjs`); `npx prettier --check` по своим файлам.
