# Входы будущего второго допуска — кандидат отсутствует

Это не запрос разрешения в текущем этапе. BuildId/packageSha256 отсутствуют,
поэтому конкретную сборку для активации предъявить пока нельзя.
Результат 0372 — [подтверждённая преграда передачи](technical-barrier.md).

До рассмотрения активации необходимо получить настоящий instrumentation patch,
CLI/helpers, manifest/recipe/schema, два совпадающих build receipts,
production-boundary negative/mutation controls и полный source-coverage review.
После этого Windows-хозяин обеспечивает разрешённое долговременное хранение
по Decisions 6; отдельная проверка перечитывает все конечные bytes и фиксирует
SHA-256, размеры, абсолютные пути и UTC. Одного source receipt недостаточно.

Ответственный за будущий второй допуск и окно — существующая 0370. Только её
collector после отдельного допуска к конкретному buildId устанавливает
реально выбранный helper через resolver/file identity/hash/process handle/handshake,
PID+creationTime/TID lifetime и effective token у ACL API. Статическая подготовка
не может дать эти факты. До окна они неизвестны, и здесь не подставлены значения
из описи stock runtime.

Лимиты остаются прежними: две сессии, четыре вызова на сессию, две минуты на
сессию, десять минут всего; 10 МиБ очищенных записей с резервом 64 КиБ.
Бюджет, locks, stop-on-loss и возврат runtime ведёт 0370. Этот документ не
разрешает setup, смену ACL/profile/привилегий или снятие исходного инцидента.
