## Why

0370 не может связать конкретный tool call с refresh, исполняющим helper/thread и effective token у ACL API: штатные журналы такой связи не дают. Принятый проект 0371 задаёт источник B, но документальный PR 286 не поставляет патч, сборку или первичные свидетельства; их отсутствие продолжает блокировать причинную диагностику 0366.

## What Changes

- Поставить отключённый по умолчанию инструментирующий патч к `openai/codex` `rust-v0.153.4`, immutable commit `3d2ee51ca2d5db578f328aa75e20aa22c0197c9a`, с явной цепью collection/launch → leaf call/attempt → singleflight refresh → helper/thread → ACL operation.
- Реализовать наблюдение effective token непосредственно вокруг ACL API, сохранение прямого результата API, проверку происхождения реально выбранного helper и обнаружение неполноты. Существующие решения resolver, singleflight и ACL не менять ради наблюдаемости.
- Поставить versioned wire contract `refresh-boundary/v1`, ограниченный writer и библиотеку чтения/проверки источника для observer 0370. Collector, планирование и учёт остаются у 0370.
- Подготовить закреплённые source manifest, патч, recipe, сборку CLI/helpers, build receipts, source-coverage review и отрицательные проверки производственных границ с подменой Windows/IPC.
- После первого допуска передать проверяемый пакет для отдельного второго допуска. После него — проверять полученные первичные свидетельства либо документировать точную техническую преграду; разработка сама по себе не закрывает живую приёмку.

## Non-goals

- Ремонт причины отказа ACL или объявление инцидента восстановленным; это 0366 и исходная incidentVerification.
- Повторный выбор A/B, переход на новую версию Codex, доказательство эквивалентности stock binary по одной строке версии.
- Запуск настоящего setup/helper, live token query, замена рабочего runtime или диагностическое окно по первому допуску.
- Второй collector, scheduler, ledger, budget gate, lock manager или обратная зависимость от 0370.
- Изменение ACL/profile/привилегий, отключение sandbox, debugger/injection, сбор секретов, полного argv/payload и личных настроек.
- Изменение правил игры, интерфейса и игровых пакетов; арена и замер кадров не требуются.

## Capabilities

### New Capabilities

Нет: используется существующая `pipeline-supervision-resilience`.

### Modified Capabilities

- `pipeline-supervision-resilience`: ADDED-требования к исполняемому источнику, проверяемому происхождению сборки, сквозной корреляции, token/API boundary, потере данных и передаче между допусками. Это новые обязанности реализации, а не MODIFIED поверх документальных требований 0371.

## Impact

Планируемые пути реализации: `supervisor/instrumentation/codex-refresh/` (manifest, patch, recipe и документация), `supervisor/lib/refresh-boundary-source.mjs` и его тесты (чтение и валидация источника без запуска процессов). Upstream source/build/test workspace располагается отдельно в `.matchlog/0372-refresh/` назначенного дерева; в TD_Game попадают патч и проверяемые receipts, не весь upstream checkout и не бинарники. Пакет первого допуска сохраняется до проверенной передачи; незавершённая карточка и её дерево не отправляются в уборку.

На отзывчивость интерфейса и игровой сетевой трафик влияния нет: источник работает только в диагностической сборке инструмента разработки, UI и протокол игры не меняются. Есть локальный ограниченный IPC и накладные расходы token/identity queries; интервалы записываются, timing instrumented build не переносится на stock. Скачивание исходников/зависимостей относится к подготовке инструмента, не к трафику матча.

## Основание, пересечения и порядок

Проект 0371 прочитан на `f7bca391bcdb7ff459b1c440ca02c18c93ce1e31`, handoff — на `e8c688290e2236b66c41f0576e6c3d949ca3ae81`. Во время design PR 286 подтверждён MERGED; повторные fetch/merge перемотали базу на `92ecb13efa8f5d76042ace398a70b8e573d7dbee`. Diff проекта между закреплёнными design и handoff SHA пуст. Первое поручение владельца от 2026-09-24 уже разрешает разработку по принятому аудиту; ожидание результатов разработки до её начала не вводится.

`design-refresh-boundary-instrumentation` задаёт исходный документальный контракт; наше изменение архивируется ПОСЛЕ `design-refresh-boundary-instrumentation`. Требования имеют самостоятельные имена, основная способность уже существует, чужие дельты не переписываются. `capture-refresh-causal-evidence` на `8f32288cf0010496d74e920ea663a673cd62a51f` (PR 283) — невлитый потребитель, а не доступный в main модуль: его observer integration и открытые tasks остаются 0370. Новая библиотека не импортирует файлы чужого дерева и не меняет существующие availability/incident вердикты. `restore-stage-command-startup` сохраняет ответственность за ремонт и регрессии. Список открытых изменений и предоставленная опись проверены; отдельного исполнителя источника помимо 0372 нет.
