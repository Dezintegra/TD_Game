# Технические решения: звук

## Контекст

Звука в проекте нет вовсе. Заводится не «пара эффектов», а целая
подсистема, поэтому решений здесь больше обычного, и почти каждое
из них выбирает между «дёшево сейчас» и «не переписывать через месяц».

Три обстоятельства задают рамку, и ни одно из них не обойти.

**Клиент рисует предсказанный мир.** Он пересобирается откатом на каждом
кадре, один и тот же тик отрисовывается по нескольку раз, а номер тика
умеет уменьшаться (`clock.ts:52-54`). Картинке это безразлично: она
чистая функция от снимка. Звуку — нет: сыгранное не отыграть назад.

**Событий в клиенте не существует.** Ни одного колбэка вида «выстрелили».
Есть записи в мире с известным сроком жизни: `WorldState.shots`,
`blasts`, `nukes`. Момент рождения выводится арифметикой:
`expiresAtTick - LIFETIME[kind]`. Отрисовка так и работает
(`shots.ts:310-312`, `blasts.ts:288-289`), и звуку придётся так же.

**В бюджете кадра нет свободного места.** Требование «двести юнитов
и не ниже 55 кадров» действует, и звук обязан в него уложиться,
а не потратить остатки.

## Решение 1. Звуки считаются арифметикой, а не берутся из файлов

**Выбрано:** каждый звук — чистая функция
`(sampleRate: number) => Float32Array`, считающая отсчёты
элементарной математикой: генераторы, шум, фильтры, огибающие.
Результат один раз укладывается в `AudioBuffer`.

**Почему.**

Замысел (7.2) запрещает файлы ресурсов прямо и объясняет почему:
мир строится процедурно целиком, растровых текстур нет ни одной,
моделей из файлов тоже. Звук из `.ogg` был бы единственным местом,
где игра берёт готовое чужое, — и первым местом, где встал бы вопрос
лицензии, веса сборки и загрузки по сети до начала матча.

Практическая выгода перевешивает идейную. Разнообразие достаётся даром:
один и тот же семпл, сыгранный полсотни раз в секунду, слышен как
дребезжание пулемёта; посчитанный звук печётся в нескольких вариантах
и воспроизводится с разбросом скорости ±6 %, взятым из хеша самого
события, — и полсотни выстрелов звучат полусотней выстрелов. Правка
«пиу слишком высокое» — это правка одного числа в коде, а не поход
в редактор.

**Альтернатива A: файлы `.ogg`/`.mp3`.** Отклонена. Нарушает 7.2,
добавляет мегабайты в сборку, загрузку до матча, лицензионный вопрос
и «пулемётный» артефакт повторения.

**Альтернатива B: собирать граф узлов Web Audio на каждое событие**
(осциллятор + фильтр + огибающая на каждый выстрел). Отклонена,
и это главное решение подраздела. В бою бывает по двадцать выстрелов
за тик; граф из восьми-десяти узлов на каждый — это двести узлов
в секунду, каждый со своим расписанием параметров. Хуже другое: такой
звук невозможно проверить тестом. Клиентские тесты идут в окружении
`node` (`apps/client/vitest.config.ts`), Web Audio там нет и не будет.

И решающее: семислойный взрыв (решение 1б) в узлах браузера не собрать
вовсе. Резонаторы на негармонических частотах, рассыпанные во времени
толчки обломков, срез, рушащийся по заданной кривой, — всё это либо
не выражается штатными узлами, либо требует `AudioWorklet`, то есть
той же своей арифметики, только в другом месте и без тестов.

**Альтернатива C: печь через `OfflineAudioContext`.** Отклонена
по той же причине: печка оказалась бы в браузере, и проверить форму
звука без браузера стало бы нечем. Своя арифметика проверяется
обычным `expect` над `Float32Array`.

**Цена решения.** Придётся написать свой маленький DSP: генераторы,
однополюсный фильтр, фильтр с переменной частотой среза и резонансом,
огибающие, мягкое ограничение. Это около двухсот строк, и они
целиком покрываются тестами.

### Что именно пишется

`dsp.ts` — кирпичи, ничего не знающие о игре:

| Функция                                       | Что делает                                                    |
| --------------------------------------------- | -------------------------------------------------------------- |
| `noiseFrom(seed)`                               | белый шум — уже есть в `game/noise.ts`, берём готовое             |
| `createSweep(from, to)`                         | частота, идущая от одной к другой по экспоненте                   |
| `createDecay(sampleRate, tau)`                  | затухание шагами: одно умножение вместо `Math.exp` на отсчёт      |
| `createDecayTo(sampleRate, total, tau)`         | то же, но с гарантированным нулём в конце — иначе щелчок          |
| `attackAt(seconds, attack)`                     | нарастание, чтобы не щёлкало на старте                            |
| `bake(sampleRate, seconds, peak, step)`         | посчитать звук целиком: цикл, ограничение, края, нормировка       |
| `createFilter(sampleRate, mode)`                | фильтр состояния переменных: низ, полоса, верх за один проход    |
| `createOnePole(sampleRate)`                     | дешёвый низкочастотный, где резонанс не нужен                    |
| `createResonator(sampleRate, hz, decay)`        | двухполюсный звон: то, чем звучит ударенный металл               |
| `createScatter(seed, sampleRate)`               | рассыпанные толчки: обломки и электрические пробои               |
| `tremolo(time, rate, depth)`                    | медленное качание громкости: то, что делает из шипения раскат    |
| `softClip(x)`                                   | страховка от перегрузки при сложении слоёв                       |
| `createDrive(amount)`                           | насыщение: плотность без прибавки громкости                      |
| `normalise(samples, peak)`                      | приведение к заданному пику                                      |

Фильтр состояния переменных (схема Чемберлина) выбран из-за переменной
частоты среза: у разряда Теслы срез падает с семи килогерц до двухсот
за полсекунды, и биквад с пересчётом коэффициентов на каждом отсчёте
обошёлся бы вчетверо дороже при том же результате.

Резонатор нормирован по толчку — вход умножается на синус угловой
частоты. Без нормировки резонатор с секундным звоном усиливает вход
в десятки тысяч раз, и вместо звона получается мгновенный уход
в ограничитель. Отсюда же правило пользования: резонатор кормят
толчками, а не сплошным шумом.

### Цена вычислений и как она сбита

Двадцать семь секунд звука — миллион с четвертью отсчётов, и записанная
в лоб выкладка обходится в 1,9 секунды работы. Замеры показали, что
дорого не то, что кажется.

| Приём                                            | Что дал  |
| ------------------------------------------------ | --------- |
| Затухания шагами (`createDecay`) вместо `Math.exp` на каждом отсчёте | немного |
| Дробно-рациональное приближение вместо `Math.tanh`  | заметно  |
| Огибающие среза с управляющей частотой, раз в 16 отсчётов | заметно |
| Кеш настройки фильтра при неизменном срезе        | заметно  |
| Обходы по индексу вместо `for..of`, поля набора в локальных переменных | заметно |

Итог — 850 мс вместо 1900. Мораль, которую стоит запомнить: главными
оказались не трансцендентные функции, а накладные расходы на каждом
отсчёте — обращения к полям объекта и создание перебирающих объектов
в горячем цикле. Догадка «виноваты экспоненты» дала шесть процентов.

## Решение 1б. Взрыв собирается из семи слоёв

**Выбрано:** каждый взрыв — сумма семи слоёв с разными огибающими,
разными затуханиями и разными спектрами: кромка, тело, низ, отражение,
обломки, металл, раскат. Четыре взрыва игры (машина, генерал, постройка,
ядерный удар) — это один и тот же набор с разными числами.

**Почему не «низкий хлопок».** Шум с экспоненциальным спадом сквозь
низкочастотный фильтр слышен дёшево при любой громкости, и причина
не в бедности, а в том, что ухо получает от такого звука ровно один
факт — «громко». Настоящий разрыв сообщает четыре: насколько он
мгновенный (кромка), насколько велик (задержка отражения), из чего было
сделано разрушенное (металл) и как далеко это было (раскат). Убери
любой слой — исчезнет соответствующий факт.

**Отражение — самый недооценённый слой.** Второй, приглушённый удар
через 30–130 миллисекунд после прямого. Ухо переводит задержку в размер
события автоматически и без обучения; взрыв без отражения слышен
маленьким, каким бы громким он ни был. У ядерного удара отражений два:
близкое от земли и далёкое, через 440 мс, — и именно второе отличает
удар, накрывший полкарты, от удара, накрывшего клетку.

**Обломки — толчки, а не шум.** Различие принципиальное: шум одинаков
в каждое мгновение, а осыпь состоит из различимых отдельных событий.
Ровное шипение на месте обломков читается не осыпью, а помехой
в тракте. Плотность толчков спадает квадратично: сначала сыплется
густо, потом поодиночке.

**Верх умирает быстрее низа.** Постоянные времени слоёв различаются
на три порядка: кромка — миллисекунды, тело — десятки, низ — сотни,
раскат — секунды. Это не подбор на слух, а физика: воздух гасит высокие
частоты на порядок сильнее низких. Взрыв с одинаковым затуханием слоёв
опознаётся синтезатором с первой ноты.

**Различие по типу — числами, а не устройством.** Постройка отличается
от машины не «другим звуком», а вдвое большим числом обломков, вчетверо
более долгой осыпью, пятью металлическими модами вместо трёх и раскатом
на две секунды вместо четверти. Такое родство слышно: поле остаётся
одним миром, а не набором несвязанных эффектов.

## Решение 1в. Выпечка уходит в рабочий поток

**Выбрано:** отсчёты считает `Worker`, готовые массивы возвращаются
передачей владения (`Transferable`), без копирования.

**Почему.** Восемьсот пятьдесят миллисекунд — это полсекунды застывшего
меню на этой машине и вдвое-втрое больше на слабой. Разложить их
по кадрам не выйдет: самый долгий отдельный звук (ядерный удар, пять
секунд) считается 180 мс за раз, а разрезать выкладку по диапазонам
отсчётов нельзя — она держит состояние фильтров в замыкании.

**Альтернатива A: считать на главном потоке по первому жесту.**
Отклонена. Жест случается в меню, и заминка в меню — это заминка
в интерфейсе, которую главное требование проекта запрещает прямо.

**Альтернатива B: `requestIdleCallback` по одному звуку.** Отклонена:
неделимая единица работы всё равно 180 мс, а это одиннадцать
пропущенных кадров.

**Что если звук ещё не готов.** Событие проходит молча. Выпечка идёт
меньше секунды и начинается в меню, поэтому к первому выстрелу всё
готово; но полагаться на это нельзя, и «не готово» обязано быть
нормальным состоянием, а не ошибкой.

## Решение 2. Подсистема живёт в `apps/client/src/audio/`, а не в пакете

**Выбрано:** новый каталог внутри клиента, без нового пакета
в `packages/`.

**Почему.** Пакет заводится тогда, когда код нужен двоим. Звук нужен
одному: сервер его не издаёт, арена прогоняет матчи без браузера,
бот тем более. Граф пакетов односторонний и проверяется линтом, и лишний
узел в нём — это лишний `package.json`, лишняя сборка в Turborepo
и лишний прогон в `pnpm verify` ради кода, у которого один потребитель.

**Альтернатива: `packages/audio`.** Отклонена до появления второго
потребителя. Если такой появится — переезд стоит одного `git mv`,
потому что зависимостей у подсистемы всего три: `@td/shared`
(константы), `game/noise.ts` (хеш и шум) и `game/effects.ts`
(кривые угасания).

## Решение 3. Звук идёт от предсказанного мира с защитой от повторов

Это самое опасное место изменения.

**Выбрано:** события выводятся из того же предсказанного мира, который
рисуется, а от повторного проигрывания защищает множество уже сыгранных
ключей.

**Ключ события** берётся готовым — обе подсистемы отрисовки уже считают
устойчивый хеш, инвариантный к перерисовкам:

```
выстрел: hashOf([from.x, from.y, to.x, to.y, expiresAtTick])   // shots.ts:326
взрыв:   hashOf([at.x, at.y, expiresAtTick, kind])             // blasts.ts:291
ракета:  nuke.id                                               // world.ts:186 — единственная запись с id
```

Тот же хеш, что уже задаёт форму искр и обломков. Второй копии
не заводится: разойдись они, звук и картинка стали бы описывать разные
события.

**Почему не подтверждённый мир.** Соблазн велик: канал
`onFrame(tick)` (`bootstrap.ts:143`) вызывается ровно один раз на тик,
по порядку, без переигрывания — дедупликация не нужна вовсе. Но
подтверждённый мир отстаёт от предсказанного на `delayTicks`, то есть
на 2–9 тиков. При тридцати тиках в секунду это от 67 до 300
миллисекунд. Звук, отстающий от собственной вспышки на треть секунды,
воспринимается не как задержка, а как поломка: глаз и ухо расходятся
задолго до сотни миллисекунд. Главное требование проекта — отклик
в том же кадре — прямо это запрещает.

**Чем платим.** Предсказание изредка ошибается, и тогда звучит событие,
которого в подтверждённом мире не случилось. Для ленты отказов это было
бы недопустимо — там показывается текст, и ложное сообщение врёт
(`bootstrap.ts:112-115`). Для звука цена другая: лишний хлопок в бою,
где их и так десятки. Промолчать там, где стреляли, хуже, чем хлопнуть
там, где почти стреляли.

**Уборка множества.** Ключи копятся, и без уборки к концу матча
в множестве были бы сотни тысяч записей. Записи мира живут не дольше
`BLAST_LIFETIME_TICKS[Nuke]`, то есть пяти секунд; ключ хранится вместе
с тиком истечения и выметается, когда мир ушёл на десять секунд вперёд.
Запас десятикратный к сроку жизни самой долгой записи — намеренно:
номер тика умеет уменьшаться, и подметать впритык значило бы забыть
о событии, которое после отката вернётся.

**Первый кадр молчит.** При входе в матч и при восстановлении по истории
команд мир уже полон записей. Первый кадр набивает множество ключей
и не играет ничего, иначе игрок получил бы залп из всего, что успело
случиться до его подключения.

**Фаза `catching-up` молчит целиком.** Восстановление проигрывает минуту
матча за доли секунды; озвучивать это нельзя ни в каком виде.

## Решение 4. Кто стрелял, выводится из оружия и точки выстрела

**Проблема.** `ShotState` хранит `weapon`, но не хранит, кто стрелял
(`world.ts:207-217`: след живёт дольше стрелка). А `ShotWeapon.Bolt` —
это и штурмовик, и базовая башня, и база; `ShotWeapon.Beam` — и снайпер,
и снайперская башня.

**Выбрано:** различать звук по оружию, а вес — по тому, постройка
это или машина. Механизм опознания уже написан и используется для
высоты дульного среза: `structureAt(world, x, y)` (`shots.ts:161-169`)
опознаёт постройку по точному совпадению точки выстрела с центром
клетки.

| Оружие   | Из машины                     | Из постройки                          |
| -------- | ----------------------------- | -------------------------------------- |
| `Bolt`   | «пиу» штурмовика               | то же на терцию ниже и чуть длиннее    |
| `Beam`   | гудящий луч снайпера           | то же на кварту ниже                   |
| `Arc`    | раскат Теслы (машин не бывает других) | —                              |
| `Missile`| ракета генерала (только он)    | —                                      |

Башня ниже и длиннее машины не ради разнообразия: она вчетверо
крупнее и неподвижна, и низкий звук — это ровно то, чем крупное тело
отличается от мелкого.

**Альтернатива: завести в `ShotState` поле «стрелок».** Отклонена
жёстко. Это поле состояния мира, оно входит в контрольную сумму, сдвигает
эталон детерминизма и поднимает `PROTOCOL_VERSION` — всё ради оттенка
звука, который выводится из уже имеющихся данных бесплатно.

## Решение 5. Бюджет звуков: потолок на кадр и слияние одновременных

**Проблема.** Двести юнитов дают до двадцати выстрелов за тик. Двадцать
одинаковых транзиентов, начатых в одну миллисекунду, — это не двадцать
выстрелов, а один перегруженный треск: амплитуды складываются,
сумма выходит за единицу, и звуковая карта её обрезает.

**Выбрано:** трёхступенчатое ограничение.

**Ступень 1 — отсечение по удалению.** Дальше тридцати двух клеток
от центра обзора событие не звучит вовсе и места среди звучащих не занимает.

**Ступень 2 — потолок на вид события за кадр.**

| Вид                    | Потолок |
| ---------------------- | ------- |
| Трассер                | 4       |
| Луч                    | 3       |
| Разряд                 | 3       |
| Гибель машины          | 3       |
| Разрушение постройки   | 2       |
| Ракета генерала        | 2       |
| Гибель генерала        | 1       |
| Ядерный удар           | 1       |
| Всего за кадр          | 12      |

Отбираются ближайшие к центру обзора: дальнее событие и так тише.

**Ступень 3 — честное слияние.** Отброшенные не пропадают бесследно.
Некоррелированные источники складываются по энергии, поэтому оставшиеся
получают прибавку `min(1.6, sqrt(всего / оставлено))`. Залп из двенадцати
трассеров звучит громче одиночного выстрела, но не в двенадцать раз —
ровно так же, как в жизни.

Сверх этого держится общий потолок в 24 одновременно звучащих источника;
голоса считаются по `onended`, и когда потолок достигнут, новые тихие
события пропускаются.

## Решение 6. Размещение в пространстве: `StereoPannerNode`, не `PannerNode`

**Выбрано:** громкость по удалению в клетках, панорама по экранному
смещению, оба — простые числа, `StereoPannerNode` для панорамы.

```
удаление d — в клетках, от центра обзора до источника
громкость  = 10 / (10 + d) · fadeOver(d, 22, 32)
панорама   = clamp(экранное Δx / (полуширина окна · 1.15), −1, 1) · 0.75
```

`fadeOver` берётся из `game/effects.ts` — та же кривая, которой гаснут
частицы. Множитель `0.75` не даёт панораме уехать в чистый левый или
правый канал: в наушниках это читается «звук в ухе», а не «звук слева
на карте».

**Почему не `PannerNode` с HRTF.** Он стоит заметно дороже на источник,
считает расстояние и конус сам и требует расставить слушателя
и источники в трёхмерных координатах. Взамен он даёт высоту и
приближение головы — ни того, ни другого в изометрии сверху нет.

**Откуда берётся центр обзора.** Камера хранит точку в экранных
координатах мира (`camera.ts:13-16`). Сцена получает свойство
`viewCentre: CellPoint` — та же точка, переведённая в клетки
`screenToWorld`. Это единственная правка в `scene.ts`, и она
не тянет в сцену ни одного звукового понятия.

## Решение 7. Автозапуск: контекст создаётся по первому жесту

Браузеры запрещают звук до действия пользователя. `AudioContext`,
созданный раньше, окажется в состоянии `suspended`, и первый десяток
событий пропадёт молча.

**Выбрано:** контекст не создаётся, пока игрок ничего не нажал. Слушатели
`pointerdown` и `keydown` вешаются на окно с `{ once: true }`, по первому
из них контекст создаётся, звуки пекутся, музыка запускается.

К началу матча жест заведомо был: игрок прошёл через меню, ввёл имя
и нажал на кнопку. Но полагаться на это нельзя — матч открывается
и по прямой ссылке.

**Дополнительно** — `resume()` при `visibilitychange`: браузер
приостанавливает контекст в скрытой вкладке и не всегда возвращает его
сам.

## Решение 8. Музыка: расписание с упреждением поверх запечённых инструментов

**Выбрано:** четыре запечённых инструмента (бочка, хэт, бас, ведущий
голос) и расписание на 128 шестнадцатых — восемь тактов при 88 ударах
в минуту, то есть примерно двадцать две секунды.

Высота баса и ведущего меняется частотой воспроизведения: один
запечённый образец на инструмент, а не по образцу на ноту.

**Планировщик** — классическая схема «двух часов»: таймер раз в 25 мс
смотрит вперёд на 120 мс и назначает всё, что попадает в это окно,
на точное время `AudioContext.currentTime`. Назначать по таймеру
напрямую нельзя: таймеры браузера дрожат на десятки миллисекунд,
и ритм разъехался бы слышимо.

Расписание — чистая функция `notesAt(step) => Note[]`, проверяемая
тестом без всякого звука.

**Альтернатива A: одна длинная запечённая петля.** Отклонена. Двадцать
две секунды стерео — это около четырёх мегабайт в памяти, а главное,
петля повторяется абсолютно точно и через три круга начинает считаться
как метроном.

**Альтернатива B: живой граф осцилляторов.** Отклонена по причинам
решения 1: не проверяется тестом и дороже.

**Что играет.** Минорная пентатоника от ля — гамма, в которой
не бывает фальшивых сочетаний, что для «незатейливой» фоновой петли
именно то, что нужно. Бочка на первой и третьей доле, хэт восьмыми
с чередованием громкости, бас — остинато по четырёхтактовой
последовательности, ведущая линия — редкие ноты только в третьем,
четвёртом, седьмом и восьмом тактах. Разреженность намеренная: музыка
обязана оставить середину диапазона бою.

## Решение 9. Ротор — непрерывный звук, а не событие

Движение генерала — это состояние (`general.direction !== DIRECTION_STOP`,
`world.ts:166-184`), а не запись с моментом рождения. Значит, и голос
у него непрерывный.

**Выбрано:** одна зацикленная петля на каждого живого генерала —
и своего, и чужого. Тумана войны нет, чужой генерал виден, и слышать
его приближение — то же самое право, что видеть его силуэт.

Петля печётся ровно из семи периодов винта при четырнадцати ударах
в секунду, то есть ровно полсекунды, — иначе на стыке щёлкает.

| Состояние генерала | Громкость | Частота воспроизведения |
| ------------------ | --------- | ------------------------ |
| стоит              | 0.15      | 1.00                     |
| движется           | 1.00      | 1.08                     |
| погиб              | 0         | —                        |

Переходы — плавные: 0.12 с на разгон, 0.35 с на выбег. Мгновенное
переключение щёлкает, а выбег дольше разгона потому, что винт
так и ведёт себя.

Совсем гасить стоящего нельзя: генерал висит в воздухе, и полная тишина
под ним читалась бы как «машина выключилась и не падает».

## Решение 10. Ядерный удар глушит остальной мир

**Выбрано:** в момент детонации шина боя приглушается до 0.35 за 60 мс
и возвращается за 1.6 с; шина музыки — до 0.15 и возвращается за 3 с.

Это одновременно приём и необходимость. Приём: после такого удара мир
на секунду оглох, и это ровно то, что удар должен сообщать. Необходимость:
ядерный удар громкий по построению, и сложенный с двумя десятками
хлопков от гибнущих в радиусе юнитов он вышел бы за единицу
и обрезался бы.

Свист снижения (три секунды, ровно `NUKE_DELAY_TICKS`) начинается
с появлением записи `NukeState` и ничего не приглушает: он предупреждение,
а не удар.

## Решение 11. Настройки: три громкости, `localStorage`, состояние в HUD

**Выбрано:** три независимых ползунка — общий, бой, музыка — плюс
выключатель. Хранятся в `localStorage` под ключом `td_sound`.

**Почему не кука.** Профиль лежит в куке потому, что его читает сервер.
Громкость сервер не читает и читать не должен; отправлять её в каждом
запросе — платить трафиком за настройку.

**Почему три, а не одна.** Музыка и бой мешают друг другу по-разному.
Игрок, которому музыка надоела на третьем матче, не должен ради этого
отключать звук боя, несущий сведения о поле.

**Где живёт состояние.** В `HudState` рядом с `selection` — там же,
где живёт прочее состояние интерфейса. Игровой цикл читает его через
`useHudStore.getState()`, как это уже делает `hudActions`, а не
подпиской: подписка перерисовывала бы HUD.

**Клавиша `M`** выключает и включает звук целиком — самое частое
действие, и лезть за ним мышью в панель незачем.

## Решение 12. Поведение при рассинхроне, переподключении и остановке

| Состояние             | Что со звуком                                                     |
| --------------------- | ------------------------------------------------------------------ |
| `connecting`          | молчит; контекст уже создан, музыка играет                          |
| `awaiting-opponent`   | музыка играет, бой молчит — его нет                                 |
| `catching-up`         | бой молчит целиком (решение 3), музыка играет                       |
| `playing`             | обычная работа                                                      |
| `desynced`            | бой молчит до конца пересборки: мир переигрывается                  |
| `stopped`, `finished` | бой молчит, музыка гаснет за 2 с                                    |
| выход из матча        | `stop()` гасит всё за 0.2 с и закрывает контекст                    |

Музыка переживает пересборку мира намеренно: она не описывает событий
и обрыв её звучал бы поломкой ровно там, где игрок и без того
встревожен.

## Что проверяется тестом, а что глазами

Клиентские тесты идут в окружении `node`, Web Audio там нет. Граница
проведена так, чтобы по ту сторону осталось как можно меньше.

**Проверяется тестом:**

| Модуль         | Что именно                                                            |
| -------------- | ---------------------------------------------------------------------- |
| `dsp.ts`       | фильтр не расходится и не даёт `NaN`; затухание монотонно; нормировка даёт заданный пик |
| `sounds.ts`    | длительность каждого звука; пик не больше единицы; отсутствие `NaN`; голос начинается и кончается тишиной (иначе щелчок); у ротора конец сходится с началом |
| `sounds.ts`    | «пиу» падает по частоте, а разряд — по яркости: сравнением числа переходов через ноль в первой и последней четверти |
| `cues.ts`      | одно и то же событие в десяти кадрах подряд даёт один звук; откат тика не даёт второго; первый кадр молчит; фаза восстановления молчит; уборка ключей освобождает память |
| `placement.ts` | громкость убывает с удалением; за отсечкой ноль; панорама не выходит за ±0.75; в центре ровно ноль |
| `budget.ts`    | потолки соблюдаются; отбираются ближайшие; прибавка за слияние не превышает 1.6; пустой кадр даёт пустой список |
| `music.ts`     | петля замкнута на 128 шагов; бочка попадает на доли; ведущая линия молчит в первых двух тактах |
| `settings.ts`  | испорченный `localStorage` даёт значения по умолчанию, а не исключение |

**Проверяется глазами и ушами:** тембр. Что «пиу» звучит как «пиу»,
арифметикой не проверить.

**Не проверяется ничем и не должно:** `engine.ts`. Это тонкая обвязка
над Web Audio без единого ветвления по игровым правилам. Всё, что можно
было из него вынести, вынесено в перечисленные выше модули — ровно
затем, чтобы непроверяемого осталось как можно меньше.
