# keep-the-world-moving

Жалоба «игра подлагивает», разобранная по приборам, а не на глаз.
Приборы поставило `measure-the-tick`; это изменение читает их первые
боевые показания, чинит найденное и достраивает то, чего для разбора
не хватило.

## Что показали приборы 24 августа 2026

Один матч на https://dezintegra.net/, 12 423 тика (6 мин 54 с),
соперник — компьютер по профилю `bulwark-2026-08`.

| прибор | значение | вывод |
| --- | --- | --- |
| `td_ticks_per_advance` max | **1** | сервер не догонял ни разу |
| `td_tick_debt_total` | **0** | и ни разу не сдавался |
| `td_world_step_duration_ms` среднее | 0,24 мс | шаг мира бесплатен |
| `td_ai_decision_duration_ms` среднее | 2,77 мс | компьютер оправдан |
| `td_event_loop_delay_ms` p99 | 11,29 мс при поле 10 | заминок нет |
| `td_client_frame_gap_ms` среднее | 16,86 мс | 59,3 кадра в секунду |
| `td_client_frame_gap_ms_over_budget` | 66 из 23 938 | 0,28 % длинных кадров |
| **`td_client_tick_frame_gap_ms` p95** | **≈ 111 мс** при ожидаемых 33,3 | **вот оно** |
| `td_client_tick_frame_gap_ms` p99 | ≈ 257 мс | |
| позже тика | 4647 из 12 422 — **37 %** | |
| вплотную к предыдущему (≤ 4 мс) | 3197 — **26 %** | двугорбое: тишина, потом пачка |

Дрожание рождается в канале игрока. Замер с его машины: до боевой
машины p50 13 мс, p95 92, максимум 155; **до собственного роутера** —
p50 2 мс, p95 59, максимум 203. То есть на первом же участке, ещё
не выйдя в интернет.

## Почему это было видно глазом

Показываемая копия мира пересобиралась ровно в двух случаях: пришёл
кадр или игрок отдал команду. Цикл отрисовки каждый кадр читал
`guest.predicted` и получал тот же самый объект, пока кадр не пришёл.

Опоздал кадр на 250 мс — картинка стояла 250 мс при честных 60 кадрах
в секунду. Пришли два кадра встык — мир проскакивал два тика за один
кадр отрисовки.

## Три новых ряда и на что каждый отвечает

| ряд | вопрос | где считается |
| --- | --- | --- |
| `td_frame_send_gap_ms` | ровно ли **сервер выпускает** кадры | ведущий матча |
| `td_player_rtt_ms` | сколько летит пакет туда и обратно | ответ на замер канала |
| `td_client_display_gap_ms` | ровно ли **двигается картинка** | браузер игрока |

Вместе с прежним `td_client_tick_frame_gap_ms` они дают решётку,
по которой виноватый находится за один взгляд.

| выпуск | доставка | показ | вывод |
| --- | --- | --- | --- |
| рвано | рвано | рвано | сервер: смотреть шаг мира и цикл событий |
| ровно | рвано | ровно | **канал дрожит, и это скрыто** — норма после этой правки |
| ровно | рвано | рвано | часы показа не работают: смотреть `advance` в цикле отрисовки |
| ровно | ровно | рвано | браузер: смотреть `td_client_frame_gap_ms` |

## Как снимать

Точка `/metrics` наружу не выставлена — nginx проксирует только
`/game`, `/api/`, `/health`, `/assets/` и `/`. Читать так:

```bash
ssh dezintegra
docker exec td-game-server-1 wget -qO- http://127.0.0.1:3001/metrics
```

Показания клиента уезжают на сервер одним запросом после исхода матча
и попадают туда же с разметкой `source="client"`. По ходу матча их
видно в атрибутах корневого элемента: `data-display-gap-p95`,
`data-display-gap-long`, `data-net-gap-p95`, `data-frame-p95`.

**Поправка на пол цикла событий обязательна.** `td_event_loop_delay_ms_p50`
на пустом сервере равна разрешению наблюдателя (на боевой машине
10,17 мс) — это гранулярность, а не заминка. Снимать на сервере без
матчей и вычитать.

## Чего это изменение не делает

Не заводит хранилища показаний и графиков, не интерполирует состояния
сущностей, не заводит буфер дрожания с добавленной задержкой,
не трогает расчёт задержки ввода, не меняет протокол и не чинит канал
игрока. Подробности и доводы — в `proposal.md` и `design.md`.
