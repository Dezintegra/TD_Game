# Список задач

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе.

## 1. Шаг множителя умеет обе модели роста

- [x] В `packages/shared/src/percent.ts` завести тип `GrowthModel`
      (`'geometric' | 'linear'`) и функцию `stepPpm(множитель, процент,
      модель)`: умножение при геометрической модели, прибавка
      `процент × PPM_ONE / 100` при линейной.
- [x] Там же — `linearPpm(процент, шагов)` рядом с `compoundPpm`:
      множитель после нескольких линейных шагов, нужен восстановлению
      состояния и тестам.
- [x] Тесты в `percent.test.ts`: линейный шаг даёт прямую, геометрический
      совпадает с прежним `growPpm`, ноль процентов не двигает множитель.

- [x] Пересобирать `UPGRADE_BRANCHES` в обработчике

- [x] Тест в `balance.test.ts`: без настройки таблица прежняя, порядок

## 5. Факторный инструмент знает те же ручки

Сторож полноты таблиц (`scripts/experiment/tuning-flags.test.mjs`) требует,
чтобы каждое поле `RuleTuning` было доступно и арене, и факторному
инструменту. Шаг появился не в замысле, а по красному CI — и остался
в списке именно поэтому.

- [x] Дополнить `FLAG_OF` в `scripts/experiment/tempo-factorial.mjs`
      пятью ключами экономики.
- [x] Научить сторожа двум таблицам арены вместо одной: разведены они
      ради разбора, а состав правил покрывают вместе.
