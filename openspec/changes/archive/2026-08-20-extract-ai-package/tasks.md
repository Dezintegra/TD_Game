профиль. Иначе доказать, что поведение не изменилось, будет нечем.

## 3. Профиль поведения

- [x] 3.1 Описать тип `AiProfile` в `packages/ai/src/profile.ts`,
      сгруппировав величины по сторонам игры: движение, строительство,
      траты, ядерный удар, оценка рубежей, фазы. В комментарии объяснить,
      почему числа хранятся в человеческих единицах (секунды, клетки,
      доли), а перевод во внутренние делается при чтении.
      *Проверка:* `pnpm --filter @td/ai typecheck` зелёный.
- [x] 3.2 Собрать профиль `baseline-2026-08` из существующих констант
      `opponent.ts` и `posture.ts`, значение в значение. Заморозить
      `Object.freeze` вглубь.
      *Проверка:* тест на неизменяемость — попытка записи не меняет
      значения.
- [x] 3.3 Реестр `PROFILES` и `DEFAULT_PROFILE_ID`. В комментарии
      объяснить, почему имя содержит дату.
      *Проверка:* профиль достаётся по имени, неизвестное имя даёт
      понятную ошибку.
- [x] 3.4 Провести профиль через `createOpponent` третьим необязательным
      аргументом и дальше в `decideMovement`, `tryBuild`, `tryTrain`,
      `tryUpgrade`, `tryNuke`, `chooseFrontier`, `frontiersOf`,
      `scoreFrontier`. Отдельно — условие сопровождения внутри `decide`:
      оно читает `ADVANCE_FRACTION`, `ESCORT_UNITS` и `ESCORT_SPEND`
      прямо в теле метода, а не через вспомогательную функцию, и при
      беглом чтении теряется. Существующие вызовы не трогать.
      *Проверка:* `pnpm --filter @td/ai test` зелёный. Отступление
      от задуманного: в `posture.test.ts` пришлось поправить три строки —
      вызов `situationOf` принимает профиль, а `THREAT_RADIUS_CELLS`
      переехал в профиль и читается как
      `BASELINE_PROFILE.posture.threatRadiusCells`. Это следствие задачи
      3.5 (убрать вторые источники истины), а не правка самого теста:
      ни одно утверждение не изменилось. Ни один
      существующий тест не правился.
- [x] 3.5 Убрать константы, переехавшие в профиль, из модулей —
      чтобы не осталось двух источников истины.
      *Проверка:* поиск по именам констант не даёт совпадений вне
      `profile.ts`.
- [x] 3.6 Второй профиль для проверки самого механизма — например,
      `wall-heavy-2026-08` с иной частотой стен. Нужен не ради игры,
      а чтобы доказать, что профиль вообще на что-то влияет.
      *Проверка:* матч с ним даёт контрольную сумму, отличную
      от матча с профилем по умолчанию.
