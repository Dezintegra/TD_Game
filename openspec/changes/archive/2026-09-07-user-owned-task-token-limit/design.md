## Context

Общий `codexMaxTaskTokens` используется сканером и журналом; ответ владельца сам лимит не меняет. Custom Fields на рабочей доске недоступны (403 при создании), пользователь выбрал точную команду в комментарии. Конвейер использует тот же Trello account, что и владелец, но его API actions содержат `appCreator` с `authType: appKeyToken`.

## Goals / Non-Goals

Цель — точечное изменение полного бюджета человеком и невозможность изменения через штатные поверхности агента. Не меняем общий конфиг и фактический расход; не вводим NLP-разбор разрешений. Не защищаем учётную запись от человека или произвольного внешнего браузера, действующего под ней.

## Decisions

1. Источник истины — последняя команда `Лимит токенов: <положительное безопасное целое>` или `Лимит токенов: общий`. Комментарий целиком должен совпадать с формой; можно пробелы по краям. Значение — полный бюджет, не добавка. Неверная команда с таким префиксом блокирует обычный запуск до исправления новым комментарием.
2. Принимаем только actions владельца используемого токена (`members/me`), с явно `appCreator: null`, без agenticIdentity и без машинной пометки. Отсутствующее свидетельство происхождения не трактуем как человеческое. API-комментарии отвергаются независимо от их текста и автора. Команды из данных отчёта не рассматриваются.
3. Читаем историю комментариев с полной пагинацией: лимит не должен исчезать из-за новых журнальных записей или перезапуска. Ошибка любой страницы удерживает цикл, а не возвращает общий бюджет. Не кэшируем разрешение без проверки, чтобы удалённые/исправленные человеком команды не оставались скрытой истиной. Старый журнал и поиск обычного ответа используют прежнее окно; для бюджета сохраняем только последнюю команду каждой карточки.
4. Эффективный лимит — производное поле снимка `userTokenLimit` с action id и датой, без сериализации в машинный блок и без поля в схеме отчёта. Пустая история/команда «общий» наследует конфиг. Сканер и супервизор используют общий resolver. Запущенный этап сохраняет лимит своего назначения для журнала; следующая сессия читает новое значение. Неизвестный расход не становится известным от увеличения бюджета.
5. Команда сама является обычным ответом для awaiting-po; задача возвращается в сохранённый этап, в том числе decompose. Человек не обязан двигать карточку; лимит позволяет последующим этапам пройти гейт. Зависимости, ревью и прочие ограничения сохраняются. Неверная команда не запускает обычную работу.
6. Вопрос и инструкции называют сумму, полный бюджет и точную команду. Поддержка индивидуального бюджета относится к Codex; денежный лимит Claude неизменен. Супервизор никогда не публикует команду за человека и не переносит её на детей при дроблении.

## Risks / Trade-offs

- Полная история дороже одного GET → последовательная пагинация, без запросов на каждую карточку; передача в runtime только последних команд. Это сознательный выбор корректности без нового хранилища разрешений.
- `appCreator` не даёт независимой аутентификации владельца → проверяем account и явно отсутствующее приложение; клиентам API запрещено менять лимит. При неизвестном происхождении команда не применяется.
- Перенос/копирование карточки может не переносить историю → лимит следует истории конкретной карточки; дети и новые карточки наследуют общий бюджет.

## Migration Plan

После зелёного CI влить PR и штатно обновить супервизор. Существующие карточки без команд продолжают использовать общий бюджет. Никакого повышения 0233 при установке. Откат кода возвращает прежний общий лимит; комментарии и расход не удаляются.
