## Why

Репозиторий пустой: нет ни сборки, ни границ между клиентом, сервером и игровой логикой. Пока каркас не зафиксирован, любая геймплейная фича будет писаться «куда попало», а детерминированную симуляцию — главное условие честного PvP — задним числом из перемешанного кода уже не вырезать. Каркас нужен первым, чтобы все последующие изменения ложились в готовые границы.

## What Changes

- Монорепозиторий на pnpm workspaces с оркестрацией задач через Turborepo.
- Единая TypeScript-конфигурация (strict, ESM, project references) и общий базовый `tsconfig`.
- Шесть рабочих пакетов с явными границами зависимостей:
  - `apps/client` — Vite + React 19 (HUD и меню) + PixiJS v8 (игровое поле).
  - `apps/server` — Node.js + Fastify (REST) и WebSocket-слой для реалтайма.
  - `packages/sim` — изоморфное детерминированное ядро симуляции.
  - `packages/protocol` — бинарный сетевой протокол поверх `ArrayBuffer`.
  - `packages/shared` — общие типы, игровые константы, балансные конфиги.
  - `packages/ui` — React-компоненты и дизайн-токены.
- Правило зависимостей: `sim` и `shared` не знают ни о клиенте, ни о сервере; `client` и `server` не импортируют друг друга.
- Тестовый контур: Vitest для юнит-тестов, Playwright для e2e, отдельный golden-тест на детерминизм `sim`.
- Контроль качества: ESLint 9 (flat config), Prettier, проверка типов в CI (GitHub Actions).
- Smoke-вертикаль: клиент поднимается, соединяется с сервером по WebSocket, обменивается ping/pong через бинарный протокол и рисует один кадр Pixi. Геймплея пока нет.

## Capabilities

### New Capabilities

- `workspace-structure`: границы пакетов монорепозитория, правила зависимостей между ними, именование `@td/*`.
- `build-tooling`: единые команды сборки, dev-режима, проверки типов и линта; кеширование задач; воспроизводимость окружения.
- `quality-gates`: обязательные проверки перед вливанием изменений — типы, линт, форматирование, тесты, включая golden-тест детерминизма.

### Modified Capabilities

Нет — это первое изменение в репозитории, существующих спецификаций ещё не заведено.

## Impact

- **Код**: создаётся вся файловая структура репозитория с нуля; существующего кода, который может сломаться, нет.
- **Зависимости**: pnpm, Turborepo, TypeScript, Vite, React, PixiJS, Fastify, ws, Vitest, Playwright, ESLint, Prettier.
- **CI**: новый workflow GitHub Actions, запускающий `turbo run lint typecheck test build`.
- **Отзывчивость интерфейса**: каркас закладывает главное архитектурное условие отзывчивости — игровой цикл живёт вне React и рендерится через PixiJS, поэтому React не перерисовывает игровое поле. Прямого влияния на время кадра в этом изменении нет, но именно здесь фиксируется граница, без которой предсказание на клиенте невозможно.
- **Сетевой трафик**: закладывается бинарный протокол вместо JSON; в этом изменении по сети ходит только ping/pong, то есть трафик пренебрежимо мал.
- **Разработчики**: новый порядок работы — задачи ведутся через OpenSpec, коммиты по Conventional Commits.

## Non-goals

- Игровая механика: башни, волны, враги, экономика, баланс — отдельные изменения.
- Нетcode как таковой: prediction, rollback, сверка контрольных сумм — отдельное изменение поверх готового `sim`.
- Матчмейкинг, аккаунты, авторизация, рейтинги, персистентность в БД.
- Арт, звук, анимации, адаптив под мобильные устройства.
- Деплой в продакшн, инфраструктура, докеризация, мониторинг.
