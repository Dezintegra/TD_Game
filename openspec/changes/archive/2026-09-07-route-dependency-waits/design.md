## Context

В main уже есть delayAnalysis: диагноз, надёжная доставка комментария, наблюдение
зависимостей и проверка перед возвратом. awaiting-po исключён из него полностью.
В 0244 отсутствует dependsOn: ожидание PR описано только текстом. 0246 для записи
этих условий тоже ждёт ответа. Новый общий канал адресных правок 0242 ещё открыт;
собственное объявление блокеров уже доступно и не требует этого канала.

## Goals / Non-Goals

Проверять смысл новых и прежних вопросов, сохранять настоящие вопросы, продолжать
технически заблокированную работу после доказанного результата. Не разбирать
естественный язык в сканере, не назначать себе ответы владельца и не менять
чужие рабочие деревья. Остальные ограничения перечислены в proposal.md.

## Decisions

1. Включить awaiting-po в сохранённую диагностику немедленно при отсутствии
проверенного диагноза. Это проверка маршрута, не пятичасовой таймер. Использовать
postmortem и штатные квоты. Сохранённый monitor возвращает прежние статус и дату;
повторное сканирование неизменного вопроса не вызывает сессию. Прочитанный ответ
владельца имеет приоритет, живые процессы, отчёты и пауза сохраняют ограничения.
Новый question сначала имеет обычную запись на доске; ближайший цикл проверяет
его маршрут. Единый контракт учит новые этапы сразу возвращать blocked.

2. Для originStatus=awaiting-po диагноз явно называет waitingFor: owner или
dependencies. Исход done/monitor допускает только owner и объясняет необходимое
решение. blocked допускает только dependencies с существующим контрактом фактов
и результатов. Первичный анализ не может вернуть done/resolved и обойти граф.
После завершения всех блокеров verifier подтверждает результат, после чего
задача возвращается в originReturnTo. Реальный ответ не создаётся, история
вопроса сохраняется. Смешанный вопрос с настоящим выбором остаётся owner.

3. Расширить blocker объект optional dependencyResult: {kind: merged-pr, pr}.
Супервизор добавляет taskId после разрешения ссылки, валидирует прежний и новый
граф до записей, объединяет условия без ослабления и отвергает конфликт номера.
Условия сохраняются на собственной карточке — не новый адресный канал 0242.
После классификации уже выполненной предпосылки разрешён технический blocked:
штатный допуск и verifier всё равно проверят реальный результат. Запрет циклов,
невалидных и безрезультатно закрытых карточек сохраняется. Упавший существующий
предшественник при классификации вопроса допускается как ожидаемая работа:
его failed удерживает граф, без создания дубликата его исправления.

4. При ответе во время диагностики сначала вернуть карточку в awaiting-po с
исходной датой вопроса, чтобы обычный answer-question обработал комментарий.
Trello readAnswer использует originSince для незавершённой проверки вопроса.
Ответ проверяется до начала анализа и перед применением классификации. Никаких
записей «Ответ принят» до обычной обработки. Проверка неизменного сохранённого
вопроса переживает сериализацию карточки и перезапуск.

5. Для зависимости, найденной после вопроса, сохранённые attempts/returnTo,
change, PR и ветка не сбрасываются. Пока условия не выполнены, нет новых рабочих
сессий. После возврата начинается свежая сессия исходного этапа. Контракт разбора
объясняет, что само ожидание легитимного предшественника не требует придумывать
новую карточку общей починки: защита здесь — машинное условие и правильный маршрут.

## Risks / Trade-offs

- Дополнительная сессия для нового вопроса → штатные квоты и один сохранённый вердикт на эпизод.
- Ошибка смысловой классификации → факты, явный waitingFor, строгие условия графа; смешанные и неопределённые вопросы остаются у владельца.
- Ответ во время проверки → исходная дата чтения и возврат в обычный обработчик.
- Пересечение с PR 177 → изменения собственного blocker-контракта не заменяют dependencyUpdates; при обновлении main сохранять оба пути.

## Migration Plan

После поставки обновлённого супервизора очередной цикл проверяет прежние awaiting-po
в штатных квотах, включая 0244 и 0246; ручное переименование колонок не требуется.
Неизменные подтверждённые вопросы больше не диагностируются. Перед откатом дождаться
завершения проверок вопросов: старая версия не знает awaiting-po как originStatus.
