## Context

`removeWorktree` возвращает отказ при `Directory not empty` до проверки регистрации. `cleanup` продолжает удалять ветки, а `reconcile` в следующем цикле снимает запись, если дерева нет в выводе Git. Фактический каталог остаётся, задача без записи пропускает уборку. Даже отказ удаления удалённой ветки теряет повтор, когда дерева в Git уже нет.

## Goals / Non-Goals

Завершать уборку фактическим удалением папки и регистрации, сохраняя повтор после отказа. Не менять основания удаления, каталог деревьев и защиту внешних путей. Исторические каталоги без реестра требуют отдельной проверки принадлежности и влитости; массовая уборка не входит в изменение.

## Decisions

1. После попытки Git всегда проверять его список деревьев, независимо от кода и текста ошибки. Пока регистрация существует или список недоступен, рекурсивного удаления нет. Список читать с NUL-разделителями: пробелы, кириллица и переводы строк в имени не должны мешать сравнению путей. Отсутствие каталога само по себе успеха не доказывает, пока Git хранит регистрацию. Отсутствие родительского каталога допустимо при повторной уборке уже удалённого дерева.
2. Сохранить проверку абсолютной цели, прямого родителя внутри проекта и реальных путей без перенаправляющих ссылок; повторить её непосредственно перед `rmSync`. Удалять весь оставшийся каталог с ограниченными повторами и проверять исчезновение. Выбор отдельных расширений или только `node_modules` снова оставлял бы мусор. Ошибка блокировки не маскируется: следующий цикл повторяет действие.
3. В сверке сохранять запись задачи в `cleanup`, даже когда дерево исчезло из Git. Проверять папку в сверке недостаточно: папка может исчезнуть, а ветка остаться. Снять запись вправе только успешно завершившаяся уборка; обычные записи других состояний сверяются по прежнему правилу.
4. При отказе удаления дерева завершать вызов уборки до удаления веток. После дерева сначала удалять удалённую ветку и только после успеха локальную. Иначе повтор задачи без PR не сможет подтвердить отсутствие своей работы через локальную ветку. Сбой любого шага сохраняет запись и задачу в `cleanup`.

## Risks / Trade-offs

Занятый файл может пережить ограниченные повторы → сохранять путь и причину для следующего цикла; не останавливать посторонние процессы. Ссылки внутри зависимостей → удалять сами ссылки, проверять тестом сохранность внешней цели. Git может вернуть неполный результат → отказывать при ошибке инвентаризации или сохранившейся регистрации. Изменение состояния пути между Git и рекурсивным удалением → повторно проверить границы и ссылки.

## Migration Plan

Узкие проверки удаления, сверки и исполнения двух циклов, реальный временный репозиторий с игнорируемыми зависимостями, формат и линт изменённых файлов. После зелёного CI изменение готово к вливанию; работающий супервизор получает его штатным самообновлением после вливания. Откат — откат коммита, формат реестра не меняется.
