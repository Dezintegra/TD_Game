## Context

Trello хранит статус колонкой, служебный контекст — блоком описания. Сканер сейчас направляет исчерпавшие бюджет задачи в decompose, а неверный лимит и неполный учёт удерживает только записью в журнале. Человеческие команды читаются из полной истории.

## Goals / Non-Goals

Сделать ожидание видимым и обратимым, включая существующие карточки. Не менять авторизацию лимита, счётчик расхода, долларовый бюджет Claude и исключения диагностики.

## Decisions

1. Отдельное ожидательное состояние `token-limit` с `tokenHold`: originStatus, resumeStatus, originSince, originPriority и снимок причины/расхода/предела. `returnTo` остаётся неизменным; общий механизм сквозных состояний не используется, поскольку он сбрасывает попытки. Возврат идёт в сохранённый статус, а новый запуск — следующим снимком.
2. Общая чистая функция бюджетного допуска используется сканером и защитой непосредственно перед порождением. Служебные переносы выполняются раньше попыток и квот, не конкурируют с отчётом, отказом API и живым процессом. Бюджетное ожидание не запускает автоматическую диагностику задержки. Зависимости не обходятся.
3. Человеческая панель в описании строится из tokenHold; собственный текст карточки сохраняется. Лимит берётся только из effectiveTokenLimit, панель не даёт разрешений. Повтор одинакового состояния не создаёт записей.
4. Новый статус, сохранение/чтение и проверка контекста поставляются вместе. Неполный tokenHold удерживает карточку, не отправляя её на случайный этап.

## Risks / Trade-offs

- Старый супервизор не понимает новую колонку → включать только после обновления, штатно остановив выдачу и дождавшись окончания работы.
- Старое awaiting-po может содержать продуктовый вопрос → мигрировать по проверенной истории, сохранять исходный статус и returnTo; автоматические переносы обычных этапов делает новый сканер.
- Ошибка после перемещения до комментария → вся существенная информация хранится вместе с колонкой и описанием, следующий снимок не теряет маршрут.
- Переносы между колонками меняют порядок → сохранять числовое положение в исходной колонке и восстанавливать при возврате.

## Migration Plan

Узкие проверки и CI PR; затем обновление запускаемого супервизора, настройка колонки и сверка карточек с расходом. Снимок до миграции сохраняется локально. Перенос старых вопросов выполняется при паузе после проверки истории; новая версия сама переносит удержанные обычные этапы. Перед откатом остановить выдачу, восстановить сохранённые статусы и удалить только служебную панель.
