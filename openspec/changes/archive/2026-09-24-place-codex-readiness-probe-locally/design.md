## Context

`checkCodexReadiness` сначала подготавливает песочницу основного каталога, затем создаёт `td-codex-ready-*` через системный `os.tmpdir()`. После перезагрузки 24.09.2026 два запланированных запуска получили `UnauthorizedAccessException` к этому новому каталогу при первой PowerShell-команде модели. В той же задаче планировщика полная проверка с `TEMP` внутри `.pipeline` подтвердила Git, GitHub, дочерний Node и SSH. Простая команда `codex sandbox` проходила и из системного Temp, поэтому проверять надо полный путь модельной пробы.

## Goals / Non-Goals

**Goals:** дать Windows-пробе каталог внутри настроенного локального хозяйства конвейера и сохранить прежние доказательства готовности и очистку.

**Non-Goals:** ослабление песочницы, настройка ACL пользовательского профиля, перенос временных каталогов всех рабочих этапов.

## Decisions

1. На Windows `checkCodexReadiness` создаёт `td-codex-ready-*` внутри `root/config.paths.local` (по умолчанию `.pipeline`), предварительно создавая родительский каталог. Тот же путь уже используется для замка и журнала, а песочница основного дерева готовится до модельной пробы. Альтернатива — оставить системный Temp и выдавать ему права — меняет личный профиль и не доказана пробой в планировщике.
2. На других платформах остаётся `os.tmpdir()`. Альтернатива — переносить все платформы — не нужна для подтверждённого Windows-отказа.
3. Файл пробы удаляется в `finally`, затем удаляется только опустевший дочерний каталог. Родительское локальное хозяйство не удаляется. Ошибка создания/выполнения по-прежнему останавливает запуск, без ложного допуска задач.

## Risks / Trade-offs

- [Локальный каталог не доступен] → проба явно падает; супервизор не выдаёт задач и пишет причину. Права песочницы автоматически не расширяются.
- [Проба оставит временный каталог после аварийного завершения] → он находится в игнорируемом локальном хозяйстве с однозначным префиксом; штатный `finally` удаляет пустой каталог.
- [Дополнительные файлы в рабочем репозитории повлияют на модель] → каталог игнорируется Git, а модельная проба уже запускается с `project_doc_max_bytes=0`.

## Migration Plan

После зелёного CI слить изменение. Живой процесс применит код при безопасном перезапуске; подтверждение — успешная стартовая проверка из штатной задачи планировщика с обычным `TEMP`. Для отката вернуть коммит, сохранив временный операционный запуск до устранения отказа.
