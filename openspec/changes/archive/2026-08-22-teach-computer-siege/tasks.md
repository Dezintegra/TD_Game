## 1. Поля профиля

- [x] 1.1 Завести `building.towerMix` — веса видов башни. Умолчание
  базового профиля: базовая башня 1, снайперская 0.
- [x] 1.2 Завести раздел `push`: `baseShare` (доля здоровья базы, при
  которой открываются ворота рывка) и `waveSize` (сколько машин копить).
  Умолчание базового: доля 1, то есть прежнее правило.
- [x] 1.3 Добавить `'wave'` в `Reserve`. `reserveOf` принимает цену волны
  и держит её по той же мерке достижимости, что и ядерный запас.

## 2. Код читает поля вместо постоянных

- [x] 2.1 `tryBuild` выбирает вид башни жребием по `towerMix` и ищет
  место по дальности выбранного вида, а не базовой. Жребий НЕ бросается,
  когда ненулевой вес один: лишний бросок сдвинул бы генератор и всю
  дальнейшую партию.
- [x] 2.2 Рывок сравнивает урон волны с `baseShare × здоровье базы`
  и возвращает вызывающему цену волны для запаса.
- [x] 2.3 Запас под волну складывается с ценой покупки в трёх местах
  трат: производство, постройка, прокачка.
- [x] 2.4 Найдено по ходу: рывок нужно ограничить снизу размером волны.
  Без этого он вырождается обратно в ручеёк — ворота открываются, места
  в очереди находится одно, туда уходит одна машина. В замере это
  выглядело как 19 «рывков» за матч, из которых волной был один.

## 3. Базовый профиль не изменился

- [x] 3.1 `profile.golden.test.ts` проходит БЕЗ правок эталона. Красный
  эталон означает неверное умолчание, и чинится он кодом, а не эталоном.
  Пройден: 106 тестов пакета `@td/ai` зелёные.
- [x] 3.2 Эталон детерминизма `determinism.golden.test.ts` зелёный:
  правила игры не тронуты. Пакет `@td/sim` — 192 теста зелёные.

## 4. Проверки поведения

- [x] 4.1 Тест: крепостной профиль строит снайперские башни и ни одной
  базовой; профиль по умолчанию — наоборот.
- [x] 4.2 Тест: роевой профиль совершает рывок и заказывает волну целиком
  (не меньше `waveSize` машин одним тиком); профиль по умолчанию рывка
  не совершает вовсе.
- [x] 4.3 Тест: достижимый запас под волну держится, недостижимый —
  не держится, а без запаса фазы цена волны ничего не меняет.
- [x] 4.4 Найдено по ходу: проверять поведение надо матчем С СОПЕРНИКОМ.
  Против бездействующей стороны крепость не поставила ни одной
  снайперской башни, а осадный не купил ни одной Теслы — обе покупки
  дорогие, и решение о них зависит от обстановки. Пустое поле — это
  не «тот же матч без помех», а другая игра. Тесты `siege.test.ts`, 11 штук.

## 5. Профили-соперники

- [x] 5.1 Осадный: только Тесла в поздней фазе, горизонт накопления 150 с.
  Рывка нет намеренно — волна из Тесл стоит сто секунд дохода
  и недостижима, а волна из штурмовиков была бы чужой манерой.
- [x] 5.2 Крепостной: ТОЛЬКО снайперские башни (нулевой вес базовой),
  стена каждая третья, горизонт 90 с.
- [x] 5.3 Роевой: только штурмовики, волна из 16 при доле 0,2.
- [x] 5.4 Смешанный: башни обоих видов, Тесла и штурмовики, волна из 6
  при доле 0,5.
- [x] 5.5 Экономический: до 300-й секунды одна экономика, затем Тесла
  и штурмовики, волна из 12 при доле 0,3.
- [x] 5.6 Все пять отличаются от базового ТОЛЬКО значениями полей.
- [x] 5.7 Найдено по ходу: манера не проявляется сама. Три причины,
  все три стоили прогонов: прокачка удорожает саму покупку, поэтому
  профиль, качающий Теслу, перестаёт её покупать; предел терпения
  отбрасывает дорогое желание целиком; а при смеси весов дешёвое
  выигрывает гонку жребия. Отсюда «только снайперские» и «только Тесла»
  вместо долей.

## 6. Чемпионат

- [x] 6.1 Круговой прогон: 30 упорядоченных пар по 8 семян — 240 матчей,
  каждая пара в обе стороны. Прогнан в отдельном каталоге через `ARENA_DIR`:
  в общем `.matchlog` параллельно работала соседняя сессия.
- [x] 6.2 Собрана база, посчитаны доли побед, длительности, состав трат
  и состояние сторон по ходу матча.
- [x] 6.3 Разбор. Итог чемпионата: роевой 90%, крепостной 64%,
  экономический 50%, базовый 39%, смешанный 34%, осадный 11%.
  Главный признак победы — **число живых юнитов на поле**: у победителя
  их в 2,18 раза больше (27,1 против 12,4), и в 205 матчах из 230
  победила сторона, у которой их было больше. Прокачка, доход и башни
  предсказывают исход заметно слабее (61%, 61%, 67%).
- [x] 6.4 Найдено по ходу: `ARENA_DIR` — новая переменная арены. Без неё
  прогоны разных сессий ложатся вперемешку, сводка считает чужие матчи
  своими, а уборка перед прогоном сносит чужую работу.
