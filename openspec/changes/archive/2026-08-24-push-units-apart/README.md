# Замеры расталкивания

Снято 24 августа 2026 на собранном `dist` этой ветки, Node.js, без сервера
и браузера. Сравнение «до и после» — двумя сборками одного и того же кода:
во второй вызов `separateUnits` в `step.ts` отключён, всё остальное
совпадает бит в бит.

Расстановка: по 200 машин на сторону, кольцами вокруг своей базы
и **только по свободным клеткам**. Это важно: машина, положенная внутрь
скалы, оттуда не выедет никогда — `moveUnitTowards` проверяет клетку
назначения, а не текущую, — и тихо испортит замер. Первая версия стенда
на этом и попалась: 126 машин из 200 родились в камне, и таблица описывала
осаду семью десятками машин вместо двухсот.

## Цена тика

400 машин на поле (200 на сторону), 900 тиков. Бюджет тика — 33,3 мс.

| карта      | p50 без расталкивания | p50 с расталкиванием | разница      |
| ---------- | --------------------- | -------------------- | ------------ |
| seed 12345 | 1,865 мс              | 2,585 мс             | **+0,72 мс** |
| seed 4242  | 1,663 мс              | 2,095 мс             | **+0,43 мс** |
| seed 909   | 1,534 мс              | 2,032 мс             | **+0,50 мс** |

Полтора-два процента бюджета. На клиенте цена умножается на горизонт
предсказания — три шага на кадр, — то есть около полутора миллисекунд
к кадру при бюджете 16,7 мс в поздней игре.

### Про хвост тика

У тика в этом стенде тяжёлый хвост: до 100 мс, около пяти процентов тиков
дороже бюджета. **К расталкиванию он отношения не имеет** — проверено
двумя способами:

|                           | без расталкивания      | с расталкиванием       |
| ------------------------- | ---------------------- | ---------------------- |
| тиков дороже 33,3 мс      | 45 из 900 (5,0 %)      | 38 из 900 (4,2 %)      |
| номера самых долгих тиков | 510, 592, 0, 529, 544… | 288, 332, 0, 788, 355… |

Номера дорогих тиков в обеих сборках разбросаны случайно, а медиана
по остатку номера тика от десяти ровная во всех десяти фазах (1,52–1,68 мс
без расталкивания, 2,02–2,17 с ним). Значит, это не периодический
пересчёт поля потока, который идёт раз в десять тиков, а сборка мусора
в стенде. Настоящий разбор этого хвоста — работа изменения
`measure-the-tick`, у которого для этого будут приборы внутри процесса.

## Плотность осады

200 машин игрока идут от своей базы к базе противника, 1400 тиков. Три
разные карты — требование задачи 6.2: одна карта могла оказаться удачной.

| карта                 | макс. машин в квадрате 3×3 | стрелков достаёт до базы | центром внутри стены |
| --------------------- | -------------------------- | ------------------------ | -------------------- |
| **без расталкивания** |                            |                          |                      |
| seed 12345            | 200                        | 200                      | 0                    |
| seed 4242             | 168                        | 198                      | 0                    |
| seed 909              | 192                        | 192                      | 0                    |
| **с расталкиванием**  |                            |                          |                      |
| seed 12345            | **61**                     | 188                      | 0                    |
| seed 4242             | **60**                     | 187                      | 0                    |
| seed 909              | **73**                     | 188                      | 0                    |

Три вывода.

**Слипание было полным.** На карте 12345 все двести машин помещались
в один квадрат три на три — и, если смотреть на исходные координаты,
в одну точку: они совпадали до единицы.

**Расталкивание разводит втрое.** Шестьдесят-семьдесят машин на квадрат
вместо двухсот. Разброс между картами (61, 60, 73) объясняется формой
подхода к базе: где скалы поджимают подход, там строй плотнее.

**Осада почти не ослабла.** Стрелков у базы 187–188 против 192–200,
то есть потеря в пределах пяти процентов. Опасение замысла — «расталкивание
сделало бы осаду позиционной» — на этих числах не подтверждается.

**В стену не заезжает никто** ни в одной сборке и ни на одной карте.

## Проверка баланса ареной

Сорок матчей одними и теми же seed (1–40), профиль `siege-2026-08`
(покупает Теслу) против `baseline-2026-08`. Дважды: на сборке
с расталкиванием и на сборке, где вызов `separateUnits` отключён.

|                                      | без расталкивания | с расталкиванием  |
| ------------------------------------ | ----------------- | ----------------- |
| побед `baseline`                     | 37 из 40 (93 %)   | 34 из 40 (85 %)   |
| побед `siege` (Тесла)                | 3 из 40 (8 %)     | **0 из 40 (0 %)** |
| ничьих по времени (предел 20 минут)  | 0                 | **6 (15 %)**      |
| медиана длительности решённых матчей | 6:22              | 7:04              |
| самый долгий решённый матч           | 13:06             | 10:22             |
| машинного времени на матч            | 25,0 с            | 62,7 с            |

### Что из этого следует

**Тесла не подкошена расталкиванием — она была слаба и до него.** Три
победы из сорока против нуля — разница в пределах случайности при таких
числах. Осадный профиль проигрывал базовому и раньше, и объяснение этому
известно и записано отдельно: матчи решают живые юниты, а Тесла —
оружие позиции. Рычаг накрытия (ближний радиус 1 → 1,5 клетки)
по этим числам **не нужен**; решение заказчика «числа Теслы не трогать»
подтверждается замером.

**А вот что действительно изменилось — доводимость матча до конца.**
Шесть матчей из сорока перестали заканчиваться вовсе: за двадцать минут
ни одна база не пала, хотя раньше все сорок доигрывались. Среди тех,
что доигрались, длительность выросла умеренно: медиана 6:22 → 7:04,
то есть на одиннадцать процентов.

Причина видна из того же замера: разведённое войско меньше теряет
(в эталоне профиля живых машин стало 14 вместо 12, а команд на докупку
94 вместо 154). Обе стороны держатся дольше, и позиция, которую раньше
продавливали числом, перестаёт продавливаться.

Это не поломка расталкивания, а обострение уже записанной в замысле
дыры: «механики эскалации нет, патовое стояние двух укреплённых баз
ничем не разрешается». Раньше её закрывало слипание — двести машин
в одной точке били по базе всей толпой сразу. Теперь не закрывает
ничто.

**Решать это здесь нельзя** — эскалация отдельная работа и отдельное
изменение. Но знать об этом до выкладки нужно, поэтому число записано
крупно: пятнадцать процентов матчей не заканчиваются за двадцать минут.

Машинное время на матч выросло в два с половиной раза (25 → 63 с) —
из цены тика (+30 %), длины матчей и того, что живых машин на поле
стало больше. Для арены это заметно: пачка в сорок матчей считается
не четыре минуты, а десять.
