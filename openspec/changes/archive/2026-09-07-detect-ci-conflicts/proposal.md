## Why

Четыре карточки оставались в «Проверках CI» от суток до четырёх дней:
их PR конфликтовали с main, поэтому GitHub не запускал проверки. Оркестратор
видел пустой список, ждал бесконечно и записывал неверную причину «проверки идут».

## What Changes

- Каждый опрос CI получает также возможность слияния PR.
- Подтверждённый конфликт возвращает карточку в «Доработку» с номером PR,
  причиной и поручением обновить ветку и устранить конфликты.
- Неопределённость GitHub и недоступность запроса сохраняют ожидание.
- Причина ожидания доходит до журнала цикла без подмены общей фразой.

## Capabilities

### New Capabilities

- `pipeline-ci-observation`: обнаружение конфликтов PR при ожидании CI
  и объяснение результата опроса.

### Modified Capabilities

Нет.

## Impact

`supervisor/lib/io.mjs`, `apply-report.mjs`, проверки перехода через
`execute.mjs` и документация конвейера. Используется существующий переход
`pr → revise`, новые состояния и поля карточки не нужны.

Отзывчивость игры и игровой трафик не меняются. Частота опроса остаётся прежней;
в существующий запрос GitHub добавляется одно поле, дополнительных запросов нет.

## Non-goals

- Разрешение конфликтов самим оркестратором: это работа этапа доработки.
- Автоматическое слияние PR или обход обязательного CI.
- Таймер для любого отсутствующего или долгого CI без доказанной причины.
- Изменение маршрута уже закрытых или влитых PR.
- Починка четырёх веток вручную: карточки возвращены штатному исполнителю.
