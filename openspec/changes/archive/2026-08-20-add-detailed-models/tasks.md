# Задачи

## 1. Объёмный примитив: поворот и освещение по нормали

- [x] 1.1 В `apps/client/src/game/prism.ts` ввести тело с основанием
      из произвольного выпуклого многоугольника: грани строятся по нормалям,
      к зрителю обращённые отрисовываются, прочие — нет. Прежняя призма
      с прямоугольным основанием остаётся в том же виде для скал, стен,
      башен и базы.
      *Проверка:* `prism.test.ts` зелёный, ожидания не правились;
      добавлен тест «на прямоугольнике даёт те же грани, что призма».
- [x] 1.2 Заменить таблицу `FACE_LIGHT` законом Ламберта с постоянным
      направлением света, подобранным так, чтобы на выровненной призме
      давать прежние 0,72 и 0,48.
      *Проверка:* тест «яркость по нормали совпадает с прежними
      множителями»; сами множители теперь выводятся из закона, а не
      задаются отдельно, поэтому разъехаться им негде.
- [x] 1.3 Добавить построение повёрнутого основания: местные координаты
      машины переводятся в мировые по румбу.
      *Проверка:* тесты «обращённых от зрителя граней не строит» (ровно две
      боковые на каждом из восьми поворотов) и «яркость видимых граней
      меняется с поворотом».

## 2. Направление юнита в ядре симуляции

- [x] 2.1 Добавить `facing` в `UnitState` и `WorkingUnit`, провести через
      `toWorking`/`fromWorking`, включить в `checksum`. То же для генерала:
      его `direction` обнуляется при отпускании клавиш, поэтому разворот
      хранится отдельным полем.
      *Проверка:* сборка и типы зелёные, упал только golden-тест.
- [x] 2.2 Выдавать направление при появлении юнита: от центра базы наружу,
      никогда не «стоять». Генералы на старте смотрят в центр карты.
      *Проверка:* тесты «свежий юнит уже повёрнут» и «на старте матча
      смотрит в центр карты».
- [x] 2.3 Разворачивать юнита по ходу шага в `movement.ts`.
      *Проверка:* тест «идущий юнит смотрит по ходу движения».
- [x] 2.4 Разворачивать стреляющего на цель в `combat.ts`, после движения.
      *Проверка:* тесты «стреляющий разворачивается на цель» и «разворот
      на цель перебивает разворот по ходу шага».
- [x] 2.5 Убедиться, что направление не влияет на исход.
      *Проверка:* тест сравнения двух прогонов с противоположными
      начальными румбами — здоровье и положения совпадают. Сверх того:
      во всём ядре `facing` только пишется и хешируется, ни одно правило
      его не читает.
- [x] 2.6 Обновить эталон в `determinism.golden.test.ts`.
      *Проверка:* golden-тест зелёный, прежнее число и причина смены
      записаны в комментарии рядом.

## 3. Модели машин

- [x] 3.1 Завести `apps/client/src/game/models.ts`: детали в местных
      координатах машины — корпус, колёса, башня, ствол.
      *Проверка:* тест «юнит собран из нескольких тел, а не из одной
      коробки».
- [x] 3.2 Задать три шасси: штурмовик, снайпер, гранатомётчик.
      *Проверка:* тест «типы различаются составом, а не только размером» —
      сверяются и число деталей, и отношение габаритов.
- [x] 3.3 Ступени оружия: атака удлиняет и утолщает ствол и на верхней
      ступени добавляет дульный тормоз, скорострельность добавляет стволов.
      *Проверка:* тесты на пороги, на монотонность длины, на независимость
      осей и на то, что срез ствола выходит за корпус — иначе длина
      в габарит не попадала бы и тест проходил бы впустую.
- [x] 3.4 Кеш силуэтов в экранных координатах по ключу
      (тип, румб, ступени, сторона).
      *Проверка:* тесты «повторный запрос возвращает ту же запись»,
      «разные комбинации дают разные записи», «смена палитры перестраивает
      кеш».
