## Context

Бюджет Codex сейчас имеет один окончательный предел. Старый переход decompose-again не хранит этап возврата, а инструкция анализа требует вопрос о повышении после превышения. Личный лимит задаётся владельцем в Trello и остаётся окончательным пределом.

## Goals / Non-Goals

Дать задачам feature один ранний анализ дробности и продолжение неделимой работы до окончательного бюджета. Не менять правила split поверх OpenSpec/PR, журнал расхода, личные лимиты, USD-политику Claude и уже идущие процессы.

## Decisions

1. Отдельная настройка codexTaskReanalysisTokens (положительное целое либо null) задаёт ранний порог **15 000 000** токенов. Окончательный codexMaxTaskTokens остаётся **25 000 000**. Окончательный допуск имеет приоритет: если расход перескочил оба порога, карточка сразу удерживается. Неизвестный расход обрабатывает существующее удержание.
2. Служебный переход analyze-token-budget сохраняет tokenReanalysis в карточке: phase, originStatus, originReturnTo, originPriority, originAttempts, originDecomposed, spent, threshold, startedAt. Затем переводит в decompose с отдельными нулевыми попытками. Это отделяет анализ от повторов прерванного этапа.
3. done с содержательным объяснением неделимости возвращает исходный статус и контекст; phase становится completed и сохраняется при дальнейших переходах. Отметка живёт вне attempts: сброс попыток, перезапуск, повышение лимита и смена этапа не назначат тот же бюджетный анализ снова. Обычный анализ и повторный анализ зависимостей не заменяют эту отметку.
4. split использует существующую проверку и создание частей; если артефакты уже есть, исполнитель объясняет невозможность дробления и возвращает done. Настоящие вопросы продукта и блокеры идут обычным маршрутом, с сохранённым контекстом бюджетного анализа.
5. Действие проверяет свежую карточку, владение, отчёты/живые сессии и свежий бюджет. Сканер выводит ожидающую служебного переноса задачу из квоты. Последняя проверка spawnStage удерживает обычный запуск, пока нужен анализ. Повторный анализ decompose также подчиняется окончательному пределу перед следующим запуском; готовый отчёт принимается штатно.
6. Применённый done имеет сохранённый ключ отчёта, чтобы повтор доставки после ошибки комментария не изменил восстановленный этап. Возвращённая карточка снова проходит все обычные проверки допуска.

## Risks / Trade-offs

- Анализ стоит токенов → один за жизнь задачи, его стоимость входит в общий накопленный расход.
- В одном запуске можно пересечь предел → останавливается следующий запуск, живой процесс не прерывается.
- Старые задачи между порогами без новой отметки → получат один анализ при следующем разрешённом запуске; уже удержанные сохранят свой маршрут, бюджет и состояние.
- Повреждённый контекст → не угадывать этап, отказать в принятии такого done с явной причиной.

## Migration Plan

Выполнить узкие тесты, проверки изменённых файлов и CI того же PR, влить, дождаться штатного обновления супервизора. Проверить действующие значения и следующий снимок маршрутизации без перехвата чужих сессий. Откат — отключение раннего порога null с сохранением кода приёмки начатого анализа.
