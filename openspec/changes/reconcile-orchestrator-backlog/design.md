## Context
На main уже есть reconcile реестра, blocked, обработка ответов, устойчивый перенос отчётов и проверка зависимостей. Новая сверка расширяет эти точки; она не заменяет их вторым автоматом.

## Goals / Non-Goals
Цель — восстановить правильный оставшийся маршрут и исключить повторную работу при наличии доказательства. Не выдавать сессии под паузой, не обходить токенные удержания, не выполнять игровые эксперименты.

## Decisions
1. Перед выбором сессии планировать ограниченную сверку карточек с PR в остановленных/рабочих состояниях. Исполнитель повторно читает состояние, проверяет вливание в main и полный diff. Служебная работа идёт в уборку; игровая — в review для восстановления обязательств по прогону/выкладке, если их исполнение ещё не доказано. Отсутствие ответа GitHub не означает завершения. Отчёты и живые этапы имеют приоритет.
2. Реестр не теряется из-за отсутствия регистрации дерева. При усыновлении хранить фактический найденный путь, а не подставлять шаблонный. Сохранять резерв принадлежности до завершения уборки; восстанавливать только собственную запись с проверкой идентичности. Не угадывать пути из заголовков.
3. Содержательное решение о поглощении приходит структурированным отчётом аналитического этапа. Перед закрытием исходника сохранить его требования в принимающей карточке и явную связь продолжения; использовать существующий splitInto для сохранения семантики ожидания результата. Незавершённый принимающий объект не считается выполнением. Отдельное поле описывает доказательство полного замещения. Отчёт проходит существующий устойчивый план доставки и повтор не дублирует записи.
4. Единый контракт инструкций задаёт blocked, уточнение существующей работы вместо автоматического размножения, область обслуживания и проверку пригодности прогонов. Неопределённость требует названных недостающих данных, а не автоматического закрытия или нового замера. Опись включает смысл задачи и связи замещения.
5. Проверка актуальности проводится при поступлении новых фактов и перед работой, не постоянными платными сессиями над неизменившейся доской. Детерминированная сверка ограничивает число внешних чтений за цикл; семантический анализ выполняется существующими аналитическими этапами с теми же бюджетами.

## Risks / Trade-offs
- Ошибочное закрытие → доказательство, сохранение всех требований, запрет затрагивать живую/чужую работу, проверка циклов и исходного состояния.
- Частичная запись → принимающая карточка раньше закрытия исходника, устойчивый журнал операций и повторяемые ключи.
- Ложное завершение после вливания → служебный diff проверяется полностью; игровая работа сохраняет review и обязательства выпуска.
- Неизвестная принадлежность → ресурсы сохраняются с диагностикой, без догадки пути удаления.

## Migration Plan
Новые поля необязательны; старые карточки читаются без миграции. Изменение доставляется через PR с CI; работающий супервизор не перезапускается этой задачей. Старые записи без доказательства остаются незавершёнными. Откат кода не удаляет сохранённые факты на доске.

## Open Questions
Нет продуктовых решений: область согласована владельцем. Обнаруженные при отдельном ревью дополнительные дефекты фиксируются с доказательствами и приоритетом.
