## Критерий узких проверок

Для каждого пункта 1.1, 2.1 и 3.1 успех требует обнаружения и фактического выполнения всех тестов во всех перечисленных в его команде файлах. Отсутствие найденных тестов или их пропуск успехом не считаются. Команды запускаются из назначенного дерева с `--root supervisor`: корневой `vitest.workspace.ts` не включает supervisor, а отдельный корень выбирает `supervisor/vitest.config.ts` и его набор тестов. Запуск без этого ключа не проверяет назначенные файлы.

## Дисциплина каждого коммита

В каждом пункте добавлять только фактически изменённые собственные пути из названного списка через `git -C <дерево> add -- <явный список файлов>`, включая обязательную отметку выполненного пункта в этом tasks.md. Проверить имена и содержание индекса командами `git -C <дерево> diff --cached --name-only` и `git -C <дерево> diff --cached`; после коммита проверить `git -C <дерево> show --stat HEAD` и `git -C <дерево> show HEAD`, затем немедленно `git -C <дерево> push`. Тестовые временные файлы остаются внутри назначенного дерева и не попадают в индекс/коммит. Незатронутые части разрешённых файлов не дают права на постороннюю правку.

Полный verify, сборку, арену и ожидание CI локально не запускать. Узкие команды сверены с allow `PowerShell(npx vitest:*)`, `PowerShell(git -C:*)` и правилом OpenSpec; новые исполняемые команды в инструкциях должны пройти существующий сторож разрешений. Свежий успех CI проверяет супервизор, последующее review повторяет допуск для своего SHA.
