# Задачи

Проверка у всех шагов одна и та же, и другой быть не может: правки лежат
в `supervisor/`, сторожа конвейера живут в чужих файлах, «своего файла
теста» у правки скилла нет вовсе.

```powershell
pnpm test:pipeline
```

Голый `npx vitest` тут не годится: без ключа `--root supervisor` тесты
конвейера не находятся, и прогон зеленеет, ничего не прогнав.

Каждый шаг — отдельный коммит, отправляемый сразу. Первым идёт шаг 1:
после него имплементация уже вправе открыть черновой pull request, а
до открытия проверки CI на отправки в ветку не запускаются вовсе.

Форма команды, которую заводят шаги 1 и 2, — дословно такая, двумя
строками одного блока, размеченного `powershell`:

```powershell
git -C <дерево> fetch origin
git -C <дерево> merge origin/main
```

      с названным файлом, потому что аудит только что признал изменение
      непересекающимся, а вернуть задачу в проработку имплементация
      не вправе — маршрут ведёт её только в `benchmark` и `pr`.
- [x] Назвать причину порядка: слияние идёт до установки зависимостей,

## 2. Доработка подтягивает главную ветку до разбора CI и до правки

- [x] Завести в `supervisor/skills/revise.md` подтягивание главной ветки
      обязательным шагом **перед** нынешним шагом 6, где идёт разбор
      красного CI по логу. Место выбрано выше правки нарочно: тот же шаг 6
      объявляет массовую красноту `format:check` признаком устаревшей базы,
      и разбор, идущий раньше освежения, гадает над ложной уликой.
- [x] Снять условность: освежение делается всегда, а не «если журнал назвал
      конфликтующие файлы либо главная ветка ушла вперёд». Назвать довод —
      признак истинен почти всегда, а условие сессия читает как разрешение
      не подтягивать.
- [x] Назвать исход конфликта: доработка разбирает его сама, это её работа,
      и перечень конфликтующих путей ей передаёт ревью; не сумев разобрать
      — отменяет слияние и завершается исходом `failed` с названным файлом.
- [x] Оговорить, что нынешний шаг 8 (перевыкладка) остаётся законным
      средством, но обязательным шагом не становится: покрытие формы
      отправки с ключом `--force-with-lease` стоящим в `deny` запретом
      на принудительную отправку не проверено, и это предмет задачи 0078.
- [x] Выправить тем же коммитом обе ссылки на номера шагов внутри

      здесь мало переставить цифру: лекарством от устаревшей базы становится
      новый обязательный шаг, стоящий выше, а перевыкладка (шаг 9) остаётся

- [x] Добавить `revise` в того же сторожа `supervisor/config/transitions.test.mjs`.

**Проверка:** `pnpm test:pipeline` зелёный; в `revise.md` строка слияния
стоит выше по файлу и разбора красного CI, и правки по замечаниям; обе
ссылки на номера ведут туда же, куда вели до вставки, — «для шага 8»
указывает на правку по замечаниям, «(шаг 9)» на перевыкладку.

- [x] Завести в `supervisor/config/transitions.test.mjs` обратного сторожа:

      запрета ничем не проявляется, подтянувшее ревью выглядит работающим

стоят в одном файле и не противоречат друг другу — первый перечисляет

## 4. Коммит слияния следом этапа не считается

- [x] Сказать прямо в трёх скиллах, которым следом объявлен собственный
      коммит и которые освежают базу, — `design.md`, `implement.md`,
      `revise.md`, — рядом с местом про подтягивание: коммит слияния следом
      этапа при исходе `done` не считается, след — это собственная работа
      этапа.
- [x] В `audit.md` и `deploy.md` оговорки НЕ заводить, хотя базу они тоже
      освежают: аудиту следом объявлена ветка без хвоста, выкладке следа
      не положено вовсе, и подменять там нечего. Правило это записано
      в дельте, чтобы «приведение к единообразию» не дописало оговорку
      позже.
- [x] Оговорить, что половина «либо впервые открытый pull request» у следа
      имплементации остаётся в силе: она про законный случай, когда вся
      правка внесена проработкой, и к освежению базы отношения не имеет.
- [x] Завести сторожа в `supervisor/config/transitions.test.mjs`: все три
      скилла содержат оговорку. Мерку взять подстрокой, которую нельзя
      выполнить случайно, и назвать её в пояснении к тесту. Там же назвать,
      почему `audit.md` и `deploy.md` в перечень не входят, — иначе перечень
      прочтут как недосмотр и дополнят.

**Проверка:** `pnpm test:pipeline` зелёный; массив сторожа перечисляет
`design`, `implement`, `revise` и не содержит `audit` с `deploy`; при
пропаже оговорки сторож называет провинившийся файл поимённо, а не падает
безымянно.

## Чего в этом списке нет намеренно

- **Шага «дождаться зелёного CI».** Закрыть его исполнителю запрещено
  по устройству, а ожидание проверок механизировано супервизором.
- **Прогона арены и замера кадров.** Правила игры, цены, доход, сила юнита
  и темп не тронуты: изменение правит только правила этапов конвейера.
- **Правки `supervisor/config/stage-settings.json`.** Все предписываемые
  формы покрыты правилом `PowerShell(git -C:*)`, новых разрешений
  не требуется.
