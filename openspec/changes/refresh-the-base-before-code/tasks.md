# Задачи

Проверка у всех шагов одна и та же, и другой быть не может: правки лежат
в `supervisor/`, сторожа конвейера живут в чужих файлах, «своего файла
теста» у правки скилла нет вовсе.

```powershell
pnpm test:pipeline
```

Голый `npx vitest` тут не годится: без ключа `--root supervisor` тесты
конвейера не находятся, и прогон зеленеет, ничего не прогнав.

Каждый шаг — отдельный коммит, отправляемый сразу. Первым идёт шаг 1:
после него имплементация уже вправе открыть черновой pull request, а
до открытия проверки CI на отправки в ветку не запускаются вовсе.

Форма команды, которую заводят шаги 1 и 2, — дословно такая, двумя
строками одного блока, размеченного `powershell`:

```powershell
git -C <дерево> fetch origin
git -C <дерево> merge origin/main
```

## 1. Имплементация подтягивает главную ветку

- [ ] Завести в `supervisor/skills/implement.md` подтягивание главной ветки
      отдельным шагом — после шага 2 (дошли хвост) и до шага 3, где стоит
      установка зависимостей.
- [ ] Назвать там же три исхода порознь: перемотка — работать дальше;
      коммит слияния — отправить сразу командой `git -C <дерево> push`,
      хвоста оставлять нельзя; конфликт — отменить слияние командой
      `git -C <дерево> merge --abort` и завершиться исходом `failed`
      с названным файлом, потому что аудит только что признал изменение
      непересекающимся, а вернуть задачу в проработку имплементация
      не вправе — маршрут ведёт её только в `benchmark` и `pr`.
- [ ] Назвать причину порядка: слияние идёт до установки зависимостей,
      потому что способно сдвинуть файл замка, и установка, сделанная
      раньше, устареет в тот же миг.
- [ ] Расширить в `supervisor/config/transitions.test.mjs` сторожа
      «проработка и аудит подтягивают свежую главную ветку» на `implement`,
      сохранив мерку — строку целиком, вместе с ключом `-C`.

**Проверка:** `pnpm test:pipeline` зелёный, и в его выводе виден сторож,
перечисляющий три этапа вместо двух.

## 2. Доработка подтягивает главную ветку до правки

- [ ] Завести в `supervisor/skills/revise.md` подтягивание главной ветки
      обязательным шагом **перед** нынешним шагом 7, где идёт правка
      по замечаниям.
- [ ] Снять условность: освежение делается всегда, а не «если журнал назвал
      конфликтующие файлы либо главная ветка ушла вперёд». Назвать довод —
      признак истинен почти всегда, а условие сессия читает как разрешение
      не подтягивать.
- [ ] Назвать исход конфликта: доработка разбирает его сама, это её работа,
      и перечень конфликтующих путей ей передаёт ревью; не сумев разобрать
      — отменяет слияние и завершается исходом `failed` с названным файлом.
- [ ] Оговорить, что нынешний шаг 8 (перевыкладка) остаётся законным
      средством, но обязательным шагом не становится: покрытие формы
      отправки с ключом `--force-with-lease` стоящим в `deny` запретом
      на принудительную отправку не проверено, и это предмет задачи 0078.
- [ ] Добавить `revise` в того же сторожа `supervisor/config/transitions.test.mjs`.

**Проверка:** `pnpm test:pipeline` зелёный; в `revise.md` строка слияния
стоит выше по файлу, чем шаг правки по замечаниям.

## 3. Ревью не подтягивает, и это записано запретом

- [ ] Завести в `supervisor/skills/review.md`, в разделе «Чего делать
      нельзя», запрет подтягивать главную ветку в дерево — ни слиянием,
      ни перевыкладкой.
- [ ] Назвать в запрете три довода: вердикт стоит на зелени, снятой
      у вершины ветки, и коммит слияния её обесценивает; свежесть главной
      ревью уже имеет расчётом `merge-tree`, не трогающим дерево; диф
      читается тремя точками и от ушедшей вперёд главной не зависит.
- [ ] Завести в `supervisor/config/transitions.test.mjs` обратного сторожа:
      правила ревью строки слияния не содержат. В пояснении к тесту
      назвать, почему обратный сторож нужен наравне с прямым: пропажа
      запрета ничем не проявляется, подтянувшее ревью выглядит работающим
      до дня, когда влитый им непроверенный коммит уронит главную ветку.

**Проверка:** `pnpm test:pipeline` зелёный; прямой и обратный сторожа
стоят в одном файле и не противоречат друг другу — первый перечисляет
`design`, `audit`, `implement`, `revise`, второй только `review`.

## 4. Коммит слияния следом этапа не считается

- [ ] Сказать прямо в четырёх скиллах, которые освежают базу, —
      `design.md`, `audit.md`, `implement.md`, `revise.md`, — рядом
      с местом про подтягивание: коммит слияния следом этапа при исходе
      `done` не считается, след — это собственная работа этапа.
- [ ] Оговорить, что половина «либо впервые открытый pull request» у следа
      имплементации остаётся в силе: она про законный случай, когда вся
      правка внесена проработкой, и к освежению базы отношения не имеет.
- [ ] Завести сторожа в `supervisor/config/transitions.test.mjs`: все
      четыре скилла содержат оговорку. Мерку взять подстрокой, которую
      нельзя выполнить случайно, и назвать её в пояснении к тесту.

**Проверка:** `pnpm test:pipeline` зелёный; сторож при пропаже оговорки
называет провинившийся файл поимённо, а не падает безымянно.

## Чего в этом списке нет намеренно

- **Шага «дождаться зелёного CI».** Закрыть его исполнителю запрещено
  по устройству, а ожидание проверок механизировано супервизором.
- **Прогона арены и замера кадров.** Правила игры, цены, доход, сила юнита
  и темп не тронуты: изменение правит только правила этапов конвейера.
- **Правки `supervisor/config/stage-settings.json`.** Все предписываемые
  формы покрыты правилом `PowerShell(git -C:*)`, новых разрешений
  не требуется.
