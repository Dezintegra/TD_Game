## ADDED Requirements

### Requirement: Именованные формы pnpm run открываются закрытым перечнем

Настройка разрешений этапов SHALL сохранять точное разрешение `pnpm run`
без аргументов и SHALL разрешать `pnpm run <имя>` с аргументами только
для имён `build`, `test:pipeline`, `e2e:perf`, `bench:tick`, `deploy`, `ship`.
В Bash и PowerShell SHALL стоять отдельные правила вида
`<оболочка>(pnpm run <имя>:*)` для каждого из шести имён.
Эти формы дают альтернативный вызов уже разрешённых операций; условия
этапа на сборку, проверки, замеры и выкладку SHALL оставаться в силе.

Настройка MUST NOT открывать остальные именованные формы `pnpm run`,
включая полные проверки, игровые тесты, арену и управление супервизором.
Она MUST NOT содержать широкое разрешение `pnpm run:*`, `pnpm:*` либо
шаблон, разрешающий произвольные имена. Добавление нового скрипта в
`package.json` MUST NOT автоматически давать ему разрешение.

#### Scenario: Перечисление сценариев сохраняется

- **WHEN** проверяется команда `pnpm run` без аргументов
- **THEN** она покрыта точным разрешением в обеих оболочках

#### Scenario: Разрешённое имя покрыто с аргументами

- **WHEN** проверяется любое из шести имён без аргументов и с аргументами
  после имени, включая `pnpm run deploy -- --ref <хеш> --no-perf`
  и `pnpm run ship -- --ref <хеш> --no-perf`
- **THEN** команда покрыта в обеих оболочках и не перекрыта `deny`

#### Scenario: Прочие сценарии не открываются

- **WHEN** проверяется `pnpm run <имя>` для любого другого имени из
  корневого `package.json`, включая `verify`, `test`, `test:match`,
  `test:all`, `verify:all`, `balance:run`, `supervisor`, `supervisor:shadow`,
  `supervisor:detached`, `supervisor:stop`
- **THEN** команда не покрыта разрешениями ни в одной оболочке
- **AND** добавленные аргументы не меняют этот результат

#### Scenario: Граница имени и неизвестное имя

- **WHEN** проверяются `pnpm run deploy-extra`, `pnpm run build-extra`
  и `pnpm run not-a-project-script`
- **THEN** ни одно поимённое разрешение их не покрывает

### Requirement: Сторож поимённых сценариев проверяет покрытие и его границы

Тесты конвейера SHALL проверять закрытый перечень правил и фактическое
покрытие команд из предыдущего требования общей меркой `permissions.mjs`,
различающей точную форму и приставку и учитывающей `allow` вместе с `deny`.
Тесты SHALL сохранять проверки прямых запретов управления супервизором.
Проверка MUST NOT ограничиваться наличием строк или считать любое правило
с именем скрипта нарушением.

#### Scenario: Удаление разрешения обнаруживается

- **WHEN** из копии настройки удалено одно из шести поимённых разрешений
  только одной оболочки
- **THEN** проверка обнаруживает непокрытую команду и называет оболочку

#### Scenario: Потеря хвоста обнаруживается

- **WHEN** в копии настройки поимённое разрешение заменено точной формой
  без хвоста `:*`
- **THEN** проверка обнаруживает потерю покрытия варианта с аргументами

#### Scenario: Перекрывающий запрет обнаруживается

- **WHEN** в копию настройки добавлен точный запрет разрешённой команды
- **THEN** проверка обнаруживает, что команда не покрыта итоговыми правами

#### Scenario: Расширение перечня обнаруживается

- **WHEN** в копию настройки добавлено широкое разрешение `pnpm run:*`,
  `pnpm:*`, шаблон имени либо отдельное разрешение `pnpm run verify:*`
- **THEN** проверка отвергает настройку и указывает нарушающее границу правило

#### Scenario: Настройка проверяется без исполнения операций

- **WHEN** тест проверяет покрытие выкладки, замеров и запрещённых сценариев
- **THEN** он сопоставляет строки и не запускает эти операции
