На этапе проработки перечисленные ниже проверки реализации не запускаются.

Проверки реализации из назначенного дерева, каждая отдельным вызовом:

```powershell
npx vitest run --root supervisor config/transitions.test.mjs
```

Ожидается: штатная настройка проходит; копии с удалённым правилом, снятым
хвостом, перекрывающим запретом и расширенным перечнем дают ожидаемую
диагностику. Запрещённые операции и выкладка тестом не запускаются.

```powershell
npx eslint supervisor/config/transitions.test.mjs
```

```powershell
npx prettier --check supervisor/config/stage-settings.json supervisor/config/transitions.test.mjs
```

```powershell
openspec validate permit-named-pipeline-scripts --strict
```

```powershell
openspec validate permit-the-pipeline-scripts --strict
```

Вторая адресная валидация нужна только при реализации, поскольку там
согласуется дельта этого изменения. Общий прогон всех дельт не нужен.

```powershell
git -C . diff --check
```

```powershell
git -C . diff --stat
```

Ожидается: формат и адресные проверки проходят; diff содержит только
настройку, её тест, три согласуемых плановых файла старого изменения
и отметку в собственном tasks.md. В старой дельте нет абсолютного запрета
именованных вызовов и утверждения, что deploy/ship закрыты; требование
осмотра инструмента и его сценарии сохранены.

Формы команд покрыты текущими `npx vitest:*`, `npx eslint:*`,
`npx prettier:*`, `openspec:*`, `git -C:*`. Штатный набор тестов конвейера
остаётся проверкой CI этого PR; ожидание CI выполняет супервизор.
Арена и фактические замеры не требуются, поскольку игровые правила не меняются.
