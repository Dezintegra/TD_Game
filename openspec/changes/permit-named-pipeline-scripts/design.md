## Goals / Non-Goals

Цель — дать альтернативные именованные вызовы уже открытых операций,
сохранив конечный перечень и обнаружение его случайного расширения.
Non-goals перечислены в proposal: новый менеджер прав, смена оболочки,
изменение скриптов пакета и фактические операции на сервере сюда не входят.

## Decisions

### 1. Шесть имён, каждое отдельной приставкой

| Имя | Уже открытая операция | Пример строки для проверки покрытия |
| --- | --- | --- |
| `build` | `pnpm build:*` | `pnpm run build -- --force` |
| `test:pipeline` | `pnpm test:pipeline:*` | `pnpm run test:pipeline -- --reporter=dot` |
| `e2e:perf` | `pnpm e2e:perf:*` | `pnpm run e2e:perf -- --check-only` |
| `bench:tick` | `pnpm bench:tick:*` | `pnpm run bench:tick -- --help` |
| `deploy` | `node scripts/deploy.mjs:*` | `pnpm run deploy -- --ref <хеш> --no-perf` |
| `ship` | тот же `scripts/deploy.mjs` в `package.json` | `pnpm run ship -- --ref <хеш> --no-perf` |

Примеры — строки для сопоставления прав, не поручение выполнять операции
и не новое обещание о разборе аргументов конкретным скриптом.
Добавляются 12 правил: шесть на Bash и шесть на PowerShell. Голый `pnpm run`
остаётся точным. Хвост `:*` относится к аргументам после полного имени;
граница слова общей мерки исключает `deploy-extra` и `build-extra`.
`install` не входит: это встроенная команда pnpm, а не скрипт пакета.
`test:scripts` и прочие имена не включаются попутно: им нет поимённого
разрешения в текущей настройке. Выбор перечня технический, он воспроизводит
уже разрешённые операции, не принимает новое продуктовое решение.

Отвергнут общий `pnpm run:*` с перечнем запретов: следующий скрипт оказался
бы открыт по умолчанию, а имен управления и тяжёлых проверок уже много.
Отвергнуты точные правила имён без `:*`: исходный дефект повторится на
`--ref`. Отвергнуто оставить только прямой `node scripts/deploy.mjs`:
это не решает поставленную задачу для именованных форм остальных операций.

### 2. Сторож проверяет правила и команды вместе

В `transitions.test.mjs` заменить blanket-проверку регулярным выражением
на точный ожидаемый набор правил `pnpm run` в `allow` по каждой оболочке.
Сохранить точное правило перечисления. Проверять отсутствие общих разрешений
на pnpm и шаблонов имени; диагностировать виновное правило. `deny` не
запрещать только за наличие `pnpm run`: он должен оцениваться по покрытию.

Положительную матрицу из шести имён проверить без аргументов и с примерами
таблицы через `uncoveredCommands`. Отрицательную матрицу брать из остальных
имён `package.json` плюс выдуманные имена, без аргументов и с ними.
Ожидаемые разрешённые имена заданы явно в тесте, не выводятся из настройки:
иначе тест повторял бы ошибочное расширение. Сверить наличие этих имён в
пакете; для `deploy` и `ship` закрепить тот же `node scripts/deploy.mjs`.

Мутационные случаи выполняются на копиях объекта в памяти: удалить правило
одной оболочки, снять хвост, добавить точный перекрывающий запрет, добавить
широкую форму, шаблон или `verify`. Каждый случай обязан вызвать ожидаемую
диагностику; настоящий JSON ради пробы не портится. Прямые запреты
`supervise.mjs` и `launch.mjs --stop/--shadow` продолжают проверяться.
Общая мерка `permissions.mjs` остаётся прежней: второй парсер не нужен.

### 3. Согласование старой дельты входит в тот же атомарный коммит

Во время реализации обновить три файла `permit-the-pipeline-scripts`:
`proposal.md`, `design.md`, `specs/dev-pipeline-supervisor/spec.md`.
В первом требовании старой дельты сохранить перечисление и прямые тесты,
заменить абсолютный запрет именованных вызовов на запрет форм вне закрытого
перечня требования «Именованные формы pnpm run открываются закрытым перечнем».
Сценарий отказа заменить на `verify`/`balance:run`; два остальных сценария
сохранить. В требовании сторожа сохранить оба сценария и запрет широкой
формы, убрать устаревший довод о запрете выкладки и указать совместимость
с поимёнными правилами. Требование осмотра инструмента сохранить целиком.
Proposal/design согласовать в местах запрета deploy/ship и всех имён;
вступление design уточнить: без хвоста совпадение точное, не приставочное.
Исторические отметки выполненных задач не переписывать.

Наша дельта ADDED содержит уникальные требования и не копирует старые.
Это позволяет архивировать её ПОСЛЕ согласованного `permit-the-pipeline-scripts`
без MODIFIED по отсутствующей основе. Архивацию на этом этапе не выполнять.
Отвергнуто оставить противоречие до архивации: реализация жила бы сразу
по двум противоположным контрактам. Отвергнуто править чужую дельту сейчас:
этап design пишет только в каталог собственного изменения.

## Risks / Trade-offs

- Правила разрешают форму команды, а не проверяют её целесообразность
  на конкретном этапе → ограничения этапов остаются обязательными.
- Покрытие строк не доказывает поведение среды или скрипта после запуска →
  тесты не называют живой пробой и не выполняют выкладку ради разрешений.
- Содержимое скриптов может измениться → явный перечень и проверка алиасов
  выкладки делают границу видимой при ревью последующих правок.
- Соседняя задача 0156 меняет набор оболочек → сверить свежую основу перед
  реализацией; текущая проработка сохраняет обе оболочки, реально имеющиеся
  в настройке и `SHELLS`. Не переносить одновременно смену оболочки сюда.

## Migration Plan

Единственный коммит реализации меняет настройку, тест и согласуемые тексты
вместе. После его отправки открывается черновой PR. Новые правила применяются
к следующим запускам, получившим обновлённую настройку; текущая сессия
не пытается обновить собственные разрешения. Откат этого коммита целиком
возвращает прежнюю согласованную настройку и сторож.

## Архитектурные ограничения

Игровой код не затронут: рассинхрон, реконнект, client-side prediction
и отклик в том же кадре сохраняются. `packages/sim` не меняется, эталоны
детерминизма не обновляются; запреты `Math.random`, `Date.now` и дробных
чисел в состоянии мира не затрагиваются. Раскладка протокола прежняя,
`PROTOCOL_VERSION` не увеличивается. Арена и замеры не нужны.
