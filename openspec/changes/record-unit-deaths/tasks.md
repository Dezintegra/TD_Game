# Шаги реализации

Каждый шаг — отдельный коммит, отправляемый сразу. Черновой pull request
открывается **после первого коммита**: до его появления пуши в ветку
не запускают проверок CI вовсе.

- [ ] 1. Запись гибели в лог арены

  `apps/arena/src/records.ts`: тип `DeathRecord` с полями `t: 'death'`,
  `tick`, `player`, `unitType`, `unitId`, `cell` и с оговоркой
  в комментарии, что клетка — последнее известное положение, снятое
  до шага.

  `apps/arena/src/deaths.ts`: чистая функция `deathsBetween` от списка
  юнитов до шага, списка после шага и номера тика — множество
  идентификаторов из второго списка, обход первого, запись на каждого
  исчезнувшего.

  `apps/arena/src/match.ts`: вызвать её сразу после `step`, до подмены
  `world = next`, и записать полученное в лог после записей команд
  и до снимка состояния.

  Шаг самодостаточен: сборка базы записи неизвестного вида молча
  пропускает (`default: break` в `ingest.ts`), поэтому лог с гибелями
  собирается и до появления таблицы.

  Проверка: `npx vitest run apps/arena/src/deaths.test.ts` — новый тест
  на собранных руками списках. Погиб один из трёх; погибли двое разных
  типов на одном тике; не погиб никто (пусто); список пополнился новыми
  юнитами (гибелей нет). Тест быстрый: ни матча, ни мира в нём нет.

- [ ] 2. Таблица `death` в базе

  `apps/arena/src/schema.ts`: таблица и индекс `death_by_match`, имя
  `death` в `CHILD_TABLES`. `apps/arena/src/ingest.ts`: разбор записи
  `death` и вставка строки.

  Отдельным шагом от первого, потому что проверяет другое свойство:
  первый отвечает за «гибель записана», этот — за «гибель собрана
  и не задвоена».

  Проверка: `npx vitest run apps/arena/src/ingest.test.ts` — в лог
  добавлены записи гибели; строки попали в базу в том же составе;
  **повторная сборка того же файла оставляет их число прежним**
  (без имени в `CHILD_TABLES` этот тест краснеет); лог без записей
  гибели собирается по-прежнему, и строк по нему в таблице нет.

- [ ] 3. Сверка на настоящем матче

  `apps/arena/src/arena.match.test.ts`: проверки на своём матче
  с пределом в три игровые минуты — общий шестидесятисекундный матч
  файла для этого не годится, за минуту стороны могут и не сойтись.

  Проверяется: гибели есть (иначе проверка пуста и ничего не сторожит);
  каждый идентификатор встречается не более одного раза; тип каждой
  гибели — один из существующих; число гибелей стороны не больше числа
  принятых ею заказов юнитов (`command`, `kind = 2`, `accepted = 1`);
  клетка лежит в пределах карты.

  Проверка: зелёный матчевый набор в CI (`матчевые тесты`). Локально
  из дополнительного дерева матчевый набор не гоняется — правило 6.

- [ ] 4. Запрос и оговорка в README арены

  `apps/arena/README.md`, раздел «Запросы»: таблица `death` в перечне
  схемы и пример запроса «доля потерянных Тесл» — гибели по типам против
  заказов по типам. Рядом — оговорка, что у матчей, сыгранных до этой
  правки, гибелей нет вовсе, и ноль там означает «не записывалось»,
  а не «никто не погиб»; отбирать матчи для сравнения потерь надо
  по `match.git_sha`.

  Проверка: `npx prettier --check apps/arena/README.md` и глазами —
  запрос выполняется на собранной базе и возвращает строки.
