## Context

Проработка 09.09.2026: назначенное дерево чистое, fetch выполнен, merge origin/main ответил `Already up to date.` База c20ccb2. `permissions.mjs:54–60` завершает приставку пробелом или концом строки; это предсказывает отсутствие пересечения, но не снимает вопрос о реальной среде.

`stage-command.mjs:40–41,96` передаёт файл настройки через `--settings` только ветке Claude; `provider.mjs:98–118` формирует иной запуск Codex. Поэтому проба через exec_command текущего Codex не проверяет спорные Bash/PowerShell-правила. На design живые пробы не выполнялись.

## Goals / Non-Goals

Получить проверяемое различение plain push / lease / force в среде, применяющей исходные правила; исправить только подтверждённое пересечение. Не менять договорённости о способе обновления ветки и не ослаблять защиту ради успешного эксперимента. Остальные границы перечислены в proposal.

## Decisions

### Изолированная проба с настоящим разбором разрешений

На implement подготовить одноразовый сценарий `.matchlog/0078-lease-probe.mjs`. Он создаёт обычный локальный репозиторий и bare origin только внутри `.matchlog/0078-lease-probe/` назначенного дерева, без git worktree add и без сети Git. Удалённый URL проверяется как разрешённый абсолютный локальный путь до любого push. Никаких ссылок на origin проекта, main или ветки других задач.

Диагностический запуск Claude конечный: ограничение времени 5 минут на заход, не более двух заходов (исходная настройка и кандидат при дефекте), без запуска боевого супервизора, без bypassPermissions и изменения его конфигурации. Версию и реально поддержанные ключи узнать из установленного CLI. Взять permission mode из действующего запуска этапа; исходный `--settings` — абсолютный путь к stage-settings.json свежей main. Зафиксировать SHA содержимого, команду запуска, действующие дополнительные источники настроек и имена реально доступных инструментов оболочки. Промпт подавать через stdin, как stage-command.mjs. Тестовые Git-команды должны вызываться самой сессией через её инструмент оболочки, не дочерним Git из Node: иначе проверялось бы разрешение на сценарий, а не на Git.

Исходный и изменённый снимки настроек различаются только заказанными deny-строками и пояснением. Для кандидата новая диагностическая сессия получает путь файла из ветки явно; изменение ветки не меняет настройки уже идущего этапа. Сценарий подготовки допустим только для устройства стенда и запуска диагностики, не для повторного исполнения отвергнутой Git-команды в обход инструментального запрета.

### Матрица и признаки исходов

`<проба>` — абсолютный путь изолированного репозитория; ветка `probe-0078` принадлежит только стенду. Все команды выполняются отдельными вызовами:

```powershell
git -C <проба> push origin probe-0078
git -C <проба> push --force-with-lease origin probe-0078
git -C <проба> push --force origin probe-0078
```

Проверить в каждом реально поддержанном инструменте Bash/PowerShell. Отсутствующий инструмент — непроверенная часть, а не успешная проба его правила. Перед отрицательным контролем локальная и удалённая головы равны: даже если force неожиданно пройдёт, он не перепишет историю. Результат отрицательного контроля определяется отказом политики до Git, а не безопасным `Everything up-to-date`.

Для lease подготовить непотомковую голову только в стенде и актуальное ожидание origin: команда должна дойти до Git и обновить локальный bare origin. Отдельно сдвинуть origin, сохранив устаревшее ожидание клиента: lease должен дойти до Git и быть отклонён с сохранением удалённого SHA. Так отказ политики отличим от исправно работающей проверки lease. Подготовка стенда не выполняет безусловных force push; головы выставляются локальными операциями внутри стенда.

В `probe-results.md` сохранить дату, версии Claude/Git, ОС, инструмент, снимок разрешений, точную команду, события вызова и отказа, stdout/stderr и код Git там, где он действительно запущен, SHA до/после. Не включать токены, личные настройки или полный посторонний журнал. Изложение модели без инструментального события не считается результатом.

### Условная минимальная правка

Если plain и lease проходят, а force получает отказ, deny остаётся прежним: в revise.md заменить только утверждение «никто не проверял» результатом с версией и границами доказательства. В stage-settings.json добавить краткое объяснение различия со ссылкой на сохранённый результат, не переписывая соседние примечания.

Если именно deny перекрывает lease, кандидат для каждой существующей формы запрета — пара точной команды, заканчивающейся на `--force`, и шаблона с явным пробелом после полного токена `--force` и последующими аргументами. Например, тела `git -C * push --force` и `git -C * push --force *`; аналогично сохранить прямые формы без `-C`. Это гипотеза исправления, пригодность определяется повтором матрицы в новой сессии. Не заменять запрет дополнительным allow: deny имеет приоритет. Не удалять защиту force и не разрешать её обход иной оболочкой.

Узкий тест настройки использует существующие patternOf/coversCommand/uncoveredCommands и настоящий JSON: lease с аргументами допустим, force с аргументами и на конце строки закрыт, с `-C` и в сохранённых прямых формах, для обоих наборов правил. Проверить тест отрицательными фикстурами: чрезмерный deny ломает lease, удаление force-deny открывает отрицательный контроль. Тест является регрессионной моделью; живой результат записан отдельно. Новый matcher и расширение STAGE_COMMANDS не нужны.

### Почему отвергнуты альтернативы

Проба обычным exec в Codex проверяет другую политику. Проверка только regex повторяет исходное предположение. Настоящий удалённый push проекта добавляет ненужный риск, а dry-run сам по себе не проверяет lease при смене головы. Превентивная правка deny без исходной пробы может ослабить уже исправную защиту. Отдельная дельта продублировала бы существующее право исполнителя.

## Risks / Trade-offs

Недоступен Claude, нужный инструмент оболочки или режим загрузки правил → не выдавать модель за живой результат; сохранить полученное и вернуть конкретное внешнее препятствие по действующему контракту. Не менять provider супервизора ради пробы и не создавать автоматически дубликат карточки 0078.

Отказ запуска самой диагностики → записать дословную причину, не прятать отказ в скрипт-обход. Если корректировка требует иной общей семантики matcher либо снимает другие запреты, остановить расширение и вернуть на проработку с доказательством: бездельтовое обоснование на это не распространяется.

Изменение внешнего CLI → вывод ограничен зафиксированной версией и источниками настроек. Непроверенную оболочку нельзя объявить исправной. Доказательства нужны до завершения implement, пункта ожидания послевливной пробы нет.

## Migration Plan

Один атомарный коммит реализации объединяет результат, пояснения, тест и подтверждённую правку deny при необходимости. После отправки открывается черновой PR. Настройки применятся к новым Claude-сессиям после штатной доставки; текущую сессию не перенастраивать. Откат — возврат этого коммита, без миграции данных. Только служебные файлы: нет геймплея, рассинхрона, реконнекта, изменения sim или байтов протокола; эталоны детерминизма и PROTOCOL_VERSION не меняются, запреты Math.random/Date.now/float в ядре не затрагиваются.

## Open Questions

Продуктовых решений нет. Технически остаются неизвестными живое совпадение спорного deny и доступность обеих оболочек у установленного Claude; их устанавливает реализация по указанной матрице, не утверждая ответ заранее.
