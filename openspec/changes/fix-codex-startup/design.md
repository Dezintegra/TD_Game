## Context
05.09.2026 оба этапа Codex получили declined на читающие Git-команды. Адаптер игнорирует config.toml, в котором задан windows.sandbox=elevated. Явная передача elevated позволила запустить команду; Git затем сообщил dubious ownership, поскольку sandbox работает другим локальным пользователем.

## Goals / Non-Goals
Восстановить запуск в штатном Windows sandbox и обнаруживать неисправную среду до работы. Не отключать sandbox, не менять глобальные настройки Git и не ослаблять корпоративные ограничения.

## Decisions
- Передавать windows.sandbox=elevated явно на Windows; допускается настроенное unelevated, но без автоматического переключения. Общие параметры одинаковы у пробы и рабочих этапов.
- Передавать safe.directory через окружение Git только для корня проекта и назначенного дерева. Список сбрасывается перед добавлением этих точных путей; wildcard запрещён. Это доверенные пользователем деревья, а Git запускается sandbox-пользователем.
- Перед первым оборотом Codex выполняет git rev-parse --is-inside-work-tree. Успех подтверждается событием command_execution с кодом 0 и выводом true, успешным терминальным событием и выходом CLI. Отказ, таймаут и ответ без команды запрещают выдачу задач. Таймаут снимает поддерево процессов.
- declined в JSONL попадает в denials, лог и сигнал ручной паузы; новые этапы после сигнала не выдаются. Сам перезапуск паузу не снимает.
- Наблюдение уведомляет о сбое на ближайшей проверке, сообщает прогресс раз в 15 минут и напоминает о нерешённой остановке.

## Risks / Trade-offs
Проба чтения Git не доказывает доступность SSH и выкладки; отдельно проверяется коммит на тестовом дереве. Sandbox может потребовать установленную системную конфигурацию; при её отсутствии явный отказ и диагностика, без обхода. Проба расходует токены один раз при старте, исключает массовые пустые попытки.

## Migration Plan
Узкие тесты, реальная проба команды и коммита на отдельном тестовом репозитории, CI PR, затем обновление main и контролируемый запуск конвейера.

Дополнительная проба: чтение Git и запись обычного файла прошли, но git add не смог создать index.lock. Стандартный workspace-write намеренно защищает .git, включая каталог из gitdir. Для автономных коммитов используем именованный профиль, наследующий :workspace, с явной записью только в общую .git и gitdir назначенного дерева; прочие защитные правила остаются. Это штатная настройка профиля, без изменения ACL вручную и без full-access.

Проба запускается из пустого временного каталога и обращается к проекту через git -C: подготовка writable-root всего основного дерева Windows sandbox превысила двухминутный срок из-за большого дерева. Основное дерево не требуется делать writable ради проверки чтения. Профиль и реализация sandbox остаются общими с этапами.
