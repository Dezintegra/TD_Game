# Задачи

Изменение доводит до игры задачи доски 0056 (свист записью, сдвинутый
к попаданию) и 0057 (звук пуска). Одним изменением, а не двумя, потому
что это один ответ владельца, одна пара записей и один набор голосов:
разведи их по двум pull request — и второй пришлось бы открывать
на конфликтующие правки тех же семи таблиц.

## 1. Записи владельца доезжают до игры

- [x] 1.1 Нарезать `nuke-fall.mp3` и `nuke-launch.mp3` из исходников
      владельца по границам кадров MP3, без перекодирования. Проверка:
      байты внутри взятого отрезка совпадают с исходником побайтно,
      нарезанное декодируется и даёт ту же огибающую со сдвигом.
      Происхождение, хеши и точные границы — в
      `apps/client/src/audio/assets/README.md`.
- [x] 1.2 Убрать исходники из `assets/source/` и переписать его README:
      каталог пуст, связь с готовыми записями — через `../README.md`,
      сами исходники остаются в истории.

## 2. Пуск как самостоятельное событие

- [x] 2.1 `Sound.NukeLaunch` во всех таблицах (`SOUND_SECONDS`,
      `SOUND_PEAK`, `SOUND_PRIORITY`, `VARIANTS`, `LOOPING`, `PER_SOUND`,
      `POOL_OF`) и ветка в `renderSound`. Посчитанное представление
      `renderNukeLaunch` обязательно: запись перекрывает выкладку,
      а не отменяет её.
- [x] 2.2 Выдача пуска в `cues.ts` — в момент появления записи о ракете,
      у базы владельца по `owner` и `StructureKind.Base`. Отсутствие
      базы даёт молчание, а не ошибку.
- [x] 2.3 Ядерный набор голосов расширен до шести мест, обоснование
      в комментарии поправлено.
      Проверка: `npx vitest run apps/client/src/audio/budget.test.ts`.

## 3. Свист приходит к попаданию

- [x] 3.1 `NUKE_FALL_TICKS` — две трети окна подлёта; `SOUND_SECONDS`
      и `cueLifetimeTicks` считаются от него.
- [x] 3.2 Выдача свиста в `cues.ts` сравнивает номер тика с тиком
      детонации, а не отсчитывает время от появления записи. Ключ
      свиста отличается от ключа пуска приметой.
- [x] 3.3 Обе записи подключены в `SOUND_FILES` с `take` и `fadeFrom`.

## 4. Чем это проверено

- [x] 4.1 Узкие тесты: `sounds.test.ts` — длительности, различимость
      пуска и свиста по направлению высоты, форма пуска (набирает тело
      и держит, а не хлопает); `budget.test.ts` — состав и вместимость
      ядерного набора; `cues.test.ts` — настоящий матч с настоящим
      пуском: три звука, каждый в своём месте, свист отстоит от пуска
      ровно на не занятую им часть окна.
      Проверка: `npx vitest run apps/client/src/audio`.
- [ ] 4.2 Прослушать в живой игре: пуск у своей базы, свист у цели,
      удар следом; при снятой записи звучит выкладка. Это единственное,
      чего числами не проверить, и на сессию оно не ложится — слышать
      она не умеет. Пункт остаётся владельцу продукта.

## 5. Что этим изменением НЕ делается

Задача 0023 требовала убрать посчитанный свист, пока замены нет.
Замена появилась, и убирать больше нечего: `renderNukeFall` остаётся
запасным путём под записью. Задача 0063 (оговорка в Purpose спеки
`sound`) ждала исключения «у ракеты в снижении звука нет» — исключения
не будет, звук есть. Обе теряют повод и закрываются, а не переезжают
сюда.
