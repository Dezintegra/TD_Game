# Задачи

Порядок продиктован тем, что **прибор нужен раньше подопытного**: раздел
сводки читается по любой пачке, в том числе по уже прогнанной, а пробные
профили без него дадут только доли побед — то есть тот же вопрос,
с которого всё началось.

Первая задача выбрана так, чтобы после неё уже открывался черновой pull
request: пока его нет, пуши в ветку не запускают проверок вовсе.

Прогонов арены среди задач нет намеренно — их заказывают задачами типа
`run` при вливании, а не делают шагом реализации.

## 1. Сводка по пачке: что каждый профиль заказал

- [ ] 1.1 Развернуть стороны матча в имена профилей: выражение
      `side(match_id, player, profile)` объединением обеих сторон
      таблицы `match`, и печать заголовка раздела на каждый профиль
      с числом сыгранных им сторон.
      *Проверка:* новый тест `apps/arena/src/report.test.ts` на базе
      в памяти — в зеркальной пачке (оба профиля с одним именем) раздел
      один, а сыгранных сторон в нём вдвое больше числа матчей.
      `npx vitest run apps/arena/src/report.test.ts`.
- [ ] 1.2 Заказанные юниты по типам, сложенные по пачке, рядом с долей,
      заявленной в профиле. Соединение `command` с `decision`
      по `tick - 1`, как в `reportMatch`.
      *Проверка:* тест — профиль, объявивший Теслу тремя четвертями
      состава и купивший её дважды при сотне штурмовиков, печатает обе
      величины, и они расходятся.
- [ ] 1.3 Постройки по видам и прокачка по целям, тем же приёмом.
      Строка «объявлено профилем, но не куплено ни разу» — единственный
      случай, когда печатается ноль.
      *Проверка:* тест — цель с ненулевым весом и нулём покупок попадает
      в эту строку, а цель с нулевым весом в неё не попадает.

## 2. Сводка по пачке: докуда сторона доживает

- [ ] 2.1 Доля решений в каждой фазе профиля и самая поздняя достигнутая
      фаза, усреднённая по сторонам. Считается по `decision.phase_index`.
      *Проверка:* тест — у стороны, все решения которой в фазе 1, доля
      поздней фазы нулевая, а самая поздняя достигнутая равна единице.

## 3. Сводка по пачке: что помешало и на чём стояла казна

- [ ] 3.1 Пометки `attempt.note` по долям, сложенные по пачке и
      разложенные по профилям.
      *Проверка:* тест — доли считаются от числа попыток этого профиля,
      а не от числа попыток пачки; сумма долей единица.
- [ ] 3.2 Длина накопления и доля накоплений, упёршихся в предел
      терпения, — тем же расчётом, что в `reportMatch`, но по пачке.
      *Проверка:* тест на подготовленной последовательности `wait_streak`
      — накоплений столько, сколько убываний, и упёршихся столько,
      сколько помечено `impatient`.
- [ ] 3.3 Медиана энергии по снимкам стороны, запросом
      с `order by energy limit 1 offset`, без выгрузки снимков в память.
      *Проверка:* тест на нечётном и чётном числе снимков; отдельно —
      что запрос не читает больше одной строки результата.

## 4. Семья пробных профилей

- [ ] 4.1 Три профиля в `packages/ai/src/profile.ts`, каждый раскрытием
      `SIEGE_PROFILE` с подменой одного поля значением **из базового
      профиля**, а не числом: `siege-probe-patience-2026-08` (горизонт
      накопления), `siege-probe-mix-2026-08` (состав войска средней
      фазы), `siege-probe-upgrade-2026-08` (прокачка средней фазы).
      Каждому — пояснение с вопросом, на который он отвечает. Запись
      всех трёх в `PROFILES`.
      *Проверка:* новый быстрый тест `packages/ai/src/probe.test.ts` —
      глубокое сравнение с `SIEGE_PROFILE` даёт ровно одно расхождение,
      и оно то, что названо в имени; `profileByName` находит все три.
      `npx vitest run packages/ai/src/probe.test.ts`.
- [ ] 4.2 Тест на связь с базовым: подменённое поле пробника равно
      соответствующему полю `BASELINE_PROFILE`, а не записанному числу.
      *Проверка:* тот же файл — сравнение с `BASELINE_PROFILE`; при
      правке базового горизонта тест остаётся зелёным сам собой.

## 5. Как этим пользоваться

- [ ] 5.1 Раздел в `apps/arena/README.md`: какой вопрос каким числом
      нового раздела отвечается, и как читать пробники — в частности,
      что пробник, выигрывающий тем, что перестал покупать Теслу,
      называет цену манеры, а не чинит её.
      *Проверка:* `npx prettier --check apps/arena/README.md`; названия
      величин в тексте совпадают с напечатанными сводкой.
