## Context

`transferReport` знает исход и созданные карточки, но пишет только summary; `cleanupTask` позднее пишет технический итог уборки. Trello не хранит task.history. `saveTask` сначала перемещает карточку, затем публикует журнал.

## Goals / Non-Goals

**Goals:** конкретная причина в финальном комментарии, сохранение доказательства через уборку, адресные продолжения и запрет закрытия при несохранённом пояснении.

**Non-Goals:** изменение семантики completed, пересмотр исторических решений, игровой код.

## Decisions

1. Сохранять `closureReason` в задаче и метаданных Trello. Это связный текст с причиной и доказательством; перенос отчёта формирует его из summary/evidence и действительно созданных карточек. Отдельное обязательное поле отчёта не требуется: существующих полей достаточно. Пустой summary для moot/split и передачи заметки отвергается.
2. Журнал выводит `closureReason` под заголовком «Причина закрытия». Уборка сохраняет этот смысловой итог и отдельно называет удалённые ресурсы. Для старой задачи в cleanup допускается восстановить дословное «Предмет снят» из истории; если причины нет, закрытие и удаление ресурсов не начинаются.
3. Trello сначала сохраняет все части комментария закрытия и только затем перемещает карточку. Отказ публикации оставляет исходную колонку. При повторе читается история комментариев самой карточки с пагинацией, уже записанные точные части пропускаются. Обычные переходы сохраняют прежний порядок.
4. Восстановление существующих 59 карточек — разовая адресная операция: прочитать историю каждой, написать короткое авторское объяснение со ссылкой на исходный комментарий и карточки продолжения. Записывать только новый комментарий, проверяя перед записью колонку и отсутствие такого же текста. Причину без исторического подтверждения не придумывать.

## Risks / Trade-offs

- Комментарий может сохраниться, а перемещение отказать → текст обозначает решение о закрытии, повтор не дублирует сохранённые части.
- Старый журнал может не содержать решение → задача остаётся незакрытой с явной диагностикой, вместо подстановки итога уборки.
- История может подтверждать только передачу работы → не называть её выполнением и ссылаться на конкретное продолжение.
- Служебный текст увеличивает описание → сохраняется существующее ограничение Trello; отказ записи не скрывается.

## Migration Plan

Внести правку через отдельный PR с узкими локальными проверками и зелёным CI. Исторические комментарии опубликовать отдельно от изменения кода. При откате кода пояснения остаются полезной историей, необязательное поле metadata совместимо с прежним читателем.
