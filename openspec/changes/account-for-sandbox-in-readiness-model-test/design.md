## Context

`checkCodexReadiness` принимает `platform`, по умолчанию равный `process.platform`. Для `win32` он сначала вызывает `start` с командой `sandbox` без модели; только код 0, отсутствие `killedBy` и точный вывод `td-workspace-ready` допускают следующий вызов с `exec`. В `stage-model.test.mjs` платформа не задана, а заглушка любого вызова возвращает код 1. Поэтому результат зависит от ОС тестового процесса.

Тесты `codex-readiness.test.mjs` уже проверяют порядок подготовки и пробы, отсутствие модели у подготовки и остановку при отказе. Здесь нужен ремонт проверки маршрута модели, а не повтор всего набора готовности.

## Goals / Non-Goals

Цель — довести тест до команды модельной пробы на обеих платформах и сохранить строгую проверку Terra. Область реализации — один существующий тестовый файл. Рабочий код, общая функция `modelFlag`, настройки моделей и полный контракт readiness не меняются.

## Decisions

1. Параметризовать существующий сценарий значениями `win32` и `linux`, передавая `platform` через уже существующий аргумент. Каждый случай хранит собственный список вызовов. Это воспроизводит Windows-ветку и на Linux runner. Только `platform: 'linux'` устранило бы падение на Windows обходом нужной ветки; зависимость от ОС оставила бы регрессию невидимой в Linux CI.
2. В заглушке распознавать подготовку по отдельному аргументу `sandbox` и возвращать для неё `{ code: 0, stdout: 'td-workspace-ready' }`. Для модельной пробы сохранить `{ code: 1, stdout: '' }`: результат readiness здесь не предмет проверки, а поддельные успешные события всех инструментов добавили бы лишнюю связанность. Все запуски остаются перехваченными через `start`.
3. После вызова readiness выделить команды с отдельным аргументом `exec`, проверить, что такая команда ровно одна, затем проверить ровно один `--model` и значение `gpt-5.6-terra` непосредственно после него. Поиск по `--model` отвергнут: исчезновение ключа не должно прятать команду. Выбор первого или последнего вызова по индексу отвергнут: подготовка уже показала хрупкость такого допущения.
4. Дополнительно проверить последовательность типов команд: Windows — `sandbox`, затем `exec`, Linux — только `exec`; у подготовки нет `--model`. Это компактное подтверждение, что именно этот тест прошёл нужную ветку. Детальные случаи отказа/таймаута остаются в `codex-readiness.test.mjs`.

## Risks / Trade-offs

- Проба не достигнута → проверка ровно одной команды `exec` падает явно, не читая аргумент по индексу -1.
- Модель исчезла, дублируется или заменена → проверки количества ключей и точного значения отклоняют изменение.
- Параметр `platform` управляет предварительной подготовкой, но часть аргументов provider зависит от ОС процесса → тест сравнивает смысловые аргументы, а не полный путь исполняемого файла или снимок всей команды.
- Настоящая готовность среды этими заглушками не доказывается → она остаётся предметом рабочего readiness и существующего специализированного набора.

Геймплей, рассинхрон и реконнект не затронуты. `packages/sim` не меняется: обновление эталонов детерминизма не требуется; запреты `Math.random`, `Date.now` и дробных чисел в состоянии мира не затрагиваются. Раскладка протокола не меняется, рост `PROTOCOL_VERSION` не нужен.

## Migration Plan

Один атомарный коммит реализации включает тест и отметку `tasks.md`, отправляется сразу и позволяет открыть черновой PR. Миграций данных и настройки машины нет; откат тестового коммита возвращает прежнюю проверку. Архивация без дельт не зависит от порядка архивации `route-models-by-stage` и `prepare-stage-workspace`.
