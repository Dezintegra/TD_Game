## ADDED Requirements

### Requirement: Cleanup recovers a lost registry entry for an existing task worktree

При сверке супервизор SHALL восстанавливать запись реестра через `adopt-worktree`, если Git регистрирует дополнительное дерево с конвейерной веткой соответствующей задачи, запись отсутствует, задача находится в `cleanup`, а её владелец — текущая машина либо не назначен. Восстановление SHALL сохранять идентификатор задачи, ветку, штатную форму пути и этап `cleanup`, не меняя владельца задачи.

Допустимость восстановления существующего дерева SHALL определяться отдельно от необходимости создавать отсутствующее. Состояние `cleanup` входить в `NEEDS_WORKTREE` MUST NOT, порождать `finish-claim` или создание дерева MUST NOT. Распознавание конвейерных веток, исключение основного дерева и запрет присвоения чужой задачи SHALL сохраняться.

Восстановленная запись SHALL передаваться штатной уборке до решения о закрытии задачи. Восстановление само по себе разрешением удалить дерево считаться MUST NOT: при наличии PR SHALL требоваться подтверждение влитости, без PR SHALL требоваться подтверждение отсутствия собственной работы в ветке. Неизвестность или отрицательный результат проверки обходиться через отсутствие записи MUST NOT. Проверки безопасности пути удаления SHALL сохраняться. Пока штатная уборка восстановленного дерева возвращает `finished: false`, задача SHALL оставаться в `cleanup`, а запись SHALL сохраняться для повтора.

#### Scenario: Своё дерево восстанавливается и убирается после подтверждения PR

- **WHEN** запись отсутствует, Git регистрирует дерево задачи текущей машины в `cleanup`, её PR подтверждён как влитый и штатная уборка успешно удаляет дерево и обе ветки
- **THEN** сверка выдаёт `adopt-worktree`, запись восстанавливается до уборки, после удаления снимается и задача переходит в `closed`
- **AND** создание дерева не вызывается

#### Scenario: Владелец не назначен

- **WHEN** существует зарегистрированное Git дерево задачи в `cleanup` без записи реестра и без владельца
- **THEN** сверка допускает восстановление записи, не назначая задаче нового владельца

#### Scenario: Отсутствующее дерево не создаётся

- **WHEN** задача текущей машины находится в `cleanup`, а её дерева и записи нет
- **THEN** сверка не выдаёт ни `adopt-worktree`, ни `finish-claim`, создание дерева не вызывается

#### Scenario: Чужое дерево не присваивается

- **WHEN** запись отсутствует, а задача найденного дерева в `cleanup` принадлежит другой машине
- **THEN** сверка выдаёт `report-orphan`, запись не создаётся и починка не вызывает удаления

#### Scenario: Основное и ручное деревья не восстанавливаются как деревья задачи

- **WHEN** инвентаризация содержит основное дерево либо дополнительное дерево с веткой вне строгого формата конвейера
- **THEN** сверка не предлагает `adopt-worktree` для этих деревьев, даже при наличии задачи в `cleanup`

#### Scenario: PR не подтверждает влитость

- **WHEN** запись дерева задачи в `cleanup` восстановлена, но её PR открыт или его состояние недоступно
- **THEN** штатная проверка соответственно останавливает уборку или откладывает её, дерево не удаляется и задача не закрывается

#### Scenario: У задачи без PR своей работы нет

- **WHEN** запись восстановлена для задачи в `cleanup` без PR и проверка собственной работы возвращает ноль
- **THEN** штатная уборка разрешена и после успешного удаления всех ресурсов задача закрывается

#### Scenario: У задачи без PR есть своя работа или проверка не удалась

- **WHEN** запись восстановлена для задачи без PR, а проверка собственной работы возвращает положительное число либо неизвестный результат
- **THEN** штатная проверка останавливает уборку, дерево и запись сохраняются, задача не закрывается

#### Scenario: Удаление после восстановления не завершилось

- **WHEN** запись восстановлена и уборка разрешена, но удаление дерева или одной из веток возвращает отказ
- **THEN** `finished` равен `false`, задача остаётся в `cleanup`, запись не снимается
- **AND** при последующей успешной штатной уборке запись снимается и задача закрывается
