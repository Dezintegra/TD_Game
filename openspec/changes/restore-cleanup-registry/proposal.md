## Why

После потери записи реестра существующее дерево задачи в `cleanup` получает `report-orphan`: `reconcile.mjs` использует `NEEDS_WORKTREE` одновременно для восстановления записи и создания дерева. Затем `mayCleanup` принимает отсутствие записи за отсутствие дерева, и задача может закрыться с оставшимися ресурсами. На свежем `origin/main` (648754b) эта цепочка сохраняется.

## What Changes

- Разрешить `adopt-worktree` для существующего дерева задачи в `cleanup`, если задача не занята другой машиной, сохранив распознавание конвейерной ветки и исключение основного дерева.
- Отделить это решение от `finish-claim`: `cleanup` по-прежнему не входит в `NEEDS_WORKTREE`, отсутствующее дерево не создаётся.
- Проверить восстановление записи и передачу её штатной уборке, включая подтверждение влитости PR, отсутствие собственной работы без PR и сохранение `cleanup` при незавершённом удалении.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `pipeline-supervision-resilience`: добавить правило восстановления потерянной записи существующего дерева в `cleanup`, независимо от необходимости создавать дерево.

## Non-goals

- Создание дерева или запуск сессии для `cleanup`, изменение маршрутов, квот и владельцев задач.
- Автоматическое присвоение деревьев другой машины, ручных деревьев или деревьев закрытых задач.
- Переписывание выполненного комментария задачи 0222.
- Удаление незарегистрированных остатков каталогов из `finish-worktree-cleanup`, изменение алгоритма удаления, мерок влитости и проверки собственных коммитов.
- Исправление иных случаев потери реестра и консолидация исторических дельт конвейера.

## Impact

Основная правка — `supervisor/lib/reconcile.mjs`; регрессионные проверки — `reconcile.test.mjs` и `execute.test.mjs` с реальными функциями `repairWorld`, `mayCleanup` и `cleanup` и поддельным IO. Формат реестра, API и зависимости не меняются.

Отзывчивость интерфейса не затронута: код исполняется только супервизором вне игрового процесса. Игровой сетевой трафик не меняется. Восстановленная задача выполняет существующие запросы проверки PR и удаления удалённой ветки; новых видов запросов и дополнительного периодического опроса нет.

## Пересечения и порядок архивации

`agent-backlog-pipeline` содержит общие правила реестра и уборки, `backlog-in-trello` — запрет присвоения чужой задачи, `close-tasks-that-lost-their-point` — мерку уборки без PR. Они находятся в открытых дельтах `dev-pipeline-orchestrator`, которой ещё нет в основных спецификациях. Наше узкое ADDED-требование размещается в уже существующей `pipeline-supervision-resilience`: это восстановление после сбоя, без копирования общих требований и без MODIFIED поверх незаархивированной основы. Зависимости порядка архивации нет.

`finish-worktree-cleanup` меняет переходник удаления и не требует правки для восстановления записи зарегистрированного дерева. `explain-why-cleanup-needs-no-tree` меняет комментарий, а не условие восстановления. Названное в назначении `persist-unapplied-stage-reports` отсутствует в списке изменений свежей базы; по постановке касается хранения отчётов, общих требований этого изменения не вводит. При реализации пересечения повторно проверяются на обновлённой базе.
