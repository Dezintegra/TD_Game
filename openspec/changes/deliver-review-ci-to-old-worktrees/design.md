## Context

На свежей базе `0d014857` `stage-command.mjs` и `provider.mjs` берут правила из home инструмента, но сохраняют cwd задачи. Вход `supervisor/bin/review-ci.mjs` импортирует command-runner и review-ci; review-ci через io импортирует дополнительные модули, а также defaults и ci-confirmation. Поэтому наличие одного bin не доказывает работоспособность. `git -C . ls-tree 96da9a6356ed75f5418cac641559b293a7991d45 supervisor/bin/review-ci.mjs supervisor/lib/review-ci.mjs` вернул пусто. Это тот HEAD, который показывает `git worktree list` для 0242.

`supervisor/lib/supervisor.mjs:spawnStage` уже проверяет живые children/orphans и ловит ошибки подготовки до spawn. Это место общего подключения для Claude и Codex; чистый stageCommand не должен начинать запись файлов. Текущий сторож review-ci-contract проверяет текст и allow/deny, но запуска старого дерева не делает.

## Goals / Non-Goals

Доставлять полный актуальный инструмент до запуска review, сохранить Git-идентичность и обычную проверку PR. Не менять алгоритм CI, маршруты pending и механизмы восстановления карточек; не делать исключения допуска для PR 177. Не писать код на design или в чужом дереве на implement.

## Decisions

### Комплект в назначенном дереве

Добавить `supervisor/lib/review-ci-runtime.mjs` с подготовкой комплекта из home. Вызвать её из spawnStage после проверок занятости и назначения, до stageCommand и порождения процесса, только для review, в том числе continuation. Подготовленный вход имеет фиксированный относительный путь `.matchlog/review-ci-runtime/review-ci.mjs`; команда: `node .matchlog/review-ci-runtime/review-ci.mjs --pr <pr> --head <sha>`.

Служебный корень принадлежит только доставке этого инструмента. Перед записью проверить абсолютную вложенность в назначенное дерево, отсутствие ссылок/junction в компонентах, отсутствие отслеживаемых файлов по целевому пути и фактическое игнорирование Git. При нарушении не менять Git exclude, .gitignore или файлы пользователя — остановить подготовку с точной причиной. Не удалять незнакомый каталог. Существующий комплект признаётся своим по манифесту и проверенным путям; обновляется только при отсутствии живого review, что проверяет владелец цикла. Временная копия строится рядом внутри этого же служебного корня и публикуется только после полной проверки. Обрыв оставляет недопущенный комплект; следующий запуск заново проверяет содержимое, а не доверяет одному маркеру.

Внутри комплекта сохраняются `supervisor/bin/review-ci.mjs`, `supervisor/lib/...` и `supervisor/config/...`. Корневой `review-ci.mjs` — фиксированный служебный launcher, импортирующий `./supervisor/bin/review-ci.mjs`; его текст принадлежит модулю доставки и также входит в digest. Он не принимает путь исполняемого файла и не меняет cwd. Это сохраняет относительные импорты исходного CLI без их переписывания. Для отдельно установленного supervisor home обозначает корень инструмента с bin/lib/config; манифест разрешается от этого корня и размещается под внутренним префиксом supervisor. Не предполагать, что home равно корню TD_Game.

Копируются только явный манифест транзитивной цепочки и необходимые ресурсы с сохранением относительной структуры. Манифест хранится в модуле доставки; исходный bin, command-runner, review-ci, io, defaults, ci-confirmation и рекурсивные зависимости io обязательны. Запрещены bare/npm зависимости, ссылки и выход за home. Не копировать node_modules, .env, настройки доступа или остальные bin. Тест независимой загрузки всей цепочки защищает манифест при изменении импортов. Источник и копия сверяются по SHA-256 каждого файла; повторное чтение источника до публикации обнаруживает обновление во время копирования. Идентификатор комплекта — digest отсортированного манифеста, а не HEAD задачи. Не вводить второй алгоритм оценки CI.

Полная проверка загрузки запускает копию настоящего входа без обязательных аргументов в отдельном Node-процессе: ожидаются JSON ошибки аргументов и код 64, без GitHub. Статические импорты должны загрузиться до проверки аргументов. Если вход будет переведён на динамический import с обработкой ошибок, этот порядок сохранить явно. Тайм-аут подготовки ограничен 15 секундами; вывод проверки не смешивается с ответом модели. Ошибка возвращается штатным `not-born` с причиной; успешный CLI не вызывается и success не выдумывается.

Отвергнуты: merge/cherry-pick инструмента в ветку review (меняет SHA); один скопированный bin (не загружает зависимости); запуск из main с cwd main (меняет репозиторий GitHub); абсолютная команда в home (требует динамического quoting/permissions и оставляет работающий review зависимым от обновления внешних файлов); копирование всего supervisor (ненужные исполняемые входы и данные). Служебная копия немного увеличивает файловую работу, но проверяется до модели и не зависит от возраста ветки.

### Единая команда и неизменный допуск

Оба места review.md — до diff и непосредственно перед ready/merge — переходят на служебный путь в одном коммите с подключением доставки. STAGE_COMMANDS и stage-settings согласуются в том же коммите. Узкая явная allow-форма указывает только этот вход для оболочек из SHELLS. Существующее разрешение `.matchlog/*` не расширяется; отрицательный контроль удаления разрешений обязан учитывать все покрывающие allow, иначе тест будет декоративным. Deny всегда приоритетнее. Новая команда не открывает запуск исходного supervise/launch или произвольный bin.

`node` вызывается по имени, без inline-кода и изменения cwd. Реальный CLI сохраняет `createCommandRunner(process.cwd())`; GitHub обращается к репозиторию задачи. `--pr` берётся из назначения, `--head` — из `git -C <дерево> rev-parse HEAD`. Перед вливанием повторно сверяются локальный HEAD и CI для первоначально проверенного SHA, merge сохраняет `--match-head-commit`. Изменение пути не меняет состояния и коды 0/1/2/3/64. Ошибка загрузки после preflight остаётся диагностируемым ненулевым отказом, никогда успехом. Для неё допустимо отсутствие JSON, как и для отказа native-инструмента; это не результат CI.

Никаких изменений sim/protocol: реконнект, рассинхрон, эталоны детерминизма и PROTOCOL_VERSION неприменимы. Запреты Math.random, Date.now и дробного состояния мира сохраняются, в ядро код не добавляется.

### Регрессионные доказательства

Fixture — самостоятельный временный Git-репозиторий внутри `.matchlog/` своего дерева, с коммитом до CLI, игнорируемым .matchlog и без node_modules. Источник инструмента — отдельный каталог, не этот репозиторий. Настоящая подготовка, реальный Node-вход и вся цепочка импортов; подменяется только gh на границе процесса. До/после сравнить HEAD, symbolic-ref, tree, индекс и status; обычный старый CLI отсутствует после опыта также.

Проверить ordinary success, подтверждённое противоречие с run/attempt, pending, failure, conflict, UNKNOWN, другой SHA/PR, ошибку/тайм-аут/испорченный JSON gh и неверные аргументы. Два последовательных вызова используют изменённые ответы gh: прежний success не разрешает второй. Записать фактические stdout/stderr/code/signal, отдельно проверить PowerShell-форму на Windows. Не вводить в боевой CLI чтение fixture/сохранённого отчёта.

Отрицательные контроли: убрать транзитивный модуль (не только bin), испортить модуль, выключить вызов подготовки в копии запуска, оставить старый digest, запретить запись, подставить ссылку/отслеживаемый путь, удалить все покрывающие allow или добавить deny, удалить второй вызов/защиту SHA из инструкции. Каждый контроль должен разрушить соответствующее доказательство; matcher не заменяет исполнение CLI.

## Risks / Trade-offs

- Манифест устаревает при новых импортах → настоящий CLI загружается до spawn, регрессия исполняет полную цепочку без зависимостей дерева.
- Обновление источника во время доставки → двойная сверка digest, публикация только целого комплекта, запрет тихого fallback.
- Сохранённая сессия помнит старую команду → актуальные правила и явная строка служебного входа выдаются при каждом continuation; тест проверяет оба provider. При несовместимом старом контексте штатный новый запуск предпочтительнее ручных правок ветки.
- Защиты окружения могут запретить запись/исполнение → точная диагностика без обхода; живая приёмка нужна отдельно от fixture.
- Пересечение с 0313 → согласовать путь вызова и сохранить её действующую маршрутизацию pending; не редактировать её артефакты и не ждать её для доставки.

## Migration Plan

Implement создаёт код и регрессии, открывает свой draft PR после первого атомарного шага. После установки исправленной версии супервизора новый review автоматически получает комплект. Отмена изменения откатывает код/правила совместно; старое дерево с отсутствующим CLI не считается восстановленным при откате. Чужие служебные копии вручную не удаляются.

Восстановление 0242 выполняет владелец цикла по действующему `return-task`: проверяет актуальную карточку, `returnTo=review`, диагноз pipeline, допустимость возврата и результаты `fixedBy`; забывает старую сессию штатным способом и сохраняет PR/branch/change. Если эти поля не подготовлены, это оформляется штатным разбором карточки, а не прямой записью исполнителя. Не добавлять обратную зависимость 0312 от 0242/PR 177 и не ждать completed 0312 для проверки самой доставки: после установки версии владелец цикла может подготовить назначенное окружение и снять read-only свидетельство до окончательного закрытия починки.

В новой назначенной сессии 0242 native-инструмент выполняет отдельно `git -C <дерево> rev-parse HEAD`, затем `node .matchlog/review-ci-runtime/review-ci.mjs --pr 177 --head <фактический SHA>`. Нужны launch/session id, provider, cwd, digest комплекта, код процесса и JSON с expectedHead/observedHead, state/why/mode/runs, сверка Git до/после. Исходный SHA 96da9a63 — свидетельство дефекта, не константа допуска. При реальном pending/failure/conflict доступность восстановлена, но PR не вливается. Повтор перед вливанием остаётся обязанностью review 0242, не implement 0312.

Эти живые действия принадлежат супервизору и назначенной сессии 0242 после установки, не пунктам implement, который не вправе захватывать чужое дерево. Implement передаёт в отчёте готовность и точный протокол; отсутствие живого свидетельства обозначается явно. Тесты и PR 0312 сами по себе не объявляют конкретную приёмку 0242 выполненной. Итоговый результат карточки включает это внешнее свидетельство; новая карточка-дубликат не требуется.
