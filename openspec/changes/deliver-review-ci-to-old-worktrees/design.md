## Context

На свежей базе `0d014857` `stage-command.mjs` и `provider.mjs` берут правила из home инструмента, но сохраняют cwd задачи. Вход `supervisor/bin/review-ci.mjs` импортирует command-runner и review-ci; review-ci через io импортирует дополнительные модули, а также defaults и ci-confirmation. Поэтому наличие одного bin не доказывает работоспособность. `git -C . ls-tree 96da9a6356ed75f5418cac641559b293a7991d45 supervisor/bin/review-ci.mjs supervisor/lib/review-ci.mjs` вернул пусто. Это тот HEAD, который показывает `git worktree list` для 0242.

`supervisor/lib/supervisor.mjs:spawnStage` уже проверяет живые children/orphans и ловит ошибки подготовки до spawn. Это место общего подключения для Claude и Codex; чистый stageCommand не должен начинать запись файлов. Текущий сторож review-ci-contract проверяет текст и allow/deny, но запуска старого дерева не делает.

## Goals / Non-Goals

Доставлять полный актуальный инструмент до запуска review, сохранить Git-идентичность и обычную проверку PR. Добавить исполняемую приёмку доставки, доступную до завершения починки. Не менять алгоритм CI, маршруты pending и условия return-task; не делать исключения допуска для PR 177. Не писать код на design или в чужом дереве на implement.

## Decisions

### Комплект в назначенном дереве

Добавить `supervisor/lib/review-ci-runtime.mjs` с подготовкой комплекта из home. Вызвать её из spawnStage после проверок занятости и назначения, до stageCommand и порождения процесса, только для review, в том числе continuation. Подготовленный вход имеет фиксированный относительный путь `.matchlog/review-ci-runtime/review-ci.mjs`; команда: `node .matchlog/review-ci-runtime/review-ci.mjs --pr <pr> --head <sha>`.

Служебный корень принадлежит только доставке этого инструмента. Перед записью проверить абсолютную вложенность в назначенное дерево, отсутствие ссылок/junction в компонентах, отсутствие отслеживаемых файлов по целевому пути и фактическое игнорирование Git. При нарушении не менять Git exclude, .gitignore или файлы пользователя — остановить подготовку с точной причиной. Не удалять незнакомый каталог. Существующий комплект признаётся своим по манифесту и проверенным путям; обновляется только при отсутствии живого review, что проверяет владелец цикла. Временная копия строится рядом внутри этого же служебного корня и публикуется только после полной проверки. Обрыв оставляет недопущенный комплект; следующий запуск заново проверяет содержимое, а не доверяет одному маркеру.

Внутри комплекта сохраняются `supervisor/bin/review-ci.mjs`, `supervisor/lib/...` и `supervisor/config/...`. Корневой `review-ci.mjs` — фиксированный служебный launcher, импортирующий `./supervisor/bin/review-ci.mjs`; его текст принадлежит модулю доставки и также входит в digest. Он не принимает путь исполняемого файла и не меняет cwd. Это сохраняет относительные импорты исходного CLI без их переписывания. Для отдельно установленного supervisor home обозначает корень инструмента с bin/lib/config; манифест разрешается от этого корня и размещается под внутренним префиксом supervisor. Не предполагать, что home равно корню TD_Game.

Копируются только явный манифест транзитивной цепочки и необходимые ресурсы с сохранением относительной структуры. Манифест хранится в модуле доставки; исходный bin, command-runner, review-ci, io, defaults, ci-confirmation и рекурсивные зависимости io обязательны. Запрещены bare/npm зависимости, ссылки и выход за home. Не копировать node_modules, .env, настройки доступа или остальные bin. Тест независимой загрузки всей цепочки защищает манифест при изменении импортов. Источник и копия сверяются по SHA-256 каждого файла; повторное чтение источника до публикации обнаруживает обновление во время копирования. Идентификатор комплекта — digest отсортированного манифеста, а не HEAD задачи. Не вводить второй алгоритм оценки CI.

Полная проверка загрузки запускает копию настоящего входа без обязательных аргументов в отдельном Node-процессе: ожидаются JSON ошибки аргументов и код 64, без GitHub. Статические импорты должны загрузиться до проверки аргументов. Если вход будет переведён на динамический import с обработкой ошибок, этот порядок сохранить явно. Тайм-аут подготовки ограничен 15 секундами; вывод проверки не смешивается с ответом модели. Ошибка возвращается штатным `not-born` с причиной; успешный CLI не вызывается и success не выдумывается.

Отвергнуты: merge/cherry-pick инструмента в ветку review (меняет SHA); один скопированный bin (не загружает зависимости); запуск из main с cwd main (меняет репозиторий GitHub); абсолютная команда в home (требует динамического quoting/permissions и оставляет работающий review зависимым от обновления внешних файлов); копирование всего supervisor (ненужные исполняемые входы и данные). Служебная копия немного увеличивает файловую работу, но проверяется до модели и не зависит от возраста ветки.

### Единая команда и неизменный допуск

Оба места review.md — до diff и непосредственно перед ready/merge — переходят на служебный путь в одном коммите с подключением доставки. STAGE_COMMANDS и stage-settings согласуются в том же коммите. Узкая явная allow-форма указывает только этот вход для оболочек из SHELLS. Существующее разрешение `.matchlog/*` не расширяется; отрицательный контроль удаления разрешений обязан учитывать все покрывающие allow, иначе тест будет декоративным. Deny всегда приоритетнее. Новая команда не открывает запуск исходного supervise/launch или произвольный bin.

`node` вызывается по имени, без inline-кода и изменения cwd. Реальный CLI сохраняет `createCommandRunner(process.cwd())`; GitHub обращается к репозиторию задачи. `--pr` берётся из назначения, `--head` — из `git -C <дерево> rev-parse HEAD`. Перед вливанием повторно сверяются локальный HEAD и CI для первоначально проверенного SHA, merge сохраняет `--match-head-commit`. Изменение пути не меняет состояния и коды 0/1/2/3/64. Ошибка загрузки после preflight остаётся диагностируемым ненулевым отказом, никогда успехом. Для неё допустимо отсутствие JSON, как и для отказа native-инструмента; это не результат CI.

Никаких изменений sim/protocol: реконнект, рассинхрон, эталоны детерминизма и PROTOCOL_VERSION неприменимы. Запреты Math.random, Date.now и дробного состояния мира сохраняются, в ядро код не добавляется.

### Регрессионные доказательства

Fixture — самостоятельный временный Git-репозиторий внутри `.matchlog/` своего дерева, с коммитом до CLI, игнорируемым .matchlog и без node_modules. Источник инструмента — отдельный каталог, не этот репозиторий. Настоящая подготовка, реальный Node-вход и вся цепочка импортов; подменяется только gh на границе процесса. До/после сравнить HEAD, symbolic-ref, tree, индекс и status; обычный старый CLI отсутствует после опыта также.

Проверить ordinary success, подтверждённое противоречие с run/attempt, pending, failure, conflict, UNKNOWN, другой SHA/PR, ошибку/тайм-аут/испорченный JSON gh и неверные аргументы. Два последовательных вызова используют изменённые ответы gh: прежний success не разрешает второй. Записать фактические stdout/stderr/code/signal, отдельно проверить PowerShell-форму на Windows. Не вводить в боевой CLI чтение fixture/сохранённого отчёта.

Отрицательные контроли: убрать транзитивный модуль (не только bin), испортить модуль, выключить вызов подготовки в копии запуска, оставить старый digest, запретить запись, подставить ссылку/отслеживаемый путь, удалить все покрывающие allow или добавить deny, удалить второй вызов/защиту SHA из инструкции. Каждый контроль должен разрушить соответствующее доказательство; matcher не заменяет исполнение CLI.

### Отдельный вход живой приёмки, не return-task

Аудит обнаружил круг: `scan.mjs:310–329` проверяет completed всех `recovery.fixedBy`, а прежний Migration Plan требовал свидетельство до completed 0312. Одного разрешения «владелец может подготовить окружение» недостаточно. Реализуется новый вход `supervisor/bin/review-ci-recovery.mjs`, его сейчас в основе нет. Исполнитель входа — владелец установки на станции, сохраняющей дерево 0242; сессии design/implement/review 0312 его не запускают и чужое дерево не получают.

Команда из корня установленного репозитория: `node supervisor/bin/review-ci-recovery.mjs --repair-task 0312-obespechit-dostupnost-instrumenta-podtve --target-task 0242-dat-otchetu-etapa-adresnoe-poruchenie-na --pr 177`. Для отдельной установки cwd остаётся корнем назначенного проекта, вход запускается владельцем из установленного home через штатный host launcher; ограничения приставок сессий на хозяина установки не переносятся. Первичная обязательная приёмка 0242 использует показанную репозиторную форму. В stage-settings разрешение на этот bin не добавляется.

Вход — конечная операция обслуживания, не второй цикл supervise. Он использует `supervisor-startup.mjs` для исключительного владения тем же supervisor.lock, проверяет сохранённые живые процессы и неизвестную живость, отказывается при другом владельце и не снимает его замок. Предварительные чтения карточек и реестра выполняются host-кодом; запись в доску отсутствует. Из актуальной карточки/реестра получает единственное существующее дерево, ожидаемую ветку, PR/change и provider из действующей настройки review. Идентификаторы команды сверяются с ними; произвольный путь или другой PR не принимается. Отсутствие/неоднозначность дерева, чужое владение, живой этап/сирота/неприменённый отчёт 0242 дают отказ до записи. Отсутствующие recovery/returnTo допустимы: они не нужны для чтения CLI и не изменяются.

Внутри `supervisor/lib/review-ci-recovery.mjs` используются настоящая доставка и отдельный построитель диагностического назначения `supervisor/lib/review-ci-recovery-command.mjs`. Он переиспользует формирование provider/permission/cwd из stage-command/provider, но заменяет задание на фиксированный протокол `supervisor/skills/review-ci-recovery.md`. Он **не** подаёт обычный review.md с поручением рассмотреть diff или влить PR. Диагностика использует текущие режим и полный набор разрешений review без ослабления, новый session id, тот же native-инструмент и cwd 0242. Допустимы только последовательные чтения Git до/после и один вызов доставленного CLI с PR 177 и SHA, прочитанным в этой сессии. Нет resume старой сессии, merge, fetch, ready, правок кода, создания PR или записи доски. Внешний host-процесс Node, исполнивший CLI сам, не заменяет native-событие назначенной сессии.

`run-stage.mjs` используется как низкоуровневый хозяин процесса с ограничением пять минут и снятием собственного поддерева. Диагностическое назначение хранит `purpose=review-ci-recovery`, `repairTaskId`, `targetTaskId`, launch id и PID с идентичностью; это не этап 0242 и не отчёт для parseReport/apply-report. Учёт расхода запуска относится к 0312 существующими функциями token-budget/provider; глобальный лимит и неизвестная полнота расхода не обходятся. Лимит — одна попытка на запуск команды, без автоматического повторения при отказе. Повтор владельцем требует новой причины и сохраняет прежнее свидетельство.

`supervisor/lib/review-ci-recovery-evidence.mjs` сопоставляет native-события команды и результата по session/tool-use id, проверяет отсутствие посторонних команд и отказов, завершённость потока, правильные PR/expectedHead/observedHead, JSON/код CLI и снимки Git. JSON из финального текста модели без событий не принимается. Различаются `availability=confirmed` и результат CI: pending/failure/conflict с корректными идентичностью и JSON подтверждают доступность, но не допуск. Несовпадение HEAD, ошибка запуска, повреждение ответа или пропавшее наблюдение оставляют `availability=unconfirmed` с причиной; неизвестное не достраивается ожидаемыми значениями.

До запуска host атомарно сохраняет дескриптор в `.pipeline/review-ci-recovery/<repairTaskId>/<launchId>/`; после — очищенные события, `evidence.json` и диагностический текст ошибки. Квитанция включает actual cwd, branch/change, provider и версию приложения, digest полного комплекта и репозиторных правил, repair PR/merge SHA, target PR, локальный SHA до/после, ожидаемый/наблюдаемый SHA, stdout JSON CLI, stderr, exit code/signal и Git-снимки. Содержимое личных настроек, env/auth и сырой неочищенный поток не публикуются. Ошибка записи оставляет приёмку неподтверждённой. Возвращаемый stdout входа — JSON с путём квитанции и классификацией; exit 0 означает подтверждённую **доступность**, поле ciState сохраняет собственный результат CLI. Это отдельный контракт host-входа; коды review-ci не меняются.

Повтор после прерывания сначала сверяет собственный сохранённый процесс; живая либо неизвестная идентичность запрещает второй запуск. Мёртвый запуск остаётся незавершённым свидетельством, новый получает новый launch id. Приёмка не записывает `completed`, не очищает fixedBy/returnTo, не меняет sessionId или attempts 0242 и не открывает ей review. `card-dependencies` продолжает применяться к её обычному возврату.

### Завершение починки только после квитанции

Новый `supervisor/lib/review-ci-recovery-gate.mjs` вызывается в `execute.mjs:cleanupTask` перед удалением дерева и завершением карточки. Узкий декларативный файл `supervisor/config/review-ci-recovery.json` связывает change `deliver-review-ci-to-old-worktrees`, repairTaskId 0312, targetTaskId 0242, PR 177 и target change `append-addressed-card-dependencies`. Это план обязательной приёмки установленного изменения, не очередь новых карточек и не исключение fixedBy. Для остальных изменений gate ничего не меняет. Доказательства читаются host-адаптером в io, не берутся из текста отчёта implement.

Gate требует подтверждённое вливание собственного PR 0312 и сохранённую квитанцию из действительного окружения 0242 с неизменными PR/branch/change и совпадающим digest установленного комплекта. Подпись владельца здесь не криптографическая: provenance дают эксклюзивный host-запуск, файловая область супервизора и полные связанные события, а не значение `confirmed` из файла пользователя. Повторная проверка структуры и событий обязательна. При неудаче cleanup возвращает skipped с точной причиной, 0312 остаётся cleanup, дерево не удаляется. После успешной приёмки обычный cleanup может завершить 0312, и только тогда fixedBy разрешит return-task 0242. Квитанция сохраняется вне удаляемого дерева и её безопасная сводка с путём включается в финальный журнал 0312 штатным io; сбой доставки сводки не разрешает тихое завершение.

Квитанция — свидетельство доступности на названном SHA и версии, не кеш допуска CI. Изменившийся SHA требует обычного свежего подтверждения review; повторное вливание защищается `--match-head-commit`. Прежнее свидетельство не разрешает вливание даже при неизменном SHA.

Отвергнуты ранний return-task (ослабляет completed fixedBy), выполнение review с доступом к merge ради пробы (смешивает диагностику и допуск), fixture вместо живого вызова (не проверяет sandbox), поручение implement писать в 0242 (нарушает владение) и новый предшественник 0312 на PR 177 (создаёт обратную зависимость). Отдельный конечный host-вход требует окна установки, зато не зависит от статуса восстановления карточки и имеет проверяемое завершение.

## Risks / Trade-offs

- Манифест устаревает при новых импортах → настоящий CLI загружается до spawn, регрессия исполняет полную цепочку без зависимостей дерева.
- Обновление источника во время доставки → двойная сверка digest, публикация только целого комплекта, запрет тихого fallback.
- Сохранённая сессия помнит старую команду → актуальные правила и явная строка служебного входа выдаются при каждом continuation; тест проверяет оба provider. При несовместимом старом контексте штатный новый запуск предпочтительнее ручных правок ветки.
- Защиты окружения могут запретить запись/исполнение → точная диагностика без обхода; живая приёмка нужна отдельно от fixture.
- Пересечение с 0313 → согласовать путь вызова и сохранить её действующую маршрутизацию pending; не редактировать её артефакты и не ждать её для доставки.

## Migration Plan

Implement создаёт код и регрессии, открывает свой draft PR после первого атомарного шага. После установки исправленной версии супервизора новый review автоматически получает комплект. Отмена изменения откатывает код/правила совместно; старое дерево с отсутствующим CLI не считается восстановленным при откате. Чужие служебные копии вручную не удаляются.

Первичную установку и живую приёмку выполняет **владелец установки станции 0242**, используя новый конечный вход выше. Это явная внешняя операция установки, не несуществующий метод старого владельца цикла и не будущий разбор карточки. Исполнитель implement передаёт точную команду и состояние `живая приёмка не выполнена`; его пункты создают и проверяют механизм, но не запускают установку.

Порядок первого включения обязателен: владелец установки предоставляет окно обслуживания до первого cleanup 0312. После старта финального review 0312 он штатной паузой останавливает выдачу новых работ, даёт уже идущему review закончить вливание и сохранить отчёт, затем штатно завершает старый процесс с сохранением неприменённых отчётов. Он устанавливает влитую версию, запускает новый recovery-вход и возобновляет цикл уже с новым cleanup-gate. Старый процесс не должен получить оборот cleanup между вливанием и установкой: его загруженный execute.mjs ещё не знает gate. Самообновление после оборота этого не гарантирует; протокол не утверждает обратного. Пауза/установка выполняются владельцем, не дочерней сессией через launch --stop. Если окно ещё не предоставлено, установка и окончательная приёмка остаются незавершёнными; не писать completed по одним тестам.

Вход запускает диагностику даже если 0242 остаётся failed и её fixedBy содержит незавершённую 0312; достаточно сохранённых валидных дерева/PR/change и отсутствия чужого процесса. Native-инструмент отдельно выполняет `git -C <дерево> rev-parse HEAD`, затем `node .matchlog/review-ci-runtime/review-ci.mjs --pr 177 --head <фактический SHA>`, затем чтения Git для сверки. Исходный SHA 96da9a63 — свидетельство дефекта, не константа допуска. Pending/failure/conflict при полноценном JSON подтверждают доставку, но не разрешают ready/merge. Недоступный GitHub либо расхождение идентичности записываются как конкретная ошибка приёмки, а не заменяются тестовыми ответами.

Владелец установки получает путь квитанции из stdout и проверяет результат конечного входа. После возобновления цикла новый gate переносит безопасное свидетельство в журнал 0312 и разрешает её штатное завершение. Обычный return-task 0242 затем проверяет returnTo, диагноз pipeline и completed **всех** fixedBy; отсутствие этих полей по-прежнему требует обычного разбора, но уже не мешает приёмке 0312. Сохранённые PR 177, ветка и OpenSpec 0242 остаются прежними. Будущий review 0242 заново подтверждает CI до diff и перед вливанием; диагностика их не заменяет.

При откате установки gate и квитанцию не объявлять успешными автоматически. Ошибки владения, native-инструмента и сохранения результата остаются видимыми владельцу установки, повтор без изменения условий не запускается. Новая карточка-дубликат 0242 и зависимость от вливания PR 177 не нужны.
