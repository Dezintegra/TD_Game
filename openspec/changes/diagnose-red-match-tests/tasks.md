## 1. Единый протокол обработки красного матчевого теста

- [x] 1.1 Обновить `supervisor/skills/revise.md` и `supervisor/skills/implement.md` одним атомарным коммитом (до 90 минут). В revise добавить именованный подпункт к разбору CI, в implement — к первому чтению CI; сохранить номера шагов. Описать классификацию assertion, запрет подгонки порога/окна, одну доказательную коррекцию с комментарием и запрет второй без нового релевантного замера с учётом истории. Описать заказ на исходной паре и отправленной ветке, переиспользование существующего run, завершение blocked с reason/result и названием заказа, новый анализ после результата. Согласовать вводные переходы и перечни исходов обоих файлов с этим исключением; добавить полные JSON-примеры отчёта по действующему контракту. Сохранить правила golden, обычного послевливательного прогона и запрет ожидания CI. Проверка: для каждого из девяти сценариев `specs/quality-gates/spec.md` указать в итоговом отчёте, какой пункт обоих скиллов задаёт нужный исход; прочитать примеры как JSON и сверить поля с `supervisor/lib/routing-contract.mjs`, `blockerReportProblem`/`planBlockers` из `supervisor/lib/blockers.mjs` и `taskFromRequest` из `supervisor/lib/requests.mjs`. Наблюдаемый результат: совпадающие requestKey/key, непустые категории и ожидание, исходная пара и ветка, нет зависимости диагностического run от родителя, нет обещания зелёного CI по одному заказу. Выполнить `npx prettier --check supervisor/skills/implement.md supervisor/skills/revise.md` и `openspec validate diagnose-red-match-tests --strict`. Отметить этот пункт выполненным вместе с рабочей правкой. В индекс добавить явным перечнем только два скилла и собственный `openspec/changes/diagnose-red-match-tests/tasks.md`; проверить пути и содержание через `git -C <дерево> diff --cached --name-only` и `git -C <дерево> diff --cached`, затем состав созданного коммита через `git -C <дерево> show --stat --oneline HEAD` и `git -C <дерево> show --format=fuller HEAD`. В tasks.md допустима только относящаяся к выполнению отметка; посторонние правки в разрешённых файлах недопустимы. Немедленно отправить коммит через `git -C <дерево> push` и открыть черновой PR штатным порядком implement.

Команды выполняются по одной из назначенного дерева; форма Git с `-C`, `npx prettier` и `openspec` покрыты `supervisor/config/stage-settings.json`. Prettier применяется к двум скиллам, не к OpenSpec. Матчи, арена, полный набор тестов, ожидание зелёного CI и архивация в этот шаг не входят. Временный файл тела PR ведётся и убирается штатным порядком implement и в коммит не добавляется.
