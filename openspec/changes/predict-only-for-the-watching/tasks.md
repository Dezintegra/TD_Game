# Задачи

Порядок продиктован одним: **сначала доказательство, что матч не меняется,
потом сама правка.** Иначе нечем будет отличить «предсказание выключено»
от «противник стал играть иначе», а различаются они не сразу.

## 1. Базовая линия

- [x] 1.1 Снять эталон, доказывающий, что матч не меняется.
      *Сделано иначе и лучше, чем задумано.* Отдельный файл с суммами
      оказался не нужен: сравнение вынесено в постоянный тест
      `packages/netplay/src/guest.predict.test.ts` — «выключенное
      предсказание не меняет ни команд, ни мира». Два участника живут
      одинаковой жизнью (12 кругов по три кадра плюс действие на каждом
      круге), после чего сверяются контрольные суммы подтверждённых
      миров и списки отправленных сообщений.
      *Проверка:* тест зелёный. Он сильнее файла с эталоном: файл
      проверяется один раз, тест — при каждом прогоне.
- [x] 1.2 Замерить нынешнюю цену пересборки у участника-компьютера.
      *Проверка:* p50 = 0,10 мс, p95 = 0,28, p99 = 0,48, максимум 1,9;
      5622 пересборки и 16 866 напрасных шагов за три минуты матча,
      0,41 % ядра. Числа в предложении.

## 2. Опция в `@td/netplay`

- [x] 2.1 Поле `predict?: boolean` в `MatchGuestOptions`, умолчание
      `true`. В комментарии записано, почему признак явный, а не выведен
      из отсутствия `onPredicted`: `predicted` читается и без подписки,
      и догадка связала бы две независимые вещи.
      *Проверка:* типы зелёные; существующие вызовы не тронуты. Тест
      «умолчание — предсказывать» стережёт значение по умолчанию:
      перевёрнутое однажды, оно отняло бы отзывчивость у клиента
      человека, и заметили бы это не сразу.
- [x] 2.2 При выключенном предсказании шагов не делается, `predicted`
      равен `confirmed`. Отдаётся он из геттера, а не из переменной:
      так это верно всегда, а не пока никто не добавил ветку без
      вызова `rebuild`. `onPredicted` вызывается по-прежнему.
      *Проверка:* тест «без предсказания шагов сверх подтверждённого
      тика нет» — тождество ссылок, а не равенство номеров.
- [x] 2.3 Тест на равенство матчей.
      *Проверка:* сверяются и контрольные суммы, и списки исходящих
      сообщений — то есть и мир, и команды.

## 3. Компьютер перестаёт предсказывать

- [x] 3.1 `predict: false` в `packages/bot/src/participant.ts`;
      комментарий переписан — он объяснял, почему предсказание не нужно,
      и был при этом объяснением работы, которая всё равно делалась.
      *Проверка:* `pnpm --filter @td/bot test` — 19 тестов зелёные,
      включая «два матча идут независимо и дают одно и то же».
- [x] 3.2 Сверка с эталоном.
      *Проверка:* `pnpm --filter @td/netplay test` — 53 теста зелёные,
      включая «матч целиком: три копии мира сходятся по контрольной
      сумме» и «участники получают одинаковые кадры».
- [x] 3.3 Перемерить цену и записать рядом с прежним числом.
      *Проверка:* на собранном коде снято 74–77 % работы гостя,
      0,6–0,8 % ядра; предсказание тождественно подтверждённому.
      Таблица трёх прогонов — в предложении. Устойчива здесь доля,
      а не миллисекунды: машина занята соседними сессиями.

## 4. Проверка живым матчем

- [ ] 4.1 Поднять сервер, сыграть матч с компьютером, убедиться,
      что противник ведёт себя как прежде: строит, копит, атакует,
      матч доходит до исхода.
      *Проверка:* матч завершается победой одной из сторон; в журнале
      сервера нет сообщений о расхождении.
      *Порты этой ветки:* `PORT=3131`, `CLIENT_PORT=5231`.
- [ ] 4.2 Проверить путь восстановления: разорвать связь компьютера
      посреди матча и убедиться, что служба поднимает нового дежурного,
      а идущий матч заканчивается по правилам (техническое поражение
      после отсрочки).
      *Проверка:* исход матча объявлен сервером, процесс не завис.
