## Why

Зелёный тест поведения не доказывает чувствительность к нарушению проверяемого свойства. Сейчас отдельного прогона такой чувствительности нет; `applyRuleTuning` позволяет вводить порчу до создания мира без пересборки каждой мутации.

## What Changes

- Ручной каталог мутаций и связей с точными именами существующих тестов, первоначально три пары.
- Последовательный исполнитель с нейтральным контролем, изоляцией процессов, подтверждением применения настройки и фактического выполнения теста.
- Раздельные результаты: detected, survived, uncovered, error. Ошибка запуска не считается обнаружением порчи.
- Отдельный ежедневный workflow и ручной запуск, сводка и артефакты; Issue поимённо перечисляет пережившие порчу проверки.

## Non-goals

Полное мутационное покрытие, генерация порчи исходников, запуск полного матчевого набора для каждой мутации, изменение игровых правил и исправление всех декоративных проверок. Не добавляем ночной прогон к обязательным проверкам каждого PR, не меняем балансную очередь и не записываем результаты в main. Не обещаем, что любые изменения скорости должны ломать любой тест движения: связь содержит конкретное нарушаемое свойство.

## Capabilities

### New Capabilities

Нет новых способностей.

### Modified Capabilities

- `quality-gates`: ADDED требования выборочного ночного контроля чувствительности тестов. Состав существующих проверок перед вливанием не меняется.

## Impact

Планируемые пути: `scripts/mutation/`, `.github/workflows/mutation.yml`, документация `docs/mutation-canaries.md`. Игровые тесты используются по текущим точным именам. Новые зависимости не требуются.

Отзывчивость интерфейса не меняется: исполнитель работает только на runner и не импортируется клиентом. Игровой сетевой трафик не меняется; добавляются только служебные загрузки артефактов и обращения к GitHub Issues.
