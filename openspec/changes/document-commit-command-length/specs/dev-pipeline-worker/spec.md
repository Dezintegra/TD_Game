## ADDED Requirements

### Requirement: Скиллы коммитящих этапов предупреждают о длине команды

Скиллы `supervisor/skills/design.md`, `supervisor/skills/implement.md` и `supervisor/skills/revise.md` SHALL рядом со своим образцом коммита называть приблизительный наблюдавшийся предел всей команды — около 965 байт — и диагностику `Command too long for parsing`. Они SHALL объяснять, что такой отказ происходит до запуска Git и добавлением правила в `stage-settings.json` не исправляется. Число MUST NOT выдаваться за точный гарантированный предел Git, оболочки или всех исполнителей; источник наблюдения и отсутствие новой проверки точной границы SHALL быть названы явно.

Каждый из трёх скиллов SHALL показывать короткий однострочный образец `git -C <дерево> commit` с заголовком и содержательным обоснованием через `-m`, сохраняя повторные `-m` для отдельных абзацев и запрет многострочной строки. Скиллы SHALL давать мерку «абзац в две-три короткие фразы, а не шесть» и пояснять, что мерка не гарантирует прохождение: длина включает путь, ключи, кавычки, заголовок и все абзацы, а байты не равны числу символов.

Скиллы SHALL направлять длинное «почему» в тело pull request, передаваемое файлом через `--body-file`, чтобы длинная проза не входила в командную строку. В коммите SHALL оставаться краткая причина изменения. Для design, где PR ещё нет, скилл SHALL предписывать сохранить подробности в `design.md` изменения для переноса в тело PR на implement. Скиллы MUST NOT предлагать длинный довод `--body` как замену длинному `-m` или объявлять тело PR безграничным: устраняется именно включение текста в разбираемую команду.

#### Scenario: Исполнитель читает любой из трёх скиллов

- **WHEN** исполнитель design, implement или revise дошёл до образца коммита
- **THEN** в этом же разделе он видит число около 965 байт, диагностику, объяснение отказа до Git и короткий образец с причиной изменения
- **AND** ему не требуется читать соседний скилл, чтобы узнать ограничение и замену

#### Scenario: Обоснование разрослось

- **WHEN** причина изменения требует нескольких длинных абзацев
- **THEN** инструкция оставляет краткую причину в коммите и направляет подробности в файл тела PR с передачей через `--body-file`
- **AND** число фраз не представлено гарантией прохождения команды

#### Scenario: На проработке ещё нет PR

- **WHEN** длинное обоснование появилось на этапе design
- **THEN** инструкция сохраняет его в `design.md` для будущего PR, не требует открывать PR на проработке и не теряет обоснование ради короткого коммита

#### Scenario: Предел прочли как точную гарантию

- **WHEN** читатель проверяет, обещает ли инструкция прохождение любой команды до 965 байт
- **THEN** текст явно называет число приблизительным наблюдением из задачи 0072 по отказам задачи 0043, без новой проверки точной границы и без универсальной гарантии
