# Задачи

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе. Кода
приложения изменение не заводит ни строки: правится `supervisor/` — таблица
переходов, разбор отчёта, разбор уборки, чтение git, скилл проработки
и README инструмента. Поэтому ни сборки, ни матчевых тестов, ни замеров
здесь нет, а проверки везде узкие и идут по своим файлам.

**Команды даны формой, покрытой правилами разрешений** — `git -C <дерево> …`,
где `<дерево>` — путь из поля `worktree` назначения. Голая приставка
покрыта не у всякой подкоманды, а `git -C:*` покрывает любую разом
(`supervisor/config/stage-settings.json:67`).

Нет `node_modules` в дереве — перед первым прогоном тестов
`pnpm install --frozen-lockfile`.

## 3. Научить уборку мерить содержимое ветки, а не наличие pull request

- [x] В `supervisor/lib/io.mjs` рядом с `unpushed` завести

${config.remote}/${config.mainBranch}..${branch}`. Команда не отработала —
      вернуть `null`. Комментарием сказать, зачем `--no-merges`: скилл
      проработки предписывает подтянуть свежую главную ветку в своё дерево,

      больше нуля → `fail` с числом коммитов; `null` → `fail`, потому что
      удаление необратимо и неизвестность толкуется в пользу сохранности.

## Чего в списке нет

- **Шага «дождаться зелёного CI» нет, и это нарочно.** Ожидание
  механизировано супервизором: он опрашивает проверки сам и сам двигает
  задачу из состояния `pr`, а исполняющей сессии караулить их запрещено.
  Отметка о таком пункте была бы новым коммитом, перезапускающим те самые
  проверки, чью зелень она фиксирует.
- **Прогона арены не заказывается.** Правила игры, цены, доход, сила юнита
  и темп не задеты ни одной строкой: правится `supervisor/`, то есть код
  вне пакетов монорепозитория.
- **Замеров кадров и стоимости тика нет** по той же причине: отрисовка
  и шаг мира не тронуты.
- **Правки правил разрешений нет.** Все команды списка покрыты:
  `PowerShell(git -C:*)`, `PowerShell(gh pr:*)`,
  `PowerShell(pnpm test:pipeline:*)`, `PowerShell(npx eslint:*)`,
  `PowerShell(npx prettier:*)`, `PowerShell(pnpm install:*)` — сверено
  чтением `supervisor/config/stage-settings.json`.
- **Схема задачи не правится.** Признака закрытия полем не заводится:
  уборка мерит содержимое ветки, а не то, как задача в неё попала.
- **Скиллы прочих этапов не правятся.** Исход `moot` применяется только
  к отчёту проработки, и объявлять его там, где он не сработает, значит
  обещать сессии несуществующий ход.
- **Архивации изменения нет.** Она переписывает `openspec/specs/`, её
  очередь задана зависимостями дельт, и решение принимает человек. Здесь
  важно одно: изменение архивируется **после** `agent-backlog-pipeline`,
  `backlog-candidates` и `supervise-the-pipeline`.
- **Сведения требований при архивации в списке тоже нет.** Три требования
  этого изменения уточняют уже принятые — «Уборка после успешного
  завершения», «Проработка ведётся через OpenSpec» и «Сессия выполняет ровно
  один переход состояния»; какое с каким и что с ними делать, сказано
  в разделе предложения о зависимостях. Работа эта делается в миг архивации,
  а не сейчас, и на неё поданы отдельные заявки.
