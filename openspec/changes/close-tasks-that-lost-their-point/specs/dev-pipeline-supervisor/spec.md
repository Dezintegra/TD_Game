## ADDED Requirements

### Requirement: Исход `moot` закрывает задачу, потерявшую предмет

Перечень исходов, с которыми сессия вправе завершиться, SHALL включать `moot` —
«предмет снят»: описанного в задаче дефекта нет, работа уже сделана чужим
изменением, либо правило, которое просят завести, действует.

Перечень этот **расширяется, а не заводится заново**. Действующая его редакция
стоит в требовании «Сессия выполняет ровно один переход состояния» (изменение
`supervise-the-pipeline`, способность `dev-pipeline-worker`), где сказано
«Состав отчёта не меняется» и названы четыре исхода — `done`, `rejected`,
`question`, `failed` — и состав отчёта без поля `evidence`. Здесь к тому же
перечню добавляется пятый исход, а к тому же составу — одно поле; прочие поля,
правило «отчёт возвращается последним сообщением» и терпимость разбора
к пояснительному тексту остаются нетронутыми. Двух составов отчёта в конвейере
быть MUST NOT.

Разбор отчёта SHALL вести задачу с исходом `moot` в состояние `cleanup`.
Записью перехода SHALL уходить в журнал причина, названная сессией, вместе
с доказательством: «Предмет снят: `<summary>`. Проверено: `<evidence>`».

Исход SHALL применяться только к отчёту этапа `design`. Отчёт с исходом `moot`
о любом другом этапе применён быть MUST NOT: задача останавливается разбором
с причиной, называющей этап. На аудите, имплементации, доработке, ревью
и выкладке работа уже сделана, и выбрасывать её решением сессии нельзя.

Исход SHALL применяться только к задаче, у которой не заведено ни изменения
OpenSpec, ни pull request. Задача с непустым `links.change` либо `links.pr`
по этому исходу закрыта быть MUST NOT: проработка, вернувшаяся из аудита
с замечаниями, обязана править заведённое изменение, а не объявлять предмет
снятым.

Отчёт с исходом `moot` SHALL содержать непустое поле `evidence` — где именно
проверено, что предмета нет: файл со строкой, номер влитого pull request,
идентификатор задачи, вывод команды. Отчёт без него применён быть MUST NOT:
заявленное без доказательства ходом не считается.

Отчёт, не прошедший любую из этих проверок, SHALL останавливать задачу
разбором, а содержимое отброшенного отчёта SHALL уходить в журнал: терять
работу сессии молча нельзя и здесь.

#### Scenario: Проработка вернула снятый предмет с доказательством

- **WHEN** отчёт этапа `design` объявляет исход `moot`, называет причину
  и в поле `evidence` — файл со строкой, где стоит уже действующее правило,
  а у задачи нет ни изменения, ни pull request
- **THEN** задача переходит в `cleanup`, а запись журнала называет и причину,
  и доказательство

#### Scenario: Снятый предмет заявлен без доказательства

- **WHEN** отчёт этапа `design` объявляет исход `moot`, но поля `evidence`
  в нём нет либо оно пусто
- **THEN** задача останавливается разбором с причиной «исход `moot` без
  доказательства», а отчёт целиком уходит в журнал

#### Scenario: Снятый предмет заявлен поверх сделанной работы

- **WHEN** отчёт этапа `design` объявляет исход `moot` у задачи, которой уже
  заведено изменение OpenSpec
- **THEN** задача останавливается разбором с причиной, называющей заведённое
  изменение, и в `cleanup` не переходит

#### Scenario: Снятый предмет заявлен с чужого этапа

- **WHEN** исход `moot` объявляет отчёт этапа `implement`
- **THEN** отчёт не применяется, задача останавливается разбором с причиной,
  называющей этап
