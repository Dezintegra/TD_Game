# add-authoritative-netplay

Матч переезжает на сервер: один мир, одно время, один судья. Компьютер
садится за тот же стол, что и человек, — со своим именем, своей комнатой
и своим соединением.

Раньше после старта матча сервер о нём не знал ничего: каждый браузер
считал свой мир, а за соперника в нём играл локальный компьютерный
противник. Двое, вышедшие из одной комнаты, получали одинаковую карту
и разные партии. Теперь сервер ведёт симуляцию, рассылает кадры команд
и объявляет исход, участники держат подтверждённую и предсказанную копии
мира, а задержка ввода одна на обоих и назначается по худшему из каналов.

**Порядок.** Второе изменение сетевой ветки, прямое продолжение
`add-player-lobbies`: то изменение выдало матчу идентификатор, seed
и стороны, это — заставило матч ими воспользоваться. Архивировать
после `add-player-lobbies`, `extract-ai-package` и `add-match-telemetry`:
дельты для `lobby`, `match-session` и `workspace-structure` написаны
от состояния спецификаций после них.

**Снято требование** «Матч из комнаты не притворяется сетевым» вместе
с жёлтой полосой в интерфейсе — то самое, которое само предписывало
своё снятие тем изменением, что введёт передачу команд по сети.

**Состояние:** реализовано, все задачи закрыты. `pnpm verify` зелёный
(622 юнит-теста в 48 файлах), `pnpm e2e` зелёный (17 сценариев, включая
матч двух браузеров с посимвольной сверкой контрольных сумм и матч
с компьютером). `packages/sim` не тронут ни строкой, эталон детерминизма
зелёный без правки числа.

**Что осталось человеку:** прогон на двух настоящих машинах через сеть.
Локальный канал не воспроизводит ни джиттер, ни потери, а именно они
двигают задержку ввода; подобранный запас на дрожание без такого прогона
остаётся предположением (см. Open Questions в дизайне).
