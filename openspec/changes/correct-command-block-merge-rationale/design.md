## Context

Проверено 07.09.2026 в назначенном дереве после `git -C . fetch origin` и `git -C . merge origin/main`: ответ `Already up to date.`, база `83f57f2`. PR 132 открыт, голова `e3fc602bd8f945c222ff798aa31b8b3da7731593`; его документы прочитаны через `git -C . show origin/worktree-0175-razmetit-komandnye-bloki-supervisor-skil:<путь>`. В main каталога `mark-every-command-block` нет. Это существующий дефект в открытой ветке, не снятый предмет.

В design.md ошибочны звено 3, итог о замкнутом круге, отказ от разметки отсутствующих строк и объяснение передачи конфликта ревью. В tasks.md ошибочно аналогичное объяснение в разделе 2; условная отметка о блоках валидатора описывает историческую базу. В proposal.md та же посылка стоит в Non-goals. Исправить только два упомянутых постановкой файла недостаточно: предложение осталось бы противоречащим решению.

## Goals / Non-Goals

Цель — согласованное объяснение факта покрытия, возможности обновления и сохранённого объёма задачи 0175. Не-цели перечислены в proposal.md: код, разрешения, действующие скиллы и остальные исторические недочёты не меняются.

## Decisions

### Покрытие определяется полной формой команды

`supervisor/config/stage-settings.json:52,67` содержит `Bash(git -C:*)` и `PowerShell(git -C:*)`; `$prefixNote` объясняет приставку, а запреты на force/reset/stash слияния не касаются. `supervisor/skills/design.md:68–91` уже предписывает fetch и merge с `-C` и отмену конфликтного слияния. Живой merge текущего этапа прошёл с кодом 0. Файл `supervisor/lib/permissions.mjs`, названный постановкой, в текущем main отсутствует; приписывать ему результат проверки этой сессии нельзя.

Исправленный текст должен прямо говорить: форма `git -C <дерево> merge origin/main` покрыта; голая `git merge origin/main` отдельным правилом не покрыта. Отсутствие перемотки при расхождении истории не запрещает слияние. Сам по себе собственный коммит тоже не доказывает невозможность fast-forward: нужны коммиты по обе стороны. Устаревший вывод о `pull --ff-only` уточняется именно условием расхождения.

Альтернатива расширить allow отвергнута: необходимая форма уже открыта. Альтернатива оставить вывод, заменив только названия команд, отвергнута: после merge отсутствовавшие строки становятся доступны правке.

### Сторож остаётся отдельной работой 0177

PR 126 на момент проверки открыт, голова `a8188ba9a81fb85b82114e693099bade87ea83ce`. `supervisor/config/shell.test.mjs` отсутствует в main, но есть в его удалённой ветке: функция `codeBlocks` уже разбирает ограждения попарно, а `bashMarkedBlocks` и `bashBodyForms` фильтруют только известные языки. Расширять этот общий разбор после вливания PR 126 предпочтительнее второго парсера и последующего сведения реализаций. На это и остаётся задача 0177 из назначения; новая карточка-дубликат не нужна.

Это технический выбор порядка и повторного использования, а не невозможность написать сторожа сейчас. Свежую main можно слить; она не приносит содержимое ещё открытого PR 126. Поэтому вывод «сторож неисправимо валил бы свой PR» отзывается, а отсрочка сохраняется с новым основанием. При вливании PR 126 до нашей реализации основание записывается исторически: работа выделена для расширения общего парсера после его доставки, ожидание уже выполнено.

Альтернатива включить сторожа в PR 132 технически осуществима, но потребовала бы отдельного разбора либо зависимости от незавершённого PR 126 и расширения согласованной текстовой задачи 0175. Альтернатива списка исключений сохраняет риск забытых блоков. Обе отвергнуты в пользу уже выделенной 0177; постоянного требования к новому тесту здесь не вводится.

### История не подменяет действующие правила этапа

Датированные номера баз, строк и выполненные отметки сохраняются с явным указанием, что это снимок 03.09.2026. Не отмечать задним числом разметку блоков, которой не было. Снять утверждение, что строки могут появиться только после пересоздания дерева: их приносит merge.

В месте про конфликт сохранить желаемое объединение содержимого команды из main и разметки powershell, но убрать запрет merge по разрешениям. Права конкретного этапа задаются действующим скиллом: design/audit отменяют конфликтное слияние и сообщают файл, ревью не обновляет базу само. Наличие разрешения на команду не даёт всем этапам права разбирать конфликт. Не переносить старую формулировку «человек или ревью» как универсальную инструкцию.

### Доставка после PR 132

Имплементация получает документы через main после вливания PR 132; чужую ветку не сливает и не редактирует. При архивации до начала правки выбирается единственная архивная копия. Если документов ещё нет, зависимый шаг не выполняется и успешный отчёт реализации не выдаётся. Предусловие должно быть передано супервизору с отчётом design.

## Risks / Trade-offs

- PR 132 меняется параллельно → перед реализацией сверить его вливание, освежить базу и перечитать три документа; уже исправленные места повторно не переписывать.
- Отсрочка оставляет пробел автоматической проверки → явно назвать существующую 0177 и повторное использование парсера после PR 126; не объявлять сторожа реализованным.
- Архивация перемещает цель → искать активную или архивную копию по имени, не создавать вторую.

## Migration Plan

Один атомарный текстовый коммит после появления цели в main, затем черновой PR собственной задачи. Откат этого коммита возвращает только прежние объяснения. Архивация собственного бездельтового изменения — позднее с `--skip-specs`, вне этапа design.

## Архитектурные ограничения

Геймплей, рассинхрон и реконнект не затрагиваются. Эталоны детерминизма и `PROTOCOL_VERSION` не меняются. Код ядра не пишется, поэтому `Math.random`, `Date.now` и числа с плавающей точкой в состоянии мира не появляются.
