# fix-saving-patience

Два числа профиля говорят об одном и том же и противоречат друг другу.
`savingHorizonSeconds: 45` разрешает **хотеть** покупку ценой в сорок пять
секунд дохода. `maxWaitDecisions: 8` разрешает **копить** на неё восемь
решений, то есть четыре секунды. Накопление обрывается на порядок раньше,
чем окупается, и деньги утекают на то, что подвернулось.

Замер на 24 зеркальных матчах (seed 3000–3023, код `62ec9682`, дерево
чистое) — предел терпения приведён в соответствие с горизонтом, больше
ничего не менялось:

| Величина                | Сейчас  | С исправленным терпением |
| ----------------------- | ------- | ------------------------ |
| ничьих по времени       | 20 из 24 | **4 из 24**             |
| средняя длительность    | 1117 с  | **726 с**                |
| снято с базы за матч    | 17,3%   | **58,4%**                |
| доход в конце матча     | 14,65   | **27,79**                |

726 секунд — это `MATCH_TARGET_SECONDS`, длительность, на которую
рассчитан весь баланс. Матч впервые попадает в неё сам.

**Складывается с `fix-ai-spending`.** Снятие неприкосновенного запаса
поверх исправленного терпения даёт 2 ничьих из 24, матч в 563 секунды
и всего 9,5 смерти генерала за матч против нынешних 30,6. Порядок важен:
то же снятие запаса **без** этой правки поднимает долю ничьих с 83%
до 92%. Запас вреден только тогда, когда накопления доходят до покупки.

**Почему это отдельное изменение.** Оно меняет одно число и даёт самый
большой сдвиг из всех проверенных. Смешивать его с чем-либо нельзя:
любая другая правка на этом фоне станет неизмеримой.

**Что этот замер отменяет.** Гипотезу о перевесе обороны над
наступлением. Долю ничьих в 62% давал не баланс, а утечка накоплений;
проверенные «улучшения» экономики (снятый запас, экономика во главе
списка, принудительная осада, вчетверо большее войско) поднимали её
до 92–100%, потому что чинили не то.
