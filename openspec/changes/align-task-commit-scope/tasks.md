## 1. Согласовать ограничения состава с отметкой выполнения

- [ ] 1.1 В `supervisor/skills/design.md`, внутри раздела составления `tasks.md`, добавить правило: ограничения добавляемых путей и проверки состава коммита учитывают рабочую правку вместе с обязательной отметкой выполненного пункта в собственном `tasks.md`; добавление остаётся явным перечнем, посторонние пути и несвязанные изменения в разрешённых файлах запрещены. Для исключения временных артефактов требовать отсутствие конкретных путей в индексе и коммите, отдельно назвать пустышку пробы и её архивированную копию; не заменять проверку подсчётом всех файлов. Соседние правила и нумерацию этапов сохранить. Оценка: до 1 часа, один самостоятельно проверяемый коммит.

  **Проверка содержания:** прочитать новую инструкцию вместе с циклом выполнения пунктов в `supervisor/skills/implement.md`; каждый случай таблицы «Проверка по сценариям» в `design.md` должен получить указанный результат. Отдельно убедиться, что обязательную отметку нельзя пропустить, а её наличие не разрешает постороннюю правку. Исторический `probe-the-deltaless-archive/tasks.md` используется только для чтения; повторная проба и её файлы не создаются.

  **Проверки реализации:** `npx prettier --check supervisor/skills/design.md`, `pnpm test:pipeline`, `openspec validate align-task-commit-scope --strict`. Команды вызываются по отдельности из назначенного рабочего дерева; формы покрыты `supervisor/config/stage-settings.json` (`PowerShell(npx prettier:*)`, `PowerShell(pnpm test:pipeline:*)`, `PowerShell(openspec:*)`). Это проверки этапа реализации, проработка их не запускает, кроме валидации своих артефактов.

  **Состав коммита:** после успешных проверок отметить этот пункт и добавить пути явно: `git -C <дерево> add -- supervisor/skills/design.md openspec/changes/align-task-commit-scope/tasks.md`. Проверить `git -C <дерево> diff --cached --name-only` и `git -C <дерево> diff --cached`: допустимы только правка инструкции по этому пункту и его отметка выполнения. Никакие временные или посторонние пути не допускаются; количество файлов не служит проверкой. После создания коммита сверить `git -C <дерево> show --format= --name-only HEAD` и `git -C <дерево> show --format= HEAD` с тем же разрешённым составом и содержанием. Форма Git покрыта `PowerShell(git -C:*)`.

  **Доставка:** немедленно отправить коммит `git -C <дерево> push -u origin HEAD` и открыть черновой pull request по правилам имплементации. Этот единственный пункт уже даёт полный проверяемый результат для PR; ожидание CI не является работой исполняющей сессии или пунктом списка задач.
