# Список задач

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе.

## 1. Шаг множителя умеет обе модели роста

- [ ] В `packages/shared/src/percent.ts` завести тип `GrowthModel`
      (`'geometric' | 'linear'`) и функцию `stepPpm(множитель, процент,
      модель)`: умножение при геометрической модели, прибавка
      `процент × PPM_ONE / 100` при линейной.
- [ ] Там же — `linearPpm(процент, шагов)` рядом с `compoundPpm`:
      множитель после нескольких линейных шагов, нужен восстановлению
      состояния и тестам.
- [ ] Тесты в `percent.test.ts`: линейный шаг даёт прямую, геометрический
      совпадает с прежним `growPpm`, ноль процентов не двигает множитель.

## 2. Ветка прокачки объявляет свою модель роста

- [ ] В `packages/shared/src/balance.ts` добавить `UpgradeBranch`
      необязательные `costModel` и `effectModel` с умолчанием
      «геометрическая», объяснив умолчание рядом с объявлением.
- [ ] Пересобирать `UPGRADE_BRANCHES` в обработчике
      `onRuleTuningApplied`, сохраняя порядок и длину таблицы.
- [ ] Тест в `balance.test.ts`: без настройки таблица прежняя, порядок
      и длина не изменились.

## 3. Покупка уровня шагает по модели ветки

- [ ] В `packages/sim/src/apply.ts` заменить оба `growPpm` на `stepPpm`
      с моделью ветки.
- [ ] Тест: при линейной модели цены третий уровень стоит ровно
      `база × (1 + процент × 2 / 100)`, при геометрической — как прежде.

## 4. Настройка правил принимает ручки экономики

- [ ] В `packages/shared/src/rules.ts` добавить `incomeEffectPercent`,
      `incomeEffectModel`, `incomeCostPercent`, `incomeCostModel`,
      `incomeBaseCost` с задуманными умолчаниями.
- [ ] Разложить проверку значений на три рода (множители, проценты,
      модели) таблицей ключей.
- [ ] Тесты в `rules.test.ts`: умолчания нейтральны, отрицательный
      процент отвергнут, неизвестная модель отвергнута, нулевой процент
      принят.

## 5. Арена даёт ручки командной строкой

- [ ] В `apps/arena/src/tuning-flags.ts` разделить ключи на числовые
      и ключи-слова, добавить новые.
- [ ] В `apps/arena/src/main.ts` научить `tuningOf` и `tuningArgs`
      обоим родам, дополнить `USAGE`.
- [ ] Проверить передачу дочерним процессам прогоном с `--jobs 2`.

## 6. Замер

- [ ] Прогнать перебор моделей всеми парами профилей, свести итоги.
- [ ] Ответ владельцу продукта: есть ли у компьютера директива считать
      необходимость прокачки экономики.
