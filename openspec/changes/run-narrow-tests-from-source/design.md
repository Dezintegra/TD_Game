## Context

`packages/shared/package.json` и `packages/sim/package.json` экспортируют dist; install его не создаёт. `turbo.json` готовит `^build` для пакетных тестов. Узкая команда из корня обходит этот граф, но попадает в `vitest.workspace.ts`: простая подмена `--config` не гарантирует изоляции (это уже объяснено в `scripts/vitest.config.ts`). Версия в package.json — Vitest 2.1.8; решение не должно опираться на проекты Vitest 3.

`scripts/mutation/vitest.config.ts` уже вычисляет корень от import.meta.url и направляет shared/sim на src/index.ts. Там же находятся специфичные descriptor, @vitest/runner, setup/reporter, таймауты и последовательность hooks. Перенос всего файла в обычный маршрут изменил бы смысл проверки.

Сохранённый `origin/worktree-0013-unit-radius-plus-25:openspec/changes/increase-unit-spacing/tasks.md` предписывает временный `.matchlog/0013-*.mjs` и прямые golden-команды. Все три игровых пункта открыты; ни один этим ремонтом выполненным не считается. PR 265 сохраняется.

## Goals / Non-Goals

Цель — один проверяемый маршрут без dist, пригодный для повседневных узких проверок и восстановления 0013. Границы — proposal.md: без игры, пересъёмки golden, общего сторожа установки 0305 и перехвата чужой задачи.

## Decisions

### 1. Переиспользовать алиасы, отделить запуск от mutation

Создать `scripts/testing/source-aliases.mjs`: вычислять корень от расположения модуля, экспортировать точные алиасы @td/shared и @td/sim на src/index.ts. Обе конфигурации используют этот модуль. Точное совпадение имён не должно случайно переписывать неподдержанные subpath imports. Сохранить в mutation-конфигурации @vitest/runner, чтение descriptor, setupFiles/reporters и остальные настройки. Проверить сохранение выбранного mutation-файла и изоляцию от обычного маршрута.

Альтернативы: отдельные копии алиасов разойдутся; наследование mutation-конфига внесёт скрытую настройку правил; предварительная сборка shared/sim возможна технически, но создаёт дополнительную подготовку и риск устаревшего dist. Изменение exports на TypeScript затронет Node-потребителей вне тестов. Поэтому выбрать алиасы только для нового маршрута.

### 2. Тонкий запускатель с явным выбором

Публичная команда — `node scripts/test-source.mjs --environment node <файлы от корня>`. Тонкий CLI использует `scripts/testing/source-runner.mjs` и `scripts/testing/vitest.source.config.ts`. Поддерживаются конкретные существующие `packages/shared/src/**/*.test.ts`, `packages/sim/src/**/*.test.ts`, `packages/ai/src/**/*.test.ts`. Из матчевых файлов в этот ограниченный маршрут допускаются ровно два golden из матрицы ниже; остальные матчевые тесты остаются штатному CI. jsdom допускается для sim; смешанный список shared/sim в node допустим. Пустой список, каталог, glob, выход за корень, дубликаты и неизвестные ключи отвергаются до запуска.

CLI запускает локально установленный Vitest дочерним Node-процессом с shell:false, явными cwd/root/config, одним worker и fileParallelism:false. Корень теста — каталог `scripts/testing`, где нет корневого workspace; include содержит абсолютные нормализованные пути только выбранных файлов. Конфигурация получает валидированный список через окружение дочернего процесса, а не через временный файл или присваивания PowerShell. Отсутствие списка → ошибка конфигурации, а не выбор всего репозитория. Корень исходников остаётся вычисленным от модуля, а cwd родителя сверяется с корнем проекта. Передача произвольного конфига/команды запрещена интерфейсом.

Результат Vitest получать штатным JSON reporter в уникальном каталоге своего `.matchlog/source-test-*`; обычный человекочитаемый вывод сохранить. Разобрать фактически выполненные assertion results, не только число collected: в каждом выбранном файле есть хотя бы один выполненный тест, ни одного лишнего файла, нет failed/unhandled errors. Ошибка процесса, сигнал, таймаут, невалидный/отсутствующий отчёт — неуспех. Отчёт сохраняет repoRoot, список запроса, окружение, фактические пути, passed/failed/skipped и диагностику. Один invocation — один свежий процесс без Turbo-кеша. Технический верхний таймаут ограничивает зависание; assertions и окна сценариев не менять.

Не выбирать прямой корневой `npx vitest run`: он уже подхватил workspace. Не ограничиваться строкой exit code 0: она не доказывает полноту выбора. Не вводить универсальную обёртку произвольных команд или новую систему тестирования.

### 3. Два уровня регрессии

Быстрый `scripts/testing/source-runner.test.mjs` проверяет отказы выбора, состав и счётчики JSON, ошибки процессов, отсутствие mutation-настроек. Небольшая отдельная установленная fixture-копия реальной оснастки с контролируемыми shared/sim экспортами и тестом потребителя доказывает настоящий импорт и видимость изменения каждого экспорта новым процессом. Не подменять этой fixture приёмку игровых файлов.

Живая матрица в `scripts/testing/check-source-tests.mjs` выполняет ровно:

| Выбор | Окружение |
| --- | --- |
| crowd.test.ts + step.test.ts | node |
| crowd.test.ts + step.test.ts | jsdom |
| determinism.golden.match.test.ts | node |
| determinism.golden.match.test.ts | jsdom |
| profile.golden.match.test.ts | node |

Все пути — под packages/sim/src, кроме profile под packages/ai/src. Число тестов берётся из текущих файлов: исторические 107 shared не считаются доказательством sim. Каждый файл обязателен, полный матчевый набор запрещён.

Локальный режим `--fresh` использует существующий `checkInstallSnapshot` из `supervisor/lib/install-snapshot-check.mjs`: чистый отправленный HEAD → новая Git-копия внутри своего .matchlog → настоящая установка с локальным store. Переиспользовать его результат snapshot и проверки путей, не менять его контракт и не создавать дополнительное связанное worktree. Все пять запусков происходят оснасткой внутри snapshot. До/после проверять отсутствие packages/shared/dist, packages/sim/dist, packages/ai/dist. Копии/результаты остаются только в своём .matchlog, установка и тесты не трогают исходное дерево.

После успешной матрицы доказать чтение реальных исходников отдельными отрицательными контролями в копии: временно вставить однозначную ошибку импорта в shared/src/index.ts и вызвать crowd, восстановить и подтвердить успех; затем аналогично sim/src/index.ts и вызвать профильный golden ai, восстановить и подтвердить успех. Называть именно ожидаемый маркер ошибки, а не любую красноту. Восстановление в finally по сохранённым байтам; контрольные ошибки и копии никогда не коммитить. Контроль дополнен fixture-тестом изменения значения экспорта, чтобы ошибка загрузки не была единственным доказательством зависимости.

Режим `--installed` предназначен для свежего CI checkout после install: проверяет отсутствие dist, выполняет ту же матрицу; контрольные изменения выполняются только в созданной принадлежащей ему копии, не в CI checkout. CI подключить отдельной job с checkout/install и без build/cache dist. Не вкладывать дорогую матрицу в обычный `test:scripts`: быстрые тесты оснастки остаются быстрыми. Job работает для изменения оснастки и её потребителей и даёт отдельный результат; простой безопасный вариант — запускать на каждом PR, последующее сужение путей не входит в ремонт.

CI checkout может иметь detached HEAD без upstream, поэтому `--installed` не вызывает требующий upstream `checkInstallSnapshot`. Для контрольной копии он использует `git -C <checkout> archive` конкретного HEAD в уникальном подкаталоге .matchlog, проверяет containment/чистоту и ставит её собственные зависимости через переиспользуемые `findPnpm`/`checkedProcess`. Новая копия содержит собственные исходники и оснастку; node_modules не подменяются ссылкой на родителя. Проверяется SHA checkout и неизменность его отслеживаемых файлов. Этот путь покрыть тестом detached HEAD; не ослаблять предусловия существующей проверки установки ради CI. Создание копии и установка нужны до отрицательных контролей, полную успешную матрицу второй раз в этой контрольной копии не повторять.

### 4. Инструкции и доставка разрешений

Согласовать CLAUDE.md (установка и локальные проверки), docs/agent-setup.md, supervisor/skills/implement.md, revise.md, design.md. Для shared/sim/ai использовать новый маршрут; пример `npx vitest` сохранить только с объяснённым применимым корнем для scripts/supervisor/других пакетов. В revise установка нужна также при отсутствии node_modules, не только изменённом lockfile. Отдельные golden явно разрешены планом, это не разрешение полного match.

В stage-settings добавить только `PowerShell(node scripts/test-source.mjs:*)` и точные формы `PowerShell(node scripts/testing/check-source-tests.mjs --fresh)` / `--installed` для пробы. CLI ограничивает аргументы, широкое `node scripts/*` не нужно. Сторож проверяет новые команды и сохранение запрета полных наборов. Изменение settings в ветке ещё не означает доставку запущенной сессии: до вливания запуск доступен через предписанный репозиторием `.matchlog`-скрипт, импортирующий публичную функцию того же runner/checker с теми же аргументами. Это только переходник вызова, никаких алиасов или временной конфигурации; путь и результат указать в отчёте. Если среда отказывает и этому разрешённому способу — сообщить отказ, не объявлять пробу состоявшейся.

### 5. Передача 0013 и подтверждение исходного implement

Доставить `docs/narrow-source-tests.md` с командами ниже и точной процедурой для 0013. Исполнитель 0337 не правит ветку или PR 265. После вливания ремонта супервизор/разбор исходного инцидента допускает пробу исходного implement по существующему контракту; не создаём второй механизм возврата или новую карточку на ту же причину. Передачу зафиксировать в отчёте 0337, а обязанность пробы — адресным amendments к существующей 0013, без смены её статуса.

В назначении 0013 исполнитель получает реальный incidentId, проверяет PR 265 и свою ветку, обновляет базу обычным порядком, устанавливает зависимости, читает доставленную памятку. Удаляет только свою временную подготовку из design/tasks и заменяет все прямые sim/ai-команды (пункты 1.1, 2.1, 3.1 и раздел передачи), сохранив требования, состав сценариев и отметки. Старые временные файлы больше не используются; чужие файлы не удаляются. Отдельная служебная отметка подготовки не закрывает игровые пункты.

Применимые команды из корня 0013 после доставки оснастки:

```powershell
pnpm install --frozen-lockfile --prefer-offline
node scripts/test-source.mjs --environment node packages/shared/src/rules.test.ts packages/shared/src/balance.test.ts packages/sim/src/crowd.test.ts packages/sim/src/step.test.ts
node scripts/test-source.mjs --environment jsdom packages/sim/src/crowd.test.ts packages/sim/src/step.test.ts
node scripts/test-source.mjs --environment node packages/sim/src/determinism.golden.match.test.ts
node scripts/test-source.mjs --environment jsdom packages/sim/src/determinism.golden.match.test.ts
node scripts/test-source.mjs --environment node packages/ai/src/profile.golden.match.test.ts
```

Для 2.1 — отдельные node/jsdom-вызовы с step.test.ts и navigation.test.ts; для 3.1 — с crowd.test.ts и step.test.ts. Сверить реальные результаты, пути своего дерева и ненулевые счётчики. Если правила уже изменены и golden отличается, это не оправдывает ошибку загрузки: игровые ожидаемые значения сверяет исходный implement, обновляет по совокупным правилам и коммитит вместе с изменением радиуса. Служебный ремонт не меняет golden ради зелени. Объяснения и неизменившиеся значения обоих эталонов сохраняются.

Результат пробы исходного implement — `incidentVerification: {incidentId, passed, evidence}` с фактическим идентификатором из назначения, SHA ремонта и головы 0013, командами, путями отчётов, числами тестов и диагностикой. Без идентификатора не выдумывать его: исходному разбору требуется восстановить связку инцидента. Вливание 0337 само по себе не даёт passed; если проба не удалась, новый диагноз опирается на новый лог. Оставшаяся игровая реализация идёт штатно после подтверждения восстановления. Проба не является неотмечаемым пунктом tasks.md служебной задачи.

## Risks / Trade-offs

- Общая конфигурация может обнаружить регрессию самой игры → сохранять ошибку assertions, не менять эталоны в 0337; отличие от ошибки загрузки подтверждать логом.
- Повторные golden стоят времени → матрица последовательная, один worker, только два явно названных файла; проверки производительности/арена не запускаются.
- Вложенная копия может разрешить сторонние зависимости вверх → install обязателен внутри неё, shared/sim разрешаются от собственной оснастки; отрицательные контроли доказывают именно этот маршрут. Общая проверка package links остаётся 0305.
- Существующая mutation оснастка может зависеть от @vitest/runner → этот alias и mutation hooks остаются на прежнем месте, проверяются отдельно.
- Изменение общего helper не участвует в Turbo-задачах нового маршрута → кеш здесь не используется. Пакетные test-конфиги и Turbo остаются прежними, их inputs менять не требуется.

## Migration Plan

Сначала рабочая оснастка с быстрыми тестами и draft PR, затем живая регрессия и CI, затем инструкции/покрытие разрешений, затем локальная проба свежего snapshot и запись доказательств. После доставки исходный implement применяет памятку и подтверждает инцидент. Откат служебного PR возвращает прежний маршрут и требует считать восстановление недоказанным; он не меняет состояние мира.

Игровые правила, протокол и состояние мира не меняются: PROTOCOL_VERSION не растёт, golden в 0337 не переснимаются; Math.random/Date/float в ядро не добавляются. Рассинхрон, реконнект и визуальный отклик остаются прежними, поскольку оснастка не входит в runtime.
