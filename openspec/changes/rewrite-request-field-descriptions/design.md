## Context

Сверка выполнена после `git -C . fetch origin` и `git -C . merge origin/main`; база `48d6c25`, ответ слияния — `Already up to date.`. Повреждены описания в triage:365–375, implement:527, review:493–501, audit:440–449, revise:520–528. В deploy:638–647 разметка исправна. Номера служат указателями снимка, искать при реализации следует поле `requests`.

`taskFromRequest` принимает `feature`, `run`, `note`; требует непустые заголовок и описание; для `run` требует непустой `run.expectation`. Нецелый или отсутствующий приоритет заменяется на 50, целый ограничивается диапазоном 0–999. Объект `run` переносится в задачу только при соответствующем типе; допустимые виды — `arena`, `perf`, `bench-tick`, по умолчанию `arena`, параметры по умолчанию — пустой объект. У других типов переданный `run`, включая `null`, не используется. Ограничение triage до двух типов установлено самим скиллом:219–221, а не этой функцией.

## Goals / Non-Goals

Цель — читаемое и непротиворечивое описание действующего контракта в пяти повреждённых местах, подтверждённое сверкой шестого. Границы работы перечислены в Non-goals предложения; изменение поведения обработчика и общая защита Markdown в эту правку не входят.

## Decisions

1. Переписать абзацы по смыслу целиком. Простая расстановка пробелов оставила бы повторения и ошибочное разрешение `note` в triage. Для обычных этапов базовый смысл: «Заявки на новые задачи — массив объектов с полями `type`, `title`, `description` и `priority`. Тип — `feature`, `run` или `note`. Заголовок и описание непустые; описание понятно без текущего разговора. Приоритет — целое число, меньшее берётся раньше; по умолчанию 50. Для типа `run` передай объект `run` с полями `kind`, `params`, `expectation`; ожидаемый результат обязателен и не может быть пустым». Это ориентир редакции, а не общий шаблонизатор.
2. В triage заменить перечень типов на «На этом этапе разрешены только `feature` и `run`; заявки типа `note` запрещены, чтобы разбор не порождал новый разбор». В остальных файлах сохранить три типа. Альтернатива — удалить `note` везде — меняет права этапов и расходится с кодом и примером revise, поэтому отвергнута.
3. Убрать дубли о типах, приоритете и `run` в audit, triage и revise. Не называть `run: null` ошибкой у обычной заявки: revise уже показывает такой пример, код поле игнорирует. Сформулировать «Объект `run` заполняется только для прогона; для остальных типов поле можно опустить или оставить `null`». Не утверждать, что обработчик отвергает неизвестный `kind` или нецелый приоритет: для них есть значения по умолчанию.
4. Сохранить локальное окружение текста: таблицу implement; самодостаточное описание в audit; пустой массив в triage, implement и revise; допустимое отсутствие поля в review и deploy; назначение заявок на замеры в review/deploy; связь с исходной задачей и соседнее описание `area`. В triage сохранить перечисление видов прогона. Исправный deploy достаточно прочитать и отметить результат в отчёте реализации. Переписывать весь раздел отчёта ради одинакового оформления не нужно.
5. Короткие вставки кода держать целиком на одной строке исходника, пробелы ставить снаружи обратных кавычек, продолжение маркированного пункта сохранять вложенным. Длинную вставку с объектом можно заменить перечислением отдельных полей. Таблица implement должна остаться корректной таблицей. Вводить тест на точный текст нецелесообразно: проверка здесь — содержательное чтение, а общий сторож разметки относится к 0187.

## Risks / Trade-offs

- Обобщение запрета triage на весь конвейер → проверять типы отдельно для каждого этапа по таблице ниже.
- Потеря полезных соседних пояснений при удалении повреждённого текста → ограничить diff описанием поля и прочитать его вместе с соседними пунктами.
- Слияние с правкой 0187 в тех же строках → при реализации освежить базу по правилам этапа, сохранить защиту Markdown соседа и повторить чтение окончательного текста. Архивационной зависимости нет.

## Migration Plan

Один коммит реализации с правками текста и отметкой tasks, немедленная отправка и открытие чернового PR по правилам implement. Миграция данных и изменение формата отчёта не нужны; откат возвращает только документацию. Проверки игры, замеры, обновление эталонов детерминизма и рост `PROTOCOL_VERSION` не требуются. Код sim не затронут: ограничения на `Math.random`, `Date.now` и float в состоянии мира сохраняются; поведение при рассинхроне и переподключении не меняется.
