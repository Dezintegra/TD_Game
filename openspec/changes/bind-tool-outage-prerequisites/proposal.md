## Why

Повтор 0244 уже расходовал сессию до появления необходимых механизмов PR 172 и 177. Постановка 0246 и запись 0245 требуют закрепить оба предусловия на существующей карточке, чтобы планировщик мог удерживать последующие старты и продолжения.

## What Changes

- После поставки адресного канала 0242 супервизор получает одно поручение дополнить 0244 зависимостями 0233/PR 172 и 0242/PR 177.
- Сохраняются остальные зависимости, состояние, счётчики и выполненная работа; независимое чтение подтверждает сохранённые условия.
- Свидетельства записи и проверки допуска разделяются: наличие условий не доказывает вливание PR и не возвращает карточку из `awaiting-po`.

## Non-goals

Не реализовывать повторно 0242, не менять алгоритм зависимостей, не править доску исполнителем, не прерывать живую сессию, не возвращать 0244 в работу принудительно. Не исправлять 0244 или доставку отчётов 0233; связь 0238 → 0233 остаётся в 0241. Не добавлять общие требования ради единичной операции.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Применяется существующая `card-dependencies` и её открытые дельты.

## Impact

Изменяются только данные зависимостей одной карточки через супервизор и доказательства выполнения в каталоге этого изменения. Исходный код, схемы и зависимости npm не меняются. На отзывчивость игрового интерфейса и игровой сетевой трафик влияния нет: операция не входит в игру. Служебный трафик — штатные чтения/запись Trello и чтение свидетельств GitHub существующим каналом, без нового опроса.

Исполнение зависит от поставки `append-addressed-card-dependencies` (0242, PR 177) на активные супервизоры. PR 172 не является условием самой записи: его невлитость должна удерживать 0244 уже после записи. Семантика результата берётся из `require-merged-pr-for-dependencies`. Изменение без дельт не зависит от порядка переноса требований и архивируется человеком с `--skip-specs`; зависимости архивации отсутствуют.

## Почему дельты нет

Это применение уже согласованных правил к одной карточке, без изменения прочтения любого требования основы или открытой дельты:

- `card-dependencies / Explicit prerequisite metadata`: сохраняется контракт `dependsOn`; одноразовое заполнение не меняет его. Одноимённая MODIFIED-дельта `require-merged-pr-for-dependencies` уже определяет `dependencyResults`.
- `Gate task launches on completion` в основе и указанной дельте: все предшественники закрыты, ожидаемые PR доказаны влитыми, ожидание не расходует попытки, живой процесс сохраняется — применяем без исключений.
- `Explicit decomposition lineage` и `Completion includes all decomposition descendants` основы: состав частей и порядок проверки закрытия не меняются; закрытие предшественников учитывает их потомков.
- `Result evidence is read without worker sessions` дельты `require-merged-pr-for-dependencies`: доказательства по-прежнему собирает супервизор; номер в поручении не является доказательством вливания.
- `Stage reports can address dependency additions`, `Dependency additions preserve current card data`, `Dependency writes require independent confirmation` дельты `append-addressed-card-dependencies`: используется точный контракт дополнения, объединения и независимого подтверждения; новый канал не добавляется.

Ни `confirm-stage-tool-outages`, ни другие открытые дельты не правятся: предусловия его tasks.md исполняются существующим механизмом. Каталог `specs/` отсутствует намеренно.
