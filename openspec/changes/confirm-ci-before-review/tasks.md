## Правила состава и проверки

Каждый пункт включает только названные рабочие файлы и собственную отметку в `openspec/changes/confirm-ci-before-review/tasks.md`. Все пути добавлять явным перечнем через `git -C <дерево> add -- <пути>`; длинный перечень разбивать на отдельные вызовы add. Путь fixture `supervisor/lib/testing/ci-pr-219.json` используется только для чтения; генерацию контрольных вариантов делать в памяти теста, исторический снимок не переписывать.

Перед коммитом проверить имена и содержание: `git -C <дерево> diff --cached --name-only` и `git -C <дерево> diff --cached`. После коммита проверить `git -C <дерево> show --format=fuller --stat HEAD` и `git -C <дерево> show --format= --patch HEAD`, затем сразу `git -C <дерево> push`. Допуск tasks.md не разрешает несвязанные правки в нём или других разрешённых файлах. В шаге 1.1 дополнительно разрешены только два явно названных файла `keep-ci-waiting-out-of-tasks` и только адресное согласование источника CI по решению 4 design.md; во втором шаге они не меняются. Код 0297, остальные чужие артефакты OpenSpec (включая tasks.md соседа), основные спецификации, доска и архивы не входят в состав этих шагов.

Проверить артефакты по имени: `openspec validate confirm-ci-before-review --strict` и `openspec status --change confirm-ci-before-review`. Статус planning не означает выполнения пунктов реализации. Полный pnpm verify, тесты игры, замеры и арена не требуются; ожидание CI ведёт супервизор. Автоматические транспортные тесты и статическое покрытие разрешений не объявлять живым результатом GitHub или запущенной сессией review.
