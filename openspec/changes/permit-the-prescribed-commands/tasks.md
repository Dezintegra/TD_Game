# Шаги реализации

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе.
Порядок не случаен: правки идут перед сторожем, который их стережёт, иначе
коммит со сторожем оказался бы красным сам по себе.

Узкие проверки гоняются по своим файлам: `npx vitest run --root plugins/pipeline`
и `npx prettier --check <свои файлы>`. Полный набор — дело CI.

## 1. Разрешить установку зависимостей

- [ ] В `plugins/pipeline/config/stage-settings.json` добавить
      `Bash(pnpm install:*)` и `PowerShell(pnpm install:*)`.
- [ ] Рядом завести `$pnpmNote`: почему именно `pnpm install`, а не `pnpm:*`
      — полный набор проверок, матчевый набор и арена запрещены скиллам
      словами, и правило `pnpm:*` сняло бы этот запрет молча. Назвать дату
      и место отказа (01.09.2026, задача 0043, `cycle.log:12736–12738`):
      заметка без следа через месяц читается как вкусовщина.

**Проверка:** `npx vitest run --root plugins/pipeline` зелёный (файл
разбирается как JSON, стоящие сторожа формы правил не покраснели).

**После этого шага открывается черновой pull request** — до него отправки
в ветку не запускают ни одной проверки CI.

## 2. Убрать форму `@{u}` из правил этапов

- [ ] Заменить её на `git -C <дерево> status -sb` в четырёх местах:
      `implement.md:72` и `:199`, `revise.md:194`, `audit.md:69`.
- [ ] Там, где нужен поимённый список коммитов (`implement.md:72` —
      разбор прерванного этапа), добавить
      `git -C <дерево> log --oneline origin/<ветка>..HEAD` и сказать, что
      имя ветки приходит в назначении полем `branch`.
- [ ] Записать в каждом из четырёх мест одной фразой, **почему** форма
      заменена: `@{u}` отказывается при стоящем правиле на приставку
      `git log`, подтверждено `cycle.log:11299` и `cycle.log:12735`.
      Без этой фразы форму вернут обратно как более короткую.

**Проверка:** поиск по `plugins/pipeline/skills/` не находит `@{u}`;
`npx prettier --check plugins/pipeline/skills/*.md` зелёный.

## 3. Сказать про приставку общо, а не одним примером

- [ ] В каждом скилле, где стоит абзац «Звать средства полным путём»,
      превратить его в общее утверждение: правило сверяется с приставкой,
      и приставку меняют — ключ перед именем средства (`npx --yes …`),
      версия через `@` (`prettier@3`), полный путь, присваивание
      переменной окружения перед командой, склейка команд.
- [ ] Примеры оставить иллюстрациями после утверждения, а не вместо него.
      Назвать случай 0043: разрешённое `npx prettier` было позвано как
      `npx --yes prettier@3 --check` и отказано (`cycle.log:12739`).

**Проверка:** в каждом файле `plugins/pipeline/skills/*.md`, содержащем
абзац о приставке, встречаются все пять названных форм; `npx prettier
--check` по правленым файлам зелёный.

## 4. Покрыть остальные предписанные команды

- [ ] Добавить в `allow` для обеих оболочек: `pnpm build:*`,
      `node scripts/deploy.mjs:*`, а для команд с двоеточием в имени
      скрипта — по две формы разом: `pnpm e2e:perf:*` и `pnpm e2e:perf*`,
      `pnpm bench:tick:*` и `pnpm bench:tick*`.
- [ ] Добавить точную форму замера кадров:
      `Bash(CLIENT_PORT=5199 PORT=3055 pnpm e2e:perf)`.
- [ ] В `benchmark.md` рядом с этой командой сказать: она идёт через Bash
      (в PowerShell присваивание перед командой — синтаксическая ошибка),
      и числа портов менять нельзя — правило сверяется с текстом.
- [ ] Завести в `stage-settings.json` список заведомо непокрытых команд
      с заменой у каждой (замена обязательна) и объясняющую его заметку.
      Туда же — удаление файлов, которое правилами не открывается вовсе
      (`$cleanupImpossibleNote`).

**Проверка:** `npx vitest run --root plugins/pipeline` зелёный; список
`allow` глазами сверен со сводкой команд скиллов — непокрытых нет, кроме
названных в списке исключений.

## 5. Сторож: команда скилла против правила разрешений

- [ ] Дописать в `plugins/pipeline/config/transitions.test.mjs` проверку
      по устройству из `design.md`: собрать команды из блоков кода всех
      `skills/*.md`, отбросить комментарии после `#`, потребовать для
      каждой либо покрывающее правило `allow` той же оболочки, либо запись
      в списке заведомо непокрытых.
- [ ] В комментарии теста записать, **чего он не ловит**: он сверяет текст
      с текстом и не знает настоящего разбора разрешений, поэтому правило,
      верное по виду и негодное по разбору (как `node .matchlog/:*`), для
      него неотличимо от годного.
- [ ] Убедиться, что сообщение о падении называет и команду, и файл
      скилла: сторож, сообщающий «не покрыто», заставит следующего искать
      руками.

**Проверка:** `npx vitest run --root plugins/pipeline` зелёный на нынешнем
дереве; проба порчей — временно убрать строку `pnpm install:*` из
разрешений, увидеть падение с именем команды, вернуть строку.

## 6. Сторож: форма `@{u}` не возвращается

- [ ] Отдельной проверкой там же потребовать, чтобы `@{u}` не встречалась
      ни в одном файле `skills/*.md`, и объяснить в комментарии, почему
      запрет держится тестом, а не словами: показанную команду сессия
      переписывает буквально.

**Проверка:** `npx vitest run --root plugins/pipeline` зелёный; проба
порчей — вернуть `@{u}` в один скилл, увидеть падение, откатить.

## 7. Записать правило в README плагина

- [ ] В `plugins/pipeline/README.md`, в разделе про `stage-settings.json`,
      сказать связь прямо: команда, показанная скиллом, обязана иметь
      правило, и это стережёт тест — чинить надо оба файла разом.
- [ ] Назвать там же ограничение из `design.md`: правка правил вступает
      в силу только после вливания, потому что настройки отдаются этапу
      из основного дерева.

**Проверка:** `npx prettier --check plugins/pipeline/README.md` зелёный;
README называет сторож поимённо.

## Чего в списке нет и почему

- **Проверки «в `cycle.log` нет отказов»** здесь нет, хотя задача просит
  именно её. Настройки отдаются этапу из основного дерева, поэтому изнутри
  своего pull request правило не проверить ничем: подтвердить его может
  только первый живой этап после вливания. Наблюдение уходит заявкой.
- **Прогона арены** не нужно: правила игры, цены, доход, сила юнита и темп
  не затронуты — правка целиком в `plugins/pipeline` и `openspec`.
- **Обновления эталонов детерминизма** не нужно: `packages/sim` не тронут.
