## 4. Арена доносит записанное до базы

- [ ] 4.1 Три столбца в `apps/arena/src/schema.ts` (`nuke_note`,

      `nuke_net` округлять к ближайшему целому и не обрезать
      отрицательные значения. Помеху хранить числом, как соседние
      перечисления.

      **Проверка:** `npx vitest run apps/arena/src/ingest.test.ts` —
      зелено. Дописать в него случай с отрицательным `nukeNet`
      и случай с отсутствующими величинами (в базе `null`, а не ноль).

- [ ] 4.2 Сторож устаревшей базы в `apps/arena/src/ingest.ts`. После
      `db.exec(SCHEMA)` в `openDatabase` проверить по
      `pragma table_info(decision)`, что три новых столбца на месте,
      и при их отсутствии бросить ошибку, называющую и причину, и
      лечение: путь к файлу базы, «схема устарела», «удалите файл
      и соберите базу заново командой `ingest`».

      Почему сторож нужен. `create table if not exists` старую таблицу
      сохраняет, а вставка в `decision` идёт **по позициям**
      (`insert into decision values (?, …)`), и SQLite отвечает
      «table decision has 17 columns but 20 values were supplied».
      Это падение, а не молчание, но оно не называет ни причины,
      ни лечения, а базы прогонов лежат у всех, кто разбирал прошлые
      замеры. Миграции по-прежнему не заводится: база — производное
      от логов, и лечение у неё одно — пересборка.

      Сторож узкий намеренно: он сверяет три наших столбца, а не всю
      схему целиком. Общая сверка схемы — отдельная работа с отдельной
      ценой, и делать её попутно значит протащить нерецензированное.

      **Проверка:** `npx vitest run apps/arena/src/ingest.test.ts` —
      зелено, с новым случаем: база, в которой `decision` заведена
      без новых столбцов, роняет `openDatabase` ошибкой, чей текст
      содержит слово «удалите» и путь к файлу.

- [ ] 4.3 В `README.md` изменения назвать несовместимость старых баз

      зелено; сторож роняется, если в собранном логе одному решению

      Живых данных этот пункт не касается намеренно: прогон арены

## Чего в этом списке нет

**Самого замера.** Прогон арены на паре `baseline-2026-08` против
`strategist-2026-08` — шестьдесят матчей, зерно 3000, тот же состав,
что у прогона 33105088891, — заказан отдельной задачей типа `run`
и здесь пунктом не стои́т.

**Сверки ведомости с живыми данными.** Разбивка помех по настоящему
прогону и толкование недобора — работа той же задачи 0120: у неё есть
и прогон, и право его запустить. В этом списке остаётся сходимость
ведомости самой с собой (пункт 5.2), проверяемая на базе, собранной
тестом.

Не по забывчивости, а намеренно: пункт списка, который этап не вправе
исполнить, никогда не будет отмечен, и работа, сделанная целиком,
навсегда останется незавершённой на бумаге. Очередь прогонов ведёт
бэклог, и связь с этой задачей держится ссылкой, а не галочкой.
