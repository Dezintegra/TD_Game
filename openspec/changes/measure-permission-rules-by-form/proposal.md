# Сторож покрытия мерит правило разрешений по его форме

## Зачем

Сторож «команды вливания покрыты правилами в обеих оболочках»
(`supervisor/config/transitions.test.mjs`) заведён затем, чтобы сужение
широкого правила `gh pr:*` не вывело молча из-под разрешений одну
из трёх команд, которыми ревью доводит изменение до `main`. Ради этого
он и написан: отказ на `gh pr ready` случается там, где рядом нет
человека, — посреди вливания.

Мерит он при этом не то, что мерит среда.

Функция `prefixOf` (строка 212) снимает с правила обёртку оболочки
и **безусловно** отбрасывает хвост `:*`, а `coversCommand` (строка 224)
сверяет остаток приставкой — то есть считает покрытой любую команду,
которая с этого остатка начинается. Для правила `Bash(gh pr:*)` это
верно: хвост `:*` и означает «с любыми доводами». Для правила,
записанного **без** хвоста — `Bash(gh pr view)`, — неверно: среда
трактует такую форму точным совпадением команды, и `gh pr view 1 --json
state,isDraft` под неё не подпадает.

Последствие ровно то, ради чего сторож заведён. Пусть кто-нибудь сузит
сегодняшние широкие `Bash(gh pr:*)` и `PowerShell(gh pr:*)`
(`supervisor/config/stage-settings.json:79,83`) до трёх точных правил
`gh pr view` / `gh pr ready` / `gh pr merge`. Среда откажет всем трём
командам `MERGE_PATH` — у каждой есть доводы, — а сторож промолчит:
приставка совпадёт. Сторож не сработает в том самом случае, ради
которого написан.

Отдельно важно, что две противоположные мерки для одного синтаксиса
живут **в одном файле**. Сторож на строках 346–365 держится на прямо
обратном прочтении: `Bash(pnpm run)` без хвоста `:*` НЕ открывает
`pnpm run verify`, и потому широкая форма запрещена, а точная требуется.
Тот же `prefixOf` прочёл бы это правило приставкой. Один файл, один
синтаксис, два несовместимых толкования — однажды введут в заблуждение
не хуже прямой ошибки.

Живой беды сегодня нет: правила широкие, покрытие честное, а до этого
сторожа не было вовсе. Чинится щель, а не поломка, — и потому приоритет
у задачи ниже обычной работы.

## Что меняется

**`supervisor/config/transitions.test.mjs`:**

- вместо `prefixOf` появляется разбор правила, отдающий вместе с телом
  признак формы: «точное совпадение» у правила без хвоста `:*`,
  «приставка» у правила с ним;
- `coversCommand` сверяет по этому признаку: приставочная форма
  допускает продолжение команды доводами, точная требует совпадения
  целиком;
- комментарии, объявляющие мерку сторожа приставочной, переписываются
  под две формы: сегодня они утверждают неверное прямым текстом;
- рядом с уже стоящими пробами на порчу (строки 404–425) встаёт третья:
  настройка из трёх точных правил `gh pr view` / `gh pr ready` /
  `gh pr merge` без хвостов обязана дать **все три** команды
  `MERGE_PATH` непокрытыми в обеих оболочках. Проба на порчу здесь
  не украшение: сторож, не краснеющий на сломанной настройке, и есть
  предмет этой задачи.

**`openspec/changes/undraft-before-merge/design.md`, Решение 4
(строки 96–113)** — мерка сторожа объявлена там только приставочной
(«Мерка у него та же, что у среды: **совпадение по приставке**»).
Изменение ещё не заархивировано, значит правится документ, а не история.

**`openspec/changes/undraft-before-merge/specs/dev-pipeline-supervisor/spec.md`** —
там же, в нормативном тексте требования, стоит «Совпадение по приставке —
единственный порядок сверки, применяемый средой, и проверять надо именно
его». Это утверждение ложно, и оставить его нельзя: заархивировавшись,
оно станет требованием проекта, прямо противоречащим требованию,
которое заводит настоящее изменение. Правится один абзац; сценарии
и смысл требования — «три команды вливания покрыты поимённо» —
не трогаются.

## Non-goals

- **Правила разрешений не сужаются.** Ни `gh pr:*`, ни любое другое
  широкое правило не дробится на перечень подкоманд. Задача чинит мерку
  сторожа, а не настройку; сужение остаётся отдельной работой
  с отдельным разбором, и после этой правки сторож наконец сможет
  её сопроводить.
- **`stage-settings.json` не меняется вовсе.** После правки сторож
  на сегодняшней настройке обязан остаться зелёным: широкие правила
  с хвостом `:*` читаются приставкой ровно как раньше.
- **Разбор правил не выносится в общий модуль и не делается заменой
  разбору самой среды.** Речь о полутора десятках строк в тестовом
  файле, а не о повторении логики Claude Code.
- **Прочие формы правил не разбираются.** Ни `Read(...)`, ни `Edit(...)`,
  ни правила с путями: `MERGE_PATH` — про команды оболочек, и сторож
  остаётся про них.
- **Смысл звёздочки внутри правила не пересматривается.** Она как стояла
  вместо довода (`git -C * push --force:*`), так и остаётся; правится
  только толкование хвоста.
- **Задача 0132 (близнецы дельт в одной способности) здесь не решается.**

## Влияние на отзывчивость интерфейса и на сетевой трафик

**Влияния нет ни на то, ни на другое, и вывод не умозрительный.**
Правится один тестовый файл конвейера и два документа OpenSpec. Каталог
`supervisor/` не входит ни в один пакет монорепозитория: он
не собирается вместе с клиентом и сервером, не импортируется из `apps/`
и `packages/` и в браузер не попадает ни байтом. Игрового кода
изменение не касается: кадр отрисовки, объём игровых сообщений
и раскладка байтов протокола не задеты, `PROTOCOL_VERSION` расти
не должен.

Единственный измеримый след — время прогона набора `pnpm test:pipeline`:
одна новая проба на порчу, считающая регулярные выражения по шести
строкам. Доли миллисекунды.

## Зависимости

Дельта пишется на способность `dev-pipeline-supervisor`, и в
`openspec/specs/` её ещё нет — заводит её незаархивированное изменение
`supervise-the-pipeline`. Сам сторож, мерку которого правит настоящее
изменение, заводит незаархивированное `undraft-before-merge`; его же
документы правятся здесь.

Поэтому **это изменение архивируется ПОСЛЕ `supervise-the-pipeline`
и ПОСЛЕ `undraft-before-merge`**. Заархивировав раньше, получим
требование, висящее без основы: `openspec validate` этого не ловит,
а падает архивация — через месяц и не у того, кто писал.
