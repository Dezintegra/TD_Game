# Задачи

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе.
Прогон сторожей везде один и тот же:

```
npx vitest run --root supervisor config/transitions.test.mjs
```

Ключ `--root supervisor` обязателен: без него тесты конвейера не находятся
вовсе, и прогон зеленеет, ничего не прогнав.

## 1. Научить сторож различать форму правила и доказать это пробой на порчу

- [x] В `supervisor/config/transitions.test.mjs` заменить `prefixOf`
      (строка 212) разбором, отдающим пару «тело правила плюс признак
      формы»: у правила с хвостом `:*` хвост снимается и признак
      «приставка», у правила без хвоста тело берётся целиком и признак
      «точное совпадение». Возврат `null` для чужой оболочки сохранить.
- [x] Научить `coversCommand` (строка 224) закрывать выражение по этому
      признаку: приставка — `^<тело>(\s|$)`, точная форма — `^<тело>$`.
      Экранирование спецсимволов и толкование звёздочки внутри тела
      (`*` → `.*`) оставить как есть.
- [x] Переписать комментарии над обеими функциями: сегодня они прямым
      текстом объявляют мерку сторожа приставочной, и после правки это
      будет ложью в самом заметном месте. Назвать обе формы и сослаться
      на соседний сторож `pnpm run` (строки 346–365) — он держится
      на точной форме, и вместе они больше не спорят.
- [x] Добавить третью пробу на порчу рядом с двумя стоящими (строки
      404–425): настройка из шести точных правил без хвоста —
      `gh pr view`, `gh pr ready`, `gh pr merge` в обеих оболочках —
      обязана дать **шесть** непокрытых команд. Проверять длину списка,
      а не вхождение одной строки.
- [x] Убедиться поиском по `supervisor/`, что на снятое имя `prefixOf`
      никто больше не ссылается. Найденные `supervisor/lib/comments.mjs`
      и его тест — самостоятельная экспортируемая функция про приставку
      комментария; со сторожем она не связана и правки не требует.
- [ ] Открыть черновой pull request сразу после этого коммита: до его
      появления пуши в ветку не запускают проверок CI вовсе.

**Проверка:** прогон сторожей выше — зелёный целиком. В нём обязаны
одновременно выполниться три вещи: новая проба даёт шесть непокрытых
команд; сторож «команды вливания покрыты правилами в обеих оболочках»
остаётся зелёным на нетронутом `stage-settings.json` (широкие `gh pr:*`
читаются приставкой, как раньше); обе прежние пробы на порчу
(`narrowed`, `shadowed`) продолжают краснеть на своих настройках.

**Проверка живости пробы:** до правки функций новая проба обязана
падать. Порядок работы — сперва проба и красный прогон, затем правка
и зелёный; в коммит едет то и другое разом, потому что порознь ни одна
половина не проверяема.

Дополнительно: `npx prettier --check supervisor/config/transitions.test.mjs`
и `npx eslint supervisor/config/transitions.test.mjs`.

## 2. Снять ложное «единственный порядок сверки» из `undraft-before-merge`

- [ ] В `openspec/changes/undraft-before-merge/design.md`, Решение 4
      (строки 96–113), поправить объявление мерки: она не «совпадение
      по приставке», а совпадение по форме правила — приставка у формы
      с хвостом `:*`, точное совпадение без него. Пример с `gh pr ready
      119` под правилом `Bash(gh pr:*)` остаётся верным и правки
      не требует; сослаться на настоящее изменение как на то, где мерка
      описана целиком.
- [ ] В `openspec/changes/undraft-before-merge/specs/dev-pipeline-supervisor/spec.md`
      переписать абзац с формулировкой «Совпадение по приставке —
      единственный порядок сверки, применяемый средой, и проверять надо
      именно его» так, чтобы он говорил о совпадении по форме правила.
- [ ] Там же переписать **WHEN** сценария «Запрет перекрыл собственное
      разрешение» (строки 31–35). Сегодня он говорит «правило,
      совпадающее с приставкой `gh pr merge` либо `gh pr ready`», и под
      это описание подпадает в том числе запрет **без** хвоста `:*` —
      а сценарий «Запрет точной формы, короче команды» настоящего
      изменения утверждает про такой запрет прямо обратное: команду
      с доводами он не гасит. Настройка `deny: ['Bash(gh pr merge)']`
      подходит под оба WHEN сразу, а THEN у них противоположные; оба
      требования архивируются в одну способность и встанут рядом.
      Поэтому WHEN обязан назвать форму — например «правило с хвостом
      `:*`, приставка которого покрывает `gh pr merge` либо
      `gh pr ready`». Смысл сценария («запрет, перекрывший собственное
      разрешение, ловится тестом») и его THEN не трогать.
- [ ] Там же, в абзаце `MUST NOT` (строки 21–23), назвать форму и во
      фразе про `.matchlog/*`: отнявший у этапа работу запрет был
      **приставочным**. Довольно одного слова; сама норма — «настройка
      MUST NOT содержать запрета, перекрывающего эти три команды» —
      остаётся дословно.
- [ ] Два других сценария дельты — «Команда вливания выведена из-под
      разрешений» и «Сегодняшняя настройка сторожа проходит» — верны
      при любой мерке и не трогаются вовсе.

**Проверка:** `openspec validate --changes --strict` зелёный,
и в дельте `undraft-before-merge` по-прежнему одна секция
`## ADDED Requirements` и ровно три сценария — секций одного типа
не должно стать две, иначе CLI молча возьмёт последнюю, а требования
предыдущих потеряет. Поиск по обоим файлам не находит ни «единственный
порядок сверки», ни объявления мерки сторожа только приставочной;
поиск по WHEN правленого сценария находит упоминание хвоста `:*`.
Прогон сторожей повторять не нужно: шаг трогает только документы.
