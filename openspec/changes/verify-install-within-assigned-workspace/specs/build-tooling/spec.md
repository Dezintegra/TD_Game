## ADDED Requirements

### Requirement: Проверка вложенной установки сохраняет назначенный workspace

Оснастка SHALL предоставлять повторяемую проверку настоящей установки pnpm в новой самостоятельной Git-копии отслеживаемой отправленной ревизии внутри `.matchlog/` назначенного рабочего дерева. На Windows cwd инструмента и граница sandbox SHALL оставаться назначенным деревом, а каталог копии SHALL передаваться дочерним процессам. Проверка MUST NOT отключать sandbox, изменять ACL, расширять доступ, использовать чужое дерево или повторно использовать старую копию.

#### Scenario: Новая копия внутри исходной песочницы

- **WHEN** исполнитель запускает проверку в назначенном дереве с включённым Windows sandbox
- **THEN** создаётся новая уникальная копия внутри этого дерева, pnpm устанавливает зависимости с cwd копии, а cwd запускающего инструмента остаётся исходным
- **AND** локальный кеш создаётся самой установкой в копии без изменения разрешений

#### Scenario: Повтор проверки

- **WHEN** в `.matchlog/` остались результаты предыдущего запуска
- **THEN** следующий запуск получает другой каталог, а прежний каталог и его результаты сохраняются

#### Scenario: Путь выходит за назначенное дерево

- **WHEN** разрешённый через реальные пути каталог проверки выходит за назначенное дерево, в том числе через junction или symlink
- **THEN** проверка останавливается до подготовки копии и запуска установки, не записывая данные по такому пути

### Requirement: Успех проверки установки подтверждается файловыми результатами

Проверка SHALL запускать настоящий `pnpm install --frozen-lockfile --store-dir .pnpm-store` с закреплённой проектом версией pnpm, отключать пользовательский ignore только для своей копии и проверять исходную чистоту, код установки 0, наличие файлов пакетов в локальном кеше, пустой полный статус Git и источник исключения в проектной `.gitignore`. Пустой созданный каталог, фиктивный маркер или успешный запуск Node MUST NOT считаться доказательством установки.

#### Scenario: Успешная установка

- **WHEN** настоящая установка завершилась успешно в новой изначально чистой копии с отключённым пользовательским ignore
- **THEN** в `.pnpm-store` обнаруживаются файлы пакетов, `git status --porcelain --untracked-files=all` пуст, а `git check-ignore -v` указывает на правило `.pnpm-store/` проектной `.gitignore`

#### Scenario: Исходник остаётся видимым

- **WHEN** после успешной проверки установки изменён отслеживаемый исходник только внутри копии
- **THEN** тот же контроль чистоты отвергает копию и называет изменённый файл; кеш остаётся игнорируемым

#### Scenario: Посторонний файл остаётся видимым

- **WHEN** после восстановления только своего контрольного изменения исходника в копии создан посторонний неотслеживаемый файл вне кеша
- **THEN** контроль чистоты независимо отвергает копию и называет посторонний файл

#### Scenario: Установка или контроль не состоялись

- **WHEN** подготовка или установка завершилась ошибкой либо таймаутом, кеш пуст, Git сообщил ошибку или хотя бы одно положительное или отрицательное условие не подтверждено
- **THEN** общая проверка завершается ненулевым кодом, сохраняет стадию и диагностику и не объявляет успех на основании пустого stdout статуса

### Requirement: Регрессия вложенной установки проверяется воспроизводимо

Оснастка SHALL иметь быстрые автономные тесты управления процессами и файловых условий без скачиваний и отдельный документированный живой Windows сценарий в действующей песочнице. При изменении способа запуска вложенной установки или используемой конфигурации sandbox подтверждение SHALL включать новую настоящую установку с записью ревизии, версий, cwd, результатов и ошибок. Проверка MUST NOT автоматически запускаться при каждом старте readiness.

#### Scenario: Живое подтверждение отличается от заглушки

- **WHEN** быстрые тесты с подменённым pnpm прошли, но живая установка ещё не завершена
- **THEN** результат обозначает только успех быстрых тестов и не подтверждает работоспособность Windows sandbox

#### Scenario: Воспроизводимый результат

- **WHEN** живой Windows сценарий завершён
- **THEN** сохранены исходная ревизия, версии Node, pnpm, Git и Codex, назначенный cwd и путь новой копии, код установки, свидетельства кеша и ignore, исходный и повторный статусы, оба отрицательных контроля и точная команда повторения без секретов
