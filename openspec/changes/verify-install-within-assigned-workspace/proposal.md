## Why

В задаче 0226 установка в назначенном дереве прошла, а во вложенной проверочной копии при смене cwd инструмента завершилась EPERM на mkdir `.pnpm-store`. Операторская диагностика из журнала 0232 установила поддерживаемый запуск дочернего pnpm из исходной песочницы, но воспроизводимой общей проверки новой копии в репозитории нет; readiness проверяет основной cwd и запуск процессов без установки.

## What Changes

- Добавить повторяемую команду проверки установки в уникальной новой копии отслеживаемого содержимого отправленного коммита внутри `.matchlog/` назначенного дерева.
- Сохранять cwd инструмента и границу Windows sandbox на назначенном дереве; рабочий каталог копии передавать только дочерним процессам подготовки, pnpm и Git. Не менять ACL или профиль доступа.
- Проверять настоящую установку с локальным непустым кешем, чистоту Git при отключённом личном ignore, проектное происхождение исключения и независимое обнаружение изменённого исходника и постороннего файла.
- Сохранять диагностические результаты, различать отказ подготовки, установки и проверки; закрепить способ в `docs/agent-setup.md` и быстрых тестах. Живой Windows запуск обязателен для завершения реализации и повторяется после изменения связанного способа запуска или sandbox.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `build-tooling`: ADDED-требования к воспроизводимой проверке установки во вложенной копии. Существующее требование «Воспроизводимость окружения» сохраняется; новая норма касается способа проверки, а не версий или CI-установки.

## Non-goals

- Не отключать sandbox, не расширять writable roots, не менять ACL, глобальную Git-конфигурацию или расположение пользовательского кеша.
- Не переносить установку в обязательный readiness каждого старта; не менять паузу машины и счётчики задачи (0127), заглушку модели readiness (0231).
- Не менять правила выкладки и её закреплённые снимки, `.gitignore`, тесты и артефакты 0226; не повторять доставленное исключение кеша.
- Не собирать игру, не запускать замеры, арену или выкладку в проверочной копии. Не исправлять внутреннюю реализацию ACL стороннего Codex и не обещать поддержку смены cwd самой песочницы на вложенный репозиторий.

## Impact

Новые `supervisor/lib/install-snapshot-check.mjs`, его узкие тесты и `supervisor/bin/check-install-snapshot.mjs`; точное разрешение новой команды с проверкой покрытия в `supervisor/config/`; инструкция в `docs/agent-setup.md`. Зависимости не добавляются. Провайдер и readiness служат контекстом, их рабочий код не требует изменения.

Отзывчивость интерфейса не меняется: код клиента и игрового цикла не затронут. Сетевой трафик игры не меняется. Явная живая проверка скачивает зависимости штатным pnpm; быстрые тесты не обращаются к сети и не запускают Codex.

## Пересечения и зависимости

Свежая база проверена через fetch и merge origin/main: `272a54e`, merge ответил `Already up to date.`. `.gitignore:2` уже исключает `.pnpm-store/`, предмет автоматизации остаётся.

0226 (`check-deploy-cleanliness-after-install`, PR 163) меняет порядок проверки выкладки и её Git-фикстуры; наша команда проверяет среду во вложенном самостоятельном репозитории и не использует его новые функции. 0231 (`account-for-sandbox-in-readiness-model-test`) меняет только `stage-model.test.mjs`, который здесь не затрагивается. Их материалы прочитаны из назначенных им деревьев только для контекста.

`prepare-stage-workspace`, `fix-codex-startup`, `check-codex-processes`, `prepare-deploy-snapshot` уже реализованы в базе; их открытые контракты не переписываются. Новая дельта добавляется в существующую `build-tooling`, не поверх открытой дельты: зависимости порядка архивации нет. Общий файл `stage-settings.json` пересекается с `one-shell-for-stages`, `permit-the-pipeline-scripts`, `write-covered-commands-in-tasks`; добавляется только точное разрешение отдельной безопасной команды, без широкого `node supervisor/bin/*`.
