# Задачи

Каждый пункт — отдельный коммит с немедленной отправкой. Проверка у всех
одна и та же по духу: `npx vitest run --root plugins/pipeline` плюс узкие
линт и формат по своим файлам. Где нужна проверка делом, она названа
отдельно.

Порядок выбран так, чтобы конвейер оставался работоспособным после
каждого пункта: сначала прирастает новое, и только разделом 6 сносится
старое.

## 1. Порождение процесса этапа

- [ ] 1.1 `lib/stage-command.mjs` — чистая функция «задача + этап +
      настройка → аргументы командной строки, рабочий каталог,
      идентификатор сессии». Ничего не запускает.
      _Проверка:_ тест на состав аргументов для этапа с деревом и без,
      на подстановку файла правил этапа, на выданный заранее UUID.
- [ ] 1.2 `lib/stage-prompt.mjs` — сборка промпта назначения из карточки:
      идентификатор, этап, ветка, дерево, причина, признак продолжения,
      описание и журнал задачи.
      _Проверка:_ тест на то, что промпт самодостаточен — в нём есть все
      поля, которые сегодня уходят в выписку `<slot>.task.json`.
- [ ] 1.3 `lib/run-stage.mjs` — запуск процесса с исполнителем-доводом
      (как в `lib/git.mjs`), сбор вывода, код возврата, длительность.
      _Проверка:_ тесты на поддельном исполнителе — успех, ненулевой код,
      пустой вывод.
- [ ] 1.4 Срок этапа и снятие поддерева процессов. Сроки по этапам —
      в `config/defaults.mjs`.
      _Проверка:_ тест на срабатывание срока с поддельным исполнителем;
      **проверка делом** — снять `taskkill /PID <pid> /T /F` реальный
      процесс, породивший потомка, и убедиться, что потомок умер тоже.
- [ ] 1.5 Разбор ответа: `is_error`, `terminal_reason`, `num_turns`,
      `session_id`, `permission_denials`, `result`.
      _Проверка:_ тесты на настоящем ответе из пробы (положить образец
      рядом с тестом) и на ответе с отказом.

## 2. Отчёт выводом вместо файла

- [ ] 2.1 `lib/parse-report.mjs` — терпимый разбор отчёта из `result`:
      последний блок JSON, приписки вокруг допустимы.
      _Проверка:_ тесты на чистый JSON, JSON в ограде из трёх кавычек,
      JSON с припиской до и после, отсутствие JSON вовсе.
- [ ] 2.2 `apply-report` принимает отчёт из вывода наравне с файловым.
      _Проверка:_ существующие тесты `apply-report` зеленеют без правок
      ожиданий.
- [ ] 2.3 Отказ доверия отчёту при непустых `permission_denials`: задача
      останавливается на разбор, отказы уходят в журнал цикла.
      _Проверка:_ тест на отчёт `done` с одним отказом — задача
      не двигается.
- [ ] 2.4 Журнал этапа: `.pipeline/logs/<taskId>-<этап>.log` с выводом
      целиком, стоимостью и длительностью.
      _Проверка:_ тест на запись файла через поддельный `io`.

## 3. Долгий цикл

- [ ] 3.1 `bin/supervise.mjs`: замок с номером процесса, отказ второго
      экземпляра, оборот цикла на существующем `runCycle`, пауза, журнал.
      _Проверка делом:_ запустить, убедиться, что холостой оборот
      не порождает процессов; запустить второй — он выходит немедленно.
- [ ] 3.2 Квота как подсчёт живых детей, включая исключительность
      `benchmark` и `deploy`.
      _Проверка:_ тесты на «квота исчерпана», «замер ждёт тишины»,
      «ожидание проверок квоту не занимает».
- [ ] 3.3 Корректное завершение по сигналу: дать детям срок, затем снять
      поддеревья.
      _Проверка делом:_ прервать супервизор при идущем этапе, убедиться
      по списку процессов, что осиротевших не осталось.

## 4. Продолжение возобновляет сессию

- [ ] 4.1 Хранение идентификатора сессии этапа в реестре и возобновление
      прерванного этапа тем же идентификатором.
      _Проверка:_ тест на состав аргументов продолжения; **проверка
      делом** — прервать этап и убедиться, что возобновлённая сессия
      знает о сделанном.
- [ ] 4.2 Предел продолжений сохраняется, снятие по сроку считается
      отдельным исходом.
      _Проверка:_ тест на исчерпание предела снятиями по сроку.

## 5. Скиллы этапов

- [ ] 5.1 Переписать раздел «Что тебе дано» во всех девяти скиллах: слот

- [ ] 5.2 Переписать раздел «Отчёт» во всех девяти: отчёт возвращается

- [ ] 5.3 Убрать из всех девяти требование задавать себе заголовок

      _Проверка для 5.1–5.3:_ существующий тест

      на каждый этап; добавить к нему проверку, что ни один скилл больше
      не поминает `.pipeline/slots` и `.pipeline/reports`.

## 6. Снос отжившего

Раздел идёт последним намеренно: до него конвейер работает по-старому,
после — по-новому, и промежуточного состояния «уже сломали, ещё
не починили» нет ни на одном коммите.

- [ ] 6.1 Удалить `bin/snapshot.mjs`, `lib/snapshot.mjs` и их тесты.
- [ ] 6.2 Вычистить `sessionLife` и признаки живости из `lib/scan.mjs`;
      поправить его тесты.
- [ ] 6.3 Удалить `lib/slots.mjs`, чтение слотов из `lib/read-state.mjs`,
      выписки и очистку слотов из `lib/io.mjs`, раздачу через слоты
      из `lib/execute.mjs`.
- [ ] 6.4 Удалить чтение отчётов из чужих деревьев (`readReports`)
      и работу с каталогом `.pipeline/reports/`.
- [ ] 6.5 Настройки: убрать `deadAfterMinutes`, `endedAfterMinutes`,
      состав слотов; добавить `stageTimeoutMinutes` и `maxConcurrent`.
      _Проверка:_ `config/defaults.test.mjs` зеленеет, обязательные
      значения по-прежнему проверяются.

## 9. Ввод в строй

Шаги те же, что и прежде, и по той же причине: конвейер вливает
и выкладывает без человека.

- [ ] 9.1 **Тень.** Супервизор работает без исполнения — считает
      и печатает. Сутки такого режима.
- [ ] 9.2 **Одна задача** типа `note` или `run` — самые дешёвые маршруты,
      не создающие веток.
- [ ] 9.3 **Полный маршрут**, вливание пока вручную.
- [ ] 9.4 **Автовливание** с тремя предохранителями.
- [ ] 9.5 **Автовыкладка.**

Второго одновременного этапа в этом списке нет намеренно: параллельность
отсюда убрана раньше, и возвращать её стоит только с ответом на вопрос,
чем именно она окупится.
