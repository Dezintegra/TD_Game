## Context

mayCleanup возвращает skip при entry=null. cleanupTask трактует skip как разрешение завершить карточку. reconcile восстанавливает запись только для обнаруженного рабочего дерева; оставшиеся ветки при снятой регистрации не покрыты.

## Goals / Non-Goals

Цель: исключить ложное завершение. Не входит: автоматическое восстановление и удаление ресурсов без записи.

## Decisions

Возвращать fail с требованием восстановить запись и проверить оставшиеся ветки и каталог. Это переводит задачу в разбор ошибки штатным halt, сохраняет ресурсы и не повторяет бесполезный цикл ожидания. Недоступность состояния PR остаётся временным wait; невлитый PR по-прежнему запрещает завершение.

Не восстанавливать запись из догадки о пути: без доказанной принадлежности это расширило бы полномочия удаления. Не возвращать skip даже когда ресурсы действительно уже убраны: текущий контракт не предоставляет доказательств этого факта.

## Risks / Trade-offs

После сбоя между dropRegistry и saveTask повтор теперь потребует восстановления записи и идемпотентной уборки. Это осознанная остановка вместо ложного успеха. Задачи без PR также требуют записи: отсутствие PR не доказывает отсутствие локальной работы. Существующая запись и штатная уборка не меняются.
