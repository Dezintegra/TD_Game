## Правила состава и проверки

Каждый коммит допускает только перечисленные в своём пункте рабочие файлы и обязательную отметку этого пункта в `openspec/changes/prepare-windows-diagnostic-host/tasks.md`. Изменения внутри разрешённых путей должны относиться только к пункту; явный список `git -C <дерево> add -- <свои пути>` можно разбить на несколько коротких отдельных вызовов. Проверить имена и содержание `git -C <дерево> diff --cached`, после коммита — `git -C <дерево> show --stat HEAD` и `git -C <дерево> show HEAD`. Отправлять `git -C <дерево> push` сразу, не копить хвост.

В индексе и коммитах должны отсутствовать `.matchlog/0302-host-contract/`, `.matchlog/0302-host-contract.mjs`, `.matchlog/0302-project-skill-host/`, `.matchlog/0302-project-skill-host-evidence.json`, прежние `.matchlog/0299-skill-write-probe/` и `.matchlog/0299-skill-write-evidence.json`; их отсутствие не разрешает другие посторонние изменения. Реальные ветки/деревья 0299 и 0083, PR 232, чужие задачи и свидетельства не править.

Узкий линт/формат — по изменённым JS/Markdown вне openspec; формы `npx eslint <свои файлы>` и `npx prettier --check <свои файлы>` покрыты stage-settings. OpenSpec проверять по имени: `openspec validate prepare-windows-diagnostic-host --strict` и `openspec status --change prepare-windows-diagnostic-host`. Полный verify, игровые тесты, арену и ожидание CI в эти шаги не включать. Внешнее введение оснастки в действие и движение зависимой карточки описаны в Migration Plan, не являются командами исполнителю и не заменяют проверку 3.1.
