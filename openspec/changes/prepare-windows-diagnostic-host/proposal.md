## Why

Живая приёмка 0299 остановилась до setup стенда: Git в хозяине запуска под `CodexSandboxOnline` отверг проверку идентичности 0083 (`detected dubious ownership`). Свидетельства PR 232 содержат ноль native-сессий; успешные unit-тесты не подтверждают готовность хозяина или права проверяемого Codex.

## What Changes

- Ввести отдельную подготовку хозяина Windows-диагностики, выполняемую штатным владельцем запуска до старта исполнителя. Хозяин проверяет Git-идентичность настоящего потребителя только чтением и создаёт фиксированный изолированный стенд.
- Предоставить ограниченный вход подготовки и библиотечный контракт подключения существующего опыта 0299. Контекст хозяина не наследуется проверяемым Codex: окружение ребёнка формируется заново для тестовых root/cwd, профиль и точные права остаются production.
- Разделить доказательства `hostReady`, готовности запуска ребёнка и полной приёмки файловых прав. Не перезаписывать прежние evidence и не расходовать native-пробы 0299 на подготовку.
- Сохранить PR 232, `permit-assigned-project-skill-writes` и артефакты 0083; после доставки и подтверждения предпосылки передать 0299 штатному повторному анализу.

## Non-goals

- Обход текущего ownership-отказа через `git -c`, env, другой инструмент, смену пользователя или отключение sandbox из активной сессии.
- Глобальный `safe.directory`, wildcard-доверие, изменение владельцев/ACL, новые write-grants основному дереву, 0083 или родителям защищённых скиллов.
- Выполнение полной приёмки 0299, закрытие её пункта 3.1, вливание PR 232 или реализация 0083 этой карточкой.
- Универсальный сервис исполнения произвольных команд от имени владельца, изменения лимитов/доски, перезапуск работающего супервизора исполнителем.

## Capabilities

### New Capabilities

Нет новых способностей.

### Modified Capabilities

- `build-tooling`: добавить требования к подготовке и доказательствам готовности хозяина фиксированной диагностики. Это новые требования внутри существующей способности, поэтому дельта имеет тип ADDED.

## Impact

Новые модули хозяина и ограниченный CLI в `supervisor/`, тесты и `docs/agent-setup.md`. Обычный запуск этапов, `codexGitEnvironment` и профиль `codexExecutionArgs` не получают дополнительных прав. Интеграция со стендом PR 232 проверяется по закреплённому исходнику; его реализация не доставляется в main попутно с 0302.

Отзывчивость интерфейса и игровой сетевой трафик не меняются: подготовка выполняется вне игры и не затрагивает client/server/sim/protocol. Подготовительный режим не обращается к модели; последующие обращения существующей диагностики ограничены её прежним бюджетом.

### Пересечения и порядок доставки

Свежая база design — `c3d7700` после fetch/fast-forward 09.09.2026. В ней отсутствуют модули PR 232; они прочитаны в существующем дереве 0299. Поэтому 0302 поставляет самостоятельный контракт хозяина, а не требует предварительного вливания зависимой 0299. Подключение проверяется как совместимость с открытым PR, без изменения его ветки; после повторного анализа 0299 использует поставленный маршрут в своём сохранённом PR.

`fix-codex-startup` ограничивает доверие Git проверяемого Codex его root/cwd; это сохраняется. `guard-permission-diagnostics` сохраняет обязательность событий инструментов, отрицательных контролей и лимитов. `verify-install-within-assigned-workspace` касается установки pnpm, а не этой диагностики. Требования этих изменений не переписываются. Дельта 0302 добавляет уникальные требования в существующую `build-tooling`, не модифицирует чужие ADDED и не требует порядка архивации относительно PR 232.
