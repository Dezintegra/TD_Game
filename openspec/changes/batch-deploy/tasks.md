# Задачи

Каждый пункт — отдельный коммит, собирающийся и проверяемый сам по себе.
Проверки набором конвейера зовутся как `pnpm test:pipeline`: обычный
`vitest` тестов инструмента не находит вовсе, ему нужен ключ
`--root supervisor`.

## 1. Сканер сворачивает задачи `deploy` в пакет

В `supervisor/lib/scan.mjs`, раздел 6: среди задач, дождавшихся выдачи
сессии, все со статусом `deploy` сворачиваются в одну ведущую (первая
по `byPriorityThenAge`); её `continue-stage` несёт поле `batch` —
идентификаторы всех задач `deploy` из этого перечня, включая её саму.
Прочим — запись «едет в пакете выкладки с <ведущая>». Если по какой-то
задаче уже идёт этап `deploy`, остальные задачи `deploy` ждут с записью
о идущем пакете и в перечень ожидающих не попадают.

**Проверка:** тесты в `scan.test.mjs`: три задачи `deploy` — одно
`continue-stage` с `batch` из трёх и две записи «едет в пакете»; идущая
выкладка — прочие ждут с записью о пакете; одна задача — `batch` из неё
одной; удержанная и исчерпавшая продолжения в `batch` не входят.

После этого пункта открывается **черновой pull request**.

## 2. Пакет уезжает в назначение, промпт и отчёт

`execute.assignmentFor` кладёт в назначение `batch` — выписки задач пакета
(`id`, `title`, `links.pr`, `links.change`); `stage-prompt` печатает
идентификаторы в JSON назначения полем `batch` и раздел «Пакет выкладки»
с выписками; `supervisor.spawnStage` запоминает перечень у дескриптора
ребёнка, а `finish` возвращает его в отчёте полем `batch`.

**Проверка:** `stage-prompt.test.mjs` — назначение с пакетом печатает
идентификаторы и раздел; без пакета раздела нет. `supervisor.test.mjs` —
отчёт несёт `batch` из назначения; без пакета поля нет.

## 3. Перенос отчёта разносит пакет

В `execute.transferReport` для этапа `deploy` с перечнем `batch`: до записи
ведущей каждая задача пакета, кроме ведущей, переводится по перечням
`deployed` (в `cleanup`) и `skipped` (в `failed` с причиной) — своей записью
журнала со сводкой и ссылками отчёта и пометкой «выложена пакетом
с <ведущая>», своим коммитом. Задача не в `deploy` пропускается молча;
не названная — остаётся с записью в `plan.notes`; чужой идентификатор
не двигает ничего и назван в `plan.notes`. Ведущая получает `related`
на переведённые задачи. Неудача записи задачи пакета возвращает неудачу
переноса до записи ведущей.

**Проверка:** тесты в `execute.test.mjs` по сценариям дельты
`dev-pipeline-supervisor`: выложенные в `cleanup`, исключённая в `failed`
с причиной, неназванная в `deploy` с записью, чужая не тронута,
уже переехавшая пропущена, неудача записи оставляет ведущую и отчёт.

## 4. Скилл выкладки становится пакетным

Переписать `supervisor/skills/deploy.md`: назначение с `batch`, проверка
вливания по каждой задаче (`gh pr view <pr> --json state,mergeCommit`
и `git merge-base --is-ancestor`), закрепление хеша, замер `pnpm e2e:perf`
силами сессии, выкладка `node scripts/deploy.mjs --ref <хеш> --no-perf`,
заявка типа `feature` при просадке с идентификаторами пакета и цифрами,
отчёт с `deployed` и `skipped`. Запрет «пропускать замер» остаётся, запрет
на сам ключ `--no-perf` снимается с объяснением. Продолжение: не выкладывать
повторно, если выложено.

Обновить `STAGE_COMMANDS.deploy` в `config/permissions.mjs`: строка выкладки
с `--no-perf`, три формы `pnpm e2e:perf`; в `transitions.test.mjs` добавить
`pnpm e2e:perf` в `GATED_PROGRAMS.deploy`.

**Проверка:** `pnpm test:pipeline` зелёный: прямая и обратная сверка
перечня со скиллом проходят.

## 5. Открыть команды выкладки в шаблоне разрешений

Добавить в `config/stage-settings.json` правила на обе приставки `ssh …
dezintegra` и на `node scripts/deploy.mjs` для обеих оболочек; переписать
в `$pnpmNote` фразу о выкладке как деле человека. Снять `deploy`
из `DELIBERATELY_CLOSED`, переписать проверку «открытие закрытого этапа
требует снять запись» под пустой реестр.

**Проверка:** `pnpm test:pipeline` зелёный: сторож «команды покрыты либо
этап закрыт» проходит на шаблоне, `uncoveredForStage(settings, 'deploy')`
пуст.

## 6. README конвейера и правила проекта

В `supervisor/README.md` описать пакетную выкладку рядом с описанием
сканера и переноса отчёта; в `CLAUDE.md` в правиле 7 оговорить, что
конвейер меряет силами сессии и выкладывает с `--no-perf`, а ручная
выкладка меряет как прежде.

**Проверка:** `npx prettier --check` по своим файлам; CI по pull request
зелёный.
