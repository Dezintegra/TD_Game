## Decisions

### 1. Сохранить Prettier, добавить проверяемое ограничение исходного текста

В каждом из одиннадцати скиллов в разделе запретов добавить короткий пункт «Вставку кода на другую строку не переносить». Назвать обратные кавычки, потерю отступа при форматировании и разрешённые формы: целая вставка на одной физической строке, даже длиннее обычной ширины, или отдельный ограждённый блок с сохранением вложенности. Перенос отображения в редакторе не является нарушением. Исполняемый блок по-прежнему подчиняется существующим правилам языка оболочки.

Существующие вставки соединять с пробелом вместо перевода строки, восстанавливая отступ оставшейся прозы в исходном пункте списка. Отдельные блоки для нынешних примеров не нужны: это упоминания и примеры запрещённых команд, превращать их в исполняемые блоки было бы двусмысленно.

Альтернативы:

- Только исправить отступы: следующий перенос вернёт дефект, а обычная проверка формата его пропустит.
- Только написать правило: его нарушение ничем не обнаруживается.
- Только сторож: без исправлений существующего текста проверка сразу красна, без правила исполнитель не знает ограничения.
- Исключить `supervisor/skills/` в `.prettierignore`: защищает от обычного запуска форматтера, но оставляет уже повреждённые списки и разрешает новые многострочные вставки. Если дополнить это исправлениями и сторожем, исключение всё равно снимает проверку остального форматирования всех скиллов. В отличие от автоматически переписываемых `manage/tasks/`, здесь нет второго генератора с несовместимым форматом. Поэтому выбираем сохранение форматтера и устраняем конкретный опасный вид исходного текста. Устойчивость этого выбора проверяется при реализации дважды на закреплённой версии; сейчас она не объявляется измеренным фактом.
- Настройка переноса прозы или `prettier-ignore` у каждого абзаца: усложняет правила форматирования и не заменяет запрет новых многострочных вставок.

### 2. Сторож остаётся внутри transitions.test.mjs

Добавить небольшой чистый помощник в существующий файл рядом с проверками текстов скиллов, без экспортируемого модуля и новой зависимости. Он получает текст и возвращает положения многострочных вставок. Проверка файлов читает все Markdown-файлы каталога `supervisor/skills/` динамически; существующие проверки соответствия `NEEDS_SESSION` сохраняются. Новый файл этапа не должен потребовать ручного дополнения перечня.

Минимальный разбор: отделить YAML-шапку и ограждённые блоки от прозы, распознавать ограждения из обратных кавычек и тильд с отступом списка, закрывать только ограждением того же символа и не короче открывающего. В прозе искать парные серии обратных кавычек одинаковой длины в пределах абзаца; серии иной длины внутри вставки являются содержимым. Экранированная кавычка снаружи вставки не открывает её. Незамкнутая серия не связывается с соседним абзацем. Перевод строки между парой — нарушение, при LF и CRLF одинаково. Сторож не требует чётности всех кавычек документа и не проверяет незамкнутые вставки: иначе он захватит отдельный дефект задачи 0186.

Диагностика называет файл и строку открывающей кавычки, собирает все найденные нарушения. Отдельная проверка в том же файле требует наличия пункта правила с причиной и допустимой заменой в каждом скилле; удаление этого пункта из одной копии должно обнаруживаться.

Не использовать подсчёт нечётного числа кавычек на строке: он путает ограждения, буквальные кавычки и вставки с двойным разделителем. Не искать только известные `gh.exe` и `Remove-Item`: это пропустит следующую длинную команду.

### 3. Контроль чувствительности и повторного форматирования

Контрольные строки в тесте строятся в памяти, без записи порчи в рабочие скиллы. Нужны негативные образцы исходных трёх типов (полный путь, труба, заголовок ADDED), обычная произвольная вставка, двойной разделитель с одиночной кавычкой внутри и LF/CRLF. Для каждого проверять конкретную диагностику. Позитивные: те же вставки в одной строке, длинная строка, две независимые вставки на соседних строках, экранированная кавычка, незамкнутая серия в отдельном абзаце, многострочные ограждённые блоки обоих типов, включая вложенный блок и кавычки внутри него. Пустая функция поиска должна провалить негативные образцы.

Добавить пробу порчи копии живого скилла в памяти: перенести одну действительную вставку и убедиться, что тот же помощник, который проверяет файлы, возвращает её строку. Не ограничиваться тестом отдельного регулярного выражения.

При реализации выполнить форматирование по одиннадцати скиллам, проверить отсутствие переносов и глазами восстановленную вложенность. Подготовленный результат добавить в индекс; повторный `prettier --write` должен дать пустой diff рабочего дерева относительно индекса по скиллам. Это проверяет неподвижность результата, не сравнивая второй прогон с заведомо испорченной базой. В тестах можно дополнительно форматировать контрольные корректные фрагменты через установленный Prettier с конфигурацией репозитория и проверять сохранение инварианта, но новый обязательный модуль для этого не нужен.

## Risks / Trade-offs

- Ограниченный разбор не является полным Markdown-парсером → область задаётся явно, ограждения и серии кавычек проверяются отдельными образцами.
- Правка 0186 пересекается с четырьмя абзацами → механически соединять строки без изменения содержания; при получении её свежей версии сохранять исправленное содержание. Исключений из сторожа для `requests` нет.
- Соседние изменения правят тот же тестовый файл → дописать свою группу, сохранить существующие проверки и номера шагов скиллов, освежить базу перед реализацией.
- Форматтер может изменить соседний текст → просмотреть весь diff скиллов, не принимать повреждённый или несходящийся результат за успех. При несходимости выбранного решения вернуть конкретный пример на проработку.

## Migration Plan

Правило, исправления и сторож входят одним атомарным коммитом реализации, вместе с отметкой tasks.md; после отправки открывается черновой PR. Откат этого коммита возвращает прежние инструкции и проверки вместе. Изменения состояния данных и выкладка игровых ресурсов не нужны.

Дельта ADDED в существующей `quality-gates` не требует создания Purpose и не зависит от архивации других изменений. Игровое ядро и протокол не затронуты: правила рассинхрона и реконнекта, эталоны детерминизма и `PROTOCOL_VERSION` не меняются; источники случайности, времени и дробное состояние мира не добавляются.
