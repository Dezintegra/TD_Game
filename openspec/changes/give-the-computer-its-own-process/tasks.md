# Задачи

Порядок продиктован одним: **сначала развязать шов, потом переезжать.**
Если сперва вынести процесс, а потом разбираться, откуда лобби узнаёт
про компьютерную сторону, посреди работы окажется нерабочая игра
без комнат компьютера.

Изменение делается **после** `measure-the-tick`: заявленная польза —
«заминка перестаёт задерживать рассылку» — проверяется приборами,
и без них она останется недоказанной.

## 1. Развязка шва в одном процессе

- [ ] 1.1 Завести на сервере список компьютерных личностей с манерой
      и сроком действия. Отвечать `computerProfileOf` из него,
      а не обходом служб в памяти.
      *Проверка:* игра с компьютером работает как прежде; тест —
      личность, чей срок истёк, компьютерной больше не считается.
- [ ] 1.2 Точка объявления личностей: принимает общий секрет, список
      личностей и манеру каждой; обновляет срок. Без секрета
      и с неверным секретом — отказ.
      *Проверка:* тест — объявление без секрета отвергается, личности
      компьютерными не считаются.
- [ ] 1.3 Пустой секрет закрывает регистрацию: игра с компьютером
      недоступна, причина видна.
      *Проверка:* при пустом секрете в списке комнат нет комнат
      компьютера, а на экране видна причина.
- [ ] 1.4 Служба, всё ещё живущая в процессе сервера, объявляет свои
      личности через новую точку вместо прямой передачи `makeId`.
      *Проверка:* `pnpm verify` зелёный; матч с компьютером играется
      от начала до конца; манера в записи матча совпадает
      с объявленной.

## 2. Приложение `apps/computer`

- [ ] 2.1 Завести приложение: точка входа, чтение настроек (адрес
      сервера, секрет, состав манер), запуск служб из `packages/bot`,
      завершение по сигналу.
      *Проверка:* `pnpm -r build` собирает одиннадцать пакетов; линт
      границ пакетов зелёный.
- [ ] 2.2 Повторные попытки объявления с нарастающей паузой, если
      сервер ещё не поднялся. Падать при недоступном сервере нельзя.
      *Проверка:* служба, запущенная раньше сервера, дожидается его
      и объявляется; в журнале не более одного сообщения на попытку.
- [ ] 2.3 Обновление объявления, пока служба работает; при завершении
      по сигналу — снятие объявления, чтобы сервер не ждал срока.
      *Проверка:* после остановки службы комнаты компьютера исчезают
      из списка сразу, а не по истечении срока.

## 3. Сервер перестаёт поднимать компьютера

- [ ] 3.1 Убрать запуск служб из `apps/server/src/main.ts` вместе
      с держателем `computerRef` и закрытием служб в `onClose`.
      Комментарий на строках 117–160, объясняющий выбор манер,
      переехать обязан вместе с ними: это единственное место,
      где записаны основания выбора.
      *Проверка:* `packages/bot` отсутствует в зависимостях
      `apps/server`; линт границ пакетов это подтверждает.
- [ ] 3.2 Проверить, что тесты сервера, которые служб не поднимали,
      не сломались, а те, что рассчитывали на компьютера, переехали
      или переписаны.
      *Проверка:* `pnpm --filter @td/server test` зелёный.

## 4. Развёртывание

- [ ] 4.1 Вторая служба в `docker-compose.yml` из того же образа
      с другой командой запуска; общий секрет и адрес сервера —
      переменными среды.
      *Проверка:* `docker compose up` поднимает оба процесса; игра
      с компьютером доступна.
- [ ] 4.2 Дописать `.env.example`: секрет регистрации и его назначение.
      Пустое значение по умолчанию, с объяснением, что оно означает.
      *Проверка:* по `.env.example` с чистого листа игра поднимается,
      и поведение при пустом секрете соответствует описанному.
- [ ] 4.3 Проверить перезапуск службы посреди матча двух людей.
      *Проверка:* матч людей продолжается и доходит до исхода;
      комнаты компьютера исчезают и появляются заново.

## 5. Доказательство пользы

- [ ] 5.1 Снять линию «до»: приборами из `measure-the-tick` замерить
      задержку цикла событий сервера и разброс промежутков между
      кадрами у клиента при обычном матче с компьютером,
      **до переезда**.
      Задачу выполнять первой из всех, а не здесь по порядку: после
      переезда линию «до» снять будет негде.
      *Проверка:* таблица получена и сохранена в файл.
- [ ] 5.2 Искусственно замедлить решение противника за флагом отладки
      настолько, чтобы оно превышало бюджет тика в несколько раз.
      Замерить задержку цикла событий сервера до и после переезда.
      *Проверка:* до переезда задержка видна на сервере; после —
      только в службе, а на сервере остаётся на прежнем уровне.
- [ ] 5.3 Записать оба замера рядом в `proposal.md`.
      *Проверка:* числа в предложении получены прогоном, а не оценкой;
      если польза не подтвердилась, это записывается тоже.

## 6. Закрепление

- [ ] 6.1 `pnpm verify` целиком.
      *Проверка:* линт, типы, тесты и сборка зелёные.
- [ ] 6.2 Прогнать матч с каждой из трёх манер до исхода.
      *Проверка:* три матча завершены; в журналах обоих процессов нет
      сообщений о расхождении.
