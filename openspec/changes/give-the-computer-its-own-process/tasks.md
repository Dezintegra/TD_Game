# Задачи

Порядок продиктован одним: **сначала развязать шов, потом переезжать.**
Если сперва вынести процесс, а потом разбираться, откуда лобби узнаёт
про компьютерную сторону, посреди работы окажется нерабочая игра
без комнат компьютера.

Изменение делается **после** `measure-the-tick`: заявленная польза —
«заминка перестаёт задерживать рассылку» — проверяется приборами,
и без них она останется недоказанной.

## 1. Развязка шва в одном процессе

- [x] 1.1 Реестр личностей в `apps/server/src/computer-registry.ts`:
      манера и срок действия, ленивая уборка протухшего на чтении.
      `computerProfileOf` отвечает из него, а не обходом служб в памяти.
      *Проверка:* `computer-registry.test.ts`, 9 тестов. Среди них —
      протухание без обновления и продление обновлением. Живая проверка:
      девять дежурных объявились, все девять комнат в списке помечены
      компьютерными.
- [x] 1.2 Точки `/api/computer/declare` и `/api/computer/withdraw`.
      Снятие объявления заведено сверх задуманного: без него комнаты
      ушедшей службы висели бы в списке до истечения срока, и игрок
      минуту смотрел бы на комнату, в которую никто не войдёт.
      *Проверка:* тесты на отказ без секрета и с неверным секретом;
      причина отказа не объясняется намеренно — тому, кто подбирает
      секрет, знать, закрыта регистрация или он ошибся, незачем.
- [x] 1.3 Пустой секрет закрывает регистрацию.
      **По ходу нашёлся изъян в самом замысле, и он исправлен.**
      Задумано было «пустой секрет — личности не считаются
      компьютерными». Но служба при этом всё равно подняла бы дежурных,
      и их комнаты встали бы в списке **непомеченными**, то есть
      человеческими на вид: игрок сел бы играть с компьютером, думая,
      что играет с человеком. Недоступная игра — неприятность; игра,
      которая врёт о сопернике, — поломка обещания, на котором стоит
      вся спецификация.

      Поэтому служба теперь **начинается с рукопожатия**: посылает
      пустое объявление («а меня примут?») и нанимает дежурных только
      после согласия. Не приняли — не поднимает никого.
      *Проверка:* два теста (без секрета и с отвергнутым объявлением).
      Живая проверка при пустом секрете: комнат 0, личностей в реестре 0,
      причина названа вслух и сервером, и службой.
- [x] 1.4 Служба объявляется через ту же точку HTTP, **даже пока живёт
      в одном процессе с сервером**. Так переезд в отдельный процесс
      не изменит в этом пути ничего — а сделай мы прямой вызов
      в память, менять пришлось бы дважды.
      *Проверка:* живой сервер с секретом — 9 личностей объявлено,
      9 комнат помечено; `pnpm --filter @td/bot test` — 17 из 17.

## 5. Доказательство пользы

- [x] 5.1 Линия «до» снята **24 августа 2026**, до единой правки
      по этому изменению. Машина разработчика под Windows, соседние
      сессии работают; матч человека против роя, 5408 тиков (три
      минуты), профиль `swarm-adapt-2026-08`.

      **Задержка цикла событий — главная величина этого изменения.**
      Снята дважды: на пустом сервере и под матчем. Пол обязателен,
      без него абсолютные числа под Windows не значат ничего.

      | | пустой сервер | матч с компьютером |
      | --- | --- | --- |
      | p50 | 15,909 мс | 16,081 мс |
      | p99 | 24,576 мс | **58,884 мс** |
      | максимум | 31,982 мс | **344,195 мс** |

      Прирост над полом и есть то, что должно уйти после переезда:
      p99 больше чем вдвое (24,6 → 58,9), максимум в десять раз
      (32 → 344).

      **Остальное на том же прогоне:**

      | величина | значение |
      | --- | --- |
      | решений компьютера | 381 на 5408 тиков — ровно расписание |
      | средняя длительность решения | 4,60 мс |
      | наибольшее решение | 128,3 мс, мимо бюджета 6 из 381 (1,6 %) |
      | проходов по реестру | 11 516, наибольший 287,6 мс |
      | проходов с догоном | 179 из 10 396 (1,7 %), до 11 тиков разом |
      | шагов мира | 5714, средний 0,41 мс, наибольший 266,3 |
      | списанных долгов | 0 |

      **Осторожно с выводами из максимумов.** Наибольший шаг мира —
      266 мс у чистой функции, которая каждый тик делает одну и ту же
      работу. Такого разброса алгоритм дать не может; это сборка мусора
      и фон машины. Значит, максимум задержки цикла (344 мс) переезд
      скорее всего **не уберёт** — он больше самого долгого решения
      (128 мс) втрое. Честный ожидаемый выигрыш — в p99 и в числе
      догонов, а не в максимуме.

      Записать это здесь важнее, чем красиво: иначе после переезда
      максимум останется прежним, и работу сочтут бесполезной.
      *Проверка:* числа сняты через `/metrics`, снимок целиком —
      во временном файле прогона.
- [ ] 5.2 Искусственно замедлить решение противника за флагом отладки
      настолько, чтобы оно превышало бюджет тика в несколько раз.

      *Проверка:* до переезда задержка видна на сервере; после —
