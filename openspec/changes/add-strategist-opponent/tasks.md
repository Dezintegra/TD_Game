# Задачи

Порядок продиктован одним: **цена решения выясняется до выпуска.**
Стратег думает дороже роя, а бюджет тика уже переполнен (28 мс из 33,33
в среднем, p99 40–59). Выпустить манеру, а потом мерить, значит выпустить
заминку в живые матчи.

## 1. Манера

- [x] 1.1 Завести `STRATEGIST_PROFILE` в `packages/ai/src/profile.ts`:
      базовый профиль с `savingHorizonSeconds: 150`. В комментарии
      объяснить, почему одного числа достаточно — через достижимость
      неприкосновенного запаса, а не через «так подобралось».
      *Проверка:* в комментарии названа связь горизонта с запасом
      и приведено измеренное число ударов.
- [x] 1.2 Записать профиль в реестр `PROFILES`.
      *Проверка:* `profileByName('strategist-2026-08')` возвращает его;
      арена принимает имя в `--profiles`.
- [ ] 1.3 Тест: стратег наносит удары, базовый профиль — нет.
      Пачкой, а не одним матчем: удар — событие поздней фазы.
      *Проверка:* тест падает при возврате горизонта к сорока пяти.

## 2. Цена решения — прежде выпуска

- [ ] 2.1 Замерить стоимость решения стратега **на сервере**, а не
      на арене: собранный `dist`, прогон тиков, время каждого решения.
      Снять среднее, p99 и максимум — и те же величины для роя, чтобы
      сравнивать своё со своим.
      *Проверка:* числа приложены к изменению; способ замера описан
      так, чтобы его можно было повторить.
- [ ] 2.2 Сравнить с бюджетом тика (33,33 мс) и с долей тактов,
      не уложившихся в него. Нынешняя доля — 4,3%.
      *Проверка:* решение записано словами: выпускаем, или сперва
      удешевляем.
- [ ] 2.3 **Если прибавка неприемлема** — не выпускать манеру, а завести
      отдельное изменение на удешевление: `scanStep` перебора точек либо
      кеш полей `dijkstraField`, которые сейчас пересчитываются трижды
      на каждое решение и ничего не кэшируют.
      *Проверка:* изменение заведено с измеренными числами, а не
      с догадками.

## 3. Служба

- [ ] 3.1 Поднять третью службу в `apps/server/src/main.ts`: имя
      дежурного «Компьютер-стратег», название комнаты в пределах
      двадцати знаков.
      *Проверка:* сервер поднимается, в списке комнат три дежурных.
- [ ] 3.2 Дополнить комментарий над `startComputer`: у манер появилась
      третья, и сказать надо не «добавили», а чем она отличается
      и какими числами это подтверждено.
      *Проверка:* в комментарии есть доля побед против обеих нынешних
      манер и число ударов.
- [ ] 3.3 Проверить, что название комнаты влезает в предел.
      «Матч с компьютером» и «Матч с оплотом» уже подгонялись под него,
      и «Матч со стратегом» — семнадцать знаков.
      *Проверка:* комната создаётся; молчаливого отказа нет.

## 4. Выбор манеры у игрока

- [ ] 4.1 `playAgainstComputer` принимает необязательное имя дежурного
      и перебирает только его комнаты. Без имени — прежнее поведение.
      *Проверка:* юнит-тест на обе ветки; при занятых комнатах выбранной
      манеры возвращается отказ, а не комната другой манеры.
- [ ] 4.2 Собрать список манер из дежурных комнат по `hostName`,
      без таблицы имён в клиенте.
      *Проверка:* служба не поднята — её манеры в выборе нет.
- [ ] 4.3 Показать выбор рядом с кнопкой «Играть с компьютером»,
      не вместо неё. Кнопка остаётся умолчанием.
      *Проверка:* существующие сквозные проверки, опирающиеся
      на `practice-start`, проходят без правки.
- [ ] 4.4 Решить открытый вопрос из `design.md`: прятать ли выбор,
      когда манера одна, и нужна ли подпись к манере. Решать на снимке
      экрана, а не рассуждением.
      *Проверка:* решение записано в `design.md` под открытым вопросом.
- [ ] 4.5 Цвета, отступы и шрифты — только токенами из `tokens.css`.
      *Проверка:* в правке нет цветовых литералов.
