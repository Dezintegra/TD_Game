## Context

Windows Codex 0.153.4 elevated разрешает запись в существующий файл вне cwd по точечному filesystem grant. Создание отсутствующего файла всё равно требует записи в родителя. Проверено отдельными пробами: absent EPERM, precreated write/unlink exit 0.

## Goals / Non-Goals

Обеспечить обязательный замер в назначенном дереве с общими замком и историей. Не расширять разрешения на main целиком и не переносить историю.

## Decisions

Супервизор создаёт только отсутствующие файлы через wx до проверки среды и назначения этапа Codex. Существующий обычный файл не трогает; каталоги и ссылки отвергает. Пути общие .perf-lock и .perf-log.jsonl, переопределение PERF_LOG разрешается относительно cwd этапа, как раньше.

Профиль Codex разрешает запись только в эти файлы дополнительно к существующим Git-путям. Для Linux используются те же дополнительные writable_roots. Замок освобождается обнулением существующего файла: пустой замок уже считается свободным currentHolder. Сохраняются файловая идентичность и ACL. Повторный вызов release ничего не меняет; чужой PID не очищается.

Выдавать запись на весь main нельзя: это затронет конфигурацию конвейера и секреты. Перенос в новый общий каталог усложняет совместимость старых деревьев и историю без необходимости.

## Risks / Trade-offs

Старый perf-run может удалить общий файл после подготовки нового этапа → замер безопасно остановится; перед следующим этапом файл будет восстановлен. Одновременный запуск старой и новой версии замеров во время обновления не допускается; текущий конвейер на паузе, замер не начался.

## Migration Plan

Узкие тесты и реальная проба Windows; все проверки CI финального коммита; вливание. Супервизор переносит ожидающие отчёты перед штатным перезапуском. Повторная выкладка подтверждается сценами и серверным health. Откат коммита сохраняет историю; пустой замок совместим со старым читателем.

## Дополнение: подготовка свежего дерева

Проверка импорта в свежем дереве подтвердила ERR_MODULE_NOT_FOUND для @td/shared/dist/index.js. pnpm install не создаёт dist. Сам perf-run перед настоящим замером собирает только внутренние packages через pnpm recursive в топологическом порядке и с одним рабочим процессом, до проверки тишины. Проверка --check-only и чтение истории сборку не запускают. Это подготовка сервера замера, а не полный verify или сборка приложения; Turbo и общий кэш не требуются. Ошибка подготовки завершает замер до замка и сцен.

## Дополнение: запуск служб без наблюдения за исходниками

Реальный прогон дошёл до свободных портов при CPU 7%, затем tsx watch упал в os.userInfo (uv_os_get_passwd ENOMEM). Проба повторила ошибку на Node 24.3 и 24.19. Для неизменяемого снимка выкладки watch не нужен: perf-подготовка компилирует также @td/server и @td/computer, а perf-конфигурация запускает их существующими start-командами (node dist/main.js). Клиент остаётся Vite, игровые сцены и GPU-флаги прежние. Обычная разработка и обычный e2e продолжают использовать dev. Права sandbox не меняются.
