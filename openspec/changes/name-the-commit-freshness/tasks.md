# Шаги реализации

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе.
Черновой pull request открывается **сразу после шага 1**: до его открытия
проверки CI на пуши в ветку не запускаются вовсе.

## Чем здесь можно проверять

Правила разрешений конвейера (`supervisor/config/stage-settings.json`)
пропускают `pnpm install`, `pnpm test:pipeline`, `npx vitest`,
`npx prettier`, `npx eslint`, `git` и `gh pr`. Проверки шагов написаны
только ими: в автономной сессии отказ не ждёт человека, а тихо меняет
результат этапа, и шаг отмечается сделанным без единой проверки.

Набор проверок инструмента зовётся с указанием своего корня —
`npx vitest run --root supervisor`. Без ключа `--root` обычный `vitest`
файлов `supervisor/**/*.test.mjs` не видит вовсе и зеленеет впустую.
Равнозначная форма — `pnpm test:pipeline`, за ней стоит та же команда.

Перед первым прогоном нужен `pnpm install --frozen-lockfile`: в новом
рабочем дереве своих `node_modules` нет, а `vitest` берётся оттуда.

## 1. Абзац о следе во всех десяти скиллах

- [ ] Заменить в разделе «Отчёт» каждого из десяти файлов
      `supervisor/skills/*.md` — `audit`, `benchmark`, `deploy`, `design`,
      `implement`, `interpret`, `postmortem`, `review`, `revise`,
      `triage` — пункт 2 перечня «Отменяют отчёт два случая» на текст,
      приведённый в `design.md`.
- [ ] Проверить, что заменены **все десять**, а не те, что попались:
      поиск по прежней формуле «коммит в ветке без хвоста» обязан
      не давать ни одного совпадения по всему дереву.
- [ ] Прочих строк скиллов не трогать. Правка касается ровно одного
      абзаца; попутные улучшения текста сделают конфликт с задачей 0152
      неразрешимым механически.

**Проверка.** Поиск «коммит в ветке без хвоста» по дереву пуст; поиск
«не раньше начала этапа» даёт ровно десять файлов.
`npx prettier --check "supervisor/skills/*.md"` зелёный.

**После этого шага** — коммит, отправка и черновой pull request:
`gh pr create --draft --base main`.

## 2. Сторож согласия правил с таблицей следов

- [ ] Объявить `TRACE` в `supervisor/lib/denials.mjs` экспортируемой
      (`export const TRACE`). Ничего другого в файле не менять: проверка
      следа верна и предметом задачи не является.
- [ ] Завести в `supervisor/config/transitions.test.mjs`, в блоке
      `describe('этапы и скиллы')`, проверку: у каждого этапа, чей след
      в `TRACE` равен `'commit'`, файл правил содержит «не раньше начала
      этапа» и не содержит прежней формулы. Отставшие называть поимённо,
      списком, а не первым попавшимся.
- [ ] Комментарий к проверке пишет **почему**, а не что: назвать заметку
      0151 и цену расхождения — отброшенный отчёт и потерянную работу
      этапа.
- [ ] Завести пробу на порчу второй проверкой — на выдуманном тексте,
      а не правкой настоящих файлов: мерка обязана называть отставшим
      текст с прежней формулой и молчать на тексте с новой. Сторож,
      не краснеющий на сломанном входе, — украшение.

**Проверка.** `npx vitest run --root supervisor` зелёный, и в его выводе
видны обе новые проверки. `npx prettier --check` по обоим правленым
файлам зелёный. `npx eslint supervisor/lib/denials.mjs
supervisor/config/transitions.test.mjs` зелёный.

## 3. Зелёный CI на pull request

- [ ] Дождаться проверок: `gh pr checks <номер> --watch`. Красное чинить
      отдельным атомарным коммитом, а не дописывать к прежнему.

**Проверка.** Все задачи CI зелёные. Задача не сделана, пока GitHub
не сказал «зелено», — локального прогона здесь недостаточно.
