## ADDED Requirements

### Requirement: Правила этапа излагают след коммитящих этапов со свежестью коммита

Правила этапа SHALL излагать след design и revise тремя условиями сразу:
ветка задачи есть у удалённого репозитория, неотправленных коммитов в ней
нет, и есть собственный коммит, сделанный не раньше начала этапа.

Для implement правила SHALL называть свой коммит, сделанный не раньше
начала этапа, ЛИБО впервые открытый pull request. Наличие удалённой ветки
без неотправленных коммитов SHALL быть обязательным для обеих альтернатив.
Свежесть SHALL относиться к коммитной половине. Требовать свежий коммит
вдобавок к впервые открытому PR MUST NOT.

Правила SHALL явно говорить, что прежние коммиты ветки не закрывают
коммитную половину, а ранее известный задаче PR не закрывает половину PR.
Объявлять след одним лишь «коммитом в ветке без хвоста», умалчивая
о свежести или альтернативе PR для implement, MUST NOT.
Коммит одного лишь освежения базы собственным результатом этапа
считаться MUST NOT.

Изложение SHALL совпадать с таблицей следов инструмента. Согласие всех
десяти копий общей формулы SHALL стеречься проверкой: проверка SHALL
различать типы commit и commit-or-pr, брать перечень этапов из таблицы
следов инструмента и проверять свежесть коммитной половины у обоих типов.
Объявлять независимый список коммитящих этапов в проверке MUST NOT.

#### Scenario: Сессия читает, чем закрывается её этап

- **WHEN** сессия design, implement или revise читает правила о следе
- **THEN** она видит требование удалённой ветки без хвоста и свежесть
  собственного коммита; для implement также явно названа альтернатива
  впервые открытого PR без нового коммита

#### Scenario: Этап пришёл в ветку с чужими коммитами

- **WHEN** implement получает коммиты проработки, своих коммитов не делает
  и не открывает впервые PR (PR отсутствует или уже известен задаче)
- **THEN** правила называют след отсутствующим и предписывают failed
  с причиной, а не done

#### Scenario: Имплементация впервые открыла pull request без нового коммита

- **WHEN** implement приходит к готовой правке проработки, нового коммита
  не делает, впервые открывает PR и имеет удалённую ветку без хвоста
- **THEN** правила признают след и разрешают done без пустого
  или выдуманного коммита

#### Scenario: Свежий коммит закрывает коммитную половину имплементации

- **WHEN** implement сделал собственный коммит не раньше начала этапа
  и отправил ветку без хвоста, а PR уже был известен
- **THEN** правила признают коммитную половину следа без требования нового PR

#### Scenario: Первый pull request не заменяет отправку ветки

- **WHEN** implement впервые открыл PR, но ветки нет у удалённого
  репозитория либо остались неотправленные коммиты
- **THEN** правила называют след отсутствующим и предписывают failed

#### Scenario: Альтернатива pull request не распространяется на другие этапы

- **WHEN** design или revise не сделал собственного свежего коммита,
  хотя в ветке есть прежние коммиты и впервые открытый PR
- **THEN** правила не признают PR заменой коммитного следа этого этапа

#### Scenario: Правку внесли не во все правила разом

- **WHEN** в одной из десяти копий формулы исчезла свежесть коммитной
  половины implement, альтернатива PR или общая оговорка о ветке без хвоста
- **THEN** проверка падает и называет отставшие файлы поимённо

#### Scenario: Таблица следов пополнилась коммитящим этапом

- **WHEN** в таблице появляется новый этап типа commit или commit-or-pr,
  а его правила не называют соответствующие условия следа
- **THEN** проверка падает и называет этот этап
