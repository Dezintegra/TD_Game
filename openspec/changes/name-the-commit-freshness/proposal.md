# Назвать в скиллах свежесть коммита

## Why

Правила этапов не называют свежесть коммита. Исходный план 0153 исправлял
это общей формулой для design, implement и revise. После вливания 0152
(PR 129) эта формула противоречит приёмке: implement вправе впервые
открыть PR без нового коммита. Задача 0170 согласует существующий план
с уже принятым решением, сохраняя свежесть коммитной половины.

## What Changes

- Для design/revise: собственный коммит не раньше начала этапа, удалённая
  ветка без хвоста.
- Для implement: такой коммит ЛИБО впервые открытый PR; удалённая ветка
  без хвоста обязательна в обоих случаях.
- Сценарий про чужие коммиты различает первый PR и отсутствие обеих
  альтернатив. Уже известный задаче PR новым следом не считается.
- Формула во всех десяти скиллах и сторож учитывают оба типа TRACE:
  commit и commit-or-pr.

## Capabilities

Сохраняются способность dev-pipeline-worker и существующее ADDED-требование
«Правила этапа излагают след коммитящих этапов со свежестью коммита».
Способность ещё отсутствует в основных спецификациях, но уже заведена
открытыми изменениями; новую способность не создаём.
Дельта необходима: меняется нормативное чтение открытого требования,
которое раньше безусловно предписывало implement failed без нового коммита.

## Non-goals

- Не менять алгоритм приёмки, отметку начала этапа и смысл новизны PR.
  В denials.mjs допускается только запланированный экспорт TRACE.
- Не требовать пустых коммитов и не распространять альтернативу PR на design/revise.
- Не архивировать изменения и не выполнять сведение требований задачи 0164.
- Не исправлять посторонние правила и не менять игру.

## Impact

Реализация затронет десять supervisor/skills, экспорт TRACE
в supervisor/lib/denials.mjs и supervisor/config/transitions.test.mjs.
На проработке меняются только артефакты этого изменения.

## Влияние на отзывчивость интерфейса и на сетевой трафик

Влияния нет: клиент, сервер, симуляция и протокол не затронуты.
Правила агентских этапов не участвуют в обработке кадра и передаче команд.

## Зависимость от других изменений

Изменение архивируется ПОСЛЕ `judge-denials-by-deeds`.
Его требования о действующей приёмке и двух половинах implement сохраняются;
наша дельта уточняет свежесть. Сведение при архивации остаётся задачей 0164.

Артефакты взяты из a70c6a8 ветки
worktree-0153-nazvat-v-skillah-svezhest-kommita-sled-k в назначенное дерево
0170: на свежей origin/main 3cccea2 их ещё нет. Это редакция того же
изменения, а не второе изменение. Ветка и дерево 0153 не изменяются.
Перед возобновлением 0153 её исполнитель должен сверить редакцию 0170:
старый план нельзя независимо реализовать поверх исправленного.
