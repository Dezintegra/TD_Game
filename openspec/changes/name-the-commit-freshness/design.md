# Проектное решение

## Context

В свежей главной ветке TRACE задаёт implement тип commit-or-pr.
Приёмка сначала требует удалённую ветку без хвоста, затем принимает
свежий коммит либо новый относительно previousPr номер PR.
Исходный сторож плана 0153 отбирал только commit и уже пропускал implement.

## Goals / Non-Goals

Сохранить свежесть и альтернативу первого PR во всех артефактах и копиях
формулы. Алгоритм приёмки, игровой код и порядок архивации не менять.

## Decisions

### Формула для шага 1

Пункт 2 раздела об отказах во всех существующих скиллах из NEEDS_SESSION
(сейчас одиннадцать, включая decompose.md) получает следующий текст:

> **отсутствие следа этапа при исходе `done`.** След объявлен поимённо:
> проработке и доработке — свой коммит, сделанный не раньше начала этапа;
> имплементации — свой коммит, сделанный не раньше начала этапа, ЛИБО
> впервые открытый pull request. Для обеих половин следа имплементации,
> как и для проработки и доработки, ветка задачи обязана быть у удалённого
> репозитория и не иметь неотправленных коммитов. Коммиты, лежавшие в ветке
> до начала этапа, коммитную половину не закрывают; ранее известный задаче
> pull request новым следом не считается. Аудиту и ревью — ветка без хвоста;
> замеру — новый номер прогона; сортировке, толкованию, разбору и выкладке
> следа не положено вовсе, и отказ у них всегда попутный, но с отметкой
> в журнале задачи.

«Не раньше начала этапа» сохраняется вместо «сегодня»: сутки не совпадают
с длительностью этапа. «Свой» отличает результат работы от освежения базы;
действующий запрет считать один коммит слияния следом сохраняется.
Обязательный коммит у implement отвергнут: теряется законный первый PR.
Формула «все три условия ЛИБО PR» отвергнута: позволила бы скрыть хвост.

### Сторож

Экспортировать существующую TRACE без изменения значений и алгоритма.
В transitions.test.mjs расширить существующие средства чтения формулы
и сторож двух половин. Отбирать из TRACE оба типа: commit и commit-or-pr.
У второго проверять свежесть коммитной половины и альтернативу PR.
Проверять все существующие копии общей формулы полным обходом NEEDS_SESSION,
называя каждый отставший файл. Сейчас это одиннадцать файлов, включая
decompose.md, добавленный реализацией decompose-before-design. Число
одиннадцать описывает текущий состав, но не ограничивает обход.
NEEDS_SESSION определяет файлы, а TRACE — коммитящие этапы внутри формулы:
добавление decompose.md в обход не добавляет коммитный след декомпозиции.
Отсутствующая формула также считается ошибкой, файл пропускать нельзя.

Сверять нормализованный абзац с различением частей design/revise и implement:
упоминания свежести где-нибудь в файле недостаточно, оно может относиться
только к design. Существующая проверка PR сохраняется либо расширяется
без ослабления её защиты.
Независимый список этапов и отбор только commit отвергнуты: пропускают
изменения таблицы. Дословная сверка отвергнута: переносы и пунктуация
не меняют смысла.
Фиксированный перечень десяти или одиннадцати файлов отвергнут: следующая
копия, добавленная вместе с этапом в NEEDS_SESSION, выпала бы из защиты.

### Проверяемые случаи

| Случай | Ожидается |
| --- | --- |
| design/revise: старые коммиты, даже с первым PR | Следа нет |
| implement: свой свежий коммит, удалённая ветка без хвоста | След есть |
| implement: старые коммиты, первый PR, удалённая ветка без хвоста | Законен done |
| implement: старые коммиты, PR отсутствует или уже известен | failed с причиной |
| implement: первый PR, но нет удалённой ветки или остался хвост | Следа нет |
| Одна копия потеряла свежесть только у implement или альтернативу PR | Сторож называет файл |
| Одна копия потеряла общую оговорку о ветке без хвоста | Сторож называет файл |
| Только decompose.md потерял свежесть коммитной половины implement | Сторож называет decompose.md |
| В NEEDS_SESSION добавлен скилл без общей формулы либо с формулой без свежести | Сторож называет новый файл |
| Новый этап типа commit или commit-or-pr без нужных правил | Сторож называет этап |

Пробы на порчу используют синтетические тексты и таблицы, не изменяя
настоящие файлы во время теста. Корректный текст и переносы строк проходят.
Отдельная проба проверяет полный обход: набор текстов скиллов строится
по NEEDS_SESSION, портится только копия decompose.md, и проверка возвращает
этот файл. Добавление синтетического этапа в перечень скиллов также должно
расширять проверяемый набор; отсутствие формулы не отфильтровывается.
Приёмка уже реализована: повторно писать её алгоритм в тесте не требуется.

## Risks / Trade-offs

- Ветка 0153 содержит прежнюю редакцию: перед её возобновлением сверить
  план с 0170; всю чужую ветку не сливать.
- Соседние изменения правят скиллы и transitions.test.mjs: освежать базу
  по правилам этапа, сохранять действующие сторожи.
- ADDED пересекается с judge-denials-by-deeds: архивировать после него
  с учётом задачи 0164, не писать MODIFIED поверх отсутствующей основы.

## Migration Plan

Два атомарных шага: формула во всех скиллах, затем сторож и экспорт TRACE.
После первого коммита имплементация открывает черновой PR.
Ожидание CI ведёт супервизор. Откат — соответствующие коммиты,
без миграций данных и протокола.

## Ограничения игры

Рассинхрон и реконнект неприменимы: геймплей не задет.
packages/sim не меняется, эталоны детерминизма не обновляются.
Раскладка байтов прежняя, PROTOCOL_VERSION не повышается.
Math.random, Date.now и числа с плавающей точкой в состояние мира
не добавляются: изменение находится вне ядра.
