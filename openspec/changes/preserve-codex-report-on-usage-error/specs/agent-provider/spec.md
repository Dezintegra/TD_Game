## ADDED Requirements

### Requirement: Итоговый текст Codex сохраняется независимо от ошибки учёта

Адаптер Codex SHALL сохранять доступный итоговый текст текущего успешно завершённого хода в result даже при ошибке учёта расхода. Неизвестность SHALL передаваться отдельно от текста с конкретной причиной из общего расчёта и долговечного status полноты `reconcile-codex-token-usage`; при непроверенном обязательном бюджете outcome SHALL оставаться failed. Наличие result MUST NOT отменять проверку терминального события, кода процесса, снятия, ошибки запуска или протокола и MUST NOT разрешать применение отчёта при непроверенном обязательном бюджете. Арифметика и долговечная полнота 0236, лимиты и правила продолжений SHALL сохраняться; baseline этапа MUST NOT возвращаться как источник истины.

#### Scenario: Уменьшение usage при доступном тексте

- **WHEN** при включённом бюджете текущий ход дал agent_message и turn.completed, процесс завершился кодом 0 без иных ошибок, а общий reducer обнаружил новое уменьшение input либо output относительно сопоставимого снимка thread
- **THEN** result содержит исходный итоговый текст без изменения, outcome равен failed и отдельно названа ошибка учёта
- **AND** наличие числовых полей usage не означает известный расход запуска

#### Scenario: Отсутствует обязательный usage

- **WHEN** при включённом токеновом лимите успешно завершённый ход оставил текст, но не сообщил обязательный usage либо сообщил непригодные поля
- **THEN** текст сохранён в result, outcome равен failed, отдельно указано, почему бюджет нельзя проверить

#### Scenario: Уменьшился только cached

- **WHEN** при полной истории текущий успешно завершённый ход уменьшил только cached, сохранив input/output
- **THEN** текст сохраняется и расход остаётся известным по арифметике 0236; диагностическое замечание о cached само по себе не делает outcome failed

#### Scenario: Валидный снимок после долговечной неполноты

- **WHEN** при включённом бюджете после ранее сохранённой неполноты приходит успешно завершённый ход с текстом и валидным большим снимком
- **THEN** текст сохраняется, но неполнота задачи и её причины не сбрасываются; отчёт не допускается к применению, итоговый ответ равен failed

#### Scenario: Некорректный JSON также сохраняется

- **WHEN** в любом из случаев ошибки учёта итоговый текст не является корректным отчётом JSON
- **THEN** адаптер сохраняет его без изменения вместе с ошибкой учёта, не выдавая его за успешно принятый отчёт

#### Scenario: Текст не доказывает завершение

- **WHEN** есть agent_message, но нет успешного терминального события текущего хода, код процесса ненулевой, процесс снят либо произошла ошибка запуска или протокола
- **THEN** ответ не становится done и текст не допускается к применению
- **AND** после нового turn.started сообщение предыдущего хода не становится result нового хода

#### Scenario: Штатный ответ и выключенный лимит

- **WHEN** процесс и текущий ход успешно завершены без ошибки учёта
- **THEN** прежний успешный путь сохраняется; отсутствие usage при выключенном лимите само по себе не превращает ответ в failed, но не делает расход известным
