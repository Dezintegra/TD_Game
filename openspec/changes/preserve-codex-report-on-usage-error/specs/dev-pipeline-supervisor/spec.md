## ADDED Requirements

### Requirement: Ошибка учёта не скрывает ответ и не изображает принятие отчёта

Супервизор SHALL разбирать сохранённый итоговый текст один раз до журналирования и ранних возвратов. При ошибке учёта журнал этапа SHALL сохранять этот текст без изменения и отдельно называть неизвестность расхода и её причину; известная сумма реестра MUST NOT выдаваться за полный расход текущего запуска. Журнал этапа и итог консоли SHALL отличать объявленный исход отчёта от его неприменения. Корректный JSON done при ошибке учёта MUST NOT получать спокойную метку успешного этапа или попадать в очередь применения. Причина ошибки учёта и неприменение SHALL также попадать в журнал цикла.

Существующие проверки этапа отчёта, кода процесса, сроков и бюджета SHALL сохраняться, как и исходные stdout, stderr и отказанные действия в журнале. Сохранение диагностического текста MUST NOT означать автоматическое повторное применение после паузы или перезапуска.

#### Scenario: Корректный done при ошибке учёта

- **WHEN** успешно завершённый ход оставил корректный JSON done своего этапа, но usage уменьшился по действующей проверке либо обязательный usage отсутствует или непригоден
- **THEN** журнал этапа содержит исходный текст, объявленный done с пометкой «не применён», ошибку учёта и неизвестность расхода
- **AND** консоль показывает неприменение с предупреждающей меткой, журнал цикла называет причину, а очередь применения не получает отчёт

#### Scenario: Некорректный JSON при ошибке учёта

- **WHEN** итоговый текст при ошибке учёта не разбирается как отчёт
- **THEN** текст сохраняется, журнал этапа и консоль называют причину разбора и ошибку учёта, не утверждая, что сессия ответа не оставила
- **AND** очередь применения остаётся пустой

#### Scenario: Ошибка учёта и чужой этап

- **WHEN** сохранённый JSON при ошибке учёта называет этап, отличный от назначенного
- **THEN** диагностика сохраняет оба имени этапов, ошибку учёта и явное неприменение, а метка остаётся предупреждающей

#### Scenario: Числовой usage с неизвестным расходом

- **WHEN** адаптер сохранил числовые поля usage, но сообщил ошибку учёта
- **THEN** журнал и консоль показывают расход запуска неизвестным с причиной независимо от наличия этих чисел

#### Scenario: Отсутствующий ответ и штатный успешный ответ

- **WHEN** итогового текста нет вовсе
- **THEN** прежнее сообщение об отсутствии ответа остаётся допустимым
- **WHEN** сохранён корректный done своего этапа без ошибки учёта и процесс успешно завершён
- **THEN** сохраняются прежняя передача отчёта на дальнейшую проверку и метка консоли; само журналирование не объявляет результат дальнейшей проверки принятым
