## ADDED Requirements

### Requirement: Ошибка учёта не скрывает ответ и не изображает принятие отчёта

Супервизор SHALL разбирать сохранённый итоговый текст один раз до журналирования и ранних возвратов. При ошибке учёта журнал этапа SHALL сохранять этот текст без изменения и отдельно называть неизвестность расхода и её причину; известная сумма реестра MUST NOT выдаваться за полный расход текущего запуска. Источником полноты SHALL служить долговечный status 0236 после обработки наблюдений запуска, а не наличие числового usage или валидного последнего снимка. Журнал этапа и итог консоли SHALL отличать объявленный исход отчёта от его неприменения. Корректный JSON done своего этапа при неполноте учёта SHALL получать обычный допуск к очереди при успешном завершении процесса и сохранении ledger независимо от наличия лимита. Причина неполноты SHALL также попадать в журнал цикла. Ошибка записи ledger SHALL запрещать приёмку и показываться как отдельная причина неприменения, в том числе при отключённом лимите.

Существующие проверки этапа отчёта, кода процесса, сроков и бюджета SHALL сохраняться, как и исходные stdout, stderr и отказанные действия в журнале. Сохранение диагностического текста MUST NOT означать автоматическое повторное применение после паузы или перезапуска.

#### Scenario: Корректный done при ошибке учёта

- **WHEN** при включённом бюджете успешно завершённый ход оставил корректный JSON done своего этапа, но reducer 0236 обнаружил уменьшение input/output, обязательный usage отсутствует или непригоден либо долговечный status задачи остаётся неполным
- **THEN** журнал этапа содержит исходный текст, done и отдельную диагностику неизвестности расхода
- **AND** консоль показывает обычную метку по исходу отчёта, журнал цикла называет неполноту, а очередь получает результат для штатной проверки и переноса

#### Scenario: Некорректный JSON при ошибке учёта

- **WHEN** при включённом бюджете итоговый текст при ошибке учёта не разбирается как отчёт
- **THEN** текст сохраняется, журнал этапа и консоль называют причину разбора и ошибку учёта, не утверждая, что сессия ответа не оставила
- **AND** очередь применения остаётся пустой

#### Scenario: Ошибка учёта и чужой этап

- **WHEN** при включённом бюджете сохранённый JSON при ошибке учёта называет этап, отличный от назначенного
- **THEN** диагностика сохраняет оба имени этапов, ошибку учёта и явное неприменение, а метка остаётся предупреждающей

#### Scenario: Числовой usage с неизвестным расходом

- **WHEN** в ответе есть числовые поля usage, но общий расчёт или долговечный status сообщил неполноту
- **THEN** журнал и консоль отдельно называют неизвестность запуска или неполноту задачи с её причиной независимо от наличия чисел

#### Scenario: Историческая неполнота не скрывается последним снимком

- **WHEN** при включённом бюджете после сохранённого unknown текущий ход завершился с валидным большим снимком и корректным done
- **THEN** finish сохраняет текст и историческую причину, допускает успешный ответ к очереди; следующий цикл переносит результат вместо повторного запуска

#### Scenario: Замечание о cached не является бюджетным отказом

- **WHEN** история полна, input/output не изменились, уменьшился только cached и текущий ход оставил корректный done своего этапа
- **THEN** замечание 0236 не показывается как неизвестный расход или неприменение; отчёт проходит обычный допуск при успешных проверках процесса

#### Scenario: Отсутствующий ответ и штатный успешный ответ

- **WHEN** итогового текста нет вовсе
- **THEN** прежнее сообщение об отсутствии ответа остаётся допустимым
- **WHEN** сохранён корректный done своего этапа без ошибки учёта и процесс успешно завершён
- **THEN** сохраняются прежняя передача отчёта на дальнейшую проверку и метка консоли; само журналирование не объявляет результат дальнейшей проверки принятым
