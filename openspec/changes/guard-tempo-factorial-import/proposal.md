## Why

Импорт `scripts/experiment/tempo-factorial.mjs` ради `cells`, `shardOf` и `FACTORS` исполняет верхнеуровневый прогон: удаляет каталоги ячеек, запускает арену и пишет результаты. Поэтому быстрый тест матрицы небезопасен; именно это оставило проверку шага 3.3 `pay-towers-for-kills` без автоматизации.

## What Changes

- Разделить вычисление матрицы и исполнение CLI внутри существующего файла: запуск допускается только при прямом вызове файла.
- Сохранить существующие экспорты, значения факторов, нумерацию ячеек, распределение по долям и поведение командной строки.
- Добавить быстрые регрессионные проверки безопасного импорта и прямого запуска с подменёнными внешними эффектами.

## Non-goals

Не добавлять `killBounty` или другие множители, не менять баланс, алгоритм замера, метрики, формат результатов, workflow арены, конфигурацию Vitest и обработку ошибочных CLI-параметров. Не запускать настоящие матчи для проверки рефакторинга.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `build-tooling`: добавить требование безопасного импорта факторного инструмента при сохранении прямого CLI-запуска.

## Impact

Реализация затрагивает `scripts/experiment/tempo-factorial.mjs` и новый `scripts/experiment/tempo-factorial.test.mjs`. Зависимости и сборка не меняются; используется существующий тестовый корень scripts.

Отзывчивость интерфейса и сетевой трафик игры не меняются: инструмент не входит в клиент, сервер или ядро. Безопасный импорт исключает непреднамеренную нагрузку ареной на рабочую станцию.

## Пересечения и зависимости

База освежена до `origin/main` (`b08fd3b6`); предмет сохраняется. `openspec list` и поиск по открытым артефактам не обнаружили другого изменения безопасного импорта. Существующие изменения `verify-install-within-assigned-workspace` и `pass-arena-tuning-through-workflow` не задают этот контракт.

Связанный PR 112 открыт, его отправленная ветка `origin/worktree-0012-energy-for-kills` добавляет в этом же файле только комментарий и `FLAG_OF.killBounty`. На main этой записи и каталога `pay-towers-for-kills` ещё нет. Наш рефакторинг сохраняет таблицу на месте и не требует PR 112: базовый контракт проверяется через поддерживаемый `baseHp`. Когда обе работы присутствуют в проверяемой базе, тест проверяет также точную развёртку `killBounty: [1, 2, 4]`; отсутствие множителя до вливания 0012 не объявляется его поддержкой. Чужие задачи не отмечаются выполненными. Зависимости порядка архивации нет: наше ADDED-требование опирается на существующую способность.
