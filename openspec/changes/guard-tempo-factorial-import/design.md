## Context

На освежённой базе `b08fd3b6` экспортированные функции находятся над разбором `process.argv` и верхнеуровневым циклом. `runCell` удаляет каталог, вызывает `execFileSync`, читает SQLite и пишет результат. Даже перенос только цикла оставил бы при импорте разбор чужих аргументов и вывод. Статический импорт `node:sqlite` также загружает ненужную вычислению матрицы зависимость.

## Goals / Non-Goals

Цель — безопасно импортировать существующие три экспорта и проверять их быстрым набором scripts; прямой запуск сохраняет прежнее поведение. Не меняются CLI-контракт, факторы, метрики, политика ошибок и игровой код. Полный перечень границ — в proposal.

## Decisions

### Оставить один файл с явной границей исполнения

Вынести разбор аргументов, загрузку SQLite и исполняемую часть в асинхронную функцию запуска. Звать её только при наличии `process.argv[1]` и совпадении `import.meta.url` с URL разрешённого пути точки входа, используя `resolve` и `pathToFileURL`. Это учитывает относительный путь, Windows-разделители и пробелы; сравнение имени файла или суффикса недостаточно. Пустой argv означает импорт, не запуск. Сохранить завершение асинхронной работы через top-level await внутри защищённой ветки.

`FACTORS`, `FLAG_OF`, `cells`, `shardOf` остаются на прежнем месте; публичный путь и сигнатуры трёх экспортов сохраняются. Функции запуска и чтения метрик могут быть локальными внутри функции запуска, чтобы `DatabaseSync` загружался динамически только при запуске. Константы путей и чистые объявления сами по себе допустимы; операции с диском, вывод и обработка CLI — только за границей исполнения.

Альтернатива — соседний модуль матрицы: устраняет побочные эффекты нового импорта, но оставляет опасным прежний путь и переносит `FLAG_OF`, которую уже меняет PR 112. Защита только через переменную среды теста отвергнута: обычные потребители оставались бы небезопасными. Новый пакет или новая конфигурация тестов не нужны.

### Сохранить CLI без расширения поведения

Перенести существующую логику без изменения порядка действий: прежние defaults, `--factors`, `--only` с приоритетом над shard, распределение modulo, run → ingest → чтение метрик → запись накопленных результатов. Сохраняются поля JSON, обработка ошибки отдельной ячейки и очистка в finally. Не исправлять заодно диапазоны аргументов и отсутствие записи при пустом выборе.

### Проверки должны оставаться безопасными даже при возврате дефекта

В `tempo-factorial.test.mjs` до динамического импорта установить Vitest-подмены `node:child_process`, используемых операций `node:fs` и `node:sqlite`, а вывод перехватывать spy. Сбрасывать кеш модулей между сценариями и восстанавливать argv/spy после них. Подмены предотвращают настоящий прогон и удаление даже при удалённой защите.

При обычном импорте подставить argv чужого тестового файла с заведомо невалидным `--factors`: импорт должен пройти, не разбирая эти аргументы. Проверить отсутствие вызовов процессов, файловых операций, открытия БД и вывода инструмента. Отдельно проверить отсутствие argv[1]. Контроль чувствительности — временное удаление защиты делает этот тест красным, не вызывает реальных эффектов; контрольную правку не коммитить.

Матрица: точные пять наборов FACTORS; 243 ячейки, c000/c242 и порядок вложенного перебора; точное декартово произведение двух факторов; `baseHp: [1, 2, 4]` даёт три точных объекта; неизвестное имя бросает; `shardOf` даёт ожидаемые id без перестановки и мутации исходного списка. Ожидания не вычислять повторением проверяемого алгоритма.

Прямой запуск проверить через повторный динамический импорт с argv[1], указывающим на реальный файл (относительный и абсолютный путь). Подмены предоставляют фиксированные строки SQLite; выполняется одна или две искусственные ячейки. Проверить точные аргументы run и ingest, параметры seed/matches/profiles/jobs, фильтрацию `--only`, выбранную долю, путь `--out`, накопление JSON и очистку. Отдельный искусственный отказ execFileSync должен дать error одной ячейки и позволить следующей завершиться. Это интеграция точки входа с подменённым вводом-выводом, не матчевый прогон. Экспортировать функцию запуска только ради обхода проверки точки входа не требуется.

### Отношение к 0012

Прочитаны отправленные tasks и diff PR 112. Упомянутая проверка killBounty относится к записи FLAG_OF в 0012, а не к изменению defaults. На текущей базе она ещё закономерно бросает. Не переносить эту запись отдельно от игрового множителя. Если 0012 уже влита к реализации, добавить безусловный тест точных трёх ячеек killBounty; если нет — зафиксировать это в отчёте реализации и использовать безусловный сценарий baseHp. Не писать тест, который ловит любое исключение killBounty и объявляет успех: он скрыл бы регрессию после интеграции. Последующий PR 112 должен сохранить защиту запуска; наш PR при обратном порядке сохраняет добавленную запись.

## Risks / Trade-offs

- Защита может ошибочно отключить CLI → положительные проверки прямого входа и отрицательные проверки импорта используют тот же файл.
- Подмена процессов может скрыть неверные аргументы → проверять конкретные argv и итоговый JSON, а не только число вызовов.
- Чужие CLI-аргументы или SQLite могут исполняться слишком рано → отдельные проверки импорта и отложенная загрузка SQLite.
- Пересечение с 0012 → оставить таблицу на месте и сверить её diff при обновлении базы; зависимости вливания и архивации нет.

## Migration Plan

Один атомарный коммит с рефакторингом и регрессионным тестом. Старый вызов `node --no-warnings scripts/experiment/tempo-factorial.mjs` сохраняется. Миграции данных нет; откат коммита возвращает прежнее поведение вместе с удалением нового теста.

Правила sim и раскладка протокола не меняются: эталоны детерминизма и PROTOCOL_VERSION не обновляются. Рассинхрон и реконнект не затронуты. Запреты Math.random, Date.now и дробного состояния мира остаются в силе: существующее измерение стеночного времени и дробные множители служебного инструмента не переносятся в ядро. Прогон баланса не нужен, поскольку правила игры не меняются.
