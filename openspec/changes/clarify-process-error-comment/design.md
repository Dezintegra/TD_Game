## Context

На актуальной `origin/main` комментарий `run-stage.mjs:121–123` смешивает событие ошибки с фактом отсутствия процесса. `startStage` сохраняет ошибку через `done(null, error)` и возвращает `child.pid`; `spawnStage` в `supervisor.mjs` проверяет `!handle?.pid` до регистрации этапа и подписки на его завершение. При наличии процесса ответ разбирается обычным порядком: снятие имеет приоритет, затем `run.error` получает причину «процесс оборвался: …».

## Goals / Non-Goals

Цель — сделать пояснение непосредственно перед `child.on('error')` согласованным с этой границей и объяснить, почему по одному событию нельзя судить о порождении.

За пределами работы — все исполняемые строки, диагностика, соседние комментарии, обработчики, порядок условий, счётчики, тесты и способы восстановления.

## Decisions

1. Написать короткий русский комментарий в существующем месте: событие `error` само по себе не означает несостоявшееся порождение; отсутствие `pid` супервизор отдельно обрабатывает как `not-born`, а ошибка уже родившегося процесса относится к обрыву сессии. Это объясняет связь двух модулей без новой логики. Альтернатива «просто удалить комментарий» оставляет границу необъяснённой и не выполняет постановку.
2. Убрать утверждение «первое лечится продолжением, второе — настройкой» целиком. Способ восстановления не выводится из одного события, а его правила эта задача не пересматривает. Альтернатива «уточнить таблицу лечения» расширяет область работы и повторяет логику супервизора.
3. Сохранить смысловой текст о границе, не обещая безусловный `failed` при сочетании ошибки со снятием процесса: существующий приоритет `killedBy` остаётся в коде. Новая проверка `pid` внутри `startStage` не нужна: она дублировала бы ответственность `spawnStage`.
4. Проверить результат просмотром diff и сверкой с `handle.pid` в `supervisor.mjs`; тест на точную прозу не добавлять, поскольку он закрепил бы формулировку вместо поведения. Состав коммита допускает только нужный комментарий и отметку выполнения собственного шага.
5. Вести изменение без дельты по обоснованию в `proposal.md`. Новая норма о комментарии ради валидатора была бы самостоятельным незапрошенным требованием.

## Risks / Trade-offs

- Общее место с `name-process-interruptions` → менять только комментарий перед обработчиком, не затрагивая уже исправленную диагностику и тесты. Порядок архивации не ограничен.
- Случайная правка обработчика либо соседнего текста → проверять полный diff индекса и созданного коммита, включая содержание разрешённых файлов.
- Комментарий снова устареет при будущей смене границы → назвать `pid` и супервизор, чтобы связь была видна следующему автору; универсальную документацию событий не создавать.

Игровые пакеты не затронуты: рассинхрон и реконнект, эталоны детерминизма и `PROTOCOL_VERSION` прежние. Запреты ядра на `Math.random`, `Date.now` и дробное состояние мира не затрагиваются, поскольку исполняемый код вообще не меняется.

## Migration Plan

Один коммит реализации с комментарием и отметкой в `tasks.md`, отправка и черновой PR по правилам этапа implement. Миграции данных нет. Для отката достаточно обратной правки комментария. Архивация позже выполняется с `--skip-specs`, за пределами design.
