# Задачи

Прогон арены шагом не делается: он заказан заявкой в отчёте этапа,
задачу-прогон заведёт супервизор. Полный набор проверок локально
не гоняется — это работа CI (правило 6 в `CLAUDE.md`); здесь названы
только точечные прогоны по своим файлам.

## 1. Число

- [ ] 1.1 В `packages/shared/src/balance.ts` заменить
      `BASE_UNIT_RANGE_CELLS = 2` на `4`. В комментарии к постоянной
      записать три вещи: что величина заказана владельцем продукта;
      что живой потребитель у неё ровно один — штурмовик, и второго
      заводить нельзя (как это уже разъезжалось со снайпером, сказано
      в комментарии к нему); что преимущество базовой башни падает
      с трёх клеток до одной и держится теперь на одной.
      В том же коммите:
      - в `packages/shared/src/balance.test.ts` — два стража: дальность
        штурмовика равна `cellsToUnits(4)`; дальность базовой башни
        строго больше дальности штурмовика (именно соотношением,
        а не сравнением с числом);
      - в `packages/ai/src/profile.match.test.ts` — ожидание
        `escortRadius` меняется с `cellsToUnits(7)` на `cellsToUnits(9)`,
        а комментарий рядом переписывается под новый вывод: пять клеток
        генерала плюс четыре штурмовика;
      - оба эталона пересняты: `packages/sim/src/determinism.golden.match.test.ts`
        и `packages/ai/src/profile.golden.match.test.ts`. У профильного
        эталона к новому числу дописывается разбор: какие наблюдаемые
        величины (постройки, войско, уровни прокачки, путь генерала)
        сдвинулись и чем это объясняется.

      Всё это одним коммитом намеренно: правка правил роняет эталоны,
      и раздельные коммиты оставили бы дерево красным, то есть
      непроверяемым (правило 4).

      _Проверка:_ четыре точечных прогона зелёные —
      `npx vitest run packages/shared/src/balance.test.ts`,
      `npx vitest run packages/ai/src/profile.match.test.ts`,
      `npx vitest run packages/sim/src/determinism.golden.match.test.ts`,
      `npx vitest run packages/ai/src/profile.golden.match.test.ts`.

## 2. Черновой pull request

- [ ] 2.1 Открыть черновой pull request на `main` сразу после первого
      коммита: `gh pr create --draft --base main --title ... --body-file ...`.
      Раньше этого проверки CI не запускаются вовсе — пуши в ветку
      без pull request не запускают ничего.
      _Проверка:_ `gh pr checks <номер>` показывает запущенные проверки.

## 3. Поведение у базы

- [ ] 3.1 Тест в `packages/sim`: штурмовик, идущий к базе противника,
      назначенной общей целью, останавливается, едва до края её
      основания остаётся четыре клетки, и наносит базе урон с этого
      расстояния. Класть рядом с существующими проверками остановки
      у назначенной цели.
      _Проверка:_ тест зелёный; и он же обязан покраснеть, если временно
      вернуть постоянной двойку — прогнать оба раза, четвёрку вернуть,
      результат обеих проверок записать в тело коммита. Тест, который
      проходит и без правки, стережёт не то, ради чего заведён.
