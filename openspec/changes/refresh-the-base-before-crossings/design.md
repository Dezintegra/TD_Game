# Проектное решение

## Где чинить: в скиллах или в супервизоре

**Решение: в скиллах этапов.**

Отвергнутый вариант — освежать дерево силами супервизора перед порождением
этапа. На первый взгляд он выглядит правильнее: дерево завёл супервизор,
ему за него и отвечать, а одно место лечило бы разом все десять этапов
вместо двух вставок в два файла.

Отвергнут по трём причинам, и каждой по отдельности хватает:

1. **Слияние не всегда проходит, а решать за конфликт супервизору нечем.**
   Он не читает содержимого файлов и не отличает конфликт в чужом
   вспомогательном файле от конфликта в предмете задачи. Всё, что он мог бы
   сделать, — уронить задачу в ошибку до начала этапа; сессия же в том же
   положении выносит осмысленный вердикт, и для аудита конфликт вообще
   не беда, а искомый результат.
2. **Слияние порождает коммит, а коммит надо отправлять.** Супервизор
   коммитит только в главную ветку и в чужие ветки не пишет вовсе —
   push-дисциплина у него написана про свою работу в `main`. Заводить ему
   право писать в ветки задач ради одного слияния значит расширить самую
   опасную его способность ради самой мелкой надобности.
3. **Гонка с живым этапом.** Дерево может быть занято продолжением
   прерванного этапа; слияние, выполненное снаружи в тот же миг, испортит
   индекс сессии, которая об этом не узнает.

Довод «одно место вместо двух» цену эту не перевешивает. Правило нужно ровно
тем двум этапам, которые проверяют пересечения, — прочим этапам свежая база
нужна по другой причине и с другой ценой ошибки (см. не-цели).

## Слияние, а не перевыкладка

**Решение: `git merge origin/main`.**

Перевыкладка (`git rebase origin/main`) отвергнута. Она переписывает хеши
уже отправленных коммитов и требует отправки с `--force-with-lease` — формы,
которая правилами разрешений покрыта, но которую скилл обязан был бы
объяснять отдельно. Выгоды от линейной истории здесь нет никакой: ветка
задачи живёт дни и вливается один раз, а её история читается по одному
коммиту на шаг `tasks.md`, и коммит слияния этому не мешает.

Слияние вдобавок безопаснее для проработки: при конфликте `merge --abort`
возвращает дерево в исходное состояние одной командой, тогда как
прерванная перевыкладка оставляет ветку в отсоединённом состоянии, из
которого автономная сессия выбирается не всегда.

Ключ `--ff-only` тоже отвергнут: он отказал бы ровно в том случае, ради
которого правило и пишется, — когда у ветки уже есть свой коммит
(проработка вернулась из аудита, аудит смотрит готовое предложение).
Шаг 6 скилла выкладки берёт `--ff-only` первым и падает на обычное слияние
вторым, но там задача другая: доказать, что дерево совпадает с тем, что
поедет на сервер.

## Куда именно вставляется правило

**Решение: внутрь существующего шага 2 обоих скиллов, без заведения нового
пункта и без перенумерации.**

У аудита шаг 2 уже называется «Подтяни ветку и убедись, что хвоста нет»
и уже зовёт `git -C <дерево> fetch origin` — подтягивание главной ложится
туда третьей строкой, и второго `fetch` не появляется. У проработки шаг 2 —
«Перейди в своё дерево», и подтягивание базы там ровно к месту: до шага 4,
на котором читается `openspec list`.

Перенумерация отвергнута нарочно. Оба файла правит прямо сейчас чужая
работа: `keep-ci-waiting-out-of-tasks` (задача 0193, pull request 135)
и `mark-every-command-block` (задача 0175, pull request 132). Новый пункт
сдвинул бы номера всех последующих шагов и превратил бы точечное слияние
в переписывание файла целиком — с настоящим конфликтом там, где сейчас
его нет.

По той же причине командный блок размечается как `powershell`: этого
требует `mark-every-command-block`, и неразмеченный блок либо конфликтовал
бы с ним, либо пережил бы его правку незамеченным.

## Сторож правила

**Решение: отдельная проверка в `supervisor/config/transitions.test.mjs`,
проверяющая присутствие подстроки в обоих файлах и называющая недостающее.**

Файл этот и есть место для сторожей текста скиллов: там уже живут проверки
«у каждого этапа с сессией есть скилл», «ни один скилл не посылает
исполнителя за слотом или отчётом на диск», «ни один скилл не показывает
коммит многострочной строкой». Заводить рядом второй файл значило бы
развести сторожей одного предмета по двум местам — задача 0176 заведена
ровно про такую беду.

Сторож проверяет **присутствие** строки, и контрольных образцов ему,
в отличие от сторожа на отсутствие, не нужно: сломанная мерка даёт пустой
поиск, пустой поиск означает «подстроки нет», и сторож краснеет. Это
противоположно случаю из `name-what-cuts-code-in-arguments`, где сломанная
мерка молча зеленела бы.

Мерка — строка `git -C <дерево> merge origin/main` целиком, вместе
с ключом `-C`. Обрезать её до слова `merge` нельзя: в скилле проработки оно
уже стоит шагом 10 — там разбирается случай, когда шаг `tasks.md` предписал
**голое** `git merge origin/main`, — и сторож по одному слову зеленел бы
на этом упоминании при полностью пропавшем правиле. В скилле аудита слова
`merge` сегодня нет вовсе, а в скилле выкладки, который этим сторожем
не проверяется, та же строка стоит по своему поводу.

Прогоняется сторож командой `pnpm test:pipeline` (`vitest run --root
supervisor`) и попадает в CI сам собой: корневой `pnpm test` зовёт
`test:pipeline` вторым звеном, а `pnpm test` стоит задачей `быстрые тесты`
в `.github/workflows/ci.yml`.

## Куда вставлять: точные места

Номера строк даны по `main` на `b9c1f19` и приведены затем, чтобы вставка
разошлась с чужой работой, а не затем, чтобы им верить слепо: место ищется
по соседнему тексту, номер лишь подсказывает, где смотреть.

- **`supervisor/skills/design.md`** — шаг 2 (строки 62–64, кончается словами
  «работает без зависимостей проекта»), вставка сразу после него и **выше**
  пустой строки перед заголовком «3. **Прочитай задачу и журнал.**».
  Чужие ветки этот файл правят в трёх местах, и все три далеко: pull request
  132 меняет ограждения блоков на строках 88, 178 и 195, pull request 135
  дописывает пункт в шаг 10 после строки 212.
- **`supervisor/skills/audit.md`** — шаг 2, **после** абзаца, кончающегося
  словами «вправе быть убрано в любой момент» (строка 77), и выше заголовка
  «3. **Прочитай задачу и журнал**». Внутрь блока строк 66–70 не лезть
  ни строкой: pull request 126 меняет там и ограждение, и третью строку,
  и вставка рядом с ними дала бы конфликт на ровном месте.
- **`supervisor/config/transitions.test.mjs`** — новый `it()` **после**
  проверки `it('проработка и аудит называют законную ошибку валидатора
дословно')` (кончается на строке 735) и перед
  `it('ответ о поведении openspec archive назван с версией и датой пробы')`
  (строка 737). Конец `describe` занят: pull request 135 дописывает туда два
  своих `it()`. Помощник `skillText` в файле уже есть — заводить заново
  не надо.

## Целевые тексты вставок

Брать дословно, вместе с отступами: сторож сверяет подстроку и читает файл
сырым.

### Скилл проработки, шаг 2 — целиком в новой редакции

````markdown
2. **Перейди в своё дерево и подтяни в него свежую главную ветку.** Всё
   дальнейшее — только там. `pnpm install` не нужен: ты не собираешь,
   не тестируешь и не запускаешь игру, а `openspec` поставлен глобально
   и работает без зависимостей проекта.

   ```powershell
   git -C <дерево> fetch origin
   git -C <дерево> merge origin/main
   ```

   Дерево завёл супервизор в миг захвата задачи, ответвив от тогдашней
   главной ветки, и больше не обновлял. К проработке оно бывает старше
   на дни, и каталогов `openspec/changes/`, влитых за это время, в нём нет
   вовсе — а значит, нет их и для тебя: `openspec list` шага 4 покажет
   позавчерашнюю картину, и соседа, правящего то же требование, ты
   пропустишь молча. 04.09.2026 задача 0190 пришла на аудит с деревом
   на пять коммитов позади, и влившееся за них
   `write-covered-commands-in-tasks` — та же способность, два общих файла —
   в её проверке не участвовало вовсе.

   Форма с ключом `-C` обязательна, и это снято делом задачей 0180:
   `PowerShell(git -C:*)` покрывает любую подкоманду разом, а правила
   `git merge:*` в перечне разрешений нет ни одного.

   Исходов у слияния три, и кончаются они по-разному:

   - **перемотка** — нового коммита нет, отправлять нечего, работай дальше;
   - **коммит слияния** — отправь его сразу, `git -C <дерево> push`:
     завершаться с неотправленным коммитом тебе нельзя;
   - **конфликт** — отмени слияние, `git -C <дерево> merge --abort`,
     и завершайся с исходом `failed`, назвав конфликтующий файл. Разбирать
     чужую правку вслепую опаснее задержки на этап, а картина пересечений
     на неосвежённой базе недостоверна.
````

### Скилл аудита, шаг 2 — что дописывается в конец шага

````markdown
Подтяни заодно и свежую главную ветку — до всякой проверки пересечений:

```powershell
git -C <дерево> merge origin/main
```

`fetch` сделан строкой выше, второго не нужно. Дерево завёл супервизор
в миг захвата задачи и больше не обновлял: к аудиту оно бывает старше
на дни, и каталогов `openspec/changes/`, влитых за это время, в нём нет
вовсе. Шаг 6 перебрал бы тогда позавчерашний список и молча пропустил бы
соседа — 04.09.2026 ровно так и вышло с задачей 0190 и влившимся
`write-covered-commands-in-tasks`.

Исходов три. Перемотка — делать нечего. Коммит слияния — отправь сразу
(`git -C <дерево> push`), хвоста тебе оставлять нельзя. Конфликт — отмени
слияние (`git -C <дерево> merge --abort`) и вынеси исход `rejected`, назвав
конфликтующий файл: конфликт здесь не беда, а находка — это пересечение,
доказанное делом, ровно то, ради чего заведён шаг 6.
````

Отступ у вставки — три пробела, как у прочей прозы внутри нумерованных
пунктов обоих скиллов.

### Сторож

```js
it('проработка и аудит подтягивают свежую главную ветку', () => {
  // Дерево задачи заводится при захвате и больше не обновляется, поэтому
  // проверка пересечений идёт на базе тех суток. Каталога чужого изменения,
  // влитого позже, в дереве нет вовсе, и пропуск выглядит как чистая
  // проверка: 04.09.2026 задача 0190 пришла на аудит с деревом на пять
  // коммитов позади и не увидела write-covered-commands-in-tasks.
  //
  // Мерка — строка целиком, вместе с ключом `-C`. Обрезать её до слова
  // `merge` нельзя: в скилле проработки оно уже стоит шагом 10, разбором
  // голой формы, и сторож по одному слову зеленел бы при полностью
  // пропавшем правиле.
  const guilty = ['design', 'audit'].filter(
    (stage) => !skillText(stage).includes('git -C <дерево> merge origin/main'),
  );
  expect(guilty.map((stage) => `${stage}.md: git -C <дерево> merge origin/main`)).toEqual([]);
});
```

## Чего решение не задевает

Правила игры, цены, доход, сила юнита и темп не тронуты — прогон арены
не нужен. Ядро симуляции не тронуто — эталоны детерминизма и профиля
не переснимаются. Раскладка байтов протокола не тронута —
`PROTOCOL_VERSION` не растёт. Поведения при рассинхроне и переподключении
изменение не касается: игрового кода в нём нет ни строки.

Запреты ядра (`Math.random`, `Date.now`, числа с плавающей точкой
в состоянии мира) к правкам правил этапов и к проверке на строках
неприменимы.

## Правила разрешений

Новых не нужно. `PowerShell(git -C:*)` покрывает `fetch`, `merge`,
`merge --abort` и `push` одной приставкой — это снято делом задачей 0180,
и на том же основании форма `git -C …` предписана шагом 10 скилла
проработки. В `deny` запрета на `merge` нет; запреты касаются
`push --force`, `reset --hard` и `stash`, в том числе в форме с `-C`.
Сверено чтением `supervisor/config/stage-settings.json`.
