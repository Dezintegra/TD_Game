# Задачи

Каждый шаг — отдельный коммит, проверяемый сам по себе. Кода приложения
изменение не заводит ни строки: правятся два файла правил конвейера и один
файл его проверок. Поэтому ни сборки, ни матчевых тестов, ни замеров здесь
нет, а проверки везде узкие и идут по своим файлам.

**Команды даны формой, покрытой правилами разрешений** — `git -C <дерево> …`,
где `<дерево>` — путь из поля `worktree` назначения. Форма эта и есть
предмет изменения; список задач, написанный иначе, опровергал бы сам себя.

## 1. Подтянуть свежую базу и открыть черновой pull request

- [x] Подтянуть главную ветку — тем самым движением, которое изменение
      и вводит: `git -C <дерево> fetch origin`, затем
      `git -C <дерево> merge origin/main`. Слияние дало коммит — отправить
      его сразу. Слияние дало конфликт — остановиться и назвать файл
      в отчёте: чужую правку разбирать вслепую нельзя (три ветки правят
      те же файлы, см. «Зависимость от других изменений» предложения).
- [x] Отправить ветку, если она ещё не отправлена
      (`git -C <дерево> push -u origin HEAD`), и открыть черновой pull
      request в `main`:
      `gh pr create --draft --base main --title "<заголовок>" --body-file <файл>`.
- [x] Тело pull request писать файлом: `--body` длинной прозой отказывается
      ещё до `gh`.

**Проверка:** `git -C <дерево> log --oneline HEAD..origin/main` пусто;
`gh pr view <номер> --json number,state,isDraft` отвечает `OPEN` и `true`.
Шаг стоит первым не из вежливости: до появления pull request пуши в ветку
не запускают CI вовсе, и каждый следующий коммит остался бы непроверенным.

## 2. Сказать в обоих скиллах о подтягивании свежей базы

Оба скилла правятся **одним коммитом**. Правило, введённое в одном из двух,
для второго не существует: этап читает свой скилл, а не соседний, — и
полувведённое правило даёт ровно ту беду, ради которой изменение затеяно,
только теперь наполовину и незаметно.

- [x] В `supervisor/skills/design.md` переписать шаг 2 целиком в новой
      редакции — текст выписан в `design.md`, раздел «Целевые тексты
      вставок», подраздел «Скилл проработки, шаг 2». Место — `design.md`,
      раздел «Куда вставлять: точные места».
- [x] В `supervisor/skills/audit.md` дописать в конец шага 2 текст
      из подраздела «Скилл аудита, шаг 2». **Внутрь командного блока строк
      66–70 не лезть ни строкой:** его правит pull request 126.
- [x] Брать тексты дословно, вместе с отступами: сторож шага 3 сверяет
      подстроку и читает файл сырым, без склейки строк.
- [x] Больше в этих двух файлах не менять **ничего**: ни соседних шагов,
      ни ограждений блоков, ни раздела запретов.
- [x] **Конфликт при слиянии в любом из двух файлов — повод остановиться
      и назвать его в отчёте**, а не разрешать по своему представлению
      о чужом тексте: значит чужая правка (pull request 126, 132 или 135)
      легла не туда, где её ждал `design.md`.
- [x] Править инструментом редактирования файла. `Set-Content`, `Out-File`
      и перенаправление `>` не применять: Windows PowerShell 5.1 читает
      UTF-8 как ANSI и превращает кириллицу в мохибейк.

**Проверка:**

- `npx prettier --check supervisor/skills/design.md supervisor/skills/audit.md`
  — зелёный;
- поиском по каждому файлу: строка `git -C <дерево> merge origin/main`
  встречается ровно один раз в каждом;
- поиском по `supervisor/skills/design.md`: прежний заголовок шага 2
  «**Перейди в своё дерево.**» не встречается больше ни разу, а нумерация
  шагов 1–13 цела и без пропусков;
- `git -C <дерево> diff --stat` показывает ровно два изменённых файла.

## Чего в списке нет

- **Шага «дождаться зелёного CI» нет, и это нарочно.** Пункт неисполним
  по устройству: караулить проверки исполняющей сессии запрещено, а отметка
  о нём была бы новым коммитом, перезапускающим те самые проверки, чью
  зелень она фиксирует. Зелень опрашивает и применяет супервизор сам —
  он же и двигает задачу из состояния `pr`. Запрет вводится изменением
  `keep-ci-waiting-out-of-tasks` (задача 0193, pull request 135); он ещё
  не влит, но писать заведомо неисполнимый пункт из-за этого незачем.
- **Прогона арены не заказывается.** Правила игры, цены, доход, сила юнита
  и темп не задеты ни одной строкой: правятся правила двух этапов конвейера
  и его сторожевой тест — всё вне пакетов монорепозитория.
- **Замеров кадров и стоимости тика нет** по той же причине: отрисовка
  и шаг мира не тронуты.
- **Правки правил разрешений нет.** `PowerShell(git -C:*)` покрывает
  `fetch`, `merge`, `merge --abort` и `push` одной приставкой, запрета
  на `merge` в `deny` нет — сверено чтением
  `supervisor/config/stage-settings.json`.
- **Перечни `STAGE_COMMANDS` и `GATED_PROGRAMS` не расширяются.** Сегодня
  в них объявлены только `review` и `deploy`; заводить там проработку
  и аудит значит включить их в механику удержания непокрытых этапов —
  это отдельное решение и отдельная задача.
- **Прочие этапы не правятся** — не-цель предложения.
- **Архивации изменения нет.** Она переписывает `openspec/specs/`,
  её очередь задана зависимостями дельт, и решение принимает человек.
  Здесь важно одно: изменение архивируется **после**
  `agent-backlog-pipeline`, которое заводит способность
  `dev-pipeline-worker`.
