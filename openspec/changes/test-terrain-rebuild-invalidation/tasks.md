## Состав каждого коммита и границы проверок

Команды выполняются из назначенного дерева, по одной за вызов. Для Git `<дерево>` — абсолютный путь назначенного дерева. Все используемые ниже формы Git покрывает `PowerShell(git -C:*)`; узкие проверки покрыты `PowerShell(npx vitest:*)`, `PowerShell(npx eslint:*)` и `PowerShell(npx prettier:*)` в `supervisor/config/stage-settings.json`.

В обоих шагах допустимы только рабочие изменения `apps/client/src/game/scene.test.ts` и обязательная отметка выполненного пункта в `openspec/changes/test-terrain-rebuild-invalidation/tasks.md`. Добавлять явным перечнем: `git -C <дерево> add -- apps/client/src/game/scene.test.ts openspec/changes/test-terrain-rebuild-invalidation/tasks.md`.

Перед коммитом проверить имена через `git -C <дерево> diff --cached --name-only` и содержание через `git -C <дерево> diff --cached`. После коммита проверить оба аспекта через `git -C <дерево> show --format=fuller --stat HEAD` и `git -C <дерево> show --format= --patch HEAD`. Недостаточно проверить только количество файлов: запрещены посторонние пути и несвязанные изменения внутри разрешённых файлов, включая tasks.md. Каждый коммит немедленно отправить командой `git -C <дерево> push -u origin HEAD`.

Локально только указанные узкие проверки после штатной подготовки зависимостей этапом implement. Полный набор, типы и сборку выполняет CI PR; пункта ожидания CI нет. На design тесты не запускаются. Арена и отдельный perf-прогон не требуются: производственный код и игровые правила не меняются.
