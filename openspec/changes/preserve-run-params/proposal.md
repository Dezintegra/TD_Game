## Why

Заявка передаёт `run.params` в `taskFromRequest`, но `metaOf` не записывает параметры в карточку Trello, а `parseCard` возвращает только kind и expectation. Новый снимок теряет заказ даже после успешной записи. Это остановило benchmark 0308 и оставило 0095 без необходимого результата.

## What Changes

- Сохранять JSON-объект params в машинном блоке карточки и восстанавливать его без преобразования вложенных значений при каждом чтении и служебной записи.
- Сохранить источники kind из метки и expectation из человеческого раздела описания; не дублировать их в машинном блоке.
- До benchmark диагностировать отсутствующий или повреждённый заказ, не запускать измерение с подставленными параметрами. Продолжения проходят ту же проверку.
- Защитить сквозной путь «заявка → Trello-запись → новый снимок → служебная запись → новый снимок → назначение» непустыми arena-параметрами и source локальных замеров, включая отрицательный контроль прежней потери.
- Доставить адресное восстановление существующей 0308 через цикл супервизора из проверенного отчёта 0095, без повторного создания карточки и повторного применения исходного blocked-отчёта. Сохранить зависимость 0095 и поручить измерения исходному benchmark.

## Non-goals

- Менять профили, баланс, игровые правила, workflow арены или вычислять результат 0308.
- Проверять вычислимость ожидания по выбранным расстановкам: это предмет 0291.
- Разрешать исполнителям прямую запись доски, менять лимиты, захватывать чужие деревья или перезапускать супервизор из этапа.
- Создавать универсальный редактор карточек, мигрировать все старые заказы по догадке либо менять контракт source.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `pipeline-task-routing`: добавляются требования к сохранности заказа, допуску benchmark и адресному восстановлению потерянных параметров. Все требования дельты ADDED: соответствующих заголовков в основе нет.

## Impact

Затрагиваются `supervisor/lib/card.mjs`, проверки заказа, подготовка назначения, хранилище и интеграция восстановления в цикл; тесты supervisor и документация `manage/README.md`. Схема уже допускает объект params с произвольными полями, новой зависимости пакетов не требуется.

Отзывчивость интерфейса игры не меняется: код выполняется только в супервизоре вне игрового цикла. Игровой сетевой трафик не меняется. Описание Trello увеличится на JSON параметров; обычная сериализация не требует дополнительных запросов. Адресное восстановление потребует служебной записи и комментария; подтверждение опирается на следующий штатный снимок, без опроса доски по каждой карточке.

## Пересечения и порядок архивации

База освежена до `b08fd3b648db710725e8751d8bdaf4f41fc0597f`; `openspec list --json` проверен. `require-local-run-source` уже влит, но открыт: пересекается по `pipeline-task-routing`, requests и подготовке benchmark. Наше изменение архивируется ПОСЛЕ `require-local-run-source`, поскольку использует его контракт source; его требования не переписываются.

`backlog-in-trello` и `backlog-candidates` описывают существующие чтение карточек и маршрут run в ещё не основной способности dev-backlog. Новую дельту поверх отсутствующей основы не создаём. В старой дельте backlog-in-trello сохранилось упоминание настраиваемого поля kind; постановка 0310 и действующий код прямо требуют сохранить метку. Чужой текст здесь не исправляется.

`persist-unapplied-stage-reports` задаёт существующие квитанции доставки, `require-merged-pr-for-dependencies` — проверку завершения предшественников. Используем реализованные механизмы без изменения их требований. 0309 затрагивает сторож команд benchmark, 0291 — семантику ожиданий; эти работы не являются предпосылками сохранения params.
