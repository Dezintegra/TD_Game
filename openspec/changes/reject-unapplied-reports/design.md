## Context

Процесс от 07.09.2026 отвергает failed-предшественника отчёта 0027. В main уже влит accept-stopped-predecessor-waits, но непустая очередь блокирует загрузку этой версии. Временный отказ Trello и постоянная ошибка planBlockers сейчас возвращают одинаковый failed.

## Goals / Non-Goals

Завершать постоянный отказ доставкой полного отчёта на разбор одной задачи. Не ослаблять проверку зависимостей. Не реализовывать дисковую очередь всех ответов: это отдельное изменение 0233.

## Decisions

1. На границах проверки содержимого явно помечать постоянный отказ. Ошибки чтения/записи и исключения не классифицировать по тексту. Обработчик переноса завершает только явный отказ; временная ошибка сохраняет очередь.
2. Новый модуль сначала доставляет полный JSON с полями blockers, requests, decisions, links, стоимостью и отказами в журнал через идемпотентный amendTask. Затем сохраняет ключ отчёта и переход в reportRejection. Для короткой записи перехода используется имеющаяся доставка entry.deliveryKey с конвертом delayJournal; большой JSON в описание карточки не попадает. Повтор сначала завершает доставку, не начисляет расход и не выполняет переход снова. Сессия исходного этапа забывается после подтверждения записи.
3. Рабочая задача переходит в postmortem с сохранением returnTo. Отказ самого postmortem переводит её в failed. Чужой или уже сменившийся этап не переименовывается обратно: отказ сохраняется без отката состояния.
4. Самообновление по-прежнему требует пустой очереди. Удаление отчёта по таймеру отвергнуто как потеря работы. Диагностика перечисляет taskId:stage и убирает двусмысленность «сливает работу».
5. Повторное снятие назначения идемпотентно: после отказа DELETE свежим GET проверяется отсутствие собственного участника. Только подтверждённое отсутствие считается успехом; другие ошибки сохраняются. Снимок начала оборота недостаточен: назначение могло поменяться.

## Risks / Trade-offs

- Сбой доставки журнала → сохранить отчёт и конверт, повторить только незавершённую доставку, не разрешать преждевременный перезапуск.
- Аварийное завершение до первой записи → нынешний риск in-memory очереди остаётся; полная персистентность предлагается отдельным этапом 0233.
- Соседние карточки и рабочие деревья → восстановление затрагивает только 0027, под паузой и после проверки нуля живых этапов.

## Migration Plan

Скопировать лог 0027 и снимок исходной карточки, поставить собственную паузу и дождаться тихого оборота. Применить исходный отчёт штатным transferBlocked из main с проверкой failed-предшественника и пустого списка новых карточек. Проверить запись на доске, снять только собственную паузу и наблюдать удаление уже принятого отчёта старым процессом и его самообновление. Новая защита доставляется отдельным PR после узких тестов и CI. Откат кода не удаляет сохранённый журнал.
