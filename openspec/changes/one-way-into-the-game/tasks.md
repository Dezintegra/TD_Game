# Задачи

- [x] 1.1 `packages/protocol`: признак приглашения у строки списка
      и у своей комнаты, состав манер в общем снимке, причина отказа
      `NoComputer`.
- [x] 1.2 `apps/server/computer-registry.ts`: манеры объявляются
      отдельным списком от личностей, со своим сроком. Дежурных
      не бывает, пока никто не позвал, — объяви мы манеры через них,
      список был бы пуст ровно тогда, когда он нужен.
      Проверка: `npx vitest run apps/server/src/computer-registry.test.ts`.
- [x] 1.3 `apps/server/lobbies.ts`: приглашение как пометка на комнате,
      сверка манеры с объявленными, срок приглашения и его снятие
      входом, вход позванного в закрытую комнату без пароля.
      Проверка: `npx vitest run apps/server/src/lobbies.test.ts`.
- [x] 1.4 `apps/server`: маршрут приглашения и подключение состава манер
      из реестра.
      Проверка: `npx vitest run apps/server/src/lobby-routes.test.ts`.
- [x] 1.5 `packages/bot`: служба перестаёт держать дежурных и комнаты;
      один поток наблюдения на манеру, дежурный поднимается
      по приглашению, играет матч и уходит.
      Проверка: `npx vitest run packages/bot/src/service.test.ts`.
- [x] 1.6 Клиент: обходной кнопки и выбора манеры в списке больше нет,
      кнопка создания названа «Новая игра», выбор соперника переехал
      в комнату, «Начать заново» заводит новую комнату и зовёт ту же
      манеру.
- [x] 1.7 Сквозные проверки: `bootGame` идёт единственным путём —
      завести комнату, позвать компьютера, дождаться, подтвердить
      готовность. Проверка «компьютер приходит по приглашению»
      подтверждает, что дежурных комнат в списке нет вовсе.
      Проверка: задача «сквозные проверки» в CI.

## Чего этой задачей не делается

Процесс службы компьютера при простое не останавливается: поднять его
обратно было бы некому, компьютера зовут из игры, а не из консоли.
Крутились не процессы, а дежурные, и их не остаётся ни одного.
Разбор — в `proposal.md`.
