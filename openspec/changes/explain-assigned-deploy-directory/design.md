## Context

В `supervisor/lib/stage-command.mjs:115–118` cwd выбирается из пути назначения для этапов `NEEDS_WORKTREE`; `deploy` входит в этот список (`supervisor/config/transitions.mjs:215`). Для Codex `supervisor/lib/provider.mjs:91–99` также возвращает cwd из `assignment.path`. Это существующее поведение проекта, менять пускатели не нужно.

Назначение выкладки уже содержит `branch: null`, `worktree` и `deploymentRevision`; `deploy.md:55–58` описывает отдельный detached-снимок. Шаги 1 и 6 проверяют ревизию и чистоту. `scripts/deploy.mjs:78` вычисляет корень через `git rev-parse --show-toplevel`, а строки 147–156 архивируют ревизию и дописывают файлы сборки из найденного дерева. Путь к самому сценарию не заменяет cwd.

## Goals / Non-Goals

Цель — привести шаг 9 в согласие с уже назначенным каталогом и сделать невозможным прочтение «своё дерево» как ветки старой задачи. Область правки и исключения перечислены в proposal: один шаг инструкции, без изменений кода, правил разрешений, кодировки и портов.

## Decisions

1. Перед блоком запуска прямо написать: «Рабочий каталог этапа уже задан пускателем: это `worktree` из назначения, отдельный снимок выкладки на `deploymentRevision` в detached HEAD. Дополнительный переход в каталог не нужен». В блоке удалить только строку `Push-Location <дерево>`. Сохранить `node scripts/deploy.mjs --ref <хеш> --no-perf` и пояснить, что `<хеш>` — полный `deploymentRevision` из назначения. Альтернатива с `Set-Location`, `cd` либо отдельным вызовом `Push-Location` сохраняла бы ненужную операцию и зависимость от состояния оболочки.
2. Во втором пункте четырёх доводов заменить неопределённое «своё дерево» на назначенный снимок и сохранить точное имя `git rev-parse --show-toplevel` вместе с последствием: запуск сценария путём из чужого каталога выбирает чужое дерево для архивации и замера. Удаление довода отвергнуто: без него прямой путь к сценарию легко принять за выбор исходников. Нового кода определения корня не требуется.
3. Не вводить самостоятельную настройку cwd в инструкции для каждого исполнителя. Она уже сделана пускателями; шаг описывает результат назначения, а не особенности API запуска. Не подменять закреплённый хеш текущим `origin/main` и не предлагать checkout или merge снимка.
4. Сохранить нумерацию и структуру четырёх доводов. Кодировка остаётся в состоянии свежей базы, определяемом задачей 0253/0169; наша правка её не удаляет и не возвращает. Если 0169 уже удалила переход, дополнить только отсутствующий смысл. Полностью выполненный соседями результат подтвердить записью источника в собственном tasks, без искусственного повторения diff. Порядок интеграции указан в proposal.
5. Дельта не нужна по разбору требований в proposal. Нового постоянного теста на редакцию одного абзаца не добавлять; достаточно сверки текста с пускателями, существующих узких проверок инструкции и CI.

Геймплей, рассинхрон и реконнект не затронуты. Изменений `packages/sim` и состояния мира нет: запреты `Math.random`, `Date.now` и дробного состояния сохраняются, обновлять эталоны детерминизма не требуется. Раскладка протокола не меняется, роста `PROTOCOL_VERSION` нет.

## Risks / Trade-offs

- Слияние соседних правок шага 9 может вернуть удалённую строку или стереть довод → перечитать весь шаг после освежения базы, сохранить результат 0253 и 0169, проверить содержание итогового diff.
- Отсутствие новой автоматической проверки оставляет возможность последующей редакционной регрессии → узкая ручная приёмка явно перечисляет удаление команды, назначенный снимок и причину зависимости от cwd; постоянный сторож не входит в заказ.
- Старые дельты `batch-deploy` и `guard-the-deploy-refresh` ещё описывают подготовку дерева иначе, чем `prepare-deploy-snapshot` → не переписывать их в локальной задаче шага 9; использовать уже действующее назначение, как предписано постановкой.

## Migration Plan

Один коммит рабочей правки и её отметки, затем черновой PR. Миграций данных и действий на сервере нет; изменение начинает использоваться при чтении обновлённого скилла пускателем. При необходимости откатывается только этот коммит с сохранением независимых правок соседей. Архивация без specs выполняется позднее с `--skip-specs`.
