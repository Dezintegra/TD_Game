## Правила коммитов и передачи

Каждый пункт — отдельный проверяемый коммит с немедленной отправкой. Все команды выполняются в назначенном дереве. Перед коммитом добавлять только свои перечисленные рабочие пути и `openspec/changes/increase-unit-spacing/tasks.md` явным списком через `git -C <дерево> add -- <пути>`; проверить имена и содержание `git -C <дерево> diff --cached`. После коммита проверить `git -C <дерево> show --stat HEAD` и `git -C <дерево> show HEAD`, затем `git -C <дерево> push`. В разрешённых файлах недопустимы несвязанные изменения.

Полный verify, сборка и полный матчевый набор локально не входят в план. Ожидание CI ведёт супервизор. Узкие проверки эталонов из корня назначенного дерева выполняются отдельными командами: `npx vitest run --root packages/sim --config vitest.match.config.ts src/determinism.golden.match.test.ts` и `npx vitest run --root packages/ai --config vitest.match.config.ts src/profile.golden.match.test.ts`. Проверку sim отдельно повторить с `--environment jsdom` для проверки изоморфности. Получение фактических сумм и наблюдаемых величин обоих golden, согласование их объяснений и проверка вместе с игровым правилом относятся к одному пункту 1.1 и тому же коммиту, а не к следующему исправляющему коммиту. Сохранять неизменившиеся значения; в теле PR указать результат каждого файла и источник проверки, не создавать фиктивную правку эталона. При последующем обновлении базы повторно сверить оба результата от совокупных правил, включая влитую работу 0035, если она появилась; суммы соседней ветки не переносить.

Арена заказана полем requests отчёта design: два уровня одного эксперимента, A и B, после появления изменения. Повторно заказывать те же прогоны при реализации не нужно. Архивация и замер кадров не являются пунктами реализации.
