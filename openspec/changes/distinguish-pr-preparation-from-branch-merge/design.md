## Context

Проверено на свежей `origin/main` (`84caeae`): `git -C . fetch origin` выполнен, `git -C . merge origin/main` вернул `Already up to date.`. Шаг 3 `supervisor/skills/implement.md` требует обновить главную и завершиться при конфликте; дополнительная подготовка в нём не разобрана. Существующий сторож в `supervisor/config/transitions.test.mjs` проверяет наличие команды обновления главной, но не границы её последствий.

План `document-permission-independent-guards` в назначенном дереве 0169, раздел «Согласование шагов без реализации соседних карточек», предусматривает получение `supervisor/config/shell.test.mjs` из отправленной версии PR 126 и собственные изменения. Порядок интеграции требует сначала влить PR 126, но подготовка до его вливания явно разрешена. Факт конфликтного слияния и успешного обновления главной взят из постановки 0254; новое слияние чужой ветки для воспроизведения не требуется.

## Goals / Non-Goals

Цель — сделать из текста инструкции однозначным выбор следующего действия при разных видах конфликта. Область реализации — скилл имплементации и его существующий файл проверок. Не меняются планировщик, зависимости карточек, рабочие деревья соседей и правила остальных этапов. Полный перечень не-целей — в proposal.

## Decisions

### Один локальный блок в существующем шаге

В шаге «Подтяни в дерево свежую главную ветку» назвать три исхода именно исходами слияния `origin/main`. Сохранить команды, безусловность, порядок до установки, немедленную отправку коммита слияния и правило следа. Следом в том же шаге добавить выделенный блок «Подготовка по открытому PR»; не вводить новый номер шага и не сдвигать ссылки на следующие шаги.

Блок предписывает прочитать согласованные design/tasks до выбора дополнительной операции. Одна лишь запись «наш PR вливается после соседнего» не требует слияния всей ветки. Если предусмотрено получение отдельного файла из отправленной версии, использовать названный источник, сделать собственную правку и сохранить предусмотренную повторную проверку после интеграции. Не включать универсальную команду копирования: источник, ревизия и состав допустимой правки определяются конкретным планом.

Отвергнуты обязательное слияние всех зависимых веток (затягивает чужую историю и конфликты) и ожидание любого открытого PR (подменяет порядок интеграции предусловием запуска). Полный запрет дополнительных слияний также неверен: конкретный план может их требовать.

### Последовательность после дополнительного конфликта

Назвать конфликтующие файлы; выполнить `git -C <дерево> merge --abort`; проверить код возврата и `git -C <дерево> status --porcelain`, отсутствие незавершённого слияния и сохранность предшествовавших правок. При ошибке отмены остановиться с фактической причиной, не сбрасывать дерево. После успешной отмены сверить план и проверить доступность именно указанной отправленной версии и файла. Если этот способ доступен — продолжить его; если нет — `failed` с проверенным препятствием. Слияние, прямо требуемое планом без альтернативы, не заменяется выборочным копированием.

В отчёте назвать отменённую операцию, конфликтующие пути и результат проверки способа. Неизвестные конфликты не разрешать вслепую ни в одной ветви. Отвергнуты безусловный `failed` сразу после любого конфликта и безусловное продолжение после отмены: первый воспроизводит 0169, второе скрывает реальную недоступность плана.

Явные предусловия запуска из назначения и карточки сохраняются. `card-dependencies` и `require-merged-pr-for-dependencies` регулируют решение супервизора о запуске; эта правка не превращает текстовое упоминание порядка PR в такую зависимость и не снимает уже заданную.

### Спецификация и пересечения

Дельта нужна: появляется общее правило будущего поведения при дополнительном конфликте, а не исправление одной исторической ссылки. Используется ADDED в уже заведённой открытыми изменениями способности `dev-pipeline-worker`; основы для MODIFIED в `openspec/specs/` нет. Требование `refresh-the-base-before-code` остаётся про слияние главной: его сценарии и смысл не заменяются. Порядок архивации указан в proposal.

Для собственной реализации достаточно файлов свежей главной ветки. `one-shell-for-stages` добавляет оговорки оболочки, 0169 — ссылки на предохранители, `guard-step-references` — сторож ссылок. Их ветки не нужны для подготовки этого изменения; сохраняются заголовки и номера шагов, новые проверки добавляются рядом со сторожем освежения без переписывания чужих тестов.

### Проверка инструкции и сценария

В `transitions.test.mjs` дополнить существующие проверки скиллов узкой проверкой блока подготовки `implement`. Извлекать этот шаг по смысловому заголовку, не по жёсткому номеру, нормализовать пробелы для переносов. Проверять отдельно основной разбор `origin/main` и блок «Подготовка по открытому PR»: выбор по плану, отсутствие автоматического требования слить соседнюю ветку, отмена, проверка результата отмены и доступности способа, условное продолжение/остановка, сохранение явного предусловия и запрета неизвестных конфликтов. Диагностика называет путь скилла и отсутствующее условие.

Положительная проверка читает реальный файл. Отрицательные пробы в памяти удаляют по одному обязательному условию, убирают блок целиком, переносят его за пределы шага, заменяют условное продолжение безусловным `failed`; каждая должна выявляться. Существующий сторож команды обновления главной остаётся. Новая проверка защищает опасную инструкцию, но не доказывает поведение модели; не создавать фиктивную функцию принятия решения, которую реальный исполнитель не вызывает.

Ручная матрица по итоговому тексту фиксируется в отчёте имплементации:

| Входные условия | Ожидаемое действие |
| --- | --- |
| 0169: main актуальна, PR 126 открыт, получение файла предусмотрено и доступно, дополнительное слияние конфликтует | Отмена, проверка восстановления и доступа, подготовка файла; порядок интеграции остаётся |
| То же, но дополнительное слияние ещё не начинали | Сразу предусмотренное получение файла |
| Конфликт `origin/main` | Отмена и `failed` с файлом |
| Отмена соседнего слияния не удалась | `failed` с ошибкой отмены, без правки и сброса дерева |
| Отмена успешна, нужная отправленная версия недоступна | Проверка доступа и `failed` с конкретной причиной |
| План требует слияния ветки, альтернативы нет | Отмена конфликта, сверка плана, `failed` с неисполненным условием |
| Есть явное предусловие запуска с влитым PR | Подготовка по открытому PR не отменяет его |

Не нужна живая проба слияния PR 126: результат зависел бы от будущего состояния соседней ветки и затронул чужую работу. Фиксированная матрица проверяет именно предписанное поведение инструкции.

## Risks / Trade-offs

- Проза допускает несколько прочтений → обязательные развилки расположить рядом, подтвердить матрицей и отрицательными пробами сторожа.
- Совпадение файлов с соседними PR → локальная вставка без перенумерации; актуализация main остаётся обязательной по действующему скиллу.
- Разрешение подготовки могут принять за обход `requires` → прямо сохранить явные предусловия и запрет самостоятельно менять план.

## Migration Plan

Один коммит реализации до двух часов: инструкция, её проверки, отметка собственного пункта tasks. Затем немедленная отправка и черновой PR. Данных для миграции нет; откат — обратный коммит. Проверки CI опрашивает супервизор. Архивацию этого изменения исполнитель не выполняет.

Игровой код не затрагивается: рассинхрон, реконнект, эталоны детерминизма и `PROTOCOL_VERSION` не меняются. `Math.random`, `Date.now` и дробное состояние мира не добавляются. Отзывчивость и трафик не затронуты.
