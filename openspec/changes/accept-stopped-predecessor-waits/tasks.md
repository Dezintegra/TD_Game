## Проверки каждого коммита

Работа выполняется в назначенном дереве. Команды проверки разрешены формой PowerShell(npx vitest:*) в supervisor/config/stage-settings.json; ключ `--root supervisor` обязателен. Формат и линт проверяются узко по изменённым файлам supervisor разрешёнными формами `npx prettier --check <свои файлы>` и `npx eslint <свои mjs-файлы>`. Полные тесты, сборку, арену и ожидание CI здесь не запускать.

В каждом шаге добавлять только фактически изменённые собственные пути явным списком командой `git -C <дерево> add -- <перечень файлов>`, включая обязательную отметку выполненного пункта этого tasks.md. Перед коммитом проверить имена и содержание через `git -C <дерево> diff --cached --name-only` и `git -C <дерево> diff --cached`; после коммита — `git -C <дерево> show --stat --oneline HEAD` и `git -C <дерево> show --format=fuller HEAD`. Разрешённые пути не разрешают несвязанные изменения внутри них. Каждый коммит немедленно отправить `git -C <дерево> push`.

В конце проверить `openspec validate accept-stopped-predecessor-waits --strict` и `openspec status --change accept-stopped-predecessor-waits`. Проверки реализации этого списка относятся к implement; на design выполняется только проверка артефактов.

Порядок будущей архивации задан в proposal.md и design.md: сначала согласовать мерку completed/splitInto и все дополнительные проверки merged-pr в require-merged-pr-for-dependencies, затем архивировать его, сверить полученную основу и лишь после этого архивировать accept-stopped-predecessor-waits. Это условие архивации, не задача implement: текущие пункты не разрешают править соседнюю дельту или основные спецификации и не требуют ждать чужого PR для доставки кода.
