## Context

Исторические ветки после squash merge конфликтуют с main. Отмена merge
в песочнице оставляет защищённые .agents. Эти ветки не являются входом выкладки.

## Goals / Non-Goals

Цель: один проверяемый снимок для обоих исполнителей, perf и deploy.
Не меняем sandbox, историю задач, правила perf и единственной попытки выкладки.

## Decisions

Перед порождением deploy супервизор fetch-ит настроенные remote/mainBranch,
создаёт detached worktree под .pipeline/deploy-checkouts и сохраняет его путь
и полный хеш в stages.json до spawn. Реестр задачи продолжает указывать старое дерево.
Назначение получает относительный путь, branch=null и deploymentRevision.

Продолжение использует сохранённый снимок даже после продвижения main.
Проверяем принадлежность каталогу снимков и тому же Git common dir, detached HEAD,
совпадение ревизии и чистоту. Грязное дерево не чистим и не сбрасываем.
Старое продолжение без снимка останавливается до spawn: неизвестно, была ли выкладка.
Подготовленный, но не запущенный снимок повторно используется.

Инструкции deploy проверяют назначенный хеш и ставят зависимости перед perf.
Слияния и push для подготовки больше не нужны. Снимки сохраняются для диагностики
и продолжений; автоматическая уборка вынесена за границы изменения.

## Risks / Trade-offs

Дополнительное место на диске → документируем сохранение снимков.
Fetch недоступен или снимок повреждён → ошибка подготовки до запуска исполнителя.
Синхронный Git задерживает цикл → ограничиваем команды тайм-аутом.

## Migration Plan

Дождаться завершения активных этапов и обработки отчётов, обновить супервизор.
Новые deploy получают снимок; незавершённые старые deploy требуют разбора,
без автоматического повторения серверной операции. Откат через revert PR.
