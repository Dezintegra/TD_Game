## Why

Заявка perf или bench-tick не называет измеряемый код: requests.mjs проверяет только expectation, а benchmark.md направляет run в main. Поэтому замер невлитой правки может успешно выдать числа для дерева без самой правки (случай 0086 из постановки).

## What Changes

- **BREAKING**: заявки локальных замеров требуют `run.params.source` с ровно одним селектором: `branch` или `worktree`. Отсутствующее, пустое или неоднозначное значение отвергается с причиной, как отсутствие expectation.
- Супервизор разрешает источник в существующее дерево данного репозитория до запуска benchmark и передаёт единый рабочий каталог обоим исполнителям. Ветка не создаётся, checkout не выполняется; отсутствие дерева не заменяется main.
- Benchmark сверяет источник перед подготовкой и перед замером, сообщает фактические путь, ветку и SHA вместе с числами. Смена исходников делает результат непригодным для ответа на заказ.
- implement, revise, review, deploy и triage получают согласованный контракт и примеры заявок. Имя OpenSpec в `params.change` источником кода не считается.

## Non-goals

- Автоматическое создание, обновление, переключение или удаление дерева источника; ожидание вливания PR вместо названного дерева.
- Новые идентификаторы локальных прогонов и изменение приёмки их следа (0293), расширение разрешений измерительных команд (0088), изменение замеров и их порогов.
- Изменение маршрута arena, игровых правил, балансный прогон, миграция старых карточек силами сессии.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `pipeline-task-routing`: добавляются требования приёмки источника локального run и назначения существующего дерева для benchmark. Существующие требования не заменяются.

## Impact

Затрагиваются supervisor/lib (приёмка заявок, подготовка назначения, cwd исполнителей, промпт), узкие тесты и пять подающих скиллов вместе с benchmark.md. Формат хранения params уже допускает новые поля, миграция схем не нужна.

Отзывчивость интерфейса и сетевой трафик игры не меняются: изменения исполняются только в конвейере до замера, код клиента, сервера и протокола не затрагивается. Дополнительные проверки Git локальны.

## Пересечения и порядок

Проверено после fetch и merge origin/main на базе 7a12154; открытые изменения просмотрены через openspec list и поиск контрактов run. `backlog-candidates` сохраняет короткий маршрут без создания ветки; использование существующего дерева его не меняет. `backlog-in-trello` описывает хранение run; новые поля остаются внутри params. `supervise-the-pipeline` содержит общее правило cwd для этапов без дерева: здесь вводится явное исключение для назначенного источника локального benchmark. При его будущей архивации это исключение должно сохраняться; наша дельта добавляет отдельные требования в существующую pipeline-task-routing и не зависит от отсутствующей основы dev-pipeline-supervisor.

Зависимости архивации нет: MODIFIED поверх открытых дельт не используется. `forbid-uncovered-benchmark-probes` названо в описи доски, но его каталога на свежей базе нет; пересечение benchmark.md нужно сверить при реализации. `align-deploy-perf-port-commands` и `rewrite-request-field-descriptions` пересекаются инструкциями; форма портов и контракт заявок сохраняются. `allow-codex-perf` пересекается provider.mjs: сохраняется подготовка разрешённых служебных путей именно для выбранного cwd.
