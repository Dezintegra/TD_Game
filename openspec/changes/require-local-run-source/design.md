## Context

На свежей базе 7a12154 `taskFromRequest` в requests.mjs сохраняет params целиком, проверяя только expectation. Схема task-schema.json уже разрешает произвольные поля params. `benchmark.md` направляет run в main; `stage-command.mjs` выбирает cwd Claude через NEEDS_WORKTREE, тогда как provider.mjs выбирает cwd Codex по assignment.path. Один новый путь в назначении без согласования этих веток исправит только одного исполнителя.

`supervisor/bin/supervise.mjs` передаёт createSupervisor обработчик prepareAssignment: сначала prepareDeploySnapshot, затем prepareCodexPerfFiles. Он вызывается перед stagePrompt и stageCommand и подходит для разрешения локального источника. Ошибка подготовки уже перехватывается, не порождая процесс; действующее исполнение записывает причину неудачного запуска. Новый автомат состояний не нужен.

## Goals / Non-Goals

Цель — связать заявку, рабочий каталог процесса и отчёт одним проверяемым источником кода. Границы перечислены в proposal. Арена и выкладка своим пакетом сохраняют существующую подготовку; речь о самостоятельных run и любом benchmark с локальным kind.

## Decisions

### 1. Явный объект source

Форма примера: `"params": { "source": { "branch": "worktree-0041-vizual-igrovogo-polya" }, "change": "blacken-the-field" }`. Альтернатива — `"source": { "worktree": "C:/src/dezintegra/TD_Game/.claude/worktrees/0041-vizual-igrovogo-polya" }`. В source ровно один ключ, непустая строка без начальных и конечных пробелов; некорректное значение отвергается, не исправляется догадкой. Branch — локальное короткое имя, не SHA, tag или origin/ref. Git-проверки используют массив доводов без shell-интерполяции.

Выбран branch/worktree из заголовка задачи. Автоматическое разрешение change отвергнуто: имя OpenSpec не задаёт однозначно ни ветку, ни содержимое и сохраняет исходную ошибку. Обязательный SHA в заявке не вводится: задача просит ветку или дерево; SHA фиксируется при подготовке и называется в результате. Следовательно, branch означает текущую локальную ревизию при старте, а не обязательно ревизию в момент подачи заявки; это явно объясняется подающим скиллам.

Чистая проверка формы в новом `supervisor/lib/run-source.mjs` используется приёмкой requests.mjs и разрешением при запуске. Она не проверяет существование файлов при подаче заявки: исполняющая станция может быть другой. Другие параметры остаются как были. Старые карточки автоматически не переписываются; повторная проверка при запуске закрывает обход через старую карточку.

### 2. Разрешение существующего дерева до порождения процесса

Новый `supervisor/lib/benchmark-source.mjs` получает root, assignment и внедряемые операции Git/FS. Для локального benchmark он проверяет форму source и читает `git -C <корень> worktree list --porcelain`. Branch сопоставляется точно с refs/heads/<имя>. Worktree разрешается относительно root, канонизируется и сравнивается с корнем зарегистрированного дерева; проверяется общий git-dir, существование и HEAD. Путь вне основного каталога допустим, если это связанное дерево того же репозитория, включая Codex worktrees. UNC, неверный путь, недоступность, чужой репозиторий, подкаталог и неоднозначность дают именованную ошибку. Detached дерево допустимо по пути; branch для него не придумывается.

Результат — assignment.path, равный разрешённому абсолютному пути, и assignment.benchmarkSource с исходным селектором, path, branch (null для detached), head. Ветка самой задачи и её запись реестра не меняются. Технический path запуска не означает владения деревом и не даёт права уборки.

В prepareAssignment после подготовки deploy и до prepareCodexPerfFiles подключается разрешение benchmark. Stage-command для Claude получает явное исключение cwd при benchmarkSource; Codex уже использует path, но проверка подтверждает совпадение cwd и разрешений. stagePrompt передаёт benchmarkSource отдельным полем назначения. Сохранённый path дочернего процесса и проверка свидетельств Codex используют тот же путь; это проверяется тестом интеграции. НЕ добавлять benchmark в NEEDS_WORKTREE: это создало бы дерево run вопреки короткому маршруту.

На продолжении источник разрешается снова. Benchmark читает журнал: завершённый ранее замер может быть использован только со своей прежней привязкой источника; новый замер получает новое подтверждение. Нет дерева — обработка ошибки подготовки без измерительных команд, с исходным selector и точной причиной. Не заменять ошибку значением root, не прятать её в успешном отчёте. Поведение счётчиков несостоявшегося запуска остаётся действующим.

Отвергнуто: только инструкция «перейди в каталог» (не меняет sandbox и исходный cwd); создание копии/checkout ветки (добавляет владение и уборку, не заказанные карточкой); поиск ветки через links.related или PR (догадка вместо контракта).

### 3. Подготовка и свидетельство результата

Скилл benchmark перед установкой сверяет назначение командами Git с ключом -C: корень, ветка, rev-parse HEAD, status --porcelain --untracked-files=no. Повторяет сверку перед измерением и после. Если отслеживаемые исходники грязны, ветка, путь или HEAD изменились — failed; чужие изменения не прятать и не исправлять. Сборка игнорируемого dist и установка зависимостей допустимы в выбранном дереве. Тишина, порты и общий perf-lock остаются обязательными; дерево источника не обновляется через merge или pull.

В существующий decisions отчёта записываются селектор, абсолютный путь, ветка/detached и полный SHA; отдельная схема отчёта не нужна. Не выдавать прежнюю запись history за измерение этого SHA. links.run остаётся обязательным согласно действующей приёмке: решение проблемы его формирования ведёт 0293 и сюда не включено. Для проверки текущего изменения реальные замеры не нужны — ошибка выбора cwd воспроизводится до запуска игры.

### 4. Согласованная доставка

Сначала добавляются отдельно проверяемые, ещё не подключённые помощники. Затем одним атомарным шагом включаются приёмка, назначение обоих исполнителей и шесть скиллов. Так нет промежуточного состояния, в котором инструкции создают отвергаемые заявки. Тесты JSON-примеров должны пропускать их через настоящую taskFromRequest с необходимыми служебными полями, а не искать только слово source.

Подающие скиллы называют: для невлитой правки — её существующую ветку; для сознательного замера main — main явно. Deploy не должен копировать путь временного снимка, который удалится после выкладки: заявка измеряет названный доступный источник и честно объясняет, что повтор на main не гарантирует историческую ревизию пакета. Если нужен именно исчезающий снимок, обещать такой повтор нельзя — это отдельная подготовка источника, не fallback.

## Risks / Trade-offs

- Между подачей и запуском дерево может исчезнуть или находиться на другой станции → явный отказ без автоматического создания; это требуемое поведение.
- Чужой автор может менять дерево во время замера → проверки чистоты и HEAD до/после отбраковывают обнаруженное расхождение. Полная изоляция от изменения-и-отката между проверками не обещается; снимки и аренда дерева вне объёма этой задачи.
- Источник в старой карточке отсутствует → безопасный отказ при запуске, карточку исправляет владелец/супервизор установленным способом; массовой миграции нет.
- Общее правило cwd в открытой дельте supervise-the-pipeline → новое требование именует узкое исключение; при последующей архивации общей дельты его нельзя потерять. Зависимой основы для нашей ADDED дельты нет.
- `forbid-uncovered-benchmark-probes` отмечено в описи доски, но его каталога в свежем main нет. Сверять будущий diff benchmark.md при реализации; не переносить невлитую инструкцию из чужой ветки. Правки портов из align-deploy-perf-port-commands и writable paths из allow-codex-perf уже учтены.

## Migration Plan

Один PR, черновик после первого шага. Подключение контракта и обновление заявок одним коммитом. Откат подключения целиком возвращает прежнее поведение; помощники без вызовов безвредны. Схемы, старые записи журнала и карточки не мигрируются. Проверки — узкие Vitest, без реальной арены, сборки игры и замеров на design.

## Архитектурные ограничения

Игровой код и сетевые байты не меняются. Рассинхрон и реконнект не затрагиваются; PROTOCOL_VERSION и эталоны детерминизма не обновляются. В packages/sim не добавляются Math.random, Date.now или числа с плавающей точкой; новые операции FS/Git остаются в supervisor.

## Open Questions

Продуктовых решений не требуется. Наличие конкретного дерева на машине будущего benchmark проверяется во время запуска, не является предпосылкой реализации контракта.
