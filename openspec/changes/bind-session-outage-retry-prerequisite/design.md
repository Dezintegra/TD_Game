## Decisions

### 1. Предусловие сессии и независимость коммита различаются

В начале tasks.md 0243, до раздела 1, поставить общее условие: весь повторный implement удерживается до closed у `0242-dat-otchetu-etapa-adresnoe-poruchenie-na` и подтверждённого MERGED PR 177 в настроенную главную ветку с links.pr=177. Ни работа над 1.1, ни повтор/возобновление уже начатой сессии не исключение. В 1.1 оставить чистую модель и самостоятельную проверяемость; явно указать, что это техническая независимость коммита после допуска.

Абзац «Предусловие шага 3.1» заменить ссылкой на общее условие с повторной проверкой свежести перед интеграцией. В design 0243 согласовать Goals/Decisions 6, порядок поставки, Risks и Migration Plan: вводная про независимые коммиты не разрешает ранний старт, «до 3.1» не является первой точкой ожидания. Сохранить все алгоритмические решения, сценарии дельты и отметки задач 0243; новую функциональность не добавлять.

Перед первым действием реализации 0243 её исполнитель проверяет актуальное подтверждение закрытия 0242, выполняет отдельно:

```powershell
gh pr view 177 --json number,state,mergedAt,baseRefName,mergeCommit
git -C <дерево-0243> fetch origin
git -C <дерево-0243> merge origin/main
git -C <дерево-0243> merge-base --is-ancestor <mergeCommit-PR-177> HEAD
```

Ожидаются number=177, MERGED, корректная дата, база main из конфигурации и код 0 проверки предка; проверить также наличие поставленного обработчика `dependencyUpdates` и post-claim `readStartTask` в назначенном дереве. SHA берётся из ответа PR, а не из головы его исходной ветки: это работает и после squash. Отсутствие SHA/результата либо несогласованность данных удерживает реализацию и отражается отчётом, не заменяется копированием файлов PR 177. Слияние и конфликт обрабатываются по правилам этапа. Эта проверка дерева дополняет карточный допуск, не заменяет его.

Альтернатива оставить запрет лишь у runtime-шагов отвергнута: это уже привело к расходу сессии вопреки решению владельца. Ждать PR в запущенной сессии также нельзя: удерживает супервизор.

### 2. Доставка исправленного существующего изменения

0247 имеет собственное имя только для этой операции; второе изменение с функциональностью 0243 не создаётся. Все изменения делаются в назначенном дереве 0247. Дерево и ветка 0243 не переключаются и не редактируются.

В implement сначала освежить main. Если полный каталог `stop-launches-on-session-outages` уже появился, править его текущую версию. Если отсутствует, прочитать свежую опубликованную ветку 0243, зафиксировать её SHA и перенести в своё дерево только полный существующий каталог артефактов (на проработке в нём шесть файлов: .openspec.yaml, README.md, proposal.md, design.md, tasks.md и одна дельта). Использовать `git -C <дерево-0247> restore --source=<проверенный-SHA-0243> -- openspec/changes/stop-launches-on-session-outages`. Это перенос того же изменения под тем же именем, без cherry-pick/merge всей ветки и без её кода; два файла отдельно не переносить, чтобы не публиковать неполный OpenSpec.

Относительно исходного SHA меняются только design.md и tasks.md; остальные артефакты сохраняются дословно. Указать SHA и разницу в verification.md. Не переписывать уже появившуюся main старым снимком. До вливания сверить актуальную ветку 0243 повторно; её новые плановые правки сохранить при совмещении. 0243 должна получить эту правку через штатное обновление main перед продолжением. До подтверждения доставки обоих плановых файлов и метаданных 0247 не считается принятой. Полный перенос ветки отвергнут: он преждевременно доставит код соседней задачи.

### 3. Точное адресное поручение и подтверждение

После поставки канала 0242 использовать следующий фрагмент последнего отчёта implement; это образец, а не поручение текущего design:

```json
{
  "dependencyUpdates": [
    {
      "taskId": "0243-ostanavlivat-novye-zapuski-pri-nesostoya",
      "dependsOn": ["0242-dat-otchetu-etapa-adresnoe-poruchenie-na"],
      "dependencyResults": [
        { "taskId": "0242-dat-otchetu-etapa-adresnoe-poruchenie-na", "kind": "merged-pr", "pr": 177 }
      ],
      "reason": "Постановка 0247 и решение владельца из 0246: удержать весь повторный implement 0243 до завершения 0242 и подтверждённого вливания PR 177"
    }
  ]
}
```

Это дополнение, не замена массивов. Обработчик 0242 объединяет его со свежей карточкой под своим временным захватом и подтверждает независимым GET. Сохраняются другие зависимости, результаты, неизвестные метаданные, человеческий текст, статус, returnTo, attempts, стоимость/токены, ссылки и назначение, кроме собственного временного захвата операции. Идентичная пара означает подтверждённый no-op; иной PR у этого ребра — конфликт, не перезапись. Занятую карточку не освобождать. Неподтверждённая запись остаётся ошибкой доставки по 0242.

Перед выдачей поля подтвердить поставку PR 177 и использование нового обработчика принимающим супервизором по предоставленным им сведениям о ревизии/журналу. Наличие кода только в дереве исполнителя недостаточно. Если канала ещё нет или поставка не подтверждена, завершить implement предусмотренным вопросом о поставке, без неизвестного старому обработчику поля; не ждать в сессии и не чинить канал здесь. Закрытие 0242 является условием запуска 0243; само дополнение можно доставить сразу после готовности канала, ещё до закрытия 0242.

Implement заканчивается до применения его отчёта и поэтому честно сообщает «поручение передано, подтверждение записи ожидается». Супервизор делает независимое чтение до перехода источника, следующая review-сессия проверяет свидетельство подтверждения в переданном журнале. Ожидания собственного отчёта в tasks нет. Для приёмки нужны адресат, точная пара, сохранность прежних полей и факт независимого GET; payload, ответ PUT или один факт перехода источника этого не заменяют. Если сведения не переданы, запросить их отчётом, не читать/править доску напрямую. Доставкой и повторным подтверждением владеет 0242.

Альтернативы requests/amendments отвергнуты: первое создаёт карточки, второе не является каналом метаданных. Общий saveTask и ручной PUT нарушают назначенного владельца записи и могут затереть свежие данные.

### 4. Изолированное доказательство допуска

В implement подготовить временную пробу `.matchlog/0247-prerequisite.mjs`, импортирующую настоящие `pendingDependencies`, `buildDependencyState`, `scan` и при необходимости `runCycle`; подставить runner доказательств вместо gh и IO вместо Trello. Не импортировать запускающий bin, не выполнять рассчитанные действия. За основу взять сценарии `supervisor/lib/dependency-state.test.mjs`. Код алгоритма допуска не копировать. Исходный текст пробы и вывод сохранить в `verification.md` для воспроизведения после очистки .matchlog. Постоянные тесты с номерами конкретных карточек не нужны: правило уже покрыто, здесь проверяются его конкретные данные.

Фикстура потребителя использует полные ID 0243/0242 и PR 177, дополнительное существующее ребро и результат как контроль. Проверять отдельно new (start), implement без sessionId и implement с прежним sessionId (continuation); положительные сценарии имеют допустимые лимиты и свободное место, отрицательные — также заведомо превышенные счётчики/расход, чтобы доказать порядок удержания. Снимок целиком сравнивать до/после, включая returnTo и все attempts; повторить скан без изменения доказательств.

| Сценарий | Наблюдаемый результат |
| --- | --- |
| 0242 closed, links.pr=177, доказательство OPEN либо CLOSED без merge | Для 0243 нет start-stage, continue-stage и fail-stage по лимитам; состояние неизменно, причина называет условие |
| 0242 closed, доказательства нет; runner бросает ошибку/возвращает негодный JSON | То же удержание без списания и перехода; новое чтение в следующем снимке |
| 0242 ещё pr/review/deploy при годном MERGED | То же удержание до closed |
| Неверный links.pr, number, база либо негодный mergedAt | Удержание, не принятие одного флага MERGED |
| Всё удовлетворено; остальные зависимости и потомки closed, лимиты и слоты позволяют | Штатные start/continuation на модельных копиях |
| PR 177 удовлетворён, но другое ребро/потомок не closed | Удержание по сохранённому прочему условию |
| Всё удовлетворено, но лимит исчерпан, нет слота или живой эксклюзивный этап | Обычное соответствующее ограничение остаётся; условие не даёт безусловного старта |
| Копия 0243 остаётся failed, returnTo=null и без права recovery | Нет самовольного return-task или запуска; смену статуса проба не исполняет |
| Живой процесс либо готовый отчёт | Нет прерывания процесса или потери переноса отчёта |

Для записи использовать имеющиеся изолированные тесты канала 0242: сохранение всех полей, повторный no-op, конфликт, отсутствие подтверждающего GET и устаревший старт после дополнения. Проверка фактической карточки принадлежит независимому чтению обработчика; успех фикстуры его не заменяет. Проба не добавляет/меняет recovery.fixedBy и не выполняет return-task, даже если иной штатный recovery когда-либо станет допустим.

### 5. Архитектура и соседние изменения

Игровые пакеты не изменяются: рассинхрон, реконнект, эталоны детерминизма и PROTOCOL_VERSION не затронуты. Запреты Math.random, Date.now и дробного состояния мира сохраняются; состояния мира эта операция не создаёт. Арена не нужна.

0073 владеет допуском; 0242 — адресным объединением и защитой от устаревшей записи; 0243 — API-доступностью. `bind-tool-outage-prerequisites` задачи 0246 применяет те же правила к другой карточке 0244; совместных правок runtime здесь нет. Ни одну чужую дельту не расширять и не архивировать.

## Risks / Trade-offs

- PR 177 ещё открыт → текст и изолированную проверку можно подготовить; адресное поле выдаётся лишь после подтверждённой поставки канала.
- Артефакты 0243 живут только в её ветке → переносить полный каталог по зафиксированному SHA, совмещать только плановые файлы и не трогать чужое дерево.
- Запись произошла, подтверждение потерялось → повторное чтение/no-op механизмом 0242, без ручного отката карточки.
- Условия записаны, но 0243 всё ещё failed → так и сообщить; положительная модель допуска не является разрешением вернуть карточку.
- Данные поменялись после проверки → каждый реальный допуск снова использует свежий снимок и post-claim guard 0242; историческое свидетельство не постоянный пропуск.

## Migration Plan

В implement доставить согласованные артефакты, проверку и адресное поручение; супервизор подтверждает метаданные при обработке отчёта, review проверяет подтверждение и доставку файлов. Последующий исполнитель 0243 обновляет своё дерево из main и проверяет PR 177 до реализации. Откат документов Git не снимает зависимость на доске; удаление условия этой задачей не разрешено.
