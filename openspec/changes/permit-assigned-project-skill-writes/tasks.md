## Проверка состава каждого коммита

Каждый пункт — отдельный проверяемый коммит с обязательной отметкой своего выполнения. Добавлять только перечисленные пути явным списком `git -C <дерево> add -- <пути>`, при необходимости несколькими короткими вызовами. Перед коммитом проверить имена `git -C <дерево> diff --cached --name-only` и содержание `git -C <дерево> diff --cached`; после — `git -C <дерево> show --format=fuller --stat --patch HEAD`. Разрешённый путь не разрешает несвязанные изменения внутри него, включая tasks.md. Сразу отправлять `git -C <дерево> push -u origin HEAD`.

Проверить отсутствие временных изменений командами `git -C <дерево> diff --cached -- .matchlog/` и `git -C <дерево> show HEAD -- .matchlog/`. Не включать чужие артефакты `guard-declared-purpose-updates`, реальные `.agents/skills`, основные specs или архивы. Проба архивации не нужна и `probe-archive-sandbox` не создаётся. При отказе уборки стенда оставить путь и причину без обхода. Полные проверки, сборка, арена и ожидание CI не являются действиями этого плана; CI наблюдает супервизор.
