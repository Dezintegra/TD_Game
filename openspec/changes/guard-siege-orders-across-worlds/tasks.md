  Рабочие файлы: `packages/ai/src/siege.match.test.ts`, `packages/ai/src/test-support/siege-canary.ts`, `packages/ai/src/test-support/siege-canary.test.ts`. Добавить явную выборку 4242, 7, 99, 2026, 31337 и отдельный предел 960 секунд; исполнять все пять независимых осадных сценариев внутри теста, останавливая их по событию, winner или пределу. Сохранить семантику события как команды siege, не команды соперника и не записи намерения. Не менять старые вызовы и утверждения крепости/роя; исправить только связанные пояснения об общем горизонте.

  В быстрых тестах оценщика проверить 3/5, 2/5, 0/5, 5/5, неизменность знаменателя при поражениях и горизонте, повторные и посторонние seed, неполный набор, обнуление событий в проходящем наборе. Для правил остановки вынести необходимые чистые решения в тот же тестовый помощник и проверить фикстурами: чужая команда и observer не засчитываются, заказ на последнем допустимом решении засчитывается, решение после лимита не вызывается, winner запрещает дальнейший ход, заказ в завершающем step имеет приоритет при сохранённом winner. Проверить содержание диагностики всех миров, включая null и тики.

  Локальная проверка на implement: `npx vitest run --root packages/ai src/test-support/siege-canary.test.ts`; ожидается выполнение перечисленных быстрых сценариев без запуска матчей. Формат и линт: `npx prettier --check packages/ai/src/siege.match.test.ts packages/ai/src/test-support/siege-canary.ts packages/ai/src/test-support/siege-canary.test.ts` и `npx eslint packages/ai/src/siege.match.test.ts packages/ai/src/test-support/siege-canary.ts packages/ai/src/test-support/siege-canary.test.ts` — отдельными вызовами. Зависимости готовятся штатным implement в своём дереве.

  Наблюдаемая приёмка матчевым CI: пять результатов, минимум три заказа, существующие проверки крепости и роя сохранены. Тест не объявлять прошедшим по одним фикстурам. Матчи локально не запускать; шага ожидания CI нет. Если текущая выборка не проходит, сохранить таблицу в теле PR и действовать по разделу Risks design, не подгонять seed/порог/горизонт и не менять профиль. Диагностика, а не увеличение числа, должна объяснить следующий шаг.

  Перед коммитом отметить этот выполненный пункт в `openspec/changes/guard-siege-orders-across-worlds/tasks.md`. Все четыре пути добавить явным списком через `git -C <дерево> add -- <перечень путей>`. Проверить имена и содержимое индекса командами `git -C <дерево> diff --cached --name-only` и `git -C <дерево> diff --cached`; допустимы только рабочая правка этого шага и его отметка. После коммита проверить `git -C <дерево> show --format=fuller --stat HEAD` и `git -C <дерево> show --format= --patch HEAD`, затем немедленно `git -C <дерево> push`. После этого первого коммита открыть черновой PR по штатному контракту implement с обоснованием через файл тела.
