## Why

Задача 0115 сообщает о пропущенных локальных проверках в имплементации 0067. На свежей базе допуски `pnpm install` и `npx eslint/prettier/vitest` уже присутствуют в обеих оболочках, но `node --check <файл>` не покрыт: разрешения отдельных сценариев Node не совпадают с этой приставкой. Нужен недостающий допуск с регрессионной проверкой, чтобы синтаксис служебного JavaScript можно было проверить до CI.

## What Changes

- Добавить разрешение приставки `node --check` для Bash и PowerShell.
- Защитить покрытие синтаксической проверки общим механизмом `uncoveredCommands`, учитывающим allow и deny; сохранить существующее покрытие установки зависимостей и трёх узких проверок.
- Проверить отрицательными контролями удаление допуска, перекрывающий запрет и нежелательное расширение до произвольного запуска Node.

## Non-goals

- Повторное добавление уже имеющихся допусков, изменение установки зависимостей или проверка принадлежности ссылок `@td/*` дереву (кандидат 0305).
- Общий допуск `node:*`, выполнение строк кода, изменение предохранителей среды и правил управления супервизором.
- Полный аудит команд этапов, расширение `STAGE_COMMANDS`, переход на одну оболочку или изменение поставки разрешений исполнителям.
- Изменение игры, CI, правил ожидания проверок, архивация чужих изменений и запуск живого супервизора.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `build-tooling`: новое требование о допуске синтаксической проверки JavaScript в конвейере. Дельта ADDED: такого требования в основе нет.

## Impact

Реализация затронет `supervisor/config/stage-settings.json` и новый `supervisor/config/syntax-check-permissions.test.mjs`. Общая мерка `supervisor/config/permissions.mjs` используется без изменения. Зависимости не добавляются.

**Отзывчивость интерфейса:** влияния нет — меняется оснастка разработки, код клиента и игровой цикл не затрагиваются.

**Сетевой трафик:** влияния на игровой протокол и трафик нет; синтаксическая проверка локальна, новых загрузок зависимостей или сетевых операций правка не вводит.

## Пересечения и порядок архивации

`openspec list --json` проверен после `git -C . fetch origin` и `git -C . merge origin/main` (Already up to date). `permit-the-pipeline-scripts` описывает `pnpm run`, `pnpm test:pipeline` и защиту управления супервизором; `hold-uncovered-stages` — общую мерку и предварительный допуск этапов; `name-what-cuts-code-in-arguments` — ограничения строк кода. Их требования сохраняются. Задачи `outlive-the-supervisor` и `pause-on-api-overload` уже упоминают `node --check`, но допуска ему не добавляют.

Дельта лежит в существующей `build-tooling`, не использует основу из открытых изменений и не требует их предварительной архивации. Общий файл разрешений может пересечься с чужой реализацией: перед implement требуется обычное освежение базы и сохранение посторонних правил. Самостоятельный вопрос шапки файла относится к кандидату 0321.
