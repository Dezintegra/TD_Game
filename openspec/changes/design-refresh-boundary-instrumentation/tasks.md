## 2. Граница будущей работы — не исполняемые пункты

Нативный патч, build receipt, отрицательные проверки производственных границ, token query, замена runtime и живое окно не разрешены этой карточке и не становятся чекбоксами. Их техническая последовательность и критерии описаны в design.md, разделы 1–6. В handoff пункта 1.1 перенести два последовательных допуска из раздела 6: сначала отдельное поручение на разработку, сборку и проверки по отправленному проекту и принятому аудиту; затем отдельный допуск к активации/живому опыту по готовому патчу, подтверждённому происхождению сборки и результатам проверок. Содержательная проверка handoff должна подтвердить, что результаты будущей разработки не названы предусловием поручения на саму разработку, а первое поручение не разрешает живой опыт. Выбор B при этом уже сделан, повторного вопроса A/B нет.

Результат документальной поставки не удовлетворяет обязательный результат 0370: фактическая доступность/пригодность источника требует последующей реализации и разрешённой проверки. Не закрывать открытые пункты 0370, не менять её checker, не создавать обратную зависимость на неё или условие вливания PR 283. Её existing collector/budget/lock route и конечная причинная приёмка сохраняются.

Установка зависимостей, тесты, сборки и прогоны для этого документального шага не нужны. OpenSpec и просмотр diff — достаточная проверка формы и области поставки; функциональная пригодность будущего источника ими не утверждается. Ожидание CI и архивация не входят в tasks.
