# Разметка есть у каждого блока скилла

## Зачем

Скилл проработки `supervisor/skills/design.md` показывает сессии три
командных блока — `openspec new change` (строка 88), `openspec validate`
со `openspec status` (178) и `git add`/`git commit`/`git push` (195), —
и ни один из них не несёт разметки языка вовсе.

Изменение `one-shell-for-stages` (задача 0156, pull request 126) заводит
в этот же файл раздел «Оболочка команд» со словами: «Разметка `powershell`
у командных блоков стоит не для красоты: она — единственное, по чему
ты выбираешь оболочку». Сами блоки при этом остаются безъязыкими. Выходит
скилл, который велит выбирать оболочку по разметке и сам её не даёт,
а сессия выбирает буквально: 03.09.2026 имплементация задачи 0149 взяла
по разметке Git Bash и получила код 127 на `pnpm install`
и `cannot spawn sh` на `git push`. Оба провала пришли молча, обычным
ненулевым кодом, и стоили этапу следа.

Молчаливым остаётся и сам недосмотр. Сторож `supervisor/config/shell.test.mjs`
из того же pull request 126 считает виновными блоки, чья разметка входит
в `BASH_LANGS`, а тела проверяет лишь у блоков из `COMMAND_LANGS`. Блок
без разметки не попадает ни в один из двух перечней: он проходит обе
проверки, ничего о себе не сообщив. Поэтому сценарий «Сегодняшние скиллы
проходят» на ветке pull request 126 зелёный, хотя утверждение «все
командные блоки размечены `powershell`» для `design.md` неверно.

Сегодня безъязыкие блоки есть только в `design.md`. В остальных девяти
скиллах разметка стоит у каждого блока: `deploy.md` показывает команды
как `powershell`, `audit.md`, `implement.md`, `review.md`, `benchmark.md`
и `revise.md` — как `bash` (их переводит pull request 126), `triage.md`,
`interpret.md` и `postmortem.md` содержат только образцы отчётов
разметкой `json`.

## Что меняется

1. Три командных блока `supervisor/skills/design.md` получают разметку
   `powershell`. Тела блоков остаются прежними: ни голого `@{`, ни строки
   с обратной косой на конце, ни приставки `ИМЯ=значение` в них нет, —
   то есть все три команды разбираются PowerShell как есть.

2. В набор тестов конвейера добавляется сторож
   `supervisor/config/skill-blocks.test.mjs`: ни один блок кода
   в скиллах этапов не остаётся без разметки языка, а провинившийся
   называется скиллом и номером строки. Это ровно та дыра, сквозь которую
   недосмотр `design.md` прошёл мимо сторожа единственной оболочки.

## Non-goals

- **Не правим сам pull request 126.** Он ведётся другой веткой и стоит
  в состоянии `pr`, то есть может вливаться прямо сейчас; чужую ветку
  сессия-исполнитель не трогает. Правка ложится своей веткой и своим
  pull request.

- **Не сводим двух сторожей в один.** `shell.test.mjs` и новый
  `skill-blocks.test.mjs` разберут ограждения каждый по-своему. Свести
  их можно будет, лишь когда обе ветки окажутся в `main`; до тех пор
  общий файл дал бы конфликт при вливании — ровно по той причине,
  по какой pull request 126 сам завёл `shell.test.mjs` отдельным файлом,
  а не дописал в `transitions.test.mjs`. Заявка на сведение подана
  отчётом этапа.

- **Не переводим на `powershell` командные блоки остальных скиллов.**
  Разметка `bash` в `audit.md`, `implement.md`, `review.md`,
  `benchmark.md` и `revise.md` — предмет pull request 126, и трогать её
  второй веткой значит гарантировать конфликт по каждой строке.

- **Не трогаем `supervisor/README.md` и общие памятки проекта.**
  Их читает человек, оболочку он выбирает сам, и примеры разметкой `bash`
  там законны.

- **Не заводим требования о том, какой именно язык у блока.** Новое
  требование говорит лишь «разметка есть»; какой она должна быть
  у команды, уже сказано в `one-shell-for-stages`.

## Влияние на отзывчивость интерфейса и на сетевой трафик

Влияния нет ни на то, ни на другое. Изменение целиком лежит
в `supervisor/` — в тексте скиллов и в наборе тестов конвейера. Ни один
файл `apps/client`, `apps/server`, `packages/sim`, `packages/protocol`
не затронут: в игру не уезжает ни строки, отрисовка и сетевой обмен
остаются прежними побайтно.

## Порядок архивации

Изменение архивируется **ПОСЛЕ `agent-backlog-pipeline`**: та заводит
способность `dev-pipeline-worker`, которой в `openspec/specs/` ещё нет
вовсе, и дельта поверх отсутствующей основы падает при архивации.

Изменение архивируется **ПОСЛЕ `one-shell-for-stages`**: наше требование
дополняет его правило о разметке `powershell` и без него читается
как повисшее в воздухе, а наш сторож встаёт рядом с его сторожом.
