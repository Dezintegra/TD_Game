# Задачи

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе.
Прогон сторожей везде один и тот же:

```powershell
npx vitest run --root supervisor config/skill-blocks.test.mjs
```

Ключ `--root supervisor` обязателен: без него тесты конвейера
не находятся вовсе, и прогон зеленеет, ничего не прогнав.

Порядок шагов обратный привычному, и это нарочно. Сторож из шага 2
краснеет на сегодняшнем `design.md`, поэтому правка скилла идёт первой:
иначе шаг 2 уехал бы в ветку заведомо красным коммитом, а правило
проекта требует, чтобы каждый шаг проверялся сам по себе.

## 1. Разметить три командных блока скилла проработки

- [ ] В `supervisor/skills/design.md` дописать `powershell` к трём
      открывающим ограждениям: строка 88 (`openspec new change`), строка
      178 (`openspec validate --changes --strict` и `openspec status
      --change`), строка 195 (`git add --`, `git commit -m` и `git push
      -u origin HEAD`). Закрывающие ограждения (90, 181, 199) не трогать:
      языка у них не бывает.
- [ ] Тела всех трёх блоков оставить **дословно прежними**. Это проверено
      при проработке по всем трём формам, которые сторожит
      `one-shell-for-stages`: голого `@{` нет, строки с обратной косой
      на конце нет, приставки `ИМЯ=значение` нет. Переписывание тел
      здесь было бы правкой не по задаче и вошло бы в спор с pull
      request 126.
- [ ] Отступ ограждений сохранить как есть: три пробела у блока в пункте
      6 и четыре у блоков в пунктах 11 и 12. Блоки лежат внутри пунктов
      перечня, и сдвиг к началу строки вынес бы их из пункта.
- [ ] Никаких других файлов в этом коммите. В частности, разметку `bash`
      в `audit.md`, `implement.md`, `review.md`, `benchmark.md`
      и `revise.md` не трогать: её переводит pull request 126, и вторая
      рука по тем же строкам даёт конфликт.
- [ ] Открыть черновой pull request сразу после этого коммита: до его
      появления пуши в ветку не запускают проверок CI вовсе.

**Проверка:** поиск по `supervisor/skills/design.md` выражением
`^\s*```\s*$` находит ровно три ограждения — 90, 181 и 199, — и все три
закрывающие. До правки их было шесть.

## 2. Завести сторожа на безъязыкий блок и доказать его пробой на порчу

- [ ] Завести `supervisor/config/skill-blocks.test.mjs`. Скиллы брать
      по перечню `NEEDS_SESSION` из `./transitions.mjs`, а не подбором
      файлов каталога: перечень — объявленный состав этапов с сессией,
      и выпавший из него скилл сторожу не подсуден.
- [ ] Разбирать ограждения **попарно**: первое открывает блок, следующее
      закрывает. Считать иначе нельзя — у закрывающего ограждения языка
      не бывает никогда, и сторож покрасил бы каждый скилл разом.
- [ ] Ограждение искать выражением, допускающим **свой отступ**
      (`^[ \t]*```(\S*)[ \t]*$`). Блоки скиллов лежат внутри пунктов
      перечня; привязка к началу строки не нашла бы ни одного блока,
      и сторож зеленел бы всегда.
- [ ] Виновным считать открывающее ограждение с пустым языком. Отдавать
      имя скилла и **номер строки** ограждения: скиллы длинны,
      а безъязыкое ограждение на глаз неотличимо от закрывающего, и
      сторож, называющий один файл, посылает читателя считать ограждения
      руками.
- [ ] О том, какая именно разметка стоит, не судить вовсе: `json`,
      `powershell` и `bash` проходят одинаково. Разметку команд сторожит
      `one-shell-for-stages`, и два суда об одном разошлись бы.
- [ ] Написать комментарием, зачем сторож отдельным файлом, а не третьей
      проверкой в `supervisor/config/shell.test.mjs`: того файла
      в базе этой ветки нет — он приезжает вливанием pull request 126,
      и дописать в него отсюда нечего. Назвать это долгом на сведение,
      чтобы через полгода два разбора ограждений не выглядели небрежностью.
- [ ] Завести **пробу на порчу**: наведённый безъязыкий блок обязан
      красить сторожа и называть номер строки. Сторож, не краснеющий
      на сломанном скилле, — украшение, и проверяется это набором,
      а не руками.
- [ ] Завести **обратную пробу**: блок с разметкой `json` — образец
      отчёта, а не команда — сторожа не тревожит. Без неё сторожа однажды
      напишут глухим запретом и обнаружат это, лишь когда он покрасит три
      скилла с образцами отчётов разом.

**Проверка:** прогон сторожей выше — зелёный целиком. В нём обязаны
выполниться три вещи сразу: на сегодняшних десяти скиллах виновных нет;
проба на порчу красит наведённый безъязыкий блок и называет номер
строки; проба с блоком `json` остаётся зелёной. Зелёный прогон на десяти
скиллах и есть механизированная сверка остальных девяти, которой просит
задача: руками её повторять не нужно.

**Проверка живости пробы:** до правки шага 1 сторож обязан краснеть
на `design.md` тремя строками — 88, 178 и 195. Если после шага 1 сторож
зелёный, а на откате шага 1 не краснеет, он не сторож.

Дополнительно: `npx prettier --check supervisor/config/skill-blocks.test.mjs`
и `npx eslint supervisor/config/skill-blocks.test.mjs`.

## 3. Дождаться зелёного CI на pull request

- [ ] `gh pr checks <номер> --watch` — дождаться, пока проверки добегут.
      Задача не сделана, пока GitHub не сказал «зелено»: локальный прогон
      узкий и о наборе конвейера целиком не говорит.
- [ ] Красный прогон — прочитать `gh run view --job <id> --log-failed`,
      починить отдельным атомарным коммитом, отправить, дождаться снова.
- [ ] Черновой статус **не снимать**: его снимает ревью первым подшагом
      вливания. Снятый раньше времени, он объявляет работу законченной
      до проверки.

**Проверка:** все задачи проверок на pull request зелёные, и в их числе
`быстрые тесты` — именно они гоняют `pnpm test:pipeline`, то есть нового
сторожа.
