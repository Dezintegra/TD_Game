## Why

Тело коммита с записью шаблона или адресом может быть отвергнуто разбором команды до Git. В design, implement, revise, review и deploy названы только повторные `-m`; общая рекомендация перенести текст в файл не называет ключ коммита. Задача 0199 требует проверить его собственным коммитом и сохранить точный текст причины.

## What Changes

- В пяти скиллах назвать `git -C <дерево> commit -F .matchlog/<имя>.txt` как выход для проблемного сообщения, оставив повторные `-m` основной формой.
- Пояснить, что файл содержит всё сообщение: заголовок, пустую строку и тело; переносы остаются в файле, команда однострочная.
- Зафиксировать дату, среду, результат реального коммита с записью класса слова и границы доказательства. При неуспехе не обещать работоспособный путь.
- Сохранить ограничения этапов review/deploy, приблизительную мерку длины команды и передачу подробного обоснования в design/тело PR.

## Non-goals

- Не менять разрешения, парсер команд, Git или механизм приёмки отчётов.
- Не давать review/deploy новых прав на коммиты и не выполнять реализацию на design.
- Не закрывать и не переделывать выполненную 0072; не измерять точную границу длины команд.
- Не выдавать пробу Codex за проверку парсера Claude и не повторять эксперименты задачи 0344.

## Capabilities

### New Capabilities

- `dev-pipeline-worker`: добавляется отдельное требование о файловой передаче сообщения коммита. Основы ещё нет в `openspec/specs`; имя уже заведено открытым `agent-backlog-pipeline`, поэтому новая параллельная способность не создаётся. При первой архивации способности потребуется её Purpose.

### Modified Capabilities

Нет MODIFIED: требование с таким именем в основной спецификации отсутствует.

## Impact

Реализация ограничена `supervisor/skills/design.md`, `implement.md`, `revise.md`, `review.md`, `deploy.md` и отметкой выполнения собственного `tasks.md`. Проба использует игнорируемый файл `.matchlog/0199-commit-message.txt`.

Отзывчивость интерфейса и сетевой трафик игры не меняются: инструкции исполняются вне игрового цикла, клиент, сервер и протокол не затрагиваются. Новых запросов супервизора к внешним службам нет.

## Пересечения и порядок архивации

База освежена 14.09.2026 до `beab87f9`. PR 137 подтверждён через GitHub как MERGED, `mergedAt=2026-09-04T01:11:03Z`, merge SHA `bc64c171d82c687e4fe36f43958a04e9bd13956e`. Старой технической предпосылки больше нет.

`document-commit-command-length` (0072, выполнена) прямо оставляет `-F` задаче 0199. Сохраняются её короткая причина, приблизительные 965 байт, design и файл PR для подробностей; файловая форма дополняет способ передачи самого сообщения и не требует удлинять его. Условный вопрос об объединении с ещё открытой 0072 больше неприменим.

`name-what-cuts-code-in-arguments` задаёт общий перенос проблемного текста в файл; здесь конкретизируется ключ коммита. `unblock-the-stalled-board/tasks.md` уже упоминает `-F` для собственной работы, но не содержит заказанную правку пяти скиллов и не заменяет пробу этой задачи. `document-permission-independent-guards` ведётся отдельно (PR 189), его код и артефакты не меняются.

Изменение архивируется ПОСЛЕ `agent-backlog-pipeline`, `name-what-cuts-code-in-arguments` и `document-commit-command-length`: они задают способность и соседние общие правила. Новое уникальное ADDED-требование не заменяет их сценарии. Архивация на этом этапе не выполняется.
