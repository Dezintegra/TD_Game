## Context

Пять целевых скиллов содержат повторные `-m`, но не называют `-F`. `supervisor/config/transitions.test.mjs:1118` проверяет дословное наличие «повторными `-m`» в design/implement/revise. `.gitignore:20` исключает `.matchlog/`; в stage-settings уже есть запись в этот каталог и форма Git с `-C`. Новые разрешения не нужны. Настройки Claude не являются доказательством их применения к текущему Codex.

## Goals / Non-Goals

Цель — сохранить точную запись причины в сообщении коммита, не помещая проблемный текст в строку команды. Границы перечислены в proposal; изменение инструкций выполняет implement после аудита. Проба собственным коммитом артефактов явно заказана этой задачей и является исключением для служебного файла `.matchlog/` на design.

## Decisions

1. Основная форма остаётся повторными `-m`. При записи шаблона, двух разделителях подряд, веб-адресе или длинной прозе всё сообщение записывается средствами редактирования файлов в собственный UTF-8 файл `.matchlog/0199-commit-message.txt`: Conventional Commit в первой строке, пустая строка, обоснование. Команда `git -C <дерево> commit -F .matchlog/0199-commit-message.txt` содержит только относительный путь с прямыми косыми. Не смешивать `-m` с `-F`. Здесь словосочетание «файл тела» означает файл полного сообщения, иначе Git примет первую строку тела за заголовок.
2. Переписать исходные категоричные фразы в пяти скиллах, сохранив запрет многострочной команды. Рядом с UNC-абзацем уточнить применение файлового пути к сообщению коммита. Отвергнута только общая ссылка: этап получает собственный скилл. В review/deploy это правило формы допустимого коммита, а не новое разрешение его создавать.
3. Сохранить полезное сокращение обоснования из 0072, число с оговорками и подробности в design/файле PR. `-F` выводит прозу из команды, но не обещает безграничный текст, не снимает ограничений остальных доводов и не требует переносить всё проектирование в Git. Отвергнуты длинный `--body`, расширение allow и замена объясняемой записи класса словами: они либо возвращают ту же проблему, либо теряют точность.
4. Проба — реальный первый коммит полного комплекта артефактов, без пустого коммита и без чужих файлов. В теле обязательно находятся `\w`, `\\w` и `/\w/`: первая запись называет класс слова, следующие сохраняют соседние разделители, из-за которых поставлена задача. После успеха немедленно отправить коммит; прочитать сообщение через `git -C . show -s --format=fuller HEAD`, сверить символы с файлом и отсутствие файла `.matchlog/` в составе коммита. Дату, Git, среду, SHA, код возврата и границы результата сохранить в `verification.md` отдельным отправленным документальным коммитом. Это запись результата после опыта, а не заранее объявленная удача. При отказе `-F` остановиться с фактической ошибкой, не добавляя обещание в скиллы и не выдумывая другой способ пробы.
5. При реализации перенести подтверждённую запись из verification рядом с правилом каждого скилла. Успех в Codex доказывает этот путь только для наблюдавшейся среды. Отдельная проверка точных разрешений Claude остаётся задачей 0344; успешное прохождение Git не объявляется доказательством работы другого парсера или отсутствия будущих отказов.

## Risks / Trade-offs

- Неверный заголовок или кодировка файла → явно объяснить полный формат сообщения и сравнить созданное сообщение с файлом.
- Служебный файл попадёт в историю → только явный список добавляемых путей, просмотр индекса и созданного коммита; `.matchlog/0199-commit-message.txt` отсутствует в обоих.
- Отказ уборки после успешного коммита → игнорируемый файл не влияет на успешность коммита; можно оставить его до штатной уборки дерева, не ослабляя ограничения среды и не объявляя уборку выполненной.
- Разные исполнители → в записи опыта назвать Codex/PowerShell, Windows и Git, а не обобщать результат на Claude. Версия парсера текущего инструмента не предоставлена; не придумывать её.

## Migration Plan

Один атомарный шаг реализации меняет согласованные абзацы пяти скиллов и отмечает tasks. Новые сессии получают обновлённые инструкции обычным механизмом конвейера. Откат — отмена этого документального коммита; формат карточек и настройки не меняются.

## Проверки

На design: только OpenSpec validate/status, чтение Git и заказанная проба коммитом. На implement: `pnpm install --frozen-lockfile --prefer-offline`, адресный Prettier пяти скиллов, `pnpm test:pipeline config/transitions.test.mjs`, проверка diff. Полный verify, игровой набор, сборка, арена и ожидание CI не планируются. Новых тестов на совпадение прозы не нужно: существующие проверки сохраняют повторные `-m` и запрет многострочных команд, точность файловой передачи проверяется реальным коммитом.

Геймплей, рассинхрон, реконнект, детерминизм, golden и PROTOCOL_VERSION не затронуты: файлы симуляции и протокола не меняются.
