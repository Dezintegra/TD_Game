## MODIFIED Requirements

### Requirement: Неопределённость не считается конфликтом

Оркестратор SHALL сохранять задачу в `pr`, если возможность слияния ещё
не определена либо данные GitHub не удалось прочитать. При `MERGEABLE`
результаты CI SHALL обрабатываться прежним маршрутом: успешные проверки
открывают ревью, неуспешные отправляют в доработку, отсутствующие и действительно идущие
сохраняют ожидание. Противоречивый незавершённый статус SHALL разрешаться только
по требованию «Противоречивые проверки подтверждаются актуальным workflow»;
одного успешного conclusion или времени завершения недостаточно.

#### Scenario: GitHub ещё вычисляет слияние

- **WHEN** GitHub сообщает `UNKNOWN`, в том числе при зелёных проверках
- **THEN** задача остаётся в `pr` до следующего опроса без ложного возврата

#### Scenario: Ответ недоступен или повреждён

- **WHEN** запрос GitHub завершился ошибкой либо данные не разобрались
- **THEN** состояние карточки не меняется, причина ожидания указывает проблему чтения

#### Scenario: Конфликта нет и CI завершён

- **WHEN** GitHub сообщает `MERGEABLE` и завершённые проверки
- **THEN** успешный CI переводит задачу в `review`, неуспешный — в `revise`

## ADDED Requirements

### Requirement: Противоречивые проверки подтверждаются актуальным workflow

Штатный опрос CI SHALL распознавать противоречие GitHub Actions CheckRun:
статус `IN_PROGRESS`, conclusion `SUCCESS` и корректное время завершения.
Перед признанием такой проверки завершённой оркестратор SHALL подтвердить
её принадлежность репозиторию и PR, связанному workflow run и заданию по
идентификаторам, равенство SHA текущей вершине PR и актуальность попытки.
Связанный workflow SHALL иметь статус `completed` и conclusion `success`.
Задание этой попытки SHALL иметь `success` и корректное время завершения;
повтор того же противоречия в статусе REST-задания допускается только
при выполнении всех остальных условий подтверждения.

Оркестратор SHALL проверить полный актуальный набор проверок PR и полный
набор заданий подтверждаемой попытки, включая все страницы. Сопоставление
по одному имени MUST NOT считаться идентичностью. Успех одного workflow
MUST NOT скрывать другую проверку или более новый связанный с этим PR
запуск того же workflow на том же SHA. Незавершённая новая попытка,
несопоставленная проверка, неизвестная полнота либо несовпадение данных
SHALL сохранять `pending`. Результат `success` SHALL требовать хотя бы
одну реально успешную проверку; штатные завершённые `SKIPPED` допускаются,
полностью пропущенный набор успехом не является.

Перед выдачей подтверждённого успеха оркестратор SHALL повторно прочитать
PR и актуальные метаданные запусков: смена вершины, набора проверок,
попытки или нового запуска SHALL отменять подтверждение этого опроса.
Конфликт PR SHALL сохранять приоритет над CI; неизвестность слияния
SHALL запрещать успех. Неподтверждённый результат MUST NOT сохраняться
как успешный кеш между опросами. Ошибка чтения, разбора или ограничение
объёма сверки SHALL давать `pending` с причиной, без изменения карточки.
Подтверждённый актуальный неуспешный CI SHALL сохранять маршрут `failure`,
но недостоверные или устаревшие сведения MUST NOT порождать ложную доработку.

#### Scenario: Сохранённый пример PR 219

- **WHEN** проверка 102229264668 возвращает `IN_PROGRESS`, `SUCCESS`, `completedAt`, workflow 34276070514 попытки 1 успешно завершён на текущем head `3ebe398ce704e377e5b6a16f4e30d3eef3f2553c`, а все условия полноты и повторной сверки выполнены
- **THEN** штатный `readExternal` возвращает `success` и допускает обычный переход к review, даже если REST повторяет противоречивый статус этого задания

#### Scenario: Действительно работающее задание

- **WHEN** при отсутствии подтверждённого актуального неуспеха проверка или задание имеет незавершённый статус и не удовлетворяет условиям подтверждения противоречия, либо актуальный workflow ещё выполняется
- **THEN** опрос не разрешает противоречие и возвращает `pending`

#### Scenario: Завершённая проверка с ошибкой

- **WHEN** PR имеет `MERGEABLE`, полнота и актуальность CI подтверждены, а проверка или задание завершено с `FAILURE`, `CANCELLED` или `TIMED_OUT` (соответственно `failure`, `cancelled`, `timed_out` в REST)
- **THEN** опрос возвращает `failure`; отсутствие успешного conclusion у завершённой ошибки не превращает её в `pending`

#### Scenario: Штатные пропуски вместе с подтверждённым успехом

- **WHEN** при `MERGEABLE` все условия подтверждения противоречивой успешной проверки выполнены, остальные проверки и задания завершены с `SUCCESS` или штатным `SKIPPED`, а хотя бы одна проверка имеет `SUCCESS`
- **THEN** опрос возвращает `success`; завершённый `SKIPPED` не считается работающим или неуспешным заданием

#### Scenario: Другая вершина или неверная связь

- **WHEN** SHA run или задания отличается от head PR, ссылка ведёт в другой репозиторий, задание отсутствует в попытке или связь с PR не подтверждена
- **THEN** опрос сохраняет `pending`, не используя чужой успешный результат

#### Scenario: Началась новая попытка или новый запуск

- **WHEN** найдена новая незавершённая попытка либо более новый запуск того же workflow для этого PR и SHA, в том числе появившийся между чтениями
- **THEN** прежний успешный run не даёт `success`; опрос сохраняет ожидание актуального CI

#### Scenario: Неполный набор или другой результат

- **WHEN** среди остальных проверок либо заданий актуального набора есть работающая, неуспешная или несопоставленная запись, либо страницы прочитаны не полностью
- **THEN** подтверждение одного задания не даёт успеха всему PR; работа и неизвестность сохраняют `pending`, подтверждённый актуальный неуспех обрабатывается как `failure`

#### Scenario: Ошибка или отмена

- **WHEN** подтверждённый актуальный workflow или завершённое задание имеет `failure`, `cancelled`, `timed_out` либо иной недопустимый результат
- **THEN** результат не считается успешным и сохраняется штатный маршрут неуспешного CI

#### Scenario: Подтверждение недоступно

- **WHEN** GitHub отвечает ошибкой, некорректным JSON, неполными полями или исчерпан бюджет сверки
- **THEN** опрос возвращает `pending` с диагностикой причины и не использует успешные сведения прошлого опроса

#### Scenario: Конфликт либо смена PR при повторной сверке

- **WHEN** повторное чтение выявляет `CONFLICTING`, `UNKNOWN`, новую вершину или изменённый набор проверок
- **THEN** конфликт возвращает `conflict`, прочая неопределённость — `pending`, и подтверждённый ранее workflow не открывает review

#### Scenario: Обычный CI без противоречий

- **WHEN** исходный ответ не содержит подходящих противоречивых CheckRun
- **THEN** сохраняется обычное сведение проверок и дополнительное подтверждение workflow не запрашивается
