# Задачи

Каждая — отдельный коммит, отправляемый сразу.

Порядок в итоге сложился не тот, что задумывался. Раскладка и окно
прокачки поехали ОДНИМ коммитом, и разделить их не вышло: полосу
с монитора снимает именно уход прокачки из плиток — пока столбцы
характеристик росли под плитками, нижней полосе было от чего расти,
и обнулять её высоту было не на что.

## 1. Иконки

- [x] **1.1. Запекатель иконок.** `apps/client/src/game/icon-sprites.ts`:
      печёт три юнита, стену, две башни и генерала через `bakeArmour`
      румбом `DIRECTION_SOUTH` с разрешением выше экранного, отдаёт карту
      `data-URL`. Проверено модульным тестом на состав ключей и ракурс.
- [x] **1.2. Иконки доезжают до React.** Поле `icons` в `useHudStore`,
      заполняется ПОСЛЕ рельефа, по одной за кадр, из `bootstrap.ts`.
- [x] **1.3. Иконки встают на плитки.** `hud/icons.tsx` берёт готовую
      иконку из store, а до её появления рисует прежний контур. Контуры
      остались именно как подложка. Проверено снимком: замерено 148 × 120
      точек у штурмовика при показе на 26.
- [x] **1.4. Решение по сводке сторон.** Иконка поставлена и в `Tally`.
      Снимок показал, что силуэты на 22 точках различимы, — оставлено
      запечённое. Заодно всплыла настоящая беда: свой значок в сводке
      СОПЕРНИКА помечал чужой состав своим цветом. Стороны стали
      печататься обе.

## 2. Раскладка по углам и окно прокачки

- [x] **2.1. Полосы обнуляются.** `--td-hud-top` и `--td-hud-bottom-*`
      стали нулём на всех размерах экрана.
- [x] **2.2. Сводки сторон уезжают в верхние углы.** Своя слева, общее
      по центру, соперник справа; строка связи под сводкой соперника.
- [x] **2.3. Миникарта переезжает влево.** `--td-field-inset-right`
      заменён на `--td-field-inset-top`.
- [x] **2.4. Плитки заказа встают в правый нижний угол.** На мониторе
      два столбца, на телефоне один. Кнопка прокачки и переходы
      к генералу и базе — служебным рядом под рейкой.
- [x] **2.5. Цель и режим атаки уезжают в левый нижний угол.**
- [x] **2.6. Значение после покупки.** `stat-rows.ts` добавил в `StatRow`
      поле `next`, посчитанное прогоном той же функции баланса
      по игроку с купленным уровнем. Проверка сверяет обещание не «больше
      ли оно», а с тем, что игрок получит на самом деле.
- [x] **2.7. Окно матрицей.** `hud/UpgradeWindow.tsx`: девять строк,
      шесть столбцов, прочерк в пустой клетке, подпись у особого.
      `StatColumn`/`StatLine` ушли из `ActionBar.tsx`, `data-testid`
      покупок и значений сохранены.
- [x] **2.8. Окно одинаково на телефоне.** Ужимается переменными,
      ни строка, ни столбец не пропадают; при нехватке высоты матрица
      прокручивается внутри окна, шапка остаётся.

## 3. Приведение проверок в порядок

- [x] **3.1. Сквозные проверки раскладки переписаны под углы.**
      Непересечение панелей с полем заменено на «поле занимает окно»
      и «центр свободен»; счёт веток чинён — отбор по приставке
      `upgrade-` ловил бы и окно, и строки матрицы.
- [ ] **3.2. Снимки трёх размеров.** Монитор, ландшафт, портрет, каждый
      с открытой и закрытой прокачкой — посмотреть глазами и сверить
      с артбордами прототипа. НЕ СДЕЛАНО: на машине не осталось памяти
      под браузер (0,9 ГБ свободных из 15,7), Playwright падает
      на запуске.
- [ ] **3.3. Зелёный CI.** `gh pr checks --watch` до зелёного.
