## Decisions

### Подготовка документов из отправленного источника

Если к имплементации каталог 0216 ещё не пришёл в main, план прямо разрешает получить его девять документов из зафиксированной выше ревизии в своём дереве. Это существующее изменение под прежним именем, а не второе изменение 0216. Полный комплект нужен, чтобы не публиковать обрезанную способность без proposal, design и остальных дельт. Из него собственная правка допускается только в worker-дельте, design и tasks; прочие шесть файлов переносятся дословно. Исходный снимок сверяется до и после подготовки; новой реализации 0216 в нём нет.

Если документы уже пришли из main, править актуальную основу, не восстанавливая её из снимка. При изменении отправленного источника до подготовки прочитать diff с указанной ревизией и зафиксировать выбранную отправленную ревизию в отчёте; неподтверждённые изменения не перетирать. Не требуется слияние всей ветки, запись в соседнее дерево или ожидание вливания 0216. Ошибка получения существующего снимка означает технический `failed`, а не отсутствие предмета.

Отвергнуты: импорт кода 0216 вместе с веткой (обходит её аудит); одна неполная копия worker-дельты (теряет контекст остальных требований); ожидание 0216 как обязательное условие запуска (согласование нужно до её интеграции).

### Точечная правка 0216

В определении после перечисления невлитой ветки/PR назвать исключение для имплементации: доступная подготовка по плану исключает отсутствие предмета только по месту файла. Предшествующее безусловное предписание исхода читать через это уточнённое определение и поддержку исхода. В сценарии «Имплементации нечего править» прямо перечислить отсутствие подготовки, введённую поддержку и отсутствие собственного PR. В сценарии «Предмета нет, но pull request уже открыт» также оговорить отсутствие доступной подготовки: наличие PR не запрещает доступную работу.

Добавить положительные сценарии подготовки с собственным PR и без него, сценарий до поддержки и сценарий технической ошибки. Все остальные сценарии и предохранители worker-требования сохраняются, включая design и повторные возвраты. В design 0216 добавить ссылку на общую матрицу; в её шаге реализации инструкции прямо потребовать сохранить приоритет 0254 и пройти эту матрицу. Чужие пункты не отмечать выполненными и не переписывать остальные планы.

Уникальное ADDED-требование нашей дельты фиксирует согласованность этих текстов; не копирует целиком большой алгоритм возврата 0216 и не создаёт MODIFIED по отсутствующей основе. Простая ссылка из proposal отвергнута: она оставляет конфликтующие нормативное определение и WHEN/THEN на месте.

### Общая матрица 0254

Проверять строки вместе по исправленной worker-дельте, её design/tasks и реальной инструкции. «Любой» означает обе комбинации собственного PR, а для поддержки — до и после введения. Сначала безопасность дерева и явные предусловия; затем доступность подготовки; затем подтверждение отсутствия.

| Условия | Свой PR | Поддержка | Результат |
| --- | --- | --- | --- |
| Файл только в отправленном PR, получение по плану доступно | Нет / есть | Нет / есть | Продолжить подготовку |
| То же после конфликта необязательного слияния | Нет / есть | Нет / есть | Отмена, проверка восстановления, продолжить подготовку |
| Конфликт обновления origin/main | Любой | Любая | Отмена и failed с файлом |
| Отмена дополнительного слияния не удалась | Любой | Любая | failed с ошибкой, без сброса дерева |
| Ошибка доступа к существующему источнику или инструмента | Любой | Любая | Технический failed, отсутствие не доказано |

### Проверка и вторая интеграция

Узкий запуск на имплементации — `npx vitest run --root supervisor config/transitions.test.mjs`. Корневой `vitest.workspace.ts` не включает supervisor; отдельный корень выбирает `supervisor/vitest.config.ts`, где включены файлы `**/*.test.mjs`. Вариант без `--root supervisor` отвергнут: назначенный сторож не запускается. Успех требует фактического выполнения сторожа и всех отрицательных проб; отсутствие найденных тестов или их пропуск проверкой не считаются.

Дополнить `transitions.test.mjs` проверкой определения и конкретных сценариев worker-текста; искать блоки по заголовкам, нормализуя пробелы. Не довольствоваться вхождением слова «подготовка» где-нибудь в документе. Отрицательные пробы в памяти возвращают прежнее определение, прежний сценарий, убирают каждое из условий поддержки/подготовки/собственного PR и превращают ошибку чтения в evidence. Каждая даёт диагностику пути и условия. Реальная инструкция остаётся под действующим сторожем 0254; фиктивную функцию выбора исхода моделью не создавать.

Чтобы проверка переживала архивацию, источник требования искать по точному заголовку сначала в `openspec/specs/dev-pipeline-worker/spec.md`, затем в активной дельте 0216, затем в её единственной архивной копии. Не брать нашу уточняющую дельту как замену проверяемому определению; отсутствие источника или неоднозначность архивных копий — ошибка. Сводный смысл матрицы проверяется вычиткой, тест текста не доказывает поведение модели.

0254 уже первая интеграция. После нашего вливания исполнитель 0216 обновляет свою main штатным способом и сохраняет исправленные документы. Её добавление исхода должно пройти имеющиеся проверки 0254 и новую проверку определения; потеря условий возвращается в доработку до вливания. Если 0216 успела первой, наша реализация применяет те же изменения поверх неё. Порядок архиваций приведён в proposal, задача его не исполняет.

## Risks / Trade-offs

Импорт полного комплекта планирования увеличивает diff → фиксировать источник и отдельно показывать собственную правку только трёх файлов. Конкурирующая правка 0216 → обновлять main и сверять отправленную ревизию перед подготовкой, неизвестные конфликты не разбирать вслепую. Жёсткие текстовые проверки → ограничить их смысловыми блоками и дать адресную диагностику, при переформулировке сохранять отрицательные пробы.

## Migration Plan

Один атомарный шаг до двух часов: согласованные документы и проверка вместе, немедленная отправка и черновой PR. Отметка выполнения только в собственном tasks. Обработчик и схемы не меняются. Откат обратным коммитом возвращает документы и проверку; данных для миграции нет.

Игровые пакеты не затронуты: рассинхрон и реконнект прежние, эталоны детерминизма и `PROTOCOL_VERSION` не меняются; `Math.random`, `Date.now` и числа с плавающей точкой в состояние мира не добавляются. Замеры и арена не требуются.
