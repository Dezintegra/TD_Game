## Context

Исторические кейсы: подготовка 0169 по отправленному файлу PR 126 и согласование 0216 с этой подготовкой. История прежней реализации сохранена в Git. Текущая инструкция implement и общий routing-contract уже используют blocked; плановая редакция приведена к ним в PR #262.

## Goals / Non-Goals

Сохранить доступную работу и однозначные исходы. Не повторять историческую реализацию и не переносить в своё дерево чужие неподтверждённые изменения.

## Decisions

1. Безопасное дерево, свежая main и явные предусловия проверяются прежде подготовки. Порядок вливания PR сам по себе не требует полного слияния соседней ветки.
2. Использовать только источник и состав подготовки, разрешённые согласованным планом. Собственный PR не запрещает доступную подготовку.
3. Конфликт дополнительного необязательного слияния: отмена, проверка восстановления и доступности предусмотренного способа, затем продолжение. Ошибка отмены, доступа, инструмента или обязательного слияния без альтернативы — технический failed с причиной, без сброса дерева.
4. Конфликт origin/main разрешается с сохранением поведения main и результата задачи; main служит основой адаптации. Сам конфликт не является причиной failed. Невозможность продолжения требует доказательной остановки по merge-conflict-resolution.
5. Подтверждённое ожидание без доступной подготовки — blocked с причиной, проверяемой ссылкой и ожидаемым результатом при любом собственном PR. Существующие артефакты сохраняются. Неподдерживаемый premature не отправляется.
6. Проверки читают реальные инструкции и worker-требование 0216; отрицательные пробы проверяют потерю каждого условия, а не только наличие нужных слов в другом документе. Старые снимки 0216 не импортируются поверх актуальных файлов.

## Матрица приёмки

| Случай | Ожидаемый исход |
| --- | --- |
| Разрешённая подготовка доступна; свой PR отсутствует/есть | Продолжить подготовку по плану |
| Необязательное слияние конфликтует, отмена успешна, подготовка доступна | Проверить восстановление и продолжить предусмотренным способом |
| Слияние не требуется планом | Не выполнять его ради подготовки |
| Конфликт main | Разобрать обе стороны, разрешить по действующим правилам и проверить результат |
| Ошибка отмены, чтения существующей ревизии, инструмента | Технический failed с конкретной причиной; отсутствие предмета не доказано |
| План требует конфликтующее слияние без альтернативы | Отмена и доказательная остановка, без самостоятельной замены плана |
| Явная зависимость запуска не выполнена | Не обходить её подготовкой |
| Предмет должен приехать, подготовки нет; свой PR отсутствует/есть | blocked с reason/result и ссылкой; работу сохранить |
| Отсутствие только предполагается | Не выдумывать зависимость, назвать недостающий факт |
| Старый текст предлагает premature | Использовать действующий blocked при доказанном ожидании |

## Risks / Trade-offs

Текстовые проверки защищают договорённость, но не доказывают поведение модели на любом входе. Обязательные условия проверяются по отдельности, а реальные переходы — тестами blockers/dependencies. Публикация требований требует сверки с текущей основной спецификацией; старые правила не возвращаются ради сохранения исторических формулировок.
