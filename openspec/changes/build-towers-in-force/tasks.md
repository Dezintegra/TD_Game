# Задачи

Порядок обычный для этого репозитория: сначала мерило, потом правка,
потом замер. Особенность одна — **запас чинится раньше группы**. Иначе
поздняя фаза, где денег на группу больше всего, останется парализованной,
и замер группы окажется снят на данных, которых она не касалась.

- [x] 1.1 Снять базовую линию на seed 1000–1019: башен на карте
      одновременно, построек за матч, покупок по фазам, ударов за пачку.

      0,56 башни, 17,1 постройки, 0 покупок в поздней фазе, 0 ударов.

## 2. Неприкосновенный запас

      *Проверка:* юнит-тест в `profile.test.ts` — при доходе 14 запас
      нулевой, при достаточном равен цене удара.
- [x] 2.2 Провести доход во все четыре места вызова `reserveOf`
      (`tryBuild`, `tryTrain`, `tryUpgrade`, `spendEfficiency`).
      *Проверка:* `pnpm --filter @td/ai typecheck` зелёный.
- [x] 2.3 Мерка достижимости вынесена в `savingLimit` и служит обоим
      применениям — терпению к покупке и осмысленности запаса.
      *Проверка:* формула в `opponent.ts` больше не повторяется.
- [x] 2.4 Замер: в поздней фазе появились состоявшиеся покупки.
      *Проверка:* было ноль на всю фазу, стало 76 построек, 344 заказа
      юнитов и 147 улучшений на сорока матчах.

## 3. Группа построек

- [x] 3.1 Постановка одной постройки вынесена в шаг цикла, работающий
      по копиям покрытия и занятости.
      *Проверка:* копии, а не исходные массивы; вызывающий владеет ими
      и уже посчитал по ним рубежи.
- [x] 3.2 `shieldBuildCell` принимает список клеток башен вместо списка
      построек: у заказанных в этом решении башен объекта ещё нет.
      *Проверка:* `posture.test.ts` и `opponent.test.ts` зелёные.
- [x] 3.3 Шаг повторяется, пока казна за вычетом заказанного покрывает
      цену с запасом и пока место находится.
      *Проверка:* юнит-тест «за одно решение случается больше одной
      постройки» зелёный.
- [x] 3.4 Покрытие, занятость и список башен обновляются после каждой
      команды группы.
      *Проверка:* тесты «клетки внутри группы не повторяются» и «каждая
      названная клетка занята постройкой сразу после `step`»; в базе
      арены отклонённых команд ноль.
- [x] 3.5 Размер группы виден разбору без правки схемы базы: команды
      постройки уже пишутся в таблицу `command` с номером тика.
      *Проверка:* запрос `group by match_id, player, tick` даёт
      раскладку по размеру группы.

      *Отступление от плана.* Изначально предполагалось записывать счёт
      состоявшихся команд в `attempt`. Отвергнуто: это поле схемы, то есть
      пересборка базы, ради величины, которая и так выводится запросом.
