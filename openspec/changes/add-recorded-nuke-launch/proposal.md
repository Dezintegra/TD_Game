## Why

Пуск ядерной ракеты сейчас не имеет собственного звука: появление `world.nukes` выдаёт только `NukeFall` у цели. Владелец просит один звук старта из переданной записи `rocket-flight.mp3`; исходник уже отслеживается в `apps/client/src/audio/assets/source/`, поэтому прежнее препятствие с Downloads снято.

## What Changes

- Добавить самостоятельный `Sound.NukeLaunch`, короткое посчитанное представление и одну записанную версию из исходника владельца, обрезанную по кадрам MP3 без перекодирования.
- Выдавать пуск при первом появлении ракеты в предсказанном мире, в центре базы её владельца; сохранить защиту от повторов, молчание при восстановлении и общую пространственную обработку.
- Расширить отдельный ядерный набор голосов с двух до шести: по пуску, свисту и удару для двух сторон. Сохранить приоритет детонации и независимость от обычного боя.
- Подключать подготовленный короткий файл через существующий загрузчик с нормализацией, удалением начальной тишины и затуханием. После проверенной нарезки удалить исходник пуска согласно README источников и документировать происхождение готового файла.

## Non-goals

- Не менять момент начала, запись и синтез `NukeFall`: это задача 0056; не реализовывать отключение свиста из задачи 0023.
- Не менять ракету генерала, ядерный взрыв, музыку, пространственную отсечку и регуляторы громкости.
- Не менять цену, урон, радиус, время полёта, откат, ИИ, симуляцию, протокол и визуал ракеты.
- Не добавлять варианты записи, новые зависимости, онлайн-загрузку сторонних ресурсов или инструмент общего назначения для монтажа звука.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sound`: новое требование отдельного звука пуска и его записи; изменение существующего требования «Число звуков ограничено бюджетом», допускающее пуск в ядерном наборе.

## Impact

Реализация затронет `apps/client/src/audio/sounds.ts`, `budget.ts`, `cues.ts`, `assets.ts`, соответствующие узкие тесты и аудиоресурсы. Загрузчик и движок используют общий путь нового события; отдельная шина не нужна.

Отзывчивость: сигнал выводится в текущем проходе по ракетам без ожидания сети; подготовка отсчётов остаётся одноразовой вне кадра. Добавляется не более четырёх мест в ограниченном наборе голосов, визуальный отклик остаётся в том же кадре. Баланс и отрисовка не меняются, отдельный прогон арены не требуется.

Трафик: игровые сообщения не меняются. Появится один статический MP3 порядка десятков килобайт вместо загрузки 49-секундного исходника; подготовленный файл загружается существующим механизмом один раз за звуковой сеанс и кешируется браузером.

## Пересечения и порядок архивации

На обновлённой базе `origin/main` от 08.09.2026 открытых дельт `sound` и изменения на пуск нет (`openspec list --json` и поиск по открытым артефактам). Основа обоих затрагиваемых правил уже в `openspec/specs/sound/spec.md`; обязательных предшественников и зависимости архивации нет.

0056 имеет пересечение по `cues.ts`, `sounds.ts`, `assets.ts` и README источников, но по журналу не является предусловием: здесь пуск добавляется независимо от времени выдачи свиста. При освежении базы перед реализацией сохранить её изменения, если они появятся. Открытые `upgrade-nuke-damage-and-radius` и `nuke-counts-own-losses` относятся к правилам удара и не служат основой звуковой дельты.
