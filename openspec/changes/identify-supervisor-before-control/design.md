## Context

Пускатель проверяет лишь signal 0. После перезагрузки Windows PID из старого
замка совпал с Docker. Сам startup допускает старый замок по времени, но
пускатель до него не доходит. Локальный codexCommand дополнительно указывал
на удалённую версию приложения.

## Goals / Non-Goals

Устранить ложную занятость и исключить остановку чужого процесса. Не менять
бюджеты, очередь или жизненный цикл Windows.

## Decisions

Перед управлением читать имя и командную строку процесса через ограниченный
по времени системный опрос. Проверять точный путь supervise.mjs для корня
из lockPath; одно имя node.exe недостаточно. На Windows использовать CIM,
на POSIX ps. Нечитаемый процесс возвращает unknown, не live и не waiting.
Пускатель при unknown не запускает и не останавливает процессы, объясняя
ошибку. При подтверждённом постороннем процессе запуск допускается, а
остановка не посылает ему сигнал. Наблюдатель использует ту же проверку.

Существующий атомарный startup продолжает управлять снятием старого замка.
Остановка повторно сверяет состояние непосредственно перед сигналом.
Проверка содержимого команды нужна и для старых замков без новых полей.

## Risks / Trade-offs

Системный опрос дороже signal 0: ограничить время и не выводить командные
строки в диагностике. Между проверкой и сигналом остаётся системная гонка
PID, полностью устранимая только нативным дескриптором процесса.

## Migration Plan

Сохранить старый замок, доказать посторонний PID и восстановить запуск.
Локальную настройку Codex перевести с пути версии на проверенный стабильный
CLI. Доставить исправление через PR с зелёными проверками.
