## Why

Установка зависимостей может создать локальный `.pnpm-store/` в снимке выкладки. На задаче 0202 это остановило пакет из 12 задач; исключение кеша уже доставлено в `origin/main` коммитом `08257f439f55cc198f6ec0886ae5058a2c61897d` (#158), но шаг 6 `supervisor/skills/deploy.md` проверяет чистоту только до установки. Изменения, возникшие при установке, могут обнаружиться лишь после дорогостоящего замера.

## What Changes

- Закрепить повторную проверку `git -C <дерево> status --porcelain` сразу после успешного `pnpm install --frozen-lockfile`, до перехода к замеру; непустой вывод или ошибка проверки останавливают выкладку без исправления снимка.
- Сохранить проектное исключение `.pnpm-store/` независимо от пользовательского Git ignore и подтвердить тестами, что отслеживаемые изменения и посторонние неотслеживаемые файлы остаются видны.
- Дополнить сторож правил выкладки проверкой порядка действий и отрицательными примерами перестановки/удаления повторной проверки.
- Проверить настоящий запуск установки в новом собственном проверочном снимке; быстрые тесты отдельно воспроизводят файловые последствия установки без сети и замера.

## Non-goals

- Повторная доставка или cherry-pick коммита `9fa4652124c358c7b670ce2d27aef84d0ee4e93c`: его diff уже доставлен #158. Ветка `codex/ignore-pnpm-store` и её дерево остаются у владельца.
- Изменение расположения кеша pnpm на машинах пользователей, глобального ignore или `.git/info/exclude`.
- Фильтрация строк `git status`, скрытие всех неотслеживаемых файлов, автоматические clean/reset/merge и починка старых закреплённых снимков.
- Перенос установки в супервизор, смена схемы назначения, серверной выкладки, замера, отчёта или правил игры.

## Capabilities

### New Capabilities

- `deployment-snapshot`: дополнить контракт снимка требованиями о служебном кеше, повторной проверке после установки и охране порядка. Способности пока нет в `openspec/specs/`; имя уже введено открытым `prepare-deploy-snapshot`, новую параллельную способность не заводим. Здесь только ADDED с новыми именами требований; Purpose будет оформлен при архивации предшественника.

### Modified Capabilities

Нет MODIFIED поверх основных спецификаций.

## Dependencies

Изменение архивируется ПОСЛЕ `prepare-deploy-snapshot`: оно вводит способность и контракт закреплённого detached-снимка. Его реализация уже присутствует в свежей базе; ожидание отдельной доставки для реализации не нужно.

`guard-the-deploy-refresh` пересекается по `supervisor/config/transitions.test.mjs`: его историческая дельта описывает прежнее освежение через merge, которое заменено `prepare-deploy-snapshot`. Охрану текущего detached-снимка сохраняем, старые команды merge не возвращаем. Пересечение по файлу не создаёт зависимости нашей ADDED-дельты от прежнего требования. Артефакты соседей здесь не исправляются.

## Impact

Правка реализации ограничена `supervisor/skills/deploy.md`, `supervisor/config/transitions.test.mjs`, `supervisor/lib/deploy-snapshot.test.mjs`. Действующий `.gitignore` служит входом проверки, повторно не меняется. Публичные API и зависимости не меняются.

Отзывчивость интерфейса не меняется: игровой цикл и клиент не затрагиваются. Сетевой трафик игры не меняется; дополнительная проверка Git локальна. Пробная установка использует штатный трафик pnpm; автоматические тесты файловых последствий обходятся без скачиваний.
