## ADDED Requirements

### Requirement: Кеш pnpm не скрывает настоящие изменения снимка

Проект SHALL исключать неотслеживаемое содержимое каталогов `.pnpm-store/` средствами версионируемого `.gitignore`, независимо от наличия и доступности пользовательского Git ignore. Проверки снимка SHALL сохранять обнаружение изменений отслеживаемых файлов и посторонних неотслеживаемых файлов вне действующих проектных исключений; они MUST NOT фильтровать вывод статуса или отключать обнаружение всех неотслеживаемых файлов ради кеша.

#### Scenario: Новый снимок после установки с локальным кешем

- **WHEN** в новом чистом снимке успешно выполнена установка зависимостей с локальным `.pnpm-store/`, а пользовательский ignore не предоставляет исключений
- **THEN** `git -C <дерево> status --porcelain` завершается успешно с пустым выводом при отсутствии настоящих изменений
- **AND** исключение кеша обеспечивается `.gitignore` назначенной ревизии

#### Scenario: Продолжение с кешем

- **WHEN** сохранённый снимок имеет только игнорируемый кеш pnpm, а пользовательский ignore отсутствует или недоступен
- **THEN** подготовка продолжения принимает тот же путь и хеш без очистки кеша

#### Scenario: Отслеживаемый файл изменён рядом с кешем

- **WHEN** при наличии `.pnpm-store/` изменён отслеживаемый исходник снимка
- **THEN** статус остаётся непустым, подготовка продолжения отклоняет снимок и сохраняет содержимое изменённого файла

#### Scenario: Посторонний файл рядом с кешем

- **WHEN** при наличии `.pnpm-store/` создан посторонний неотслеживаемый файл вне проектных исключений
- **THEN** статус показывает этот файл, подготовка продолжения отклоняет снимок и сохраняет файл

### Requirement: Чистота повторно проверяется после установки до замера

Правила deploy SHALL сохранять исходную проверку снимка и предписывать после успешного `pnpm install --frozen-lockfile` немедленно повторить `git -C <дерево> status --porcelain` в том же назначенном дереве до замера кадров. Непустой вывод либо ненулевой код возврата проверки SHALL завершать этап исходом `failed` с причиной до замера и выкладки. Исполнитель MUST NOT исправлять снимок, менять закреплённый хеш или чистить файлы для прохождения проверки. Неуспешная установка SHALL останавливать этап до замера.

#### Scenario: Установка оставила только служебные файлы

- **WHEN** установка успешна и повторная проверка успешно возвращает пустой статус
- **THEN** исполнитель может продолжить обычные последующие проверки и замер назначенного снимка

#### Scenario: Установка изменила исходник или оставила посторонний файл

- **WHEN** повторная проверка после установки возвращает непустой статус
- **THEN** этап завершается с `failed`, называет изменения и не начинает замер или выкладку
- **AND** файлы и закреплённый хеш не исправляются

#### Scenario: Проверка не выполнилась

- **WHEN** команда статуса завершилась ненулевым кодом даже с пустым stdout
- **THEN** этап завершается с `failed` и ошибкой проверки до замера, пустой stdout не считается доказательством чистоты

#### Scenario: Установка не завершилась успешно

- **WHEN** установка зависимостей завершилась ненулевым кодом
- **THEN** этап завершается с `failed` и причиной установки до замера и выкладки

### Requirement: Порядок установки и повторной проверки охраняется

Автоматическая проверка правил deploy SHALL проверять наличие исходной проверки чистоты, затем установки, затем повторной проверки и условия остановки до замера. Наличие слов или команды статуса только до установки MUST NOT удовлетворять этой проверке. Диагностика SHALL указывать `deploy.md` и нарушенный порядок либо отсутствующий элемент.

#### Scenario: Повторную проверку удалили

- **WHEN** из правил удалена проверка после установки, но исходная проверка осталась
- **THEN** автоматическая проверка падает с указанием отсутствующей повторной проверки

#### Scenario: Повторная проверка переставлена

- **WHEN** повторная проверка стоит до установки или после начала замера
- **THEN** автоматическая проверка падает с диагностикой порядка

#### Scenario: Условие остановки исчезло

- **WHEN** команды стоят в правильном порядке, но нет правила остановки при грязном снимке или ошибке проверки
- **THEN** автоматическая проверка падает с указанием отсутствующего условия
