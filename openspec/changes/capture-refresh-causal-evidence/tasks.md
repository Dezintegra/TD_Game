Каждый отмечаемый пункт — самостоятельный проверяемый коммит, не более двух часов, с немедленной отправкой. В назначенном дереве перед реализацией выполнить отдельными вызовами `git -C <дерево> fetch origin`, `git -C <дерево> merge origin/main`, `pnpm install --frozen-lockfile --prefer-offline`. ## Состав коммитов и финальная форма

Каждый пункт допускает только названные в нём рабочие пути плюс собственную отметку в `openspec/changes/capture-refresh-causal-evidence/tasks.md`. В пункте 2.1 изменения run-stage допустимы только для pre-input hook и его тестов. В пункте 4.1 интеграция ограничена записью/проверкой свидетельства и подключением режима; не менять политику инцидентов, счётчики или размер лимитов.

Все пути добавлять явным перечнем: `git -C <дерево> add -- <свои-пути>`, при необходимости несколькими короткими вызовами. Перед коммитом проверять имена и содержание `git -C <дерево> diff --cached`; после — `git -C <дерево> show --stat HEAD` и `git -C <дерево> show HEAD`. В индексе и коммитах исключены `.matchlog/0370-refresh/`, `.pipeline/`, первичные внешние логи, секреты и чужие изменения; отсутствие этих путей не разрешает остальные посторонние файлы. После каждого коммита `git -C <дерево> push`; не копить хвост.

Узкий линт/формат changed JS и документации вне openspec — `npx eslint <свои-js-файлы>` и `npx prettier --check <свои-поддерживаемые-файлы>`. Проверить форму только своего изменения: `openspec validate capture-refresh-causal-evidence --strict`, `openspec status --change capture-refresh-causal-evidence`. Не добавлять шаг ожидания CI, архивации или вливания. PR и зелёный CI сами по себе не заменяют живое свидетельство пункта 5.1.
