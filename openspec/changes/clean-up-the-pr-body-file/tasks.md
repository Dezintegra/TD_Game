## 1. Порядок обращения с телом PR

- [x] 1.1 Дополнить существующий шаг открытия чернового PR в `supervisor/skills/implement.md` всем порядком из design одним атомарным коммитом (до 90 минут): единый путь внутри дерева с учётом 0139, сохранение номера после успеха, проверка происхождения и отсутствия чужих правок, разрешённого абсолютного пути и Git-категории, точечный `git -C <дерево> clean -f -- <точный относительный путь>`, последующий статус и оговорка для игнорируемого `.matchlog/`. Сохранить запреты широкого удаления, повторного Remove-Item и ослабления разрешений; не менять нумерацию верхних шагов, новые командные блоки оформить как powershell. Проверка: вручную сопоставить готовый текст со всеми шестью сценариями дельты — каждому соответствует явная инструкция; путь рядом с командой совпадает с её доводом, исходная команда чернового PR и сохранение links.pr остаются. Выполнить отдельными вызовами `npx prettier --check supervisor/skills/implement.md`, `pnpm test:pipeline` и `git -C <дерево> diff --check`; новые тесты и пробы удаления не добавлять. Отметить этот пункт, закоммитить только `supervisor/skills/implement.md` и собственный `openspec/changes/clean-up-the-pr-body-file/tasks.md`, сразу отправить через `git -C <дерево> push -u origin HEAD` и открыть черновой PR командой `gh pr create --draft --base main --title "docs: describe PR body cleanup" --body-file .matchlog/0237-pr-body.md`. Если PR уже открыт, сохранить его номер без повторного создания. После первого коммита вся инструкция уже целостна и доступна проверкам PR.

Перед реализацией действуют штатные отдельные команды `git -C <дерево> fetch origin` и `git -C <дерево> merge origin/main`. По свежей базе сверить размещение из 0139, если оно появилось, и сохранить его единым; пока пример — `.matchlog/<taskId>-pr-body.md`. При выборе другого пути соседней задачей также согласовать довод открытия собственного PR выше.

Каждая команда выполняется отдельным вызовом в назначенном дереве; `<дерево>` обозначает только его. Формы сверены с `supervisor/config/stage-settings.json`: `PowerShell(git -C:*)`, `PowerShell(gh pr:*)`, `PowerShell(npx prettier:*)`, `PowerShell(pnpm test:pipeline:*)`. Проверки реализации выполняются на имплементации, не на проработке. Ожидание CI ведёт супервизор, пункта ожидания нет.
