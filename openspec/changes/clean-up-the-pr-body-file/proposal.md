## Why

Шаг 5 `supervisor/skills/implement.md` открывает черновой PR через `--body-file <файл>`, но не говорит, что делать с этим файлом после успеха. Собственный неигнорируемый файл остаётся в статусе дерева; попытка удалить его через Remove-Item уже отклонялась в задаче 0197. Постановка 0237 фиксирует подтверждённую там точечную форму Git, которую нужно сделать доступной исполнителю рядом с открытием PR.

## What Changes

- Дополнить существующий шаг открытия PR единым порядком: назвать файл тела внутри назначенного дерева, после успешного создания PR сохранить номер, проверить принадлежность файла и его путь, убрать собственный неигнорируемый неотслеживаемый файл точечной командой и повторно проверить статус.
- Указать форму `git -C <дерево> clean -f -- <точный относительный путь>` только для проверенного отдельного файла, без шаблонов, каталогов и расширяющих ключей.
- Объяснить, что игнорируемый `.matchlog/` не загрязняет обычный статус и эта форма clean его не удаляет; ради него широкая очистка не нужна.
- Согласовать упоминание размещения с задачей 0139, не меняя формат отчёта этапа и не расширяя разрешения.

## Non-goals

- Автоматизация удаления в коде супервизора, уборка деревьев, веток, баз и чужих временных файлов.
- Изменение `stage-settings.json`, `.gitignore`, повтор отказанного Remove-Item или обход отказов среды.
- Решение всей задачи 0139 о размещении тела PR и устаревшем указании писать отчёт файлом.
- Новые тестовые сторожа текста, изменение CI, игровые изменения и прогон арены.

## Capabilities

### New Capabilities

- `dev-pipeline-worker`: добавить требование «Файл тела PR убирается только в пределах собственной задачи». Способность уже заведена открытым `agent-backlog-pipeline`, но отсутствует в `openspec/specs/`; используется её имя, а не новый синоним. Дельта — ADDED с уникальным требованием. Purpose при первичной архивации способности оформляет владелец `agent-backlog-pipeline`.

### Modified Capabilities

Нет MODIFIED: существующие требования об отдельном дереве и раннем PR сохраняются полностью.

## Impact

Реализация меняет только шаг открытия PR в `supervisor/skills/implement.md` и отметку собственного `tasks.md`. Поведение клиента, сервера и протокола не меняется: влияния на отзывчивость интерфейса и сетевой трафик игры нет. Дополнительных сетевых запросов для уборки не требуется, Git проверяет локальный файл.

## Зависимости и пересечения

Изменение архивируется ПОСЛЕ `agent-backlog-pipeline`, которое заводит `dev-pipeline-worker`. Наше новое требование не заменяет его требование об атомарных коммитах и раннем PR.

По переданному снимку задача `0139-skill-implementacii-velit-pisat-otchet-f` находится в new, `links.change` пуст; в свежей базе её отдельного изменения нет. Она отвечает за размещение тела PR. В этой задаче рядом с командой допустимо назвать используемый уже соседними задачами путь `.matchlog/<taskId>-pr-body.md`; это пример в существующем игнорируемом каталоге, не новая политика хранения. Если 0139 к реализации задаст иной путь внутри дерева, использовать его в одном месте и в команде, сохранив оба случая уборки. Зависимости от ещё несуществующей дельты 0139 нет.

Открытые `one-shell-for-stages` (по снимку доски), `name-what-cuts-code-in-arguments`, `refresh-the-base-before-code`, `probe-the-deltaless-archive` затрагивают тот же скилл или форму команд; сохранить их текст вне шага открытия PR, новые командные блоки размечать powershell. `guard-step-references` касается ссылок на шаги: новых номеров верхнего уровня не добавлять. Порядок архивации с ними не требуется, общих имён требований нет.
