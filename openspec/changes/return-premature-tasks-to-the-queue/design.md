## Context

Это переработка существующего плана 0216 с требованиями 0218/0219. Основание — согласованная постановка после оптимизации бэклога и текущие blockers.mjs, dependencies.mjs, report-delivery.mjs, routing-contract.mjs. Редакция до PR #262 сохраняется в истории Git; её указания о premature больше не являются задачами реализации.

## Goals / Non-Goals

Цель — дождаться проверяемого результата без потери работы и без холостых кругов. Не меняются продуктовые решения, учёт исторического расхода и права на чужие ресурсы.

## Decisions

1. Единственный исход ожидания — blocked. Допустимые этапы берутся из BLOCKABLE; обычные review/pr/deploy не получают произвольного нового перехода. Их техническое ожидание обрабатывается существующими допусками и разбором задержки.
2. Проверка безопасности дерева и явных предусловий предшествует подготовке. Доступная подготовка по согласованному плану продолжается независимо от собственного PR; необязательное слияние всей соседней ветки не требуется. Если безопасной подготовки нет, исполнитель записывает blockers с reason/result и taskId либо requestKey, а для конкретного PR — dependencyResult. Неизвестную зависимость выдумывать нельзя.
3. Наличие change или PR не доказывает готовность оставшейся работы и не запрещает blocked. Артефакты и выполненная подготовка сохраняются. moot по-прежнему означает доказанно снятый предмет и проходит собственные предохранители.
4. Граф ожидания один: dependsOn/dependencyResults. Проверяются ссылки, циклы, недостающие и двусмысленные карточки, наследование результата через splitInto. После закрытия без результата сохраняется dependencyRecheck; решение требует доказательства либо живой замены.
5. В ожидании обычные рабочие сессии не повторяются. Разбор затянувшегося ожидания использует действующий предел задержки и бюджет. Возврат из failed ограничен recovery.returns; расход не обнуляется. Специального счётчика холостых кругов нет.
6. Перенос blocked использует существующий устойчивый план. Отчёт не подтверждается до записи состояния, причины и освобождения назначения; после обрыва операции повторяются по ключам. Пока отчёт не применён, карточку не перехватывают. Не вводить отдельную неустойчивую последовательность release/save.
7. addWorktree сначала читает Git. Совпадение абсолютного ожидаемого пути и ветки позволяет вернуть готовое дерево без worktree add. Чужая ветка, detached HEAD или ошибка описи не разрешают продолжение. Если ветка уже выложена по другому пути, не создавать второе дерево: вернуть диагностируемый отказ для штатной сверки реестра. Если дерева нет, сохранить создание от существующей локальной/удалённой ветки либо origin/main.

## Сведение требований 0218 и 0219

Перечень исходов берётся из apply-report.mjs, список блокируемых этапов — из BLOCKABLE. Исключение design при доказанном ожидании не требует создавать пустое OpenSpec-изменение. Предохранители moot остаются в apply-report; блокеры проверяет blockerReportProblem. При архивации сверить требования 0206/0207 с основной спецификацией: заменить только устаревшее перечисление, не копировать его как новый конкурирующий контракт. Дельты этого изменения не добавляют premature и не требуют новых полей ожидания.

## Risks / Trade-offs

Чтение Git добавляет одну локальную операцию при взятии; недоступная опись приводит к отказу без изменения ресурсов. Условия ожидания могут требовать внешнего результата или решения владельца; это не разрешение обходить бюджет. Приёмка карточки после снятия её исторического удержания отдельно сверяет актуальную постановку с подготовленными изменениями.
