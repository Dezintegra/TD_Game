# Задачи

Каждый шаг — отдельный коммит, собирающийся и проверяемый сам по себе. Кода
приложения изменение не заводит ни строки: правятся `supervisor/` и две схемы
записи задачи. Поэтому ни сборки, ни матчевых тестов, ни замеров здесь нет,
а проверки везде узкие и идут по своим файлам.

**Команды даны формой, покрытой правилами разрешений** — `git -C <дерево> …`,
где `<дерево>` — путь из поля `worktree` назначения. Голая приставка покрыта
не у всякой подкоманды, а `git -C:*` покрывает любую разом. Перечень покрытого
живёт в `supervisor/config/stage-settings.json`, и сверяться надо с ним.

Нет `node_modules` в дереве — перед первым прогоном тестов
`pnpm install --frozen-lockfile`.

Файлы правятся инструментом редактирования. `Set-Content`, `Out-File`
и перенаправление `>` не применять: Windows PowerShell 5.1 читает UTF-8 как
ANSI и превращает кириллицу в мохибейк.

- [ ] Четвёртым проверить предел. Мерка идёт **без прибавки**:

## Чего в списке нет

- **Шага «дождаться зелёного CI» нет, и это нарочно.** Ожидание
  механизировано супервизором: он опрашивает проверки сам и сам двигает
  задачу из состояния `pr`, а исполняющей сессии караулить их запрещено.
  Отметка о таком пункте была бы новым коммитом, перезапускающим те самые
  проверки, чью зелень она фиксирует.
- **Прогона арены не заказывается.** Правила игры, цены, доход, сила юнита
  и темп не задеты ни одной строкой: правится `supervisor/` и схемы записи
  задачи, то есть код вне пакетов монорепозитория.
- **Замеров кадров и стоимости тика нет** по той же причине: отрисовка и шаг
  мира не тронуты.
- **Правки правил разрешений нет.** Все команды списка покрыты:
  `PowerShell(git -C:*)`, `PowerShell(gh pr:*)`,
  `PowerShell(pnpm test:pipeline:*)`, `PowerShell(npx eslint:*)`,
  `PowerShell(npx prettier:*)`, `PowerShell(pnpm install:*)` — сверено
  чтением `supervisor/config/stage-settings.json`.
- **Механизма предусловия нет** — ни поля «ждёт задачу X», ни опроса чужого
  pull request, ни выдержки перед повторным взятием. Это задача 0073.
- **Скиллы прочих этапов не правятся.** Исход `premature` применяется только
  к отчёту проработки, и объявлять его там, где он не сработает, значит
  обещать сессии несуществующий ход.
- **Исход `moot` не трогается** ни одним шагом: ни его предохранители,
  ни маршрут `design` → `cleanup`, ни формулировка записи журнала.
- **Архивации изменения нет.** Она переписывает `openspec/specs/`, её очередь
  задана зависимостями дельт, и решение принимает человек. Здесь важно одно:
  изменение архивируется **после** `agent-backlog-pipeline`,
