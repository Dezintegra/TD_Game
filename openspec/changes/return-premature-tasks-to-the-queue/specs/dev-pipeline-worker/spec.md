## ADDED Requirements

### Requirement: Исполнитель сохраняет ожидание предмета через blocked

При безопасном дереве, обновлённой main и соблюдении явных предусловий доступная подготовка по согласованному плану SHALL исключать вывод об отсутствии предмета только по отсутствию файла в main. Собственный PR подготовку не запрещает. После конфликта необязательного слияния SHALL выполняться отмена и проверка восстановления дерева. Конфликт обновления origin/main, ошибка отмены, доступа, инструмента или обязательного слияния без альтернативы SHALL давать технический failed, а не доказательство отсутствия.

Если подготовки нет и ожидается конкретный результат другой задачи, исполнитель SHALL использовать действующий blocked с reason/result и проверяемой ссылкой. Отдельный premature вводиться MUST NOT. Поддержка означает введённые в рабочую версию правила, допустимый исход и его обработчик; текст планового документа сам по себе её не создаёт. Существующие change и PR сохраняются и ожидание не запрещают.

#### Scenario: Имплементации нечего править
- **WHEN** имплементация, подтянув свежую главную ветку, подтверждает, что предмета в дереве ещё нет и его принесёт другая задача; доступной подготовки по плану нет
- **THEN** сессия завершается с исходом blocked, сохраняет ожидание и доказательство в reason/result, указывает taskId и ожидаемый результат; кода не пишет, собственный PR не открывает

#### Scenario: Предмет лежит в чужой невлитой ветке
- **WHEN** design доказал отсутствие предмета и назвал задачу, которая его принесёт
- **THEN** он возвращает blocked с конкретным результатом, не создавая пустого изменения OpenSpec и не выдумывая вопрос владельцу

#### Scenario: Предмета нет, но pull request уже открыт
- **WHEN** имплементация на свежей базе подтверждает отсутствие предмета оставшихся шагов; доступной подготовки по плану нет, собственный PR уже открыт
- **THEN** она возвращает blocked с причиной и ожидаемым результатом, без автоматического возврата в очередь и удаления начатой работы

#### Scenario: Доступная подготовка без собственного PR
- **WHEN** файл только в отправленной версии открытого соседнего PR, подготовка по плану доступна, собственного PR нет, дерево безопасно, main обновлена и явные предусловия соблюдены
- **THEN** имплементация SHALL продолжить подготовку по плану без обязательной попытки слияния всей ветки

#### Scenario: Доступная подготовка с собственным PR
- **WHEN** файл только в отправленной версии открытого соседнего PR, подготовка по плану доступна, собственный PR уже открыт, дерево безопасно, main обновлена и явные предусловия соблюдены
- **THEN** имплементация SHALL продолжить подготовку по плану; собственный PR доступную работу не запрещает

#### Scenario: Неподдерживаемый исход из старого плана
- **WHEN** старый план предлагает premature, а действующий обработчик предоставляет blocked
- **THEN** неподдерживаемый premature отправлять MUST NOT; при доказанном ожидании без доступной подготовки используется blocked

#### Scenario: Техническая ошибка проверки подготовки
- **WHEN** возникла ошибка доступа к существующей ревизии, инструмента, отмены слияния либо конфликт требуемого планом слияния без альтернативы
- **THEN** требуется технический failed независимо от собственного PR, с конкретной ошибкой; ошибка чтения доказательством отсутствия предмета быть MUST NOT

#### Scenario: Заведённый план ожидает новую предпосылку
- **WHEN** change уже существует, но оставшаяся работа требует невыполненной зависимости
- **THEN** change сохраняется, ожидание идёт через blocked без проверки выдуманного счётчика возвратов

#### Scenario: Предмет приехал к ожидающей задаче
- **WHEN** необходимый результат подтверждён штатным механизмом зависимостей
- **THEN** исполнитель сверяет сохранённые артефакты со свежей базой и продолжает обычный маршрут; до этого повторная рабочая сессия не запускается

#### Scenario: Подозрение вместо проверки
- **WHEN** отсутствие предмета предполагается, но источник результата не установлен
- **THEN** зависимость выдумывать MUST NOT; исполнитель называет недостающие данные, а ошибку инструмента отличает от продуктового вопроса

#### Scenario: Предмет снят, а не отсутствует
- **WHEN** предмет доказанно снят и выполнены действующие предохранители moot
- **THEN** используется moot; существующие ограничения этого исхода не переносятся на blocked
