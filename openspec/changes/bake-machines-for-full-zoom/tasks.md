# Задачи

Каждая — отдельный коммит, отправляемый сразу. Порядок выбран так, чтобы
любая остановка оставляла работоспособное состояние: плотность полезна
и без прогрева, прогрев невозможен без долгоживущего отрисовщика.

## 1. Плотность покрывает весь диапазон приближения

- [x] 1.1 `bake-density.ts`: `armourBakeDensity` выводится из `MAX_ZOOM`
      (импорт из `camera.ts`, не число), потолок `MAX_ARMOUR_BAKE_DENSITY`.
      `ZOOM_OVERSAMPLE`, `MAX_BAKE_DENSITY` и `armourSupersample` уходят;
      кратность становится постоянной `ARMOUR_SUPERSAMPLE = 1.5`.
- [x] 1.2 Проводка: машины, постройки, командный центр и дуги берут новую
      плотность; скалы — прежний бюджет, но с новым потолком.
      Поправить `fx-probe`.
- [x] 1.3 Тесты `bake-density.test.ts` переписать под новые величины.
      Обязательный: **кратность черновика больше единицы** — именно это
      сломается при следующей правке плотности, и сломается тихо.

## 2. Отрисовщик переживает меню и смену матча

Сегодня `scene.destroy()` зовёт `app.destroy()`, а `session.ts` заводит
`#scene` и новое приложение на каждый матч. Прогреть заранее нечем:
текстура принадлежит контексту WebGL, в котором запечена.

- [x] 2.1 Завести `renderer-host.ts`: одно приложение PixiJS и кеши
      спрайтов, живущие с загрузки страницы. Канвас лежит в постоянном
      `#scene`, скрытом за меню.
- [x] 2.2 `createScene` принимает готовое приложение и кеши вместо того,
      чтобы заводить их; `destroy` снимает только матчевое, а приложение
      и кеши оставляет.
- [x] 2.3 `session.ts` перестаёт заводить и удалять `#scene` на каждый
      матч. Проверено сквозным тестом: перезапуск против компьютера,
      второй матч рисуется (скалы, миникарта, испечённые иконки),
      канвас на странице ровно один.
- [x] 2.4 Убедиться, что в меню приложение не жжёт кадры впустую
      (тикер остановлен, пока матча нет).

## 3. Прогрев базового набора в меню

- [x] 3.1 Кеши машин и построек получают перечисление базового набора
      и шаг прогрева — по одной комбинации за вызов, как у иконок.
- [x] 3.2 Прогрев идёт покадрово с бюджетом, начинается на экране меню.
      Пока прогрев не кончился, матч всё равно начинается: недостающее
      допекается по надобности.
- [x] 3.3 Проверить, что меню остаётся отзывчивым: ни один кадр
      не занят прогревом дольше бюджета.
