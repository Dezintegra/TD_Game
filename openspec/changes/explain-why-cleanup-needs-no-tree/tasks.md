# Задачи

Проверка у обоих шагов одна и та же, и другой быть не может: правка лежит
в `supervisor/`, а сторожа конвейера прогоняются только своим корнем.

```powershell
pnpm test:pipeline
```

Голый `npx vitest` тут не годится: без ключа `--root supervisor` тесты
конвейера не находятся, и прогон зеленеет, ничего не прогнав.

Каждый шаг — отдельный коммит, отправляемый сразу. Первым идёт шаг 1:
после него имплементация уже вправе открыть черновой pull request,
а до открытия проверки CI на отправки в ветку не запускаются вовсе.

Перед первой правкой базу освежить обязательно — тот же файл
`supervisor/config/transitions.test.mjs` правят соседние открытые
изменения:

```powershell
git -C <дерево> fetch origin
git -C <дерево> merge origin/main
```

Форма с ключом `-C` обязательна и здесь, и во всех прочих командах git
этого списка: правило разрешений `PowerShell(git -C:*)` покрывает любую
подкоманду разом, а правила на голое `git merge` нет ни одного —
голая форма молча отказалась бы, и сессия пошла бы дальше, считая шаг
сделанным.

Массив `NEEDS_WORKTREE` не трогается ни на одном шаге, кроме временной
пробы шага 2, которая откатывается в том же шаге и в коммит не попадает.

## 1. Переписать пояснение к `NEEDS_WORKTREE`

- [ ] В `supervisor/config/transitions.mjs` переписать **только последнюю
      фразу** пояснения над массивом — ту, что сейчас гласит «Уборка
      входит — ей дерево нужно, чтобы его же и снести». Первый абзац
      и фраза про прогон остаются дословно.
- [ ] Назвать в новой редакции все четыре вещи, перечисленные
      в `design.md` (раздел «Что именно пишется вместо старой фразы»):
      уборка в перечень не входит; сессии ей не выдают, и в `NEEDS_SESSION`
      её тоже нет; дерево она сносит снаружи, из основного дерева, по пути
      из записи реестра (`execute.mjs` → `cleanup.mjs` → `io.mjs`,
      `git worktree remove --force`); изнутри сносимого дерева снос
      невозможен — каталог держит собственный процесс.
- [ ] Назвать там же, чем вхождение уборки в перечень было бы вредно,
      и назвать это **проверенным**, а не тем, что стояло в постановке
      задачи: снос перечня не спрашивает вовсе, а пострадала бы сверка
      мира — починка `finish-claim` в `reconcile.mjs` завела бы дерево
      заново сразу после сноса. Довод целиком — в `design.md`, раздел
      «Довод постановки „снос отказал бы“ не подтвердился».
- [ ] Ссылаться в пояснении только именами файлов, без номеров строк:
      номера стареют молча, имена при переименовании ловит поиск.
- [ ] Массив оставить как есть, ни одного элемента не добавляя и не убирая.
- [ ] Проверка: `pnpm test:pipeline` зелёный (правка комментария не должна
      ронять ничего, а синтаксическую поломку внутри блочного комментария
      прогон поймает немедленно), и
      `git -C <дерево> diff --stat origin/main HEAD` называет ровно один
      файл — `supervisor/config/transitions.mjs`.

## 2. Закрепить положение сторожем

- [ ] Добавить в `supervisor/config/transitions.test.mjs`, в уже
      существующий `it` «дерево нужно только тем состояниям, что правят
      код», строку `expect(NEEDS_WORKTREE).not.toContain('cleanup');` —
      рядом с такими же строками про `benchmark`, `triage` и `postmortem`.
      Отдельного `it` не заводить: довод — в `design.md`, раздел «Почему
      сторож — строка в существующем `it`».
- [ ] Дать строке короткое пояснение в том же виде, в каком дано соседнее
      про `postmortem`: уборка сносит дерево снаружи, по пути из записи
      реестра, и собственного дерева ей не нужно.
- [ ] Проверка положительная: `pnpm test:pipeline` зелёный.
- [ ] Проверка обратная, обязательная: временно вписать `'cleanup'`
      в массив `NEEDS_WORKTREE`, прогнать `pnpm test:pipeline` и убедиться,
      что краснеет именно новая строка, после чего массив вернуть
      к прежнему виду и прогнать ещё раз до зелёного. Проверка, пережившая
      выключение своей особенности, — декоративная; проба в коммит
      не попадает.
- [ ] Проверка состава коммита: `git -C <дерево> diff --stat origin/main HEAD`
      называет ровно два файла — `supervisor/config/transitions.mjs`
      и `supervisor/config/transitions.test.mjs`; временной пробы шага
      в отправленном виде нет.
