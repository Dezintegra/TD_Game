# Задачи

Изменение делается **после** `report-rejected-commands` и
`extract-ai-package`. Без первого лог команд врёт, без второго арена
не имеет права импортировать противника.

Порядок внутри изменения выбран так, чтобы каждая ступень давала
работающий результат: сначала арена гоняет матчи и печатает сводку,
и только потом появляется запись из браузера. Если сил хватит только
на первую половину — она уже полезна.

## 1. Каркас арены

- [x] 1.1 Завести `apps/arena` с `package.json`, `tsconfig.json`
      через `extends` и зависимостями `@td/shared`, `@td/sim`, `@td/ai`.
      Разбор аргументов — вручную, без библиотек: команд четыре.
      *Проверка:* `pnpm --filter @td/arena build` зелёный,
      `arena --help` печатает список команд.
- [x] 1.2 Запретить арене импорт приложений в `eslint.config.js`
      по образцу правил для клиента и сервера.
      *Проверка:* временно вставленный импорт из `apps/client` валит
      `pnpm lint`.
- [x] 1.3 Добавить `.matchlog/` в `.gitignore` с комментарием, что это
      локальные логи разбора и в репозиторий они не едут.
      *Проверка:* после прогона `git status` чист.

## 2. Безголовый матч

- [x] 2.1 Функция прогона одного матча: мир по seed, два противника
      с профилями и своими seed, цикл тиков до победы либо до предела.
      Предел — двадцать игровых минут, исход «ничья по времени».
      *Проверка:* тест на три seed — каждый матч завершается за конечное
      время с одним из двух исходов.
- [x] 2.2 Измерить стоимость матча и записать замер в `design.md`.
      Ожидание — две-четыре минуты процессорного времени на матч.
      *Проверка:* число получено; если оно на порядок хуже, дальнейшие
      задачи по параллелизму придётся пересматривать.
- [x] 2.3 Команда `run`: набор seed, профили сторон, число процессов.
      Параллелизм дочерними процессами по числу ядер минус одно.
      *Проверка:* прогон четырёх матчей на четырёх процессах занимает
      заметно меньше, чем на одном.
- [x] 2.4 Версия кода в записи матча: `git rev-parse HEAD` и признак
      незакоммиченных изменений.
      *Проверка:* в логе матча есть и то, и другое; на грязном дереве
      признак взведён.

## 3. Подробный лог

- [x] 3.1 Точка наблюдения за противником. Устройство — наблюдатель,
      которому противник сообщает уже посчитанное; вызовов ради лога
      противник делать не должен. В комментарии объяснить, почему
      наблюдатель не имеет права трогать `rng`.
      *Проверка:* тест «лог не сдвигает случайность» — матч с логом
      и без дают одинаковую контрольную сумму.
- [x] 3.2 Записи решений: фаза, порядок трат, что пытался купить
      и с каким исходом, `waitStreak`, сорвалось ли терпение, выбранный
      рубеж.
      *Проверка:* в логе матча число записей решений равно числу тиков,
      делённому на интервал решений, для каждой стороны.
- [x] 3.3 Записи всех оценённых рубежей: доля, клетка, покрытие, выгода,
      риск, оценка, вероятность гибели, признак выбранного. Противник
      считает их все и так — берём готовое.
      *Проверка:* на каждое решение приходится столько записей, сколько
      рубежей вернул расчёт, и ровно одна помечена выбранной.
- [x] 3.4 Записи заметок о том, чего не произошло: места под башню нет,
      коплю на дорогое, терпение кончилось, положительной выгоды нет
      нигде. Коды закрытым перечислением.
      *Проверка:* в матче, где противник заведомо упирается в отсутствие
      места, соответствующая заметка присутствует.
- [x] 3.5 Записи команд с исходом: применена или отклонена и почему.
      Источник исхода — `rejections` из состояния мира.
      *Проверка:* число отклонённых команд в логе совпадает с числом
      записей отказа за матч.
- [x] 3.6 Сэмплы обеих сторон раз в игровую секунду: энергия, доход,
      юниты, постройки, здоровье базы, клетка и здоровье генерала,
      очередь, суммарный уровень прокачки.
      *Проверка:* число сэмплов равно длительности матча в секундах,
      умноженной на число сторон.
- [x] 3.7 Писатель JSONL: буфер в памяти, сброс на диск порциями.
      *Проверка:* прерванный прогон оставляет файл, читаемый до
      последней целой строки.

## 4. База и сводка

- [x] 4.1 Схема SQLite: шесть таблиц из `design.md`, индексы по
      `(match_id, tick)` и по `(match_id, player)`.
      *Проверка:* схема создаётся на пустой базе без ошибок.
- [x] 4.2 Команда `ingest`: чтение JSONL, вставка пачками в транзакции,
      пропуск битой последней строки с предупреждением.
      *Проверка:* лог из двадцати матчей ингестится; намеренно обрезанный
      файл даёт предупреждение, а не падение.
- [x] 4.3 Идемпотентность: повторный `ingest` того же лога не задваивает
      строки.
      *Проверка:* два прогона подряд дают одинаковое число строк
      в таблицах.
- [x] 4.4 Команда `report` по одному матчу: исход, длительность, путь
      генерала по долям пути, ведомость трат по фазам, распределение
      причин несостоявшихся покупок, отрыв выбранного рубежа
      от следующего.
      *Проверка:* сводка помещается в десятки строк и читается целиком.
- [x] 4.5 `report` по пачке: доля побед по профилям, средняя
      длительность, доля ничьих по времени, разброс самой дальней
      достигнутой доли пути.
      *Проверка:* прогон двадцати матчей даёт сводку, по которой видно
      различие между двумя профилями.
- [x] 4.6 Сводка приводит величины и не выносит суждений.
      *Проверка:* в выводе нет слов «хорошо», «плохо», «лучше»,
      «проблема».

## 5. Запись матча человека

- [x] 5.1 Тонкая запись в `apps/client`: seed мира, seed и профиль
      противника, версия кода, команды человека с тиками, контрольная
      сумма раз в секунду. Только в режиме разработки.
      *Проверка:* в промышленной сборке кода записи нет — проверяется
      поиском по собранному бандлу.
- [x] 5.2 Отправка по таймеру раз в полминуты и по концу матча.
      В горячем пути — только дописывание в массив.
      *Проверка:* замер кадра до и после не показывает различий;
      сериализация в профиле видна только в момент отправки.
- [x] 5.3 Плагин Vite: обработчик `POST /__matchlog` в `configureServer`.
      Только локальный адрес, имя файла составляется обработчиком,
      предел на размер тела, путь из тела не берётся.
      *Проверка:* тест — запрос с именем файла вида `../../x` пишет
      в файл с составленным именем; запрос сверх предела отклоняется.
- [x] 5.4 Команда `replay`: прогон записи заново со сверкой контрольных
      сумм, при расхождении — остановка с указанием тика и без создания
      подробного лога.
      *Проверка:* запись воспроизводится; после намеренной правки числа
      в профиле реплей падает с указанием тика.

## 6. Завершение

      *Проверка:* линт, типы, тесты и сборка зелёные.

      *Проверка:* сводка описывает тот матч, который был сыгран.
- [x] 6.3 Прогнать пачку из двадцати матчей двумя профилями и
      напечатать сводку.
      *Проверка:* прогон укладывается примерно в десять минут на восьми
      ядрах, сводка получена.
- [x] 6.4 Записать в `README.md` изменения короткую памятку: как
      запустить прогон, как заингестить, как посмотреть сводку, где
      лежит база.
      *Проверка:* по памятке всё воспроизводится с нуля.
