# Задачи

Порядок продиктован одним: **сначала прибор, потом провод, потом
показания.** Гистограмма без отдачи бесполезна, но отдача без
гистограммы — это ещё одно среднее, то есть ровно та беда, ради которой
всё затевается.

## 1. Гистограмма

- [x] 1.1 Гистограмма в `packages/shared/src/histogram.ts`: границы,
      счётчики, сумма, точный максимум, точный счётчик превышений,
      перцентили линейной оценкой внутри корзины.
      *Проверка:* `histogram.test.ts`, 6 тестов. Максимум и число
      превышений считаются отдельными счётчиками, а не выводятся
      из корзин: ответ на главный вопрос не должен зависеть от того,
      удачно ли выбраны границы.
- [x] 1.2 Границы выведены из `MS_PER_TICK`, а не записаны числами.
      *Проверка:* тест «граница бюджета едет вслед за темпом
      симуляции» связывает `TICK_BUDGET_MS`, `MS_PER_TICK`
      и `TICKS_PER_SECOND`.
- [x] 1.3 Замер расхода самого прибора: миллион добавлений, три прогона.
      *Проверка:* **27,1 / 35,9 / 30,7 нс** на наблюдение при пороге
      в сто. При тридцати тиках в секунду и десятке точек замера это
      порядка десяти микросекунд на секунду работы.

## 2. Отдача

- [x] 2.1 Решение: **свой рендер, без `prom-client`.** Уложился в 170
      строк вместе с комментариями. Довод записан в `design.md`:
      игровой сервер стоит в интернете, и зависимость ради полусотни
      строк вывода оплачивается своим деревом транзитивных пакетов.
      *Проверка:* новых зависимостей в `apps/server/package.json`
      не появилось.
- [x] 2.2 Точка `/metrics` в текстовом формате Prometheus.
      *Проверка:* живой запрос отдаёт 200 и разбираемый текст;
      `metrics.test.ts` — 7 тестов, среди них накопительность корзин
      (требование формата) и экранирование кавычек в разметке.
- [x] 2.3 Разметка только именем профиля манеры.
      *Проверка:* в выводе живого матча нет ни прозвища «Человек»,
      ни билета, ни номера комнаты — только `profile="..."`.

## 3. Приборы сервера

- [x] 3.1 Задержка цикла событий через `monitorEventLoopDelay()`.
      *Проверка:* показания снимаются живым запросом.
      **Важное открытие:** на пустом сервере без единого матча медиана
      равна 15,97 мс — это гранулярность таймера Windows, а не заминка.
      Разбор и способ поправки — в `design.md`.
- [x] 3.2 Длительность прохода `sweep()` и число тиков за `advance()`.
      *Проверка:* на живом матче 7822 прохода, наибольший 62,4 мс;
      догон случился в 22 проходах из 7565, наибольший — 5 тиков разом.
      Границы у счётной величины в штуках, а не в миллисекундах.
- [x] 3.3 Счётчик списанных долгов в `host.ts`.
      *Проверка:* на живом матче ноль — наверстать сервер всегда
      успевал. Раньше об этом не было никакого следа.
- [x] 3.4 Длительность шага мира вокруг `step` в `host.ts`, не в ядре.
      Ведущий часов не читает: он отдаёт шаг обёртке, а чем засечь —
      решает тот, кто прибор поставил. Так `packages/netplay` остаётся
      без платформенных вызовов, как требует его спецификация.
      *Проверка:* в `packages/sim` не появилось ни одного обращения
      к часам; линт зелёный. На живом матче 3898 шагов, средний
      0,37 мс, ни одного мимо бюджета.

## 4. Игровые приборы

- [x] 4.1 Длительность `opponent.decide` и счётчик решений, разметка
      именем профиля из того же значения, которым служба играет.
      *Проверка:* в выводе три ряда с именами трёх манер; работает
      тот, чья комната занята.
- [x] 4.2 Число команд за одно решение.
      *Проверка:* на живом матче в среднем 0,68, наибольшее 16.
- [x] 4.3 Первые настоящие показания сняты и записаны в `proposal.md`.
      *Проверка:* 260 решений на 3613 тиков — ровно расписание;
      средняя длительность 5,16 мс, наибольшая 120,5, мимо бюджета
      3 из 260.
      **Прогон нашёл ошибку в самом приборе:** счётчик показывал 4165
      решений вместо ~240, потому что замер обнимал каждый вызов
      `decide`, а тот в четырнадцати случаях из пятнадцати
      возвращается сразу. Исправлено: противник теперь называет свой
      следующий тик решения сам (`Opponent.nextDecisionTick`),
      а не вычисляется наблюдателем — второй источник расписания
      разошёлся бы с первым при первой же правке частоты.

## 5. Приборы клиента

- [ ] 5.1 Гистограмма длительности кадра в `apps/client/src/game/loop.ts`
      по аргументу `now`, который `requestAnimationFrame` уже передаёт.
      Нового обращения к часам не заводить.
      *Проверка:* число обращений к `performance.now` в цикле кадров
      не выросло; искусственная блокировка на 200 мс видна
      в распределении.
- [ ] 5.2 Разброс промежутков между приходами кадров команд.
      *Проверка:* при искусственной задержке рассылки на сервере
      в показаниях клиента появляются промежутки около нуля подряд.
- [ ] 5.3 Суммарное время в `rebuild` и число шагов симуляции
      за секунду.
      *Проверка:* число шагов сходится с ожидаемым `delayTicks + 2`
      на кадр.
- [ ] 5.4 Вывести показания плавности в диагностические атрибуты
      корневого элемента, обновляя их с частотой снимка матча,
      а не каждый кадр.
      *Проверка:* сквозная проверка читает атрибуты; счётчик записей
      в DOM за секунду не превышает частоту снимка.
- [ ] 5.5 Отправка показаний одним запросом после исхода матча;
      неудача отправки матча не задевает.
      *Проверка:* при выключенном приёмнике матч доигрывается
      и показывает итог без ошибок в консоли, кроме одного
      предупреждения.

## 6. Отметки времени в записи матча

- [ ] 6.1 Необязательное поле `atMs` в `ThinChecksum`, заполняется
      в `apps/server/src/recording.ts` при снятии суммы.
      *Проверка:* запись нового матча содержит отметки; запись,
      снятая раньше, читается по-прежнему.
- [ ] 6.2 Воспроизведение отметки игнорирует.
      *Проверка:* тест — воспроизведение записи с отметками и без них
      даёт одинаковые контрольные суммы.
- [ ] 6.3 Запрос к арене, показывающий неровность темпа: ожидаемое
      время против прошедшего по каждой секунде матча.
      *Проверка:* запрос выполняется на записи настоящего матча
      и печатает ряд; на записи ровного матча отклонения близки к нулю.

## 7. Доказательство, что приборы ничего не портят

- [ ] 7.1 Прогнать один и тот же матч с приборами и без них.
      *Проверка:* контрольные суммы итоговых состояний совпадают
      точно; длительность в реальном времени совпадает в пределах
      погрешности.
- [ ] 7.2 Проверить, что ни один секундомер не стоит внутри обхода
      по сущностям.
      *Проверка:* глазами по списку мест замера из `design.md`;
      каждое место названо и соответствует целой операции.
