# Задачи

Порядок продиктован одним: **сначала прибор, потом провод, потом
показания.** Гистограмма без отдачи бесполезна, но отдача без
гистограммы — это ещё одно среднее, то есть ровно та беда, ради которой
всё затевается.

## 1. Гистограмма

- [ ] 1.1 Завести в `packages/shared` гистограмму с явными границами
      корзин: массив границ, массив счётчиков, сумма, максимум, число
      наблюдений. Метод добавления наблюдения и метод чтения
      перцентилей.
      *Проверка:* юнит-тест — на известной выборке p50, p95, p99
      и максимум совпадают с посчитанными вручную; наблюдение
      сверх последней границы попадает в переполнение и учитывается
      в максимуме.
- [ ] 1.2 Задать общий набор границ, привязанный к бюджету тика:
      1, 2, 4, 8, 16, 33, 66, 133, 266 мс. Вывести константу из
      `MS_PER_TICK`, а не записать числом: изменится темп симуляции —
      границы обязаны поехать следом.
      *Проверка:* тест — при изменении `TICKS_PER_SECOND` граница
      «бюджет тика» смещается вместе с ним.
- [ ] 1.3 Замерить расход самой гистограммы: миллион добавлений
      подряд, время на одно.
      *Проверка:* добавление наблюдения стоит меньше ста наносекунд;
      иначе прибор слишком дорог для горячего пути и нужен другой.

## 2. Отдача

- [ ] 2.1 Решить, писать текстовый формат Prometheus своими руками
      или брать `prom-client`. Признак решения назван в `design.md`:
      своя реализация берётся, если укладывается в полторы сотни строк.
      Записать выбор и его причину в `design.md`.
      *Проверка:* решение записано; если выбрана внешняя библиотека —
      она в зависимостях только сервера, границы пакетов не нарушены.
- [ ] 2.2 Точка `/metrics` на игровом сервере. Ни прозвищ,
      ни идентификаторов, ни номеров комнат в выводе.
      *Проверка:* тест — в ответе `/metrics` во время матча с двумя
      игроками не встречается ни одно прозвище и ни один билет.
- [ ] 2.3 Разметка только именем профиля манеры и номером стороны.
      *Проверка:* тест — набор имён разметки в ответе совпадает
      с разрешённым списком.

## 3. Приборы сервера

- [ ] 3.1 Задержка цикла событий через `monitorEventLoopDelay()`
      из `node:perf_hooks`, включается при старте процесса.
      *Проверка:* искусственная блокировка цикла на 200 мс отражается
      в показаниях; без блокировки максимум остаётся в единицах
      миллисекунд.
- [ ] 3.2 Длительность прохода `sweep()` и число тиков за один
      `advance()` в `apps/server/src/matches.ts`.
      *Проверка:* при обычном матче число тиков за проход равно нулю
      или единице; после искусственной заминки появляются проходы
      с числом больше единицы.
- [ ] 3.3 Счётчик списанных долгов в `packages/netplay/src/host.ts`:
      место, где сегодня отставание списывается молча.
      *Проверка:* тест — матч, у которого отняли время, увеличивает
      счётчик.
- [ ] 3.4 Длительность шага мира — секундомер вокруг `step`
      в `host.ts`, не внутри ядра.
      *Проверка:* в `packages/sim` не появилось ни одного обращения
      к часам; линт на запрет `Date`/`performance` в ядре зелёный.

## 4. Игровые приборы

- [ ] 4.1 Длительность `opponent.decide` и счётчик решений
      в `packages/bot/src/participant.ts`, разметка именем профиля
      из `computerMindOf` — того же источника, что у записи матча.
      *Проверка:* тест — имя манеры в показаниях совпадает с именем
      манеры в записи того же матча.
- [ ] 4.2 Число команд, отданных за одно решение.
      *Проверка:* показания сходятся с числом вызовов `issue`
      за то же решение.
- [ ] 4.3 Прогнать матч с компьютером и снять первые настоящие
      показания: p50, p95, p99 и максимум длительности решения,
      частота решений, задержка цикла событий.
      *Проверка:* таблица получена и записана в `proposal.md` рядом
      с прогнозом. Расхождение с прогнозом больше чем вдвое —
      повод разобраться, а не подправить прогноз.

## 5. Приборы клиента

- [ ] 5.1 Гистограмма длительности кадра в `apps/client/src/game/loop.ts`
      по аргументу `now`, который `requestAnimationFrame` уже передаёт.
      Нового обращения к часам не заводить.
      *Проверка:* число обращений к `performance.now` в цикле кадров
      не выросло; искусственная блокировка на 200 мс видна
      в распределении.
- [ ] 5.2 Разброс промежутков между приходами кадров команд.
      *Проверка:* при искусственной задержке рассылки на сервере
      в показаниях клиента появляются промежутки около нуля подряд.
- [ ] 5.3 Суммарное время в `rebuild` и число шагов симуляции
      за секунду.
      *Проверка:* число шагов сходится с ожидаемым `delayTicks + 2`
      на кадр.
- [ ] 5.4 Вывести показания плавности в диагностические атрибуты
      корневого элемента, обновляя их с частотой снимка матча,
      а не каждый кадр.
      *Проверка:* сквозная проверка читает атрибуты; счётчик записей
      в DOM за секунду не превышает частоту снимка.
- [ ] 5.5 Отправка показаний одним запросом после исхода матча;
      неудача отправки матча не задевает.
      *Проверка:* при выключенном приёмнике матч доигрывается
      и показывает итог без ошибок в консоли, кроме одного
      предупреждения.

## 6. Отметки времени в записи матча

- [ ] 6.1 Необязательное поле `atMs` в `ThinChecksum`, заполняется
      в `apps/server/src/recording.ts` при снятии суммы.
      *Проверка:* запись нового матча содержит отметки; запись,
      снятая раньше, читается по-прежнему.
- [ ] 6.2 Воспроизведение отметки игнорирует.
      *Проверка:* тест — воспроизведение записи с отметками и без них
      даёт одинаковые контрольные суммы.
- [ ] 6.3 Запрос к арене, показывающий неровность темпа: ожидаемое
      время против прошедшего по каждой секунде матча.
      *Проверка:* запрос выполняется на записи настоящего матча
      и печатает ряд; на записи ровного матча отклонения близки к нулю.

## 7. Доказательство, что приборы ничего не портят

- [ ] 7.1 Прогнать один и тот же матч с приборами и без них.
      *Проверка:* контрольные суммы итоговых состояний совпадают
      точно; длительность в реальном времени совпадает в пределах
      погрешности.
- [ ] 7.2 Проверить, что ни один секундомер не стоит внутри обхода
      по сущностям.
      *Проверка:* глазами по списку мест замера из `design.md`;
      каждое место названо и соответствует целой операции.

## 8. Закрепление

      *Проверка:* линт, типы, тесты и сборка зелёные.
