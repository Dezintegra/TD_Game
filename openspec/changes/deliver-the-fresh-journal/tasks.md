# Задачи

Каждый пункт — отдельный коммит, собирающийся и проверяемый сам по себе.
Проверки узкие и местные; полный набор гоняет CI (правило 6 в `CLAUDE.md`).

**Оговорка о проверке.** Тесты конвейера в CI не входят: слово `supervisor`
не встречается ни в одном файле `.github/workflows/`, а рабочее пространство
Vitest этот корень не видит намеренно. Зелёный CI об этой правке не скажет
ничего, поэтому проверка каждого шага — местный узкий прогон. Он дешёвый:
чистые функции от строки, ни диска, ни сети.

Порядок не случаен. Сперва появляется разбор журнала на записи, которым
пользуются оба следующих шага; затем выдержка; затем подключение к промпту;
и только потом отдельный раздел вердикта. Каждый промежуточный шаг оставляет
конвейер работоспособным: новые функции никем не зовутся, пока до них
не дойдёт черёд.

## 1. Журнал разбирается на записи

- [ ] `supervisor/lib/stage-prompt.mjs`: завести `splitJournalEntries(text)`,
      возвращающую записи по порядку. Границей считать строку, целиком
      равную `## …` либо `**… → …**` — со стрелкой обязательно. Текст
      до первой границы (заголовок журнала) возвращать первым куском.
- [ ] Границ не нашлось — вернуть весь текст одним куском. Это признак
      журнала старого образца, и разбирать там нечего.
- [ ] Тесты в `supervisor/lib/stage-prompt.test.mjs`: журнал доски
      (`**design → audit**`) и файловый (`## 2026-09-02 · design → audit`)
      разбираются одинаково; жирные подзаголовки тела — `**Решения:**`,
      `**Отказано в действиях:**` — границами **не** считаются; склейка
      разобранного даёт исходный текст без потерь.

**Проверка:** `npx vitest run --root supervisor lib/stage-prompt.test.mjs`
зелёный. После этого коммита открыть черновой pull request — до его
появления пуши в ветку не запускают проверок CI вовсе.

## 2. Выдержка набирается целыми записями с конца

- [ ] `supervisor/lib/stage-prompt.mjs`: завести `clipJournal(text, limit)`.
      Хвост — записи с конца, пока укладываются; последняя запись входит
      всегда, даже одна переросшая предел; голова добавляется, если после
      хвоста осталось место; между ними пометка с числом пропущенных знаков
      **и** числом пропущенных записей.
- [ ] Потолок на чудовищную последнюю запись — четырёхкратный предел.
      Перевалившую резать `clipMiddle`, а не `clip`: голова и хвост
      сохраняются, пропуск назван.
- [ ] Разбор не дал границ — вернуться к `clipMiddle` по знакам.
- [ ] Тесты там же: журнал короче предела приходит целиком и без пометки;
      длинный отдаёт последнюю запись дословно; последняя запись длиннее
      предела всё равно цела; запись длиннее потолка урезана серединой,
      а не хвостом; пометка называет оба числа.

**Проверка:** `npx vitest run --root supervisor lib/stage-prompt.test.mjs`
зелёный.

## 3. Промпт берёт журнал новой меркой

- [ ] `supervisor/lib/stage-prompt.mjs`, `stagePrompt()`: заменить
      `clip(journal, journalLimit)` на `clipJournal(journal, journalLimit)`.
      `clip()` убрать, если других вызовов у неё не осталось.
- [ ] Тест, закрепляющий признак сделанности из постановки: промпт для
      задачи с журналом заведомо длиннее предела содержит **последнюю
      запись целиком** — не начало её, а весь текст, включая последнюю
      строку.
- [ ] Тест, что прежняя пометка «целиком — в журнале задачи» больше
      не отсылает исполнителя на доску.

**Проверка:** `npx vitest run --root supervisor lib/stage-prompt.test.mjs`
зелёный; `npx vitest run --root supervisor` целиком зелёный — здесь
меняется поведение, на которое смотрят соседние тесты.

## 4. Вердикт возврата подаётся отдельным разделом

- [ ] `supervisor/lib/stage-prompt.mjs`: завести поиск записи возврата —
      перебором записей с конца, первая, у которой `куда` равно нынешнему
      этапу, а `откуда` — проверяющий. Проверяющих брать из таблицы `TRACE`
      в `supervisor/lib/denials.mjs` (след `branch`), своего списка
      не заводить.
- [ ] `stagePrompt()`: раздел `## Вердикт, с которым вас вернули` перед
      журналом, текст записи целиком, без обрезки. Возврата нет — раздела
      нет вовсе.
- [ ] Тесты там же: вернувшемуся из аудита раздел дан и цел даже при
      журнале длиннее предела; служебная запись «Этапу выдана сессия»,
      легшая после вердикта, разделу не мешает; зашедшему впервые раздела
      не дают.

**Проверка:** `npx vitest run --root supervisor lib/stage-prompt.test.mjs`
зелёный.
