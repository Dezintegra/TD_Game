## Context

На обновлённой базе `7a12154` нет проектной обёртки архивации. `CLAUDE.md` и `.agents/skills/openspec-archive-change/SKILL.md` предписывают глобальный `openspec archive`; Claude-скилл и `.claude/commands/opsx/archive.md` непосредственно перемещают каталог через `mv`. `.claude/commands/opsx/sync.md`, как и Claude sync-скилл, останавливается при отсутствии дельт и предлагает TBD для новой способности. Поэтому подключение только четырёх SKILL.md оставляет штатный командный маршрут без защиты. `supervisor/skills/design.md` оставляет Purpose новой способности ручной работой. `package.json` уже включает `scripts/*.test.mjs` через `test:scripts`; новый отдельный workflow не нужен.

Постановка разрешает два технических решения. Выбрана проверка внесённой замены: нам принадлежит проектный порядок архивации, но не глобальная установка OpenSpec. Факт успешного validate дельты не доказывает перенос Purpose.

## Goals / Non-Goals

Цель — сделать потерю явно объявленного Purpose причиной исполняемого отказа до архивации. Машинный контракт должен поставляться вместе с командой, документацией и тестами. Исключения и границы перечислены в proposal; в частности эта работа не заменяет частную задачу 0058 и не переписывает старые архивы.

## Decisions

### 1. Отдельное объявление, без изменения грамматики дельт

Файл `purpose-updates.json` имеет форму `{"version":1,"updates":[{"capability":"build-tooling","purpose":"Полный согласованный текст."}]}`. Это пример формата, не заказ на замену Purpose build-tooling в этой задаче. Наше изменение само такого файла не создаёт.

JSON выбран ради штатного JSON.parse и отсутствия новой зависимости. Массив позволяет обнаружить повтор способности после разбора, в отличие от объекта с именами способностей в ключах. Неизвестные поля, лишние типы, пустой массив и текст из пробелов — ошибка. Имена change/capability проверяются целиком по kebab-case (буквы a–z и цифры, группы разделены одиночным дефисом); `archive` запрещён как имя активного изменения. Пути вычисляются только внутри собственного openspec; символьные ссылки/переадресации за его пределы отвергаются.

Добавление `## Purpose` к дельте отвергнуто: без изменения глобального CLI оно создавало бы видимость поддержки. Форк/patch глобального пакета не воспроизводится вместе с репозиторием. Поиск обещаний в прозе отвергнут: невозможно надёжно отличить пример от поручения и восстановить дословный ожидаемый текст. Контракт распространяется на новые объявления; существующие пометки переводятся при последующей работе над соответствующим изменением, без массовой миграции здесь.

### 2. Проверить до запуска, текст внести при синхронизации

`scripts/openspec-purpose.mjs` — импортируемая логика чтения объявления, извлечения раздела и сравнения. Импорт не запускает команды. `scripts/openspec-archive.mjs` — тонкая CLI-точка входа, принимает одно имя и только `--yes`, `--skip-specs` (каждый не более одного раза). Нет `--no-validate`, произвольных CLI-хвостов, выбора внешнего store или ключа обхода проверки. Корень привязан к расположению скрипта в репозитории, дочерний CLI получает этот же cwd; случайный текущий каталог не выбирает другой OpenSpec store.

Сначала полностью прочитать и проверить объявления и все цели. Даже совпадение первой цели не разрешает запустить CLI до проверки последней. При отсутствии файла объявления разрешён штатный путь; любые прочие ошибки чтения не считаются отсутствием. Логика проверки сама ничего не пишет. Диагностика содержит change, capability и путь/причину; сообщение CLI сохраняется.

Полный текст вручную или средствами sync-specs вносит уполномоченный архивирующий при предварительной синхронизации. Для новой способности сначала создаётся основная спецификация с требованиями и окончательным Purpose, затем используется `--skip-specs`, как и в действующем маршруте предварительной синхронизации. Для существующей способности можно обновить один Purpose, а требования передать штатной архивации. Для изменения только Purpose без требований сохраняется бездельтовый порядок и `--skip-specs`. На implement это не создаёт пункта ручной архивации: реализация механизма закрывается до неё.

Тело Purpose — строки после единственного заголовка `## Purpose` до следующего настоящего h1/h2, с поддержкой ограждений из backtick/tilde. Пример заголовка в коде не считается заголовком. Нормализация меняет только CRLF и крайние пустые строки (с пробелами/табуляциями); внутренние строки не переформатируются. Два настоящих Purpose — ошибка, не выбор первого. Так содержательная разница не теряется под слишком широкой нормализацией.

### 3. Штатный CLI остаётся исполнителем архивации

После проверки вызывается установленный `openspec` по имени с массивом проверенных доводов. Запуск на Windows должен учитывать shim установленного CLI и сохранять вывод и код завершения; использовать существующий подход проекта к запуску команд на Windows, без интерполяции пользовательского произвольного shell-текста. Повторной реализации переноса требований нет.

Отказ нашего preflight гарантирует отсутствие изменений. Ошибка уже запущенного штатного CLI не обещает транзакционный откат его собственных действий: вывести ошибку, оставить диагностику и не объявлять успех. Повторный запуск повторяет проверку. Синхронизация/архивация по-прежнему не запускаются параллельно на одной цели.

### 4. Подключение к порядку и проверкам

В CLAUDE.md документируется проектная команда вместо прямого вызова для рабочих изменений. Историческая проба глобального CLI сохраняется как факт о названной версии. В openspec/config.yaml и supervisor/skills/design.md добавляется правило объявления, без отмены формата ADDED/MODIFIED и запрета архивации на design/implement.

В `.agents/skills/openspec-archive-change/SKILL.md` и `.claude/skills/openspec-archive-change/SKILL.md` все исполняемые пути реальной архивации этого репозитория переводятся на обёртку, в том числе `--skip-specs`. Внешний store обёртка не поддерживает: инструкция не должна подменять его локальным деревом; для внешнего store требуется его собственный порядок. В sync-specs-скиллах явно читается объявление и переносится Purpose, а для новых способностей объявленный текст заменяет совет ставить TBD. Условие «нет дельт — остановиться» уточняется: сначала проверить наличие purpose-updates.json, поскольку замена одного Purpose может идти без дельты. Claude allowed-tools согласуется с конкретной командой обёртки. Новое разрешение архивации в stage-settings не нужно: этапам по-прежнему нельзя архивировать реальные изменения; узкие тесты запускаются уже покрытым `npx vitest`.

Тот же контракт подключается непосредственно в `.claude/commands/opsx/archive.md` и `.claude/commands/opsx/sync.md`: команды являются самостоятельными точками входа, наличие правильного SKILL.md рядом их не защищает. В archive-команде шаг оценки синхронизации читает и дельты, и объявление даже без `specs/`. Шаг переноса целиком заменяется вызовом `node scripts/openspec-archive.mjs <change> --yes`, с `--skip-specs` после предварительной синхронизации требований либо при отсутствии дельт. Создание каталога архива, выбор даты и перемещение выполняет штатный CLI через обёртку; исполняемого `mv`, `Move-Item` или прямого `openspec archive` для рабочего изменения в этом маршруте не остаётся. Выбор «архивировать без синхронизации» не отменяет проверку Purpose: несовпадение блокирует архивацию, даже если пользователь согласился пропустить синхронизацию требований или предупреждения о незакрытых задачах. Итоговый отчёт об успехе формируется только при успешном завершении обёртки. Правила внешнего store и allowed-tools согласуются в командном файле так же, как в скилле.

В sync-команде и обоих sync-скиллах список доступных изменений включает изменения с дельтами **или** `purpose-updates.json`. Отсутствие обеих сущностей означает «синхронизировать нечего»; отсутствие только дельт не завершает операцию. Объявление читается и проверяется до правок, весь ожидаемый Purpose переносится дословно с сохранением остальных разделов. Новая способность получает объявленный Purpose вместе с ADDED-требованиями; одно объявление без основной спецификации и без ADDED не разрешает выдумывать требования или создавать пустую способность — операция сообщает недостающую основу. После переноса сверяются все объявленные тексты по правилам §2, повторный запуск не меняет результат, изменение остаётся открытым. Сводка называет перенос Purpose отдельно от требований и не приравнивает «нет дельт» к «нет изменений».

Тесты в `scripts/openspec-purpose.test.mjs` и `scripts/openspec-archive.test.mjs` входят в существующий scripts-набор CI. Первый проверяет реальные Markdown/JSON fixtures, второй — временный проект внутри `.matchlog/` и подставной исполнитель CLI: вызов/отсутствие вызова, доводы, cwd, exit code, отсутствие изменения файлов при отказе. Нужен отрицательный контроль: те же fixtures с закрытыми tasks и устаревшим Purpose отказывают, после замены только Purpose проходят. Отключённая проверка должна ломать тест по факту запуска архиватора. Отдельный тест читает действующие инструкции и проверяет, что рабочие маршруты используют обёртку и не предлагают ключ обхода.

Проверка маршрутов в `scripts/openspec-archive.test.mjs` охватывает поимённо CLAUDE.md, четыре SKILL.md и оба `.claude/commands/opsx/{archive,sync}.md`. Для каждой архивной точки входа проверяются исполняемая команда обёртки, сохранение preflight при `--skip-specs`/пропуске синхронизации, отсутствие самостоятельного переноса и согласованное allowed-tools там, где оно объявлено. Для каждой точки синхронизации проверяются выбор изменений с объявлением без дельт, чтение объявления до раннего выхода, перенос полного текста и отсутствие совета подменять объявленный текст TBD. Отрицательные контроли на копиях текстов отдельно возвращают в archive-команду прямой перенос, а в sync-команду безусловный выход при отсутствии дельт: каждый ломает соответствующую проверку. Одного поиска имени обёртки где-нибудь в документе недостаточно. Поведенческие fixtures отдельно показывают отказ обёртки без дельт при старом Purpose и успех с `--skip-specs` после замены только этого раздела. Эти тесты проверяют механизм и договор инструкций, а не имитируют исполнение Markdown моделью.

## Risks / Trade-offs

- Прямой запуск глобального `openspec archive` человеком обходит обёртку → гарантия относится к проектной команде; оба archive-скилла, `/opsx:archive` и общий порядок называют её единственной штатной точкой входа. Не обещаем перехват внешнего бинарника.
- Необъявленное намерение в старой прозе не обнаруживается → новая проработка требует явный файл; массовая эвристическая миграция исключена.
- Изменение Purpose после проверки параллельной сессией → сохраняется действующий запрет конфликтующих синхронизаций; межпроцессная транзакция не добавляется.
- Различие shim Windows и POSIX → тестировать подбор запуска для обеих платформ через подстановку platform/исполнителя; ошибку отсутствующего CLI возвращать явно. Образец shell-запуска уже есть в scripts/perf-run.mjs:183–188; разрешены только проверенные имена и фиксированные ключи. Установка сторонних пакетов для проверки не нужна.

## Migration Plan

Механизм, инструкции и регрессии поставляются одним атомарным коммитом реализации. Старые изменения без объявления продолжают работать. Откат этого коммита возвращает прежний порядок; созданные впоследствии объявления при таком откате требуют ручной сверки и не должны молча удаляться. Само изменение архивируется позже уполномоченным человеком, не на текущем этапе.

Симуляция, состояние мира, Math.random/Date.now, эталоны детерминизма, бинарная раскладка и PROTOCOL_VERSION не затрагиваются. Поведение при рассинхроне и реконнекте не меняется. Арена и замеры кадров не нужны.
