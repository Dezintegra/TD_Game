# Задачи

Каждый шаг — отдельный коммит, проверяемый сам по себе. Кода изменение
не заводит, поэтому ни `pnpm install`, ни сборка, ни тесты пакетов здесь
не нужны; проверки везде узкие и идут по одному файлу.

## 1. Открыть черновой pull request на артефактах проработки

- [ ] Артефакты проработки (`proposal.md`, `design.md`, `tasks.md`)
      уже лежат в ветке отдельным коммитом — отправить ветку, если она
      ещё не отправлена, и открыть черновой pull request в `main`:
      `gh pr create --draft --base main --title "<заголовок>" --body-file <файл>`.
- [ ] Тело pull request писать файлом: `--body` длинной прозой
      отказывается ещё до `gh`.

**Проверка:** `gh pr view <номер> --json number,state,isDraft` отвечает
`OPEN` и `true`; `gh pr checks <номер>` показывает запущенные проверки.
Шаг стоит первым не из вежливости: до появления pull request пуши
в ветку не запускают CI вовсе, и каждый следующий коммит остался бы
непроверенным.

## 2. Подтянуть в ветку свежий `origin/main`

- [ ] `git fetch origin`, затем `git merge origin/main` в своей ветке.
      Переключений веток и отправки в `main` не делать: работа уезжает
      только через pull request.
- [ ] Конфликта в `supervisor/config/stage-settings.json` быть не должно
      ни при каком состоянии `main` — обоснование в `design.md`,
      Решение 3. **Если конфликт всё же случился, остановиться и назвать
      его в отчёте**: значит файл тронул кто-то третий, и правку надо
      класть поверх его текста, а не поверх своего представления о нём.

**Проверка:** `git rev-list --count HEAD..origin/main` отвечает `0`.
Если `origin/main` уже был влит, шаг обходится без коммита — пустой
коммит не заводить, просто перейти к следующему.

## 3. Переписать `$formNote` на `PowerShell`

- [ ] В `supervisor/config/stage-settings.json` заменить значение ключа
      `$formNote` (строка 12) на текст, выписанный в `design.md`
      («Целевой текст `$formNote` целиком»). Значение — **одна строка**
      JSON, переводов строк внутри быть не должно.
- [ ] Править инструментом редактирования файла. `Set-Content`,
      `Out-File` и перенаправление `>` к этому файлу не применять:
      Windows PowerShell 5.1 читает UTF-8 как ANSI и превращает
      кириллицу в мохибейк (`design.md`, Решение 5).
- [ ] Больше в репозитории не менять **ничего**: ни правил в `allow`
      и `deny`, ни соседних примечаний, ни `$readNote` с его ссылкой
      на `$formNote`, ни сторожей в `supervisor/config/`.

**Проверка**, вся по одному файлу:

- `npx prettier --check supervisor/config/stage-settings.json` — зелёный.
  Он же ловит сломанный JSON: невалидный файл prettier не разберёт;
- `npx vitest run --root supervisor config/transitions.test.mjs` —
  зелёный. Ключ `--root supervisor` обязателен: без него тесты конвейера
  не находятся вовсе, и прогон зеленеет, ничего не прогнав. Сторож этот
  читает `stage-settings.json` как данные, то есть подтверждает, что
  файл разбирается и список правил цел;
- поиском по файлу: в значении `$formNote` есть `PowerShell(node
  .matchlog/:*)` и `PowerShell(node .matchlog/*)`, а `Bash(` в нём
  не осталось ни разу;
- глазами, три сохранённые дословно вещи: дата `31.08.2026`, команда
  `node .matchlog/pipeline-33423722570/schema.mjs`, обороты «четырежды
  подряд» и «без единого отказа»;
- глазами же: строка `"PowerShell(node .matchlog/*)"` в списке `allow`
  на месте — иначе пример снова указывает в пустоту;
- `git diff --stat` показывает ровно один изменённый файл и одну
  изменённую строку.

## 4. Дождаться зелёного CI

- [ ] `gh pr checks <номер> --watch`. Красное чинить, коммитить отдельно
      и ждать снова: задача не сделана, пока GitHub не сказал «зелено».
- [ ] Локально ничего сверх шага 3 не прогонять: полный набор проверок
      живёт в CI (правило 6 `CLAUDE.md`), а из дополнительного дерева
      его не запускают.

**Проверка:** все задачи pull request зелёные. Черновой статус
на этом шаге **не снимать** — его снимает ревью первым подшагом
вливания.

## Чего в списке нет

- **Прогона арены не заказывается.** Правила игры, цены, доход, сила
  юнита и темп не задеты ни одной строкой: меняется текст примечания
  в настройках конвейера, лежащих вне пакетов монорепозитория.
- **Замеров кадров и стоимости тика нет** по той же причине: отрисовка
  и шаг мира не тронуты.
- **Архивации изменения нет.** Она переписывает `openspec/specs/`, её
  очередь задана зависимостями дельт, и решение это принимает человек.
  Здесь важно помнить одно: изменение архивируется **после**
  `supervise-the-pipeline`, которое заводит способность
  `dev-pipeline-supervisor` (см. «Зависимости» предложения).
