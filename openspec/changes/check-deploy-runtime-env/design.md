## Context

Общий `.env.example` содержит настройки приложения и локального супервизора. Deploy ошибочно требует каждую из них на игровом сервере. Docker Compose уже задаёт TELEMETRY=1 по умолчанию, что также объяснено в серверном config.ts.

## Goals / Non-Goals

Goals: различать применимые настройки, явные умолчания и обязательные отсутствующие значения.

Non-Goals: менять настройки или значения секретов, политику сбора показаний, игровую отзывчивость, трафик, рассинхрон и реконнект.

## Decisions

- Источник применимости — Compose, Dockerfile и конфигурация запускаемых сервисов выбранной ревизии. Образец окружения — справочник, а не перечень обязательных серверных имён.
- Имеющееся явное серверное значение сохраняется. При отсутствующем необязательном имени используется существующее документированное умолчание, которое отражается в отчёте.
- Отсутствие обязательного значения без умолчания, например TD_DOMAIN, остаётся вопросом. Неизвестная или неоднозначная настройка также требует вопроса, а не угадывания секрета.
- Только поправка общего deploy skill: отдельный парсер Compose дублировал бы его семантику без необходимости.

## Risks / Trade-offs

- Ошибочная классификация новой настройки → исполнитель читает реальные потребители выбранной ревизии, при неоднозначности останавливается с точным вопросом.
- Разглашение серверных значений → сохраняется сверка только имён и запрет чтения/вывода значений.

## Migration Plan

После CI и слияния перезапустить супервизор штатно, сохранив отчёты. Вернуть остановленную ложным вопросом выкладку с новым снимком main и повторить обязательный замер. Откат инструкции возвращает прежнее строгое поведение без изменений на сервере.
