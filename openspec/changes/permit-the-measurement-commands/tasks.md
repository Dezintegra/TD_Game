# Задачи

Каждый пункт — отдельный коммит, отправляемый сразу.

Порядок выбран так, чтобы **правила легли первым коммитом**: до них
конвейер неисполним на трёх этапах, и любой день задержки стоит
сгоревшей сессии. Сторож ставится вторым — раньше он был бы красным,
а красный шаг нельзя проверить в одиночку.

Тесты конвейера обычным `vitest` не видны, у них свой корень:

```
npx vitest run --root supervisor config/transitions.test.mjs
```

Тесты оснастки замера видны обычным:

```
npx vitest run scripts/perf-common.test.mjs
```

## 1. Правила разрешений

- [ ] 1.1 Дописать в `permissions.allow` файла
      `supervisor/config/stage-settings.json` по строке на каждую
      оболочку (`PowerShell(...)` и `Bash(...)`) для:
      `pnpm install:*`, `pnpm build`, `pnpm build:*`, `pnpm e2e:perf:*`,
      `pnpm bench:tick:*`, `node scripts/deploy.mjs:*`,
      `node scripts/perf-run.mjs:*`, `node scripts/bench-tick.mjs:*`.
      Рядом завести пояснение `$pnpmNote`: почему открыты ровно эти
      команды, почему `pnpm balance:run` и полные наборы проверок
      остаются закрытыми, почему у двух команд замера положен запасной
      вызов без двоеточия и что покажет первая задача-замер после
      вливания. В `permissions.deny` не добавлять ничего: перекрытий
      с новыми разрешениями там нет — запреты касаются только `git`
      и `gh repo delete`, и это проверено сверкой файла целиком.
      Проверяемо: `npx vitest run --root supervisor
      config/transitions.test.mjs` зелёный (файл остаётся разбираемым
      JSON, форма `путь/:*` не появилась, правил на удаление нет);
      глазами — у каждой из восьми команд ровно две строки, по одной
      на оболочку

  Открыть черновой pull request сразу после этого коммита: до открытия
  PR проверки CI на пуши в ветку не запускаются вовсе.

## 2. Сторож согласованности правил и предписаний

- [ ] 2.1 Добавить в `supervisor/config/transitions.test.mjs` проверку
      покрытия. Вспомогательная функция считает правило покрывающим
      команду, если правило вида `Средство(приставка:*)` совпадает
      с началом команды либо правило вида `Средство(команда)` совпадает
      с ней точно. Обязаны быть покрыты в обеих оболочках: команды
      из `supervisor/pipeline.config.json` полей `perf`, `perfCheck`,
      `benchTick`, `deploy`, а также `pnpm install --frozen-lockfile`
      и `pnpm build`. Обязаны остаться непокрытыми: `pnpm balance:run`,
      `pnpm verify` (поле `verify`), `pnpm verify:all` (поле `verifyAll`),
      `pnpm test`, `pnpm test:match`, `pnpm test:all`. Комментарий
      называет цену вопроса поимённо: 0086 — 1,85 доллара и шесть
      отказов, 0012 — исчерпанные продолжения на доработке.
      Проверяемо: тест зелёный на текущем файле; временно убранная
      строка `PowerShell(pnpm e2e:perf:*)` делает его красным
      с именем непокрытой команды; временно добавленная строка
      `PowerShell(pnpm:*)` делает его красным на прогоне арены

## 3. Порты замера кадров ключами

- [ ] 3.1 Вынести в `scripts/perf-common.mjs` функцию
      `resolvePorts(argv, env)`, возвращающую `{ clientPort, serverPort }`
      по правилу «ключ важнее переменной окружения, переменная важнее
      умолчания»: `--client-port` / `CLIENT_PORT` / `5173`
      и `--server-port` / `PORT` / прежнее умолчание сервера. Значение
      принимается и слитно (`--client-port=5199`), и следующим словом.
      Нечисловое либо выходящее за 1–65535 значение — остановка
      с внятной причиной, а не молчаливый откат к умолчанию: молчаливый
      откат отправил бы замер на чужой порт, ровно в ту беду, от которой
      ключи и заводятся. Проверяемо: разделом в
      `scripts/perf-common.test.mjs` — ключ побеждает переменную; без
      ключей берётся переменная; без обоих берётся умолчание; обе формы
      записи ключа дают одно значение; `--client-port abc`
      и `--client-port 70000` останавливают разбор

- [ ] 3.2 Подключить `resolvePorts` в `scripts/perf-run.mjs` вместо
      чтения `process.env` напрямую, добавить `--client-port`
      и `--server-port` в набор «своих» ключей, чтобы они не уехали
      в Playwright вместе с остальными аргументами, и поправить образец
      в тексте подсказки о занятом порте на однокомандную форму.
      Проверяемо: `npx vitest run scripts/perf-common.test.mjs` зелёный;
      `npx eslint scripts/perf-run.mjs scripts/perf-common.mjs`
      и `npx prettier --check scripts/perf-run.mjs
      scripts/perf-common.mjs` без замечаний; поиском по файлу —
      `process.env['CLIENT_PORT']` больше не читается в обход функции

## 4. Правила этапа замера

- [ ] 4.1 Переписать в `supervisor/skills/benchmark.md` шаг 5.4:
      вместо `CLIENT_PORT=5199 PORT=3055 pnpm e2e:perf` — одна команда

      (`node scripts/perf-run.mjs …`, `node scripts/bench-tick.mjs …`)
      и сказать, что браться за неё следует только при отказе основной,
      а сам отказ — называть в отчёте. Шаг 6 (замер стоимости тика)
      портов не требует, и трогать его не надо. Скилл выкладки править
      не надо тоже: он зовёт `pnpm e2e:perf -- --check-only`,
      `-- --history` и `node scripts/deploy.mjs --ref …`, а все три
      покрыты правилами из шага 1.1. Проверяемо: сторожем в
      `supervisor/config/transitions.test.mjs` — ни один файл
      `supervisor/skills/*.md` не содержит образца с `CLIENT_PORT=`
      перед командой, а `benchmark.md` содержит строку
      `pnpm e2e:perf -- --client-port`; тест краснеет на прежней
      редакции скилла

## Чего в этом списке нет и почему

**Живой пробы правил на конвейере.** Проверка разрешений применяется
к сессии при её запуске и по ходу не перечитывается, поэтому доказать
делом новое правило может только этап, которому оно адресовано, —
а этап реализации на замер не вправе. Доказательством станет журнал
первой задачи-замера после вливания: либо он чист от отказов, либо
называет форму, которую чинить дальше. Пунктом `tasks.md` это быть
не может: пункт, который этап не вправе исполнить, делает исход `done`
недостижимым.
