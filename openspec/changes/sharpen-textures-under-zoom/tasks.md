# Задачи

Каждая — отдельный коммит, отправляемый сразу. Порядок выбран так, чтобы
любая остановка оставляла работоспособное состояние.

## 1. Расчёт плотности запекания

- [x] 1.1 Завести `apps/client/src/game/bake-density.ts`: плотность сцены
      `min(плотность экрана × ZOOM_OVERSAMPLE, MAX_BAKE_DENSITY)` и плотность
      слоя скал из бюджета `clamp(sqrt(бюджет / площадь), 1, плотность сцены)`.
      Константы с обоснованием в комментарии: `ZOOM_OVERSAMPLE = 2`,
      `MAX_BAKE_DENSITY = 3`, `ROCK_BAKE_BUDGET_MB = 64`,
      `ROCK_CELL_AREA_PX = 14000` (измерено).
- [x] 1.2 Модульные тесты `bake-density.test.ts`: запас, потолок, нижняя
      граница, бюджет на карте вдвое большей, карта без скал.

## 2. Скалы и командный центр перестают запекаться в единицу

- [x] 2.1 `relief-render.ts`: `mountRockDiagonal` принимает плотность,
      число `1` из `RenderTexture.create` уходит.
- [x] 2.2 `base-render.ts`: `bakeBase` принимает плотность, число `1` уходит.
- [x] 2.3 `scene.ts`: считает плотность один раз, передаёт в оба места;
      плотность скал считается от числа скальных клеток карты.
- [ ] 2.4 Проверить глазами на снимке при единичном приближении, что облик
      не изменился, а чёткость выросла.

## 3. Мип-уровни на запечённых текстурах

- [x] 3.1 Общий помощник «включить уровни и построить их однажды»

- [ ] 3.2 Проверить на снимке при уменьшении (масштаб 0,4), что мерцание

## 4. Запас плотности у машин, построек и дуг

- [x] 4.1 `scene.ts`: машины и постройки получают плотность сцены вместо
      `app.renderer.resolution`.
- [x] 4.2 `arc-render.ts`: плотность приходит снаружи, число `2` уходит.
- [x] 4.3 `armour-render.ts`: `SUPERSAMPLE` перестаёт быть постоянной
      кратностью — постоянной становится плотность черновика, а кратность
      выводится делением. Время запекания не меняется.
- [x] 4.4 Решётка проб в шейдере сведения отвязана от кратности: она
      целая, а кратность стала дробной. Проб на сторону — две, шаг между
      ними приходит числом.
