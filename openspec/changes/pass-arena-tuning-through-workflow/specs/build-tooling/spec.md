## ADDED Requirements

### Requirement: Ручной workflow арены принимает множители правил

Workflow `.github/workflows/arena.yml` SHALL предоставлять необязательный строковый вход `tuning_args` с пустым значением по умолчанию. Вход SHALL принимать последовательность пар `--ключ число`, разделённых пробельными символами, для ключей `--income`, `--speed`, `--tower-hp`, `--base-hp`, `--radius`, `--map`. Значение SHALL быть конечным положительным десятичным числом (включая дробную и экспоненциальную запись); единица означает нейтральный множитель относительно правил выбранной ревизии.

Корректные пары SHALL передаваться отдельными аргументами существующей команде `run` собранной арены из выбранной ревизии. Пустая или состоящая из пробельных символов строка SHALL оставлять прежний запуск без дополнительных аргументов. Существующие входы `matches`, `profiles`, `seed`, `seconds`, `upload_logs` SHALL сохранять свой смысл и умолчания. Новое поле MUST NOT менять выбранную ревизию или настройки других запусков.

#### Scenario: Запуск без множителей совместим с прежним

- **WHEN** `tuning_args` не задан либо содержит только пробельные символы
- **THEN** арена получает прежние аргументы из существующих полей без дополнительных ключей множителей

#### Scenario: Несколько множителей доходят до арены

- **WHEN** задано `--base-hp 0.8 --income 1.2` вместе с явными числом матчей, профилями, seed и ограничением времени
- **THEN** процесс арены получает обе пары отдельными аргументами вместе с неизменёнными параметрами остальных полей

#### Scenario: Любой из поддержанных ключей доступен

- **WHEN** каждый из шести перечисленных ключей по отдельности передан с положительным множителем, включая `1`, `0.8` или `1e-1`
- **THEN** соответствующая пара передаётся в `run` без переименования ключа и изменения числового смысла

#### Scenario: Два сравнения используют одну ревизию

- **WHEN** два отдельных запуска выбраны на одной неизменной ревизии с одинаковыми прочими входами и значениями `--base-hp 1` и `--base-hp 0.8`
- **THEN** команды запуска отличаются только множителем прочности базы, а для смены настройки не требуется править исходники или создавать ветки с разным балансом

### Requirement: Вход множителей проверяется до запуска и не исполняется

Workflow SHALL передавать `tuning_args` через окружение в адаптер, разбирающий данные в массив аргументов. Подставлять вход в исходный текст исполняемого скрипта, использовать `eval`, интерпретировать shell-подстановки, перенаправления или расширять маски файлов MUST NOT. Запуск арены SHALL происходить без shell-интерпретации массива аргументов.

Адаптер SHALL отвергать неизвестный ключ, повтор ключа, отсутствующее значение, лишний токен, форму `--ключ=значение`, кавычки и недопустимое число до создания процесса арены. Ошибка SHALL завершать шаг ненулевым кодом с понятной диагностикой; молча игнорировать ввод или запускать нейтральную настройку вместо ошибочной MUST NOT. Переопределять параметры других полей и служебные ключи через `tuning_args` MUST NOT.

#### Scenario: Опечатка не превращается в нейтральный прогон

- **WHEN** передано `--base-hpp 0.8` либо `--base-hp` без значения
- **THEN** шаг завершается ошибкой, называющей неизвестный ключ либо отсутствие значения, и процесс арены не создаётся

#### Scenario: Неверное число отвергается

- **WHEN** значение множителя равно `0`, отрицательно, содержит текст, задано как `NaN`, `Infinity` либо переполняет конечное число
- **THEN** шаг завершается ошибкой до запуска арены

#### Scenario: Повтор и чужие параметры не получают приоритет

- **WHEN** передано `--base-hp 1 --base-hp 0.8`, `--matches 1000` либо `--jobs 1`
- **THEN** шаг отвергает ввод до запуска арены, не выбирая первое или последнее значение и не меняя существующих полей

#### Scenario: Содержимое оболочки остаётся данными

- **WHEN** вход содержит точку с запятой, подстановку команды, обратные кавычки, перенаправление, кавычки или маску файлов вместо допустимой пары
- **THEN** вход отвергается, ни одна вложенная команда не исполняется и ни один процесс арены не создаётся

### Requirement: Инструкция ручной арены объясняет сравнение настроек

Документация арены SHALL описывать имя поля, шесть ключей, формат, пустое умолчание и смысл множителя. Для сравнения двух настроек SHALL быть объяснены два отдельных запуска на одной неизменной ревизии с одинаковыми seed, профилями, числом матчей и ограничением времени. Указывать абсолютный запас здоровья в качестве множителя MUST NOT.

#### Scenario: Владелец повторяет парное сравнение

- **WHEN** владелец следует инструкции в `apps/arena/README.md`
- **THEN** он может запустить нейтральный вариант и `--base-hp 0.8` на одном неизменном теге без правки кода, понимает уменьшение прочности на 20 процентов и сохраняет результаты отдельных запусков раздельно
