### Проверки шага

Команды запускаются отдельно из назначенного рабочего каталога; `<дерево>` означает назначенное дерево задачи. Зависимости подготавливаются штатным этапом implement. Покрытие команд проверено по `supervisor/config/stage-settings.json`: `PowerShell(npx vitest:*)`, `PowerShell(npx eslint:*)`, `PowerShell(npx prettier:*)`, `PowerShell(git -C:*)`.

```powershell
npx vitest run --root scripts arena-workflow.test.mjs
```

```powershell
npx eslint scripts/arena-workflow.mjs scripts/arena-workflow.test.mjs
```

```powershell
npx prettier --check .github/workflows/arena.yml scripts/arena-workflow.mjs scripts/arena-workflow.test.mjs apps/arena/README.md
```

Ожидается: точный argv для пустого ввода, всех шести ключей и сочетания `--base-hp 0.8 --income 1.2`, при этом существующие поля сохраняются; неизвестные, повторные, служебные ключи и некорректные числа не вызывают spawn; shell-содержимое не исполняется. Проверить сохранение ненулевого кода арены, ошибку запуска и завершение сигналом. Проверить реальную проводку нового поля в YAML. Тест передачи аргументов должен падать при удалении добавления tuning-пар из адаптера. Ни матчи, ни сборку арены ради этих проверок не запускать; подмена процесса должна записывать аргументы, а не считать симуляцию.

Ручная проверка документации: описаны имя поля, все ключи, ограниченный формат без кавычек и `=`, пустое умолчание, два запуска на одном неизменном теге с одинаковыми остальными входами, множители `1` и `0.8` и раздельные результаты. Уменьшение на 20 процентов не выдается за абсолютные 400 HP.

### Состав атомарного коммита

Разрешены только связанные с задачей изменения в четырёх рабочих файлах и обязательная отметка пункта 1.1 в собственном tasks.md. Добавлять все пять путей явным перечнем:

```powershell
git -C <дерево> add -- .github/workflows/arena.yml scripts/arena-workflow.mjs scripts/arena-workflow.test.mjs apps/arena/README.md openspec/changes/pass-arena-tuning-through-workflow/tasks.md
```

До коммита проверить и имена путей, и содержание индекса:

```powershell
git -C <дерево> diff --cached --name-only
```

```powershell
git -C <дерево> diff --cached
```

После коммита и немедленной отправки проверить содержание созданного коммита:

```powershell
git -C <дерево> show --stat --oneline HEAD
```

```powershell
git -C <дерево> show --format=fuller HEAD
```

Посторонние пути и несвязанные изменения внутри разрешённых файлов недопустимы. Файлы игры, основные спецификации, чужие изменения OpenSpec и временные результаты не входят в этот коммит. `proposal.md`, `design.md` и дельта уже доставлены коммитом проработки; пункт 1.1 не разрешает их несвязанную правку. Ожидание CI и балансные прогоны не являются пунктами этого плана.
