## Context

Задача 0253 выделена из 0168 и касается только вывода. База проверена 07.09.2026: `git -C <дерево> fetch origin` и `git -C <дерево> merge origin/main` завершились успешно, слияние ответило `Already up to date.`. Шаг 9 всё ещё содержит вызов .NET. Доказательство отказа `Command invokes .NET methods` дано постановкой; повторная проба запрещённой операции не требуется.

`scripts/deploy.mjs` прочитан целиком. `capture` использует `execFileSync` с `encoding: 'utf8'` и возвращает строку после `trim()`. Через него читаются путь Git, хеш, тема коммита, домен, health и HTTP-код. Ни один текущий вызов не переопределяет encoding. `run` использует `spawnSync` с `stdio: 'inherit'`; текущие вызовы не заменяют stdio. Так выполняются архивирование, передача файла и длительная удалённая сборка. Собственные русские сообщения печатаются через `console.log` и `console.error`.

## Goals / Non-Goals

Цель — убрать известный недопустимый подготовительный вызов из инструкции. Рабочий diff — удаление одной строки шага 9, если она ещё присутствует после освежения базы. Если её уже удалила влитая задача, собственная работа — проверка результата и запись доказательства в tasks. Подробные границы приведены в proposal: исправление `Push-Location` принадлежит 0252, а общий справочник предохранителей — 0169, которая также затрагивает нашу строку.

## Decisions

### Достаточно удаления строки

Присваивание свойства консоли PowerShell не является частью логики Node-сценария и не нужно для уже явно заданного декодирования `capture`. У `run` нет захваченной строки, которую сценарий должен декодировать: он передаёт потоки дочернему процессу. Поэтому переносить настройку encoding в `run` бессмысленно как решение проблемы наследуемого вывода. Это вывод по существующему пути данных, а не заявление о поддержке любых кодировок сторонних программ.

Альтернативы отвергнуты:

- Новое правило разрешений для вызова .NET не снимает предохранитель по пробе 0168.
- Замена вызова на `chcp`, переменные среды или профиль PowerShell добавляет неподтверждённую предпосылку запуска вместо удаления ненужной.
- Захват всего вывода `run` с последующей печатью задержал бы сообщения до завершения длительной команды. Асинхронная передача с декодированием потребовала бы переработать синхронный сценарий и обработку ошибок без установленного дефекта в них.
- Принудительная локаль дочерних процессов не устраняет отказ на строке инструкции и не обоснована постановкой.

### Единичная правка без новой нормы

Не добавлять ни общее запрещающее требование, ни тест на точное отсутствие строки: это восстановление согласованности примера с известным ограничением. Проверка — просмотр diff, отсутствие вызова и сохранность соседних команд. Обоснование отсутствия дельты сверено в proposal по основным требованиям и открытым дельтам.

### Общая строка с 0169 и порядок выполнения

Отправленные tasks (пункт 1.1) и design изменения `document-permission-independent-guards` требуют удаления того же `[Console]::OutputEncoding = [Text.Encoding]::UTF8` из шага 9. Это общее действие, а не только общий файл. В tasks 0169 уже есть условие «Не восстанавливать строки, уже исправленные соседней задачей»; на него опирается согласование без редактирования чужих артефактов.

Основной порядок: 0253 выполняет удаление и вливается до 0169; 0169 сохраняет результат и делает остальную работу своего пункта. Если 0169 успела влиться первой, 0253 после штатного fetch/merge подтверждает отсутствие строки и сохранность вызова сценария, находит удаляющий коммит в истории deploy.md и записывает его вместе с проверенным HEAD в собственном tasks. Коммит реализации тогда содержит только отметку и доказательство проверки. Это выполненная проверка существующего изменения, а не исход `moot`, который при заведённом изменении запрещён. Если источник удаления не подтверждён либо исчез сам запуск сценария, пункт не закрывается: исполнитель сообщает конкретную проблему по правилам имплементации.

При одновременной подготовке обеих веток повторная сверка после освежения базы перед вливанием определяет уже доставленное удаление. Не возвращать строку для искусственного повторения diff. Порядок и результат сверки назвать в PR и отчёте. Ждать чужое вливание отдельным пунктом tasks не требуется; основной путь 0253 не зависит от готовности 0169.

Отвергнуты: безусловное требование нового удаления (невыполнимо после 0169), восстановление строки ради удаления (возвращает дефект), перенос общего справочника в 0253 или изменение чужого tasks (выход за назначение). Отдельная новая зависимость архивации не нужна: наша правка не доставляет дельту.

Не менять номера шагов, четыре существующих довода, `Push-Location`, ключи запуска и описание фонового чтения. Сохранить уже влитую работу 0252 и остальные правки 0169: их перенос сюда не требуется.

## Risks / Trade-offs

- Наследуемые потоки сами по себе не гарантируют читаемость текста программы, использующей произвольную локаль → не обещать универсальную перекодировку. Подтверждённого дефекта такого рода в постановке нет; реальная новая проблема требует собственного примера, а не упреждающей замены всего вывода.
- Соседние задачи правят тот же шаг → перед реализацией освежить базу по правилам этапа и проверить содержимое diff, сохранив чужие изменения.
- Удаление строки не доказывает исправность всей выкладки → не запускать боевую выкладку ради проверки документа и не заявлять, что остальные известные препятствия сняты.

Игровой код, рассинхрон и реконнект не затрагиваются. Запреты sim на `Math.random`, `Date.now` и дробное состояние не затрагиваются; обновление golden-эталонов и `PROTOCOL_VERSION` не требуется.

## Migration Plan

Один коммит реализации: удалить оставшуюся строку либо подтвердить уже влитое удаление, отметить задачу с доказательством выбранного случая, проверить diff и формат документа, отправить коммит и открыть черновой PR. Изменение начнёт действовать в следующих сессиях, читающих обновлённый скилл. Миграции данных нет. Откат коммита с удалением вернёт известное препятствие запуска; откат коммита только с записью проверки изменит лишь tasks и не вернёт строку. Архивация без дельт выполняется с `--skip-specs` вне этапа проработки.
