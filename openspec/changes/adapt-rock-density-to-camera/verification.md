## Узкие проверки

- Vitest: `bake-density.test.ts` — 15; `rock-bake-queue.test.ts` — 13; `relief-render.test.ts` — 7; `scene.test.ts` — 10; `bootstrap.test.ts` — 1. - Установленная PixiJS проверена по исходникам: `Mesh.destroy` не освобождает геометрию. Временные буферы и Shader теперь уничтожаются явно; общая GlProgram и зерно сохраняются. Контроль проверяет отдельное освобождение геометрии и шейдера.

## Подготовка и ограничения

`pnpm install --frozen-lockfile --prefer-offline` выполнен после fetch/merge origin/main. Собственные зависимости shared, sim, protocol, netplay, ui, ai, bot и службы server/computer подготовлены адресными вызовами tsc для запуска тестов. Полный verify, матчевые тесты, арена и perf не запускались.

Штатный `tsx watch` остановился до игры на `uv_os_get_passwd` / ENOMEM. Применён уже существующий способ запуска собранных служб через Node, описанный в `playwright.perf.config.ts`; сам набор perf не запускался. Первый запуск Playwright завис при завершении служб; остановлена собственная exec-сессия. Адресное чтение процесса через `Get-CimInstance Win32_Process -Filter "ProcessId = 4436"` получило `Access denied`; повторов или изменения разрешений не было.

Окончательный запуск выполнен `node .matchlog/0040-playwright.mjs`: тот же узкий Playwright-тест, собственные порты 5242/3242/3243, перед запуском проверена их свобода; службы управляются собственными дочерними дескрипторами через существующий `scripts/perf-services.mjs`. Локальный конфиг наследует основной, исключая автоматический запуск служб. Процессы успешно завершены; прежние порты 5240/3240/3241 и окончательные порты больше не отвечают HTTP. Вспомогательные файлы остаются в игнорируемой `.matchlog/`.

Git сообщал о недоступном глобальном ignore-файле (`Permission denied`), но все операции Git завершались успешно. Ограничения доступа не менялись.

Старый расчёт постоянной плотности по числу скал удалён. Функция `rockBakeDensity` оставлена как тонкий совместимый вход для статического `fx-probe`, обнаруженного проверкой типов; игровая сцена использует `rockBaseDensity` и очередь.

Сценарий `framerate.perf.spec.ts` расширен: начальное построение заканчивается до окна, а внутри шести секундных выборок меняются масштаб и направление камеры; записываются снимки начального построения и адаптации. Его исполнение остаётся штатному этапу перед выкладкой. Наблюдавшееся отсутствие превышений в коротком браузерном сценарии не доказывает отсутствие просадок FPS; неделимый GPU-проход всё ещё может выйти за оценку.
