# Задачи

Порядок тот же, что и в соседних изменениях: сначала мерило, потом
правки. И одно особое условие — **проверка «не запереть себя» делается
раньше всего остального**. Без неё любое успешное сужение подхода
рискует обернуться против исполнителя, и отлаживать это на готовых
правилах размещения будет поздно.

## 2. Не запереть себя

- [x] 2.1 Проверка достижимости при постановке: после гипотетической
      постройки поле проходимости от своей базы должно достигать базы
      противника. Считать **только для выбранного места**, а не для
      каждого кандидата — иначе сотни обходов карты за решение.
      *Проверка:* юнит-тест на карте с единственным проходом — стена
      туда не ставится.
- [x] 2.2 Отказ по достижимости — не молчаливый: берётся следующее
      по ценности место, и это отражается в записи решения отдельной
      причиной.
      *Проверка:* причина доезжает до таблицы `attempt`.
      Перебор следующего места добавлен здесь же: прежде причина
      записывалась, но группа построек обрывалась на первом отказе.
- [ ] 2.3 Замерить стоимость: обход карты на постройку при нескольких
      постройках в минуту.
      *Проверка:* длительность матча на арене не выросла в разы.

## 3. Живучесть в выборе места под башню

- [x] 3.1 Считать прикрытие места своими башнями — суммарный урон в тик
      достающих до него. Функция симметрична существующей `incomingAt`.
      *Проверка:* юнит-тест — место в кольце двух своих башен получает
      вдвое большее прикрытие, чем в кольце одной.
- [x] 3.2 Считать, насколько новая башня прикроет уже стоящие.
      *Проверка:* тест — место рядом с одинокой башней оценивается выше,
      чем равное ему место в пустоте.
- [x] 3.3 Сложить с покрытием пути через энергию, а не подобранным весом.
      В комментарии объяснить, почему тяга к своим — величина
      для сравнения, а не правило: правило повторило бы прежний счётчик
      «не больше трёх башен рядом», который не различал скальное горло
      и чистое поле.
      *Проверка:* оба сценария спецификации — в узком месте собираются,
      в чистом поле расходятся.
      **Не воспроизвелись, и ожидание замысла оказалось обратным.**
      Замер: в чистом поле место отходит от своей башни на 6,4 клетки,
      в проходе шириной в три — на 7,1. Причина видна из самой мерки:
      в узком коридоре первая же башня накрывает почти весь путь рядом,
      ненакрытого возле неё не остаётся, и вторую гонит прочь; в широком
      коридоре ненакрытые клетки есть и в двух шагах, поэтому прикрытие
      успевает перевесить. Проверено то, что верно и проверяемо:
      на ОБЕИХ картах место смещается к своим против прежней мерки
      чистого покрытия, и меньшее покрытие под прикрытием обходит
      большее в пустоте.
- [x] 3.4 Использовать плотность потока при выборе места, ту же, что
      в оценке рубежей. Отдельного правила «удерживай важное место»
      не вводить.
      *Проверка:* тест — при равном покрытии выбирается место с большей
      плотностью.
      Плотность разрешает ничью, а не входит множителем: множитель
      удалённости, применённый к покупке, обращает в ноль ценность башни
      у собственной базы — беда, названная в `value.ts`.

## 4. Узкие места коридора

- [x] 4.1 Считать ширину коридора по глубине от базы одним проходом
      по `onPath` и `fromHome`. Обходов карты не добавлять.
      *Проверка:* тест на карте-восьмёрке — узкое место найдено там,
      где оно есть глазами.
      *Сделано вместе с 1.2:* мерка одна на прибор и на правило, иначе
      после правки мерили бы похожим, а не тем же.
- [x] 4.2 Ценность перекрытия обратна ширине на глубине клетки.
      *Проверка:* тест — клетка в горле оценивается выше клетки
      в широком месте.
      Прикрытие башни выражено в тех же долях подхода
      (`shieldWorthCells`), поэтому две задачи складываются, а не спорят.
- [x] 4.3 Записать в комментарии, чего мерка не умеет: она видит узость
      по глубине, а не топологию, и два раздельных прохода одинаковой
      глубины сложит в одну ширину. Ошибка безопасная — недооценка,
      то есть осторожность.
      *Проверка:* комментарий на месте; поведение при двух проходах
      проверено тестом и признано приемлемым.
- [x] 4.4 Сохранить локальное прикрытие башни стеной.
      *Проверка:* существующий тест на стену перед башней зелёный.

## 5. Величины в профиль

- [x] 5.1 Вынести все новые числа в `AiProfile` в человеческих единицах:
      вес живучести против покрытия, вес узости, сколько кандидатов
      перебирать при отказе по достижимости.
      *Проверка:* поиск по именам новых констант не даёт совпадений вне
      `profile.ts`.
      **Новых чисел вышло два, а не три.** «Вес живучести против
      покрытия» заводить оказалось нечего: множитель выведен из времени
      гибели атакующих — `(D + C) / D`, — то есть отношение величин одной
      природы, и подбирать в нём нечего. Спецификация этого прямо
      и требует: «Отдельных подобранных весов вводиться MUST NOT».
      В профиль ушли `shieldWorthCells` (во сколько долей подхода ценится
      щит своей башне) и `sealRetries` (сколько мест перебрать при отказе
      по достижимости).
