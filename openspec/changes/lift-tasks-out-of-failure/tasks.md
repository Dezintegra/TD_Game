# Задачи

Каждый пункт — отдельный коммит, отправляемый сразу. Черновой pull request
открывается сразу после первого: до его появления пуши в ветку не запускают
проверок вовсе.

## 1. Зеркало состояния в служебном блоке

- [ ] 1.1 Писать в служебный блок состояние, записанное конвейером
      (`metaOf`), и читать его отдельным полем задачи, не подменяя колонку
      (`parseCard`). Передать `metaOf` состояние `failed` при уносе карточки
      в карантин. Проверяемо: `card.test.mjs` — собранный блок несёт колонку
      задачи, разбор возвращает её отдельно от `status`;
      `backlog-trello.test.mjs` — карантин пишет в блок `failed`, а не
      прежнюю колонку
- [ ] 1.2 Открыть черновой pull request на ветку задачи. Проверяемо:
      `gh pr checks <номер>` перечисляет проверки, а не молчит

## 2. Причина отбраковки переживает лежание в «Ошибке»

- [ ] 2.1 Записывать в задачу причину отбраковки при переходе в `failed`:
      время, этап (унаследованный `returnTo`) и текст причины дословно;
      возить её служебным блоком. Проверяемо: `task-file.test.mjs` — переход
      в `failed` даёт заполненную отметку, переход в рабочее состояние её
      гасит; `card.test.mjs` — отметка переживает сборку и разбор блока

## 3. Чистый счёт возврата

- [ ] 3.1 Завести `returnTargets(task)` — законные для задачи колонки
      из таблицы маршрутов плюс `closed`, — и `absorbReturn(task, { now })`:
      обнуление счётчиков, гашение `returnTo` и причины, рост счётчика
      возвратов, новая отметка смены состояния. Проверяемо:
      `task-file.test.mjs` — прогон даёт нули у всех счётчиков, единицу
      у возвратов и пустой `returnTo`; перечень колонок для `feature`, `run`
      и `note` разный и совпадает с таблицей

## 4. Решение сканера

- [ ] 4.1 Распознавать ручной переезд — по расхождению зеркала с колонкой,
      а при отсутствии зеркала по непустому `returnTo` в рабочем состоянии —
      и выдавать действие возврата прежде переноса отчётов. Помечать задачу
      занятой на этот оборот: ни отчёта, ни сессии, ни опроса по ней больше
      не назначается. Проверяемо: `scan.test.mjs` — пять случаев: возврат
      по зеркалу, возврат по старой карточке без зеркала, отсутствие возврата
      у нетронутой задачи, единственность действия по возвращённой задаче,
      порядок действий в обороте

## 5. Исполнение возврата

- [ ] 5.1 Погасить отчёты задачи и забыть сессии её этапов: `dropReports`
      в наборе действий и `forgetSessions` у супервизора. Проверяемо:
      `io.test.mjs` — гасятся все отчёты задачи и только её;
      `supervisor.test.mjs` — после забывания этап начинается заново, а не
      возобновляется
- [ ] 5.2 Исполнить возврат: приём законной колонки с записью журнала
      (дата отбраковки, этап, причина словами, номер возврата, обнуление
      счётчиков, новое состояние) и отказ незаконной с возвратом карточки
      в «Ошибку» и перечнем законных колонок. Проверяемо:
      `execute.test.mjs` — законный возврат обнуляет счётчики и пишет
      комментарий; незаконный возвращает карточку и счётчиков не трогает;
      отсутствие сохранённой причины называется прямо, а не пустой строкой

## 6. След этапа в записи об отбраковке

- [ ] 6.1 Дописывать в запись об остановке имя изменения, ветку с признаком
      наличия дерева, номер pull request и состояние его проверок.
      Проверяемо: `execute.test.mjs` — запись содержит все четыре сведения;
      при молчащем `gh` состояние проверок названо неизвестным, а остановка
      состоялась

## 7. Документы

- [ ] 7.1 Описать ручной возврат в `manage/README.md` (что делает человек,
      что за него делает конвейер, куда законно тащить карточку)
      и в `plugins/pipeline/README.md` (зеркало состояния и порядок разбора).
      Проверяемо: описанное не противоречит таблице переходов и разделу
      о карантине негодных карточек
