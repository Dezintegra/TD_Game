## Requirements
### Requirement: Единый набор корневых команд

Корневой `package.json` SHALL предоставлять команды `dev`, `build`, `typecheck`, `lint`, `format`, `test`, `test:match`, `test:all`, `verify`, `verify:all` и `e2e`.

Команды, работа которых распадается по пакетам — `build`, `typecheck`, `test` и `test:match`, — SHALL делегировать выполнение Turborepo, который обходит пакеты в порядке их зависимостей. Команды `lint`, `format` и `e2e` SHALL выполняться единым проходом по репозиторию: они не разбиваются по пакетам и в оркестрации не нуждаются. Команды `verify` и `verify:all` SHALL быть последовательностями из перечисленных выше и собственной работы не выполнять.

Команда `test` SHALL прогонять только быстрый набор, `test:match` — только матчевый, `test:all` — оба.

#### Scenario: Сборка идёт в порядке зависимостей

- **WHEN** разработчик выполняет `pnpm build` в корне
- **THEN** `@td/shared` собирается раньше `@td/sim`, `@td/protocol` и `@td/ui`, а приложения `client` и `server` — после всех библиотек

#### Scenario: Одна команда поднимает всю среду разработки

- **WHEN** разработчик выполняет `pnpm dev`
- **THEN** параллельно стартуют дев-сервер Vite для клиента и сервер разработки с автоперезапуском, оба остаются в наблюдающем режиме

#### Scenario: Быстрый набор идёт по умолчанию

- **WHEN** разработчик выполняет `pnpm test` в корне
- **THEN** прогоняются только тесты, не помеченные как матчевые, а ни один файл `*.match.test.ts` не запускается

#### Scenario: Матчевый набор запускается отдельной командой

- **WHEN** разработчик выполняет `pnpm test:match` в корне
- **THEN** прогоняются только файлы `*.match.test.ts`, а быстрый набор не запускается

### Requirement: Кеширование результатов задач

Turborepo SHALL кешировать результаты задач `build`, `typecheck`, `test` и `test:match` по хешу входных файлов и конфигурации. Повторный запуск задачи без изменений во входных данных SHALL завершаться из кеша, не выполняя работу заново.

Во входные файлы задач `test` и `test:match` SHALL входить конфигурация Vitest пакета наравне с исходниками: правка конфигурации меняет состав и окружение прогона, и результат от неё зависит не меньше, чем от кода.

#### Scenario: Повторный запуск без изменений берётся из кеша

- **WHEN** `pnpm build` выполняется дважды подряд без правок в исходниках
- **THEN** второй запуск помечает задачи как выполненные из кеша и завершается заметно быстрее первого

#### Scenario: Правка в библиотеке инвалидирует зависимые задачи

- **WHEN** изменяется файл в `packages/shared` и запускается `pnpm build`
- **THEN** пересобирается `@td/shared` и все зависящие от него пакеты, а независимые пакеты берутся из кеша

#### Scenario: Правка конфигурации тестов сбрасывает кеш

- **WHEN** изменяется `packages/sim/vitest.config.ts` и запускается `pnpm test`
- **THEN** задача `@td/sim#test` выполняется заново, а не отдаётся из кеша

#### Scenario: Правка в клиенте не пересчитывает тесты ядра

- **WHEN** изменяется файл только в `apps/client` и запускается `pnpm test`
- **THEN** задача `@td/client#test` выполняется, а `@td/sim#test` и `@td/ai#test` берутся из кеша

### Requirement: Воспроизводимость окружения

Репозиторий SHALL фиксировать версию Node.js и версию pnpm в корневом `package.json` через поля `engines` и `packageManager`. Файл `pnpm-lock.yaml` SHALL быть закоммичен.

#### Scenario: Несовместимая версия Node останавливает установку

- **WHEN** `pnpm install` запускается на версии Node.js, не удовлетворяющей `engines`
- **THEN** установка завершается ошибкой с указанием требуемого диапазона версий

#### Scenario: Установка в CI не меняет lockfile

- **WHEN** в CI выполняется `pnpm install --frozen-lockfile`
- **THEN** установка проходит успешно и `pnpm-lock.yaml` остаётся неизменным

### Requirement: Горячая перезагрузка клиента

Дев-сервер клиента SHALL поддерживать горячую замену модулей. Правка в React-компоненте HUD SHALL применяться без полной перезагрузки страницы и без потери состояния игрового цикла PixiJS.

#### Scenario: Правка HUD не сбрасывает сцену

- **WHEN** во время работающего `pnpm dev` изменяется разметка React-компонента HUD
- **THEN** обновлённый HUD появляется в браузере, а сцена PixiJS продолжает рендериться без переинициализации

### Requirement: Библиотеки публикуют типы

Каждый пакет из `packages/*` SHALL экспортировать декларации типов и указывать точки входа через поле `exports` с раздельными путями для типов и исполняемого кода.

#### Scenario: Автодополнение работает через границу пакета

- **WHEN** в `apps/client` импортируется символ из `@td/sim`
- **THEN** редактор показывает его тип и сигнатуру, а `pnpm typecheck` проходит без ошибок разрешения типов
