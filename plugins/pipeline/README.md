# Конвейер агентской разработки

Очередь работ, автомат состояний и планировщик, который берёт задачи сам,
заводит под них сессии и доводит до продакшена. Владелец продукта участвует
двумя действиями: кладёт запись в бэклог и отвечает на вопрос, если конвейер
спросит.

Каталог переносится в другой проект копированием. Всё, что зависит
от репозитория, названо в `pipeline.config.json`; в коде зашитых путей
и команд нет.

## Что здесь лежит

```
plugins/pipeline/
  pipeline.config.json      настройка под этот проект
  config/
    defaults.mjs            умолчания и перечень обязательных значений
    transitions.mjs         состояния, маршруты, цена каждого состояния
    settings.snippet.json   разрешения, без которых конвейер встаёт
  lib/                      решающая часть, покрытая тестами
  bin/
    cycle.mjs               один прогон оркестратора
    board.mjs               перерисовать доску задач
  skills/                   что делает сессия на каждом этапе
```

## Как это работает

**Оркестратор** просыпается по расписанию, читает бэклог и реестр, считает
решение детерминированным скриптом и раскладывает работу по слотам. Сам он
ничего не выполняет.

**Исполнители** — постоянный пул задач планировщика. Проснувшись, исполнитель
читает свой слот: пусто — выходит через секунду, есть назначение — берёт
в работу, делает ровно один переход состояния и завершается.

Слоты и есть квота: сколько их заведено, столько работ и идёт одновременно.
Считать нечего.

## Установка в новый проект

1. Скопировать каталог `plugins/pipeline/` и завести `manage/` по образцу
   (схема, каталоги задач и журналов, файл вопросов).
2. Заполнить `pipeline.config.json`: имя удалённого репозитория и главной
   ветки, каталог рабочих деревьев, команды проверки, выкладки и замеров.
   Обязательные значения перечислены в `config/defaults.mjs`; без них
   конвейер останавливается с внятным сообщением, а не подставляет умолчание
   наугад.
3. Слить `config/settings.snippet.json` в местные настройки разрешений.
   **Шаг обязательный.** Любой неотвеченный запрос подтверждения в автономной
   сессии не тормозит её, а запирает её задачу планировщика насмерть:
   незавершённый прогон не даёт начать следующий, и слот молчит навсегда.

   Про запись файлов отдельно: в обычном режиме она спрашивает подтверждение
   **всегда**, а конвейер пишет много. Первый живой запуск встал ровно на этом —
   на снимке сессий. Правила названы каталогами, а не «разрешить всё»:
   за пределы репозитория конвейер не пишет, и незачем ему это позволять.

4. Завести пул задач планировщика руками: оркестратор с расписанием раз
   в пять минут и исполнители — два рабочих, ревьюер, одиночка для замеров
   и выкладки. **Создавать задачи планировщика на ходу конвейер не умеет
   намеренно:** этот вызов требует подтверждения человека при каждом
   обращении и не предлагает разрешить его навсегда.
5. Прогнать `node plugins/pipeline/bin/cycle.mjs` вручную и посмотреть, что
   он собирается делать. По умолчанию он ничего не делает — только печатает.

## Ввод в строй по шагам

Включать всё разом не стоит: конвейер вливает и выкладывает без человека.

1. **Тень.** Цикл работает без `--execute`. Пара суток такого режима
   показывает, верно ли он читает картину.
2. **Одна задача.** Один рабочий слот, только типы `run` и `note` — самые
   дешёвые маршруты, не создающие веток.
3. **Полный маршрут** при одном слоте, вливание пока вручную.
4. **Автовливание** с тремя предохранителями: зелёный CI, чистое ревью,
   отсутствие конфликтов.
5. **Автовыкладка** и второй рабочий слот.

Откат на любом шаге — файл `.pipeline/pause` либо отключение задачи
планировщика. Ни бэклог, ни журналы при этом не теряются: это обычные файлы
в репозитории.

## Что конвейер не делает

**Не удаляет рабочие деревья по своему усмотрению.** Свои он узнаёт
по строгому виду имени ветки; всё остальное — включая деревья, заведённые
человеком вручную, — называет и не трогает. Уборка возможна только после
доказанного вливания pull request.

**Не пишет за пределы рабочего каталога.** Запись наружу требует
подтверждения человека и запирает автономную сессию.

**Не отправляет чужие коммиты.** Найдя в главной ветке неотправленный коммит
не от конвейера, он не публикует его и откладывает заведение деревьев:
дерево ответвляется от удалённой ветки и вышло бы без этих правок.

**Не принимает продуктовых решений.** Упёршись в вопрос уровня продукта,
сессия завершается с исходом `question`, а вопрос попадает
в `manage/questions.md`.

## Хозяйство вне гита

`.pipeline/` — реестр деревьев, отчёты сессий, слоты, замок цикла, журнал
цикла и рубильник паузы. В репозиторий не едет намеренно: бэклог общий
на все машины, а деревья и замки существуют только на своей.

Журналов два, и путать их не надо. Журнал задачи (`manage/journal/<id>.md`)
хранит состояние задачи и решения по ней. Журнал цикла (`.pipeline/cycle.log`)
хранит работу самого конвейера: отказы отправки, хвосты, конфликты. Иначе
запись о неудавшейся отправке пришлось бы отправлять — и она не уехала бы
ровно тогда, когда нужнее всего.

## Проверки

```bash
npx vitest run --root plugins/pipeline
```

Быстрые, без единого настоящего вызова git, заведения дерева и сессии:
исполнитель команд везде приходит доводом. Поэтому дорогие и редкие ходы
событий — гонка за отправку, пропавшая сеть, конфликт перевыкладки, чужая
правка в дереве — проверяются за миллисекунды.
